## 审计目标

对国学传统文化综合平台做一次全业务链路的端到端审计，覆盖后端 50+ 模块和管理后台全部视图。

---

## 审计维度（逐项检查，不可跳过）

### 一、资金流向全链路

从用户付钱到平台结算的每一条资金路径，逐一追踪闭环：

#### 1. 用户购买商品
下单 → 支付（微信/支付宝/云闪付/虚拟币）→ 回调验签 → 订单状态变更 → 分账 → 退款/售后

| 检查点 | 说明 |
|--------|------|
| 支付回调验签 | 各支付渠道回调是否都有验签？ |
| 订单状态机 | 待支付→已支付→已发货→已收货→已完成 / 待支付→已取消 / 已支付→退款中→已退款，是否完整？ |
| 超时取消 | 超时未支付是否自动取消？ |
| 部分退款 | 是否支持部分退款？ |

#### 2. 虚拟币体系
充值 → 到账 → 消费 → 冻结 → 解冻/扣除

| 检查点 | 说明 |
|--------|------|
| 充值回调幂等性 | 重复回调是否导致重复入账？ |
| 余额负数防护 | 是否存在并发消费导致余额为负？ |
| 冻结解冻配对 | 冻结与解冻是否成对出现，有无遗漏？ |

#### 3. 分佣结算
商品售出 → 按比例分佣 → 运营商/推客账户入账 → 提现申请 → 审核 → 打款

| 检查点 | 说明 |
|--------|------|
| 分佣精度 | 比例计算是否有浮点精度损失？ |
| 提现限额 | 是否有金额下限/上限？ |
| 打款失败回滚 | 打款失败时账户余额是否回滚？ |

#### 4. 对账
支付渠道账单 vs 平台订单 vs 分佣记录，是否有三方对账逻辑？

#### 5. 退款
原路退回 vs 退虚拟币，退款审批流程，退款后分佣是否回收？

---

### 二、管理后台功能完整性与合理性

逐一比对后端 API（`apps/server/src/modules/`）与管理后台页面（`apps/admin/src/views/`）：

#### 检查维度

| 类型 | 例子 |
|------|------|
| **有后端但无入口** | 后端支持批量退款/封禁/IP白名单，但管理后台找不到按钮 |
| **有页面但功能残缺** | 列表页有"删除"但没有"批量操作"、有筛选但无日期范围、有导出但无分页 |
| **操作不合理** | 物理删除而非软删除、敏感操作无二次确认、高危操作（退款/封号/改价）无审批流 |
| **数据展示不合理** | 金额未显示货币符号/未格式化、时间未做时区转换、枚举值展示为英文代码而非中文 |

---

### 三、跨模块业务一致性

#### 用户注销/封禁后
- 其订单/内容/评论/圈子/收藏是否做对应处理？
- 资金是否可正常提现？

#### 分站模式
- 数据隔离是否在各模块一致生效？
- 运营商只能看到自己分站的数据吗？

#### RBAC 权限体系
- 权限定义是否在所有管理后台页面正确应用？
- 有没有越权路径（普通管理员能操作超管功能）？

#### FeatureFlag
- 功能开关控制的特性，关闭后前后端是否都正确隐藏/拦截？

---

### 四、边界与异常场景

- 并发下单是否可能超卖？
- 支付回调与用户取消同时发生如何处理？
- 优惠券过期/活动结束的临界时刻下单如何处理？
- 涉及多表资金变动的操作是否在同一事务内？
