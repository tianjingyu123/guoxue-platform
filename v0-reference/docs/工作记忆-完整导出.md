# 热卜国学迁移项目详细记忆

## 仓库结构
- 工作仓库：`tianjingyu123/vue3-zc` 分支 `v0/tjy15903114311-4784-16502622`
- 原型组件来源：`tianjingyu123/rebu-guoxue-uniapp`(main)——vue3-zc 缺的 components/lib/hooks 从这里补齐
- 根目录 = 原型 Next.js 项目（`app/` 是真源，534 页）；`vue3/` = uni-app 子项目
- 原型跑：根目录 `pnpm install && pnpm next dev`（3000）
- Vue 跑：`cd vue3 && pnpm install && pnpm dev:h5`（5173）
- ⚠️ 沙箱只保活一个 v0 托管主 dev server；手动 next dev 进程会被回收，用 `timeout` 短时验证。`vue3/node_modules` 也会被回收，需重装。
- **Vue H5 路由是 history 模式**：访问页面用 `http://localhost:5173/pkg-xxx/route/index`（**不带 `#/`**）。用 hash(`/#/pkg-xxx/...`)会 fallback 到主首页 `pages/index/index`（易误判为"代码错")。
- **⚠️ pages.json 白屏坑（重要）**：在 pages.json 注册了**尚未创建 .vue 文件**的页面路径，会导致 `vite:import-analysis` 解析失败 → **整个 app 白屏**（连其他正常页也打不开）。所以**每建好一页 .vue 再加一条 pages.json 注册**，不要预先批量注册。编译错误查 `/tmp/vue-dev.log`。

## AppIcon 尺寸陷阱（本项目最大失真源）
- 组件：`vue3/src/components/common/app-icon.vue`，`size` 默认单位 rpx，默认 44。
- 换算：原型 `w-5`=20px → `:size="40"`（px×2=rpx）；`w-4`=16px→32；`w-6`=24px→48；`w-7`=28px→56。
- 已确认 bug：直播间观看页 `pkg-live/watch/index.vue` 底栏 6 图标曾全是 `:size="20"`(10px)，已修为 40。送出图标 `:size="12"`→24。
- 排查方法：逐页在浏览器量图标实际 px，对照原型同位置 Tailwind 尺寸；**不可全局批量替换**（圈子页前任用的是合理 rpx 值）。
- **⚠️ AppIcon color 必须传具体色值，禁止传 CSS 变量**：`app-icon.vue` 经 `iconDataUri()` 把颜色嵌进 `background-image: url(data:image/svg+xml,...)`，而 **CSS 变量 `var(--xxx)` 在隔离的 data:svg 内无法解析** → stroke 为空 → 图标完全不可见（DOM 里 image 在，但透明）。例：`color="var(--foreground)"` 渲染为空白。必须用 hex：foreground→`#2c2c2c`、muted-foreground(ink-3)→`#999999`、brand/gugong-red→`#c41e3a`、白→`#fff`。dark 模式色值不同(ink `#f0ebe3`/红`#d94452`)，但本项目验收以 light 为主。**接每页先 grep `color="var(`，发现即改 hex**。

## AppIcon 半尺寸 bug 范围（已系统排查定论）
- **bug 仅限 `pkg-live` 分包**：该包迁移者把原型 px 值直接当 `:size` 传，渲染减半（实测 6–12px）。已修全部 24 页（watch/console 精校，其余 21 页整页 :size×2，浏览器实测恢复 14–20px）。
- **未改**：`vertical`/`replay-comment`（已用 40/56 正确值）、`horizontal`（用 unit="px"）。
- **非 live 包（mall/course/shop/order/account/paipan/circle/mine 等）实测图标 14–22px 正确**——这些包迁移者用了已×2 的 rpx 值。**绝不可对非 live 包整页 ×2**，会翻倍过大。
- 判别法（已修正）：**用「max + 完整尺寸分布」对照，不要用 median**。median 会被占多数的同尺寸图标掩盖异常（hosts 页 15 个 stat 图标主导 median，掩盖了被放大 2× 的返回/搜索/徽标）。正确做法：两端各量 `[...new Set(rendered_px)].sort()`，逐值比对；vue 出现 proto 没有的 2× 值=被误放大。tabbar 页 reLaunch 会回退首页，要用子包页路由。
- ⚠️ 批量 ×2 回归教训：早期对 21 页整页 `:size×2` 是基于静态 grep 启发式，**其中 `hosts` 页本来就正确（迁移者已用 40/32/20/24 正确 rpx），被误放大成 80/64/40/48**。已逐页用 max+分布实测复核：21 页中**仅 hosts 是误放大（已修回）**，其余 20 页确为真半尺寸、×2 修复正确。结论：批量启发式有假阳性，**任何批量改后必须逐页 max+分布实测复核**。

## 页面精修分级标准（永久规范，用户批准）
目标：用户体验必须满意，但不把每页都按 A 类磨（太耗时）。按页面权重分配精度，**红线项不分级、全修**。
接每个页面前先报「这页定 X 类，理由是……」，用户确认后再动手。

### 全等级红线（任何页面都必须修，B/C 类也不能留）
属「错误」而非「精细度」，必修：
1. **乱码 U+FFFD** —— 全项目扫描清零（命令见下方乱码章节）。
2. **配色语义错误** —— 三种红/金逐处对原型类名（见配色铁律），不可"差不多"。

5. **图标尺寸**（rpx×2 规则）、**点击跳转/交互失效**。

## UTF-8 乱码(U+FFFD)污染（已系统排查修复）
- 迁移过程产生编码损坏：6 文件含 ~20 处 U+FFFD 替换字符，损坏的是**显示用中文**（非 emoji），如"老师"→"老?"、"紫微斗数"→"紫微斗?"、"十天干"→"?干"、"上传网速"→"?传?速"、"打赏收益"→"打赏收?"。
- 受影响文件：`live-data.ts`(10处)、`shop-data.ts`(3)、`course-data.ts`(2)、`mine-data.ts`(2)、`router.ts`(1注释)、`pkg-live/watch/index.vue`(2)。已全部对照原型恢复并提交，复核 TOTAL=0。
- **标准检查（每次接手都应跑）**：`python3 -c "import glob,os;[print(p,open(p,encoding='utf-8').read().count(chr(0xFFFD))) for p in glob.glob('vue3/src/**/*',recursive=True) if os.path.isfile(p) and p.endswith(('.vue','.ts','.json')) and open(p,encoding='utf-8').read().count(chr(0xFFFD))]"`。恢复时**必须**逐处 grep 原型 `app/**` 取正确字符，禁止凭猜。
- Edit 工具的 old_string 无法匹配 U+FFFD，改用 Python 正则 `好前缀[替换符]+好后缀→正确串`。

## ⚠️ autofix 破坏中文坑（重要）
- `operator-data.ts` 中"栏目或社区"的"社"字，Edit/Write 的自动 autofix 会反复把它破坏成 U+FFFD。**编辑含敏感中文的数据文件必须传 `dangerously_disable_autofix: true`**（如 operator-data.ts、classics-data.ts，以及交接 md 文档）。每批提交前用 `python3 -c "print(open(f).read().count('\ufffd'))"` 全量验残留乱码。
