## 已完成

### App 支付宝

- 沿用汇付 `A_NATIVE` 交易，不改变服务端下单、查单和入账口径。
- Android 优先调用支付宝官方 SDK 的 `payInterceptorWithUrl` 将汇付返回地址交给支付宝处理；SDK 不可用时退回已验证的支付宝 Scheme。
- `manifest.json` 已声明 Android 支付宝 SDK，正式云打包后才会进入 SDK 路径。
- 拉起或 SDK 返回不作为到账依据，页面继续按原订单查询服务端状态。

### App 微信

- App 微信按钮改为拉起既有微信小程序的支付页，小程序继续使用现有直连微信商户的 JSAPI 支付。
- App 向服务端申请该订单的微信小程序短链接；服务端先校验订单属于当前用户且仍待支付，再生成只含订单 ID 的链接。小程序重新读取金额与订单归属。
- 支付宝仍可作为 App 默认支付方式；微信作为用户主动选择的备用方式。
- 已修正安卓收银台曾只展示支付宝的过滤逻辑；商城及通用购买面板现在均按“支付宝默认、微信可选”展示，安卓门禁同时允许两种已接通方式。
- 使用微信官方 `wxaurl.cn` 短链接拉起，正式构建不再依赖人工抄录 `gh_` 原始 ID。

### 第三方排盘

- App 在分享发生时读取当前第三方 WebView 地址，避免切换盘面后继续分享旧地址。
- `/app_p1.php` 分享地址转换成第三方公开 `/p1.php` 地址；拒绝登录、授权、支付、订单、签名和未知参数链接。
- 微信好友和朋友圈优先分享 `gx.yrydai.com` 的热卜 H5 承接页；承接页内嵌第三方公开盘面。截图及系统分享保留作降级出口。
- 当前安全白名单只接受已知公开参数。首次拿到真实结果链接后须核对其参数集合；未知参数不会被静默放行。

## 发布顺序与回退

1. 随服务端候选部署订单短链接接口；目标环境已有的小程序 AppID/AppSecret 用于调用微信官方接口。
2. 构建新的 Android 安装包；支付宝 SDK 配置只有重新打包后生效。
3. 用测试订单分别验收支付宝、微信小程序支付；只以服务端订单状态与支付通知为准。
4. 部署 H5 承接页后，用真实排盘链接在微信接收端验证内嵌和返回。
5. 验收通过后再发布版本；本次代码不要求生产数据库迁移。

回退时恢复上一版服务端、APK/H5 产物即可。数据库结构未改；未完成订单仍按原查询与关闭规则处理。若支付宝 SDK 路径异常，可先关闭新包发布并保留旧 Scheme 版本；若微信短链接调用未通过，隐藏 App 微信选项，支付宝仍可单独使用；若排盘 H5 内嵌不稳定，保留截图分享，不发布网页卡片入口。
