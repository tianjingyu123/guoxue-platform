未注册的 3 个遗留文件为 `distribution.vue`、`calendar.vue`、`analytics.vue`；它们没有在页面清单中，也未找到从现有圈子页面到这些路径的导航。`calendar.vue` 含 2026 年 6 月硬编码示例活动，`analytics.vue` 是全零静态展示；不能将其描述为在线功能，更不能仅因源码存在就对用户开放。后续若要恢复入口，必须先替换为真实数据和完整失败/权限状态。

另发现“我的圈子”中的“我的活动”快捷入口通向已停用、固定返回空列表的兼容接口，造成可点击但没有真实内容的死路。现已将此入口改为“圈内动态”，直接打开圈子广场中已接入的成员近期动态分区；历史 `/circles/activities` 路由仅保留旧链接兼容，不再作为当前活动能力宣传。

个人概览复核又发现三个容易误导的断点：圈子事务页“帖子”数字原来会跳到圈子列表；“发布审核与草稿”实际只有审核记录；我的圈子列表把统计接口失败默认为零。现分别改成纯“发帖数”、如实标“发布审核”，并独立加载圈子列表与内容统计；统计失败显示未确认并可重试，列表失败也不显示虚假的零个圈子。搜索/角色筛选无匹配时可一键清除，原生输入框文本与筛选状态同步；列表使用真实圈子封面，无图才用生成封面。通用封面在图片加载前以主题底色衔接，避免透明空框。隔离 H5 回归 `tests/release/circle-my-overview-browser.mjs` 覆盖上述状态、封面显示和错误恢复；截图保存在 `artifacts/circle-my-overview-20260922/`。该回归只证明本地浏览器行为，仍需小程序真机复核。

列表完全为空或读取失败时，搜索与角色筛选不再露出无效的“0”选项；角色筛选保留键盘可操作状态。隔离回归覆盖真实空列表和读取失败两种情况。

上述改动在隔离工作树重跑移动端类型检查、圈子概览交互回归及既有圈子体验回归（11 项）均通过。最终源码的小程序正式构建通过 WXML 615 文件、文本兼容 2683 文件校验；主包 1.63 MB、保守上传口径 1.92 MB（余量 0.08 MB），`pkg-circle` 1.00 MB，最大分包 `pkg-paipan2` 1.94 MB。包量只是本次候选结果，后续整合必须重算。

排行榜专项复核发现：排行榜 API 失败原被吞成空列表，页面的重试态无法出现；不足三条时仍绘制空的第二、三名；“最活跃”按成员数取数却用帖子数展示。现使独立排行榜页区分读取失败与真空，领奖台只画实际记录，前三名可点击进入圈子，触控区和键盘操作补齐。原“最活跃”明确改为“综合”，口径为成员数＋帖子数，服务端先按同一口径排序再分页，界面显示同一数字。这个综合分只是现有成员与内容数量之和，不代表真实日活或发帖频率。`circle-post.service.spec.ts` 验证服务端排序和分页（3/3 通过）；`tests/release/circle-ranking-browser.mjs` 用隔离数据覆盖失败恢复、1/2/3 条、入口跳转与 320/390px 截图。服务端构建、移动端类型检查及小程序正式构建均通过；真实环境排行数据和小程序真机仍未覆盖。

排行榜右上角装饰图标也接入微信胶囊真实边界避让；这项仅有代码与构建证据，胶囊实际位置需开发者工具和真机复核。

继续从个人入口检查发现，“我的圈子”快捷区的“我的勋章”未传圈子 ID，而徽章接口必须指定圈子，点击必定报错。快捷区改为可直接打开的“圈子排行”；历史无 ID 徽章链接保留兼容，但会提示先选圈子并提供返回选择入口。嘉宾管理的右上角邀请按钮和徽章页计数按微信胶囊真实边界避让，返回/邀请控件扩大触控区。隔离浏览器覆盖了快捷入口和徽章缺参回退；胶囊位置仍需小程序运行环境确认。

目前发现的已知边界：圈内动态聚合只取前 6 个已加入圈子各 2 条，不是全量消息中心；圈内课程和商品当前展示接口首批近期资源，不是完整目录；小程序正式胶囊避让和所有页面触控、真实 AI/语音、支付/退款/审核及弱网链路均缺真机与目标环境证据。咨询新分页端点、本人问答新端点与移动端必须同批发布。小程序包量接近限制，后续合并每次均需重新测算。
