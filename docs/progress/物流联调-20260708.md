# 物流查询真机联调 — 20260708

快递100（kuaidi100）密钥今日解冻，`third_party.kuaidi100` 已配。本轮验证签发链路并打通前端实时轨迹。

## 一、链路现状（Read 摸底结论）

| 层 | 位置 | 说明 |
|---|---|---|
| 后端签名服务 | `apps/server/src/modules/shop/logistics.service.ts` | `queryTrack(no, company?)`：指定公司→`queryWithCompany`，否则/失败→`autoDetect`。签名=`MD5(param+apiKey+customer).toUpperCase()`。归一化返回 `{state,isCheck,company,logisticsNo,tracks:[{time,status,location}]}`；apiKey 缺失时返回 `{track:[],state:'unknown',message:'物流服务未配置'}` |
| 后端端点 | `shop.controller.ts:836` `GET /shop/logistics/track?no=&company=` | **无鉴权守卫**，直调 `queryTrack`。另有 `GET /shop/orders/:id/logistics`（`getLogistics`，JWT，返回 `{order, logistics}`，logistics 来自 DB 表 `OrderLogistics`，含手工存储的 `trackingData`） |
| 前端页面 | `apps/mobile/src/pkg-order/logistics/index.vue` | 三态齐全（loading/error+重试/空态由空 tracks 体现）；时间线渲染 `data.tracks`；`orderApi.logistics(orderId)` 取数 |
| 前端数据层 | `apps/mobile/src/lib/order-data.ts` | `logistics()` 原仅调 `getLogistics`，`adaptLogistics` 把 DB `trackingData` 转时间线 |

### 关键发现（本轮核心）
**实时快递100端点 `/shop/logistics/track` 此前从未被前端调用。** 前端物流页只渲染 DB 表 `OrderLogistics.trackingData`（管理员手工录入的静态数组）。即使 kuaidi100 密钥可用、端点功能正常，用户侧也看不到实时轨迹——快递100集成实际处于「悬空」状态。

## 二、生产签发链路验证（已通过）

- 短信登录：`redis-cli SET 'sms:code:LOGIN:13912340099' '246810' EX 600` → `POST /auth/login/sms` 返回 accessToken（200）。
- 快递100端点（免鉴权，直测）：
  ```
  GET https://api.rebugx.cn/api/v1/shop/logistics/track?no=SF1355607113805&company=顺丰
  → {"code":200,"data":{"state":"unknown","message":"找不到对应公司"},"message":"ok"}
  ```
  - 返回 **200**，且 message 为快递100业务级响应「找不到对应公司」，**非** `物流服务未配置`（证明密钥已从 DB 加载进 process.env、apiKey 非空），**非** 签名错误类响应（证明 **MD5 签名被 kuaidi100 接受**）。
  - 服务器 `.env` 无 `KUAIDI100_*`，密钥由 `ThirdPartyConfigLoader` 从 DB `third_party.kuaidi100` 解密写入 process.env，与运行时表现一致。
  - **结论：签发链路（密钥加载 + MD5 签名 + kuaidi100 通信）已打通。**

### 验证边界
- **无真实发货单可验完整轨迹**：测试号 13912340099 名下仅 4 单（COMPLETED 的 CIRCLE_JOIN / CANCELLED 的 PRODUCT / REFUNDED 的 PRODUCT / PAID 的 COURSE），无 `status=SHIPPED` 的实物单，且所有单 `getLogistics` 返回 `logistics: null`（DB 中无任何 OrderLogistics 记录、无真实运单号）。
- 未能用真实在途运单跑出正向轨迹数组（缺真实运单号）。签名接受性已由业务级响应间接证实；正向 `tracks` 非空验证需一张真实可查运单（建议后续用管理员对一笔实物单 `PUT /shop/orders/:id/logistics` 填真实单号后端到端复验）。

## 三、前端修复（发现即修，仅 lib 物流数据层 + 适配）

`apps/mobile/src/lib/order-data.ts`：把实时快递100轨迹接入 `orderApi.logistics()`。
1. 新增 `RawKuaidiResp` 接口（对齐后端 queryTrack 归一化结构）。
2. 新增 `kuaidiStateMap` + `mapKuaidiState()`：快递100顶层数字 state（0在途/1揽收/3签收/5派件）→ 前端 `logisticsStatusMap` 键。
3. 新增 `adaptKuaidiTracks()`：快递100轨迹（已倒序，最新在前）→ 前端 `LogisticsTrack[]`，`isCurrent=i===0`。
4. 改造 `logistics()`：取订单物流后，若有 `trackingNo` 则 **best-effort** 调 `GET /shop/logistics/track?no=&company=` 覆盖为实时轨迹；失败/未配置 **回退 DB 存储的 trackingData**，不阻断页面三态。

页面 `pkg-order/logistics/index.vue` 无需改动：三态、时间线、复制单号、承运/单号展示均已就绪，实时轨迹经数据层透明接入。
