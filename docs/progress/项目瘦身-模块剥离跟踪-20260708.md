# 项目瘦身 · 模块剥离跟踪（2026-07-08）

> 背景：开发期想法多，堆积了暂时用不上的功能模块。目标：把用不上的板块从系统剥离，为后续重新梳理后台目录结构腾空间。

## 一、依赖侦察结论（动手前测绘）
- **古籍(Classic*)/电子书(Ebook*)/诗词(Poetry*)/运势(Fortune*) 数据表各自独立**，古籍代码零引用电子书/诗词——"相似"只是阅读器 UI 范式，非耦合。**误伤古籍的担心不成立**。
- 待剥离模块（ebook/poetry/fortune/bounty/consult-call/question）后端**全是零反向依赖的叶子模块**。
- 唯一耦合点：`User` 模型有指向 Ebook 表的反向关系字段 → **删表要连带改 User schema，故表放最后**。
- 电子书被 `recommend`（保留模块）引用于推荐流 → 软下线时已同步摘除。
