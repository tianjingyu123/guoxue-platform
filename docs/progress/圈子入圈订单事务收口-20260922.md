# 圈子入圈订单事务收口

基线 `ddc3469436960be7844b02564702b495653740f9`。隔离分支中的独立收口，未部署、未操作真实订单或成员、无生产迁移。

## 问题和实现

原付费入圈确认先校验订单 PAID，随后在事务外创建成员并增加圈子人数，最后另行把订单标记为 COMPLETED。后一步失败时，成员和订单可能不一致；并发请求也没有在订单层认领。

现在对已付、同用户、同圈子、同类型订单在事务中做 PAID→COMPLETED 条件更新。仅认领到一行的请求继续在同一事务建立成员并增加人数。任一步失败事务整体失败，不返回入圈成功。支付方式、金额、推荐收益规则没有调整，通知与真实资金流也没有变化。

## 隔离验证

- 与续费定向测试及圈子既有回归一起运行，3套共35/35通过。

## 发布边界

需同付款后权益恢复客户端及续费事务修复进入同一发布候选。已完结订单不会重放；真实回调延迟、缓存失效和双节点下的事务竞争还需受控测试订单与目标数据库核验。此前已付但成员关系异常的历史订单应只读盘点并制定单独处理方案，不在本批自动补发。
