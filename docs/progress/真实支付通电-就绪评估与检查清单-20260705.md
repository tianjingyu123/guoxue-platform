## 二、🔴 侦察中发现并已修复的致命隐患（本次 commit）

**回调 URL 文档与实际路由不一致**：`config/third-party-services.ts` 契约里微信/支付宝/银联的回调地址提示写的是 `…/api/v1/pay/wechat/notify` 等，但代码实际路由是 `…/api/v1/shop/pay/notify`（`@Controller("shop")` + 全局前缀 `api/v1`）。而三通道的 `notify_url` 取自 `process.env.*_NOTIFY_URL`（= 商户按此提示填的值）。

**后果（若不修）**：商户照错误提示填 → 支付网关回调打到不存在的路由 → **404 → 支付成功但订单永不置 PAID → 卡单/钱货两空**。

**已修**：契约提示 URL 全部改为实际路由（微信 `/shop/pay/notify`、退款 `/shop/refund/notify`、支付宝 `/shop/alipay/notify`、银联 `/shop/unionpay/notify`；汇付本就正确 `/huifu/notify`）。纯文档字符串·零运行时风险·tsc0+支付spec104绿。
