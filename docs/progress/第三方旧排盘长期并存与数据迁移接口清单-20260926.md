# 第三方旧排盘长期并存与数据迁移接口清单（待第三方确认）

## 目标与现状

用户已确定新版排盘为主入口、旧版长期保留按钮。旧用户、起盘记录、历史已购解盘和有效会员权益应成为热卜可独立保存、查询和提供服务的数据；旧版继续可用期间，旧系统新增和变更须持续进入热卜。新报告与智能解读只依据热卜按原始输入重新排出的盘，旧解盘原文单独保留供有权用户查阅。

本文件是**向第三方提出的接口需求**，不是已开放权限或已完成迁移的证明。主工作区 `D:/gx-deploy-91/docs/progress/第三方排盘接入规则与交接-20260911.md` 记录了第三方已说明的 App 签名入口、`mobileUser.php` 按手机号查询数字 `userid`、合伙人接口与 H5 推荐入口。这些接口没有提供排盘记录、会员、订单或解盘正文。`mobileUser.php` 返回用户 ID 也不能证明请求者有权认领该账号的数据。

## 请求第三方开放的最小只读范围

| 数据 | 必需字段或能力 | 用途 |
| --- | --- | --- |
| 账号核验 | 稳定旧 `userid`、当前绑定手机号核验、旧站登录态或一次性授权凭证、换绑／合并／注销事件 | 由用户主动关联两端账号；不能仅凭历史手机号认领 |
| 排盘记录 | 稳定记录 ID、所属 `userid`、盘式、完整起盘输入、旧结果、算法版本、创建／修改时间、删除标记 | 原盘留作核对；热卜按同一输入重排并生成新报告 |
| 历史解盘 | 稳定解盘 ID、关联记录 ID、正文、附件及可展示地址、版本、生成／修改时间 | 将原购买内容长期提供给有权用户查阅 |
| 会员权益 | 会员记录 ID、权益类型、生效与到期时间、续费叠加规则、状态、退款／撤销事件 | 只在旧会员剩余有效期内兑现约定的新系统权益 |
| 已购凭证 | 旧订单 ID、用户 ID、购买对象 ID、支付成功、退款／撤销状态与时间 | 核定历史解盘永久查阅权；旧购买不自动赠送新语音时长 |
| 增量与对账 | 分页、稳定游标或版本、变更事件、删除墓碑、导出截止时间、字段字典、分类数量及校验值 | 首次全量导入后持续同步、去重、重试与差异核对 |

先取得脱敏测试样本和字段字典，核对八字、奇门等盘式的历法、时区、地点、真太阳时、闰月及特有参数。缺关键输入的旧盘只能展示原记录或提示补全，不能猜参数生成新盘。服务端以 `(来源系统, 旧记录 ID)` 做幂等映射；旧结果与新排盘结果、旧解盘与新报告均保留来源和版本，不互相覆盖。

## 权益及访问边界

- 旧会员到期前的新报告／对话权益和每月语音额度，需要明确与热卜小卜 AI 会员的映射及成本口径；到期或退款后的发放与撤销要可追溯。
- 旧已购解盘原文单独赋予长期只读权限；旧购买不等同于新报告订单，也不赠送语音。历史查看与新报告生成、文字问答、语音会话分别做权限判断。
- 第三方须明确允许热卜复制、长期保存并向原有权用户展示旧解盘正文和附件。用户侧应能看到来源、同步时间和权益状态。
- 不请求旧系统密码、微信凭据、支付密钥、银行卡资料或数据库管理员权限。热卜不因此向第三方开放全部用户、订单或报告数据。若旧版也要展示热卜新建的记录，再单独约定仅限已关联用户排盘的反向接口。

## 接入与发布门槛

1. 双端身份核验后保存稳定 `旧 userid ↔ 热卜 User.id` 映射；手机号仅用于核验，换绑和回收不能自动转移历史资产。普通用户使用排盘不以绑定手机号为准入条件；无手机号时的旧站授权路径须按主工作区交接规则单独验收。
2. 第三方提供可验证的批量导出、服务端只读接口或签名增量事件。首次导入和持续同步均记录来源、版本、游标、结果及错误，不盲目重复执行支付或权益操作。
3. 以账号、记录、已购解盘、有效会员、退款／删除五类样本做双端核对；再验收 H5、微信内 H5、App 和小程序的旧版进入／返回。构建通过不能替代真机或真实数据验收。
4. 本分支的 `PAIPAN_LEGACY_ENTRY_ENABLED` 默认关闭；启用前必须核对主工作区已验证的第三方入口协议和“无手机号普通用户可使用排盘”的规则，不能仅以当前手机号签名路径覆盖所有用户。
