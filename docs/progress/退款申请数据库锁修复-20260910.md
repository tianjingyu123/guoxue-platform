# 退款申请数据库锁修复（2026-09-10）

## 现象与根因

用户确认微信内 H5 支付成功，但订单退款提交提示“服务器内部错误，请稍后重试”。两台新节点日志均出现 `POST /api/v1/shop/orders/4fc12050-3e10-46d7-93c8-e4a5b79bcf55/after-sale` 500。

实际异常：`PrismaClientKnownRequestError` / `P2010`，`Failed to deserialize column of type 'void'`。`ShopCouponService.applyAfterSale` 使用 `$queryRawUnsafe` 读取 `pg_advisory_xact_lock` 的 void 返回值，创建售后记录之前即抛出错误。

诊断时订单状态 PAID，实付 0.01 元，售后数量 0。错误尚未进入微信渠道退款流程。

## 修复与验证

- 同服务内两处锁语句（售后申请、优惠券发放）增加 `::text`，保留原参数绑定、事务锁与防重复行为。
- `shop-coupon.service.spec.ts` 共 50 项测试通过。首次测试缺 Prisma 生成客户端和 shared 构建产物，补齐后通过，没有关闭类型检查。
- 线上真实数据库：旧语句复现 P2010，新语句 `TEXT_LOCK_OK`。
- 线上真实 `ShopCouponService.applyAfterSale` 在外层事务内创建待审核售后单成功；同事务重复申请被拦截；随后主动抛出回滚标记，确认测试售后单未留存。
- 事务验证 TAT `cmd-2y3w73m6` / `inv-j8gfa60g2p`，输出 `REAL_SERVICE_CREATE_OK DUPLICATE_BLOCKED PROBE_ROLLED_BACK CURRENT_AFTERSALES=[] VERIFY_OK`。
- 没有执行渠道退款、审批退款或修改订单金额。
