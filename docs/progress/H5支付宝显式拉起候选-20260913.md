# H5 支付宝显式拉起候选

基于 `2202691c` 的原始错误保留候选继续实现，尚未发布；不涉及云闪付配置、后端、APP 原生、小程序或 904 候选。

## 官方依据与兼容边界

本轮重新下载[汇付支付宝H5支付指引](https://paas.huifu.com/help/dev_guide/zf/zfb/h5.md)，该页给出 A_NATIVE 正扫付款码及 `alipays://platformapi/startapp?saId=10000007&qrcode=...` 的使用路线。正文仍主要给出 Android/iOS App 调用示例，不能据此保证所有手机浏览器均可拉起支付宝。候选只在用户显式点击时尝试，不自动跳转，不通过超时判定是否安装或是否付款。

## 实现

- 普通 Android/iPhone 手机浏览器、顶层收银页、支付宝 pending 付款码显示“打开支付宝付款”。电脑、微信及识别出的常见内嵌浏览器保留二维码，不提供此按钮。
- 点击时同步校验当前账号、原订单、本地同一汇付流水对应的原码及状态，复用既有交易；按钮不会调用下单或初始化接口。
- 仅允许确切 `https://qr.alipay.com/` 来源，拒绝用户信息、端口、混淆主机、任意 scheme、空白与反斜杠；完整原码作为一个编码后的参数，固定 scheme 前缀。
- 两小时仅是本地凭据使用上限，不是渠道实时有效保证。过期、已付、未知、账号变化或凭据不一致均不拉起，不自动生成新交易。
- 用户取消、未安装、浏览器拦截或拉起失败时仍保留原二维码和查询入口，不显示支付成功，不换交易重试。
- 补充 `visibilitychange` 和 `pageshow`；浏览器隐藏停止轮询，恢复时只查原单。与 uni 页面生命周期共同约束，避免后台页面恢复查询；离开时清理监听。并发查询由原收银状态工具合并。

## 验证与实机入口

23 项执行测试通过，包括可信二维码参数、手机/桌面/微信环境、状态/有效期/原码归属、显式双击防重复、浏览器恢复时只查同流水、已隐藏路由不恢复及卸载清理。类型检查与 H5 构建结果、最终包 SHA 见主工作区 `artifacts/h5-existing-order-cashier-20260913/` 的 alipay-launch 日志和 manifest。

本候选尚未发布，线上仍是 `abcf5a7e`，因此现用域名暂时看不到新按钮。审核发布后，使用普通手机浏览器打开现用 H5，经商城结算选择支付宝，生成原订单付款码后点击“打开支付宝付款”。已有明确未完成、仍具有效原码的同一订单也可经“订单详情 → 去支付 → 支付宝”进入；不能盲目跨渠道重试历史异常订单。

具体路由为 `/h5/#/pkg-shop/huifu-paying/index?orderId=实际本人订单ID&method=alipay`；不要把占位符当真实测试链接。浏览器视觉、外部钱包实际拉起、返回后结果更新及真实付款仍待真机验收。本轮没有真实下单、拉起支付或交易操作。
