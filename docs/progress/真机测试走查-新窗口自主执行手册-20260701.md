## 3. 四条走查线（每个模块都过一遍·这是本轮质检的核心方法）

本轮上一窗口的教训：**单测/vue-tsc 全绿但真人一跑就露**的都是接入/体验层 bug（配置存空、token 掉线、工作台聚合页崩、列表 reduce 崩）。用这四线系统揪：

1. **会话/权限线**：登录/登出/token 续期（15m→2h + refreshToken 无感续期，需真机回归）、多标签页、切角色（超管/圈主/商家/普通/审核员）能看到与能操作的边界、越权（改 URL id 访问他人资源）。
2. **配置保存线**：后台所有"保存"表单**真存真读**（重点第三方密钥 20 服务 + 系统设置 + 任何"前端传 JSON 字符串、后端 JSON.parse"的字段——SanitizePipe 转义存空那类雷；已修 value，但每个新表单都自测存了能读回）。
3. **页面状态线**：每页的 **loading / error / empty 三态**提示是否正确；**Promise.all 多接口聚合页**任一接口失败会不会整页崩/白屏（工作台/驾驶舱/数据大屏/各数据中心）；**接口返回对象 vs 数组契约错配**（`.map/.slice/.reduce` 崩）。上窗口 B 走查已扫一批，但要真机逐页确认。
4. **交易闭环线**：下单→支付→退款、课程报名、圈子入圈、时长包购买（真扣国学币）、送礼、提现、结算、赛事报名——**真实走一遍，验资金账目守恒**（扣款=到账·无钱货两空·幂等）。**⚠️ 涉真钱的谨慎**（微信支付真扣款·用小额或测试号）。

## 5. 发现即修 + 重部署闭环

1. **记录**：每个问题写入 `docs/progress/真机测试-问题与修复清单-20260701.md`：`[模块] 页面 — 现象 — 复现步骤 — 根因 — 修法 — 严重度 — 状态`。
2. **修**：前端在 `apps/mobile/src` 或 `apps/admin/src`·后端 `apps/server/src`。守四闸（真连/三态/Vue 化/资金安全）。改完 `vue-tsc`/`tsc`/`jest` + `bash apps/mobile/scripts/scan-mock-imports.sh` 全绿。
3. **重部署**（详见 [[guoxue-production-deploy]]）：
   - 后端：`git commit` → `git bundle create /tmp/x.bundle <上一commit>..master` → scp → ssh `git fetch bundle master && git reset --hard FETCH_HEAD` →（有 schema 改）手写 additive `db execute`（**剔 migrate diff 误报的 DROP·如 PlatformKnowledge.embedding**）+ **`cd apps/server && ./node_modules/.bin/prisma generate`** → `pnpm build:server` → `pm2 restart guoxue-server --update-env`（先 `set -a;source .env;set +a`）→ `curl 3001/health`。
   - 前端 admin：`cd apps/admin && pnpm build` → scp dist → 服务器替换（nginx 静态无需重启）。
   - 前端 H5：`pnpm --filter @guoxue/mobile build:h5` → tar `dist/build/h5` → scp → 服务器 `mv dist dist.bak && mkdir dist && tar xzf ... -C dist` → curl `/h5/` 验 JS hash 变了。
   - **⚠️ 服务器无 tsx**：注入数据用 SQL `INSERT ON CONFLICT`（`db execute --stdin`）。**枚举加值** `ALTER TYPE ... ADD VALUE IF NOT EXISTS`。
4. **复验**：修完在真机重走该场景确认。
