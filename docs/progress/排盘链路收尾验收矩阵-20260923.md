# 排盘链路收尾验收矩阵（2026-09-23）

本矩阵只针对“排盘 → 购买／续费 → 报告生成 → 提问 → 工作台交付与复盘”的当前收尾，不把后续内容运营和长期产品增长算作一次性交付。订单与权益以服务端数据为准，埋点只用于观察行为。

| 项目 | 必须完成的场景 | 通过证据 | 当前状态 |
| --- | --- | --- | --- |
| 1. 可重复构建 | 当前提交在依赖指向本工作树的环境运行 `build:prerequisites`、服务端和移动端全量类型检查、相关 Jest | 构建日志、失败项清零、提交 SHA；核对 `node_modules` junction 不指向其他工作树 | **待验收**：当前工作树依赖指向外部目录，不能把旧声明导致的失败当成源码结论 |
| 2. 付款与权益 | 微信小程序、微信内 H5、外部 H5 分别验证报告首购、会员续费、回调延迟、取消、退款、重复回跳与已付生成失败重试 | 专用 QA 订单号、回调和权益流水、前端录屏；同一订单只兑现一次，失败重试不新增付款 | **待隔离支付环境**：本机无测试库、Docker 或 QA 支付凭据；不可用生产真单替代 |
| 3. 报告与交付并发 | 隔离 PostgreSQL 双设备编辑、预览后另一设备保存、生成／撤回／换链、客户打开与提问期间撤回；AI 失败与限流释放 | 数据库版本及分享令牌、API 响应、客户页截图和 AI 用量记录；旧版本不能覆盖或交付新稿 | **局部代码验证完成**：排盘报告 13 组 Jest 共 124 项通过；真实 PostgreSQL／Redis／模型延迟仍待验收 |
| 4. 多端完整动线 | 从原排盘购买并回到原报告；已购旧链接失效时从原排盘恢复；报告问答、工作台导入、老师预览与客户只读页、案例归档和预约 | H5、微信小程序及微信内 H5 的逐步录屏和缺陷清单；换设备后无需重新录入盘面或再次付款 | **待真机**：页面和服务已联通，尚无多端逐屏证据 |
| 5. 用户效果 | 校验权限页、下单、支付成功、生成、阅读、提问、交付、回访埋点的匿名口径；抽样检查真实报告内容和退费原因 | 漏斗分端分首购／续费；支付后到达率、生成恢复率、提问成功率、退款／投诉原因及人工内容审校样本 | **待真实样本**：事件代码已加，不能声称转化率或满意度已经提升 |

## 执行顺序

1. 先建独立 QA 工作树与依赖，再做全量构建；不清理指向其他工作树的 junction。
2. 由具备 QA 权限的单一执行方验证测试库和 API 身份，只读确认目标环境后才创建 `QA_` 测试数据。真实支付、退款、回调仅在明确隔离的商户环境执行。
3. 按“订单 → 权益 → 报告 → 提问／交付”保存同一任务的关联 ID 与脱敏证据。超时先查原订单或报告，不能盲目重发付款或生成请求。
4. 上述五项都有通过证据、缺陷关闭或明确产品决定后，才标记本轮工作完成；不能用模拟测试替代第 2–5 项。
