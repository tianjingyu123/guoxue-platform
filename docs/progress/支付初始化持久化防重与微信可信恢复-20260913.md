# 支付初始化持久化防重与微信可信恢复

基线360ac6d3，独立分支codex/huifu-payment-intent-20260913。仅候选代码，不部署、不安装、不发起真实交易；Android245在独立分支。本变更不涉及Apple、退款审批和佣金策略。

## 问题与最终行为

原汇付每次用时间戳创建新支付流水，渠道受理后才落库。请求超时、丢失响应或多个设备并发可能产生第二笔；原微信四入口也在外部下单后才保存，而且可能把汇付流水送微信关单。现改为渠道调用前提交数据库占用，由数据库条件更新决定唯一出站者。

- 汇付：Serializable事务内核对本人、PENDING、正数安全分金额，再CAS占用Order.payTransactionId，同时创建HuifuSplitRecord唯一记录。原日期、32位内流水、金额和请求在首次调用前持久化。复用既有orderId/outTradeNo唯一约束，无表结构迁移。
- 汇付记录rawResponse._paymentInit=RESERVED表示尚未发送、发送中或结果未知，不能按时间/锁过期重新发送。已验证响应按RESERVED状态CAS保存为RESOLVED；初始落库、提交回包、出站、响应保存任一步失败都不会在重试中自动新建第二笔。唯一/序列化冲突仅重新读取胜者。
- 同渠道同金额且原流水一致时复用已保存凭据；无凭据返回原outTradeNo及UNKNOWN，超过两小时不重放凭据。业务拒绝、过期、记录不一致不自动重建。跨渠道或变更金额拒绝原单初始化。
- 微信App/JSAPI/Native/H5购买入口使用相同Order行CAS。外部调用前保存WECHAT_INIT和原流水；得到初始化响应后CAS为WECHAT。短Redis锁保留用于减少无效请求，数据库占用负责安全性。
- 微信初始化结果未知时，再次进入会进行严格验签查单。只有NOTPAY且商户/单号/金额匹配，才能把INIT确认成WECHAT，保留原流水，再走明确关单后创建流程。USERPAYING、查询失败、签名失败、ORDER_NOT_EXIST不释放。SUCCESS交统一履约，失败不向客户端宣称已入账。
- 普通payment-status按主库归属和渠道分流，不把HF流水发送微信。汇付未明确成功/失败的状态返回USERPAYING，不当作明确未支付。已支付终态读取本地结果，不拿渠道transaction_id当商户单号重新查询。
- 汇付提交后清订单详情缓存，便于Android245读订单取得原流水后查单。无凭据的原单仍可查验，不保证凭据丢失后可再次拉起支付宝。

## 微信查询验签

新增queryOrderVerified专用方法，不整体改造所有微信API。按照[官方平台证书验签规则](https://pay.wechatpay.cn/doc/v3/merchant/4013053420)，使用timestamp、nonce与原始响应body构造签名串；校验五分钟时间窗、签名头、精确平台证书序列号或已配置的公钥ID，再核对商户、商户单号、人民币分金额和交易状态。缺公钥/证书即失败关闭。真实RSA测试覆盖正文仅增加空格也失败。

[官方订单查询](https://pay.wechatpay.cn/doc/v3/merchant/4013070356)区分NOTPAY、SUCCESS等状态。旧关单失败后的成功补账也改用严格查询，不再相信未验签查询。删除当前商户关单/查单均ORDER_NOT_EXIST时允许重建的旧逻辑。另修正204无响应体的关单成功不应解析JSON，避免成功关单被误判为解析失败。

## 恢复及发布边界

1. 汇付RESERVED发生在提交后、实际发送前进程退出时也会保留，不能根据一次“查不到”删除。本候选不提供自动重发、后台强制解锁或重新取得已丢失QR的接口。运维须核对原商户、req_date/req_seq_id、渠道受理/关单/退款证据，再处理业务订单；禁止直接清空流水让用户再付。
2. 微信INIT只有可信NOTPAY可自动恢复。未配置验签公钥ID/证书或查询持续未知时，保留订单并依赖原商户对账；不得放宽验签。现有Order未新增原微信商户快照，禁止在未核清的INIT存量上直接切换商户，需先与原商户对账。当前查询严格绑定所请求的运行商户，不能据此宣称完成任意历史商户迁移。
3. 新旧版本混跑时旧代码可绕过新占用规则。统一发布需暂停新支付初始化并排空旧请求，确保两节点都运行同一候选后恢复；旧版本已经产生的未知/孤儿支付不由本变更自动消除。
4. 本保证限于本次HuifuService.createPayment及四个微信商城购买入口。充值、其他独立订单表、历史独立支付宝/银联接口、管理员人工入账、人工改库及异步取消/退款竞态不在本次初始化互斥保证内，须保持整套审计边界。
5. 原微信普通queryOrder仍保留供既有非本次路径使用，不能把全站所有微信接口都描述为已具备同步响应验签。本次资金恢复和旧关单成功补账使用queryOrderVerified。
