## 一、红线风险（开 flag 前必须处置）

1. **🔴 保证金支付是模拟到账**：`merchant-deposit.service.payDeposit` 直接置 SUCCESS 并推进状态机（无真实支付渠道）。生产开启前二选一：
   - a. 接真实支付（复用 shop 微信支付链路·需开发排期）；或
   - b. 首批定向招商暂免保证金（depositAmount=0 审批通过），S2 阶段再接真支付。
2. **🔴 `merchant_auto_approve` / `merchant_deposit_auto` 生产必须保持关闭**：自动审核+自动到账组合 = 任意人零门槛成为 ACTIVE 商家上架商品。生产只走人工审核。
3. 上架商品走三层内容审核漏斗（已上线）+ R4 定性红线：商品定性「民俗工艺品/文化礼品」，禁功效承诺词（开运/化解/辟邪已入违禁词库）。

## 二、执行步骤（生产 · SSH 一次连完 · 增量 SQL 勿 db push）

### 步骤 1：TEMPLATE 占位商家（协议模版 FK 依赖）
`MerchantAgreement.merchantId` 外键指向 `Merchant.id`，协议模版固定挂 `merchantId='TEMPLATE'`。Merchant.userId 唯一且 FK → 需先建系统占位用户。幂等 SQL（示例·执行前核对生产无冲突）：

```sql
-- 占位系统用户（若平台已有系统账号可复用其 id，跳过本条）
INSERT INTO "User" (id, nickname, "createdAt", "updatedAt")
VALUES ('SYSTEM-MERCHANT-TEMPLATE', '商家协议模版占位', NOW(), NOW())
ON CONFLICT (id) DO NOTHING;

INSERT INTO "Merchant" (id, "userId", "shopName", "contactName", "contactPhone", "idCardNumber", status, "createdAt", "updatedAt")
VALUES ('TEMPLATE', 'SYSTEM-MERCHANT-TEMPLATE', '协议模版占位（勿动）', 'SYSTEM', '-', '-', 'DISABLED', NOW(), NOW())
ON CONFLICT (id) DO NOTHING;
```
> 注：idCardNumber 为必填明文占位 '-'（非真实证件·DISABLED 状态不参与任何业务）。

### 步骤 2：协议挂载
定稿文本经 admin 后台录入：`POST /admin/merchants/agreements`（SUPER_ADMIN/OPERATION_ADMIN·body: version/title/content HTML）。验证：`GET /merchant/agreement-preview` 返回 200 且为定稿版本（此端点被 flag 门控，可在步骤 3 开 onboarding 后验）。

### 步骤 3：FeatureFlag 逐个开（admin 后台「系统→功能开关」或 PUT /admin/feature-flags/:key）

| 顺序 | key | 生产值 | 说明 |

| 1 | `merchant_onboarding` | ✅开（可先 percentage 灰度） | 入驻链路 7 页解锁 |
| 2 | `merchant_backend` | ✅开 | 商家后台 15 页解锁（含发货/贺卡任务视图） |

### 步骤 4：自营供应商主体（S1 自营先行）
平台自营账号走入驻 → admin 人工审批 ACTIVE → 首批 SPU 以 `supplierType=CERTIFIED_MERCHANT` 上架（或维持现有 PLATFORM 商品双轨）。商品打场景标签（供-P1 七场景），进「按场景取货」触点池。

### 步骤 5：端到端验证（生产）
1. 未登录/无 flag 用户访问入驻页 → 之前 404，现进入驻表单
2. 入驻提交 → admin 商家列表可见 PENDING_REVIEW → 审批（录入保证金/0 元暂免）→ 签协议 → ACTIVE
3. ACTIVE 商家上架 1 个测试商品 → 过内容审核 → C 端商城可见 → 下单闭环（含归因分佣/白标贺卡任务出现在商家发货单）
4. 测试商品下架/删除，测试单退款
