## 一、执行纪律（每个窗口开工前读）

1. 开工先读总账 → 只做排期中当前批次 → 完成销号附证据（commit+验收结果）→ 回写总账
2. 新想法/新发现 → 总账 backlog 区，不许当场做
3. 设计文档是**契约**：数据模型/端点/验收标准按文档执行；发现文档与现实冲突 → 停下记录，不自作主张改设计
4. 商业数值（价格/比例/阈值）只能用文档标注的"建议值"实现为**后台可配**，默认值用建议值——数值拍板权永远在用户
5. 验收铁律不变：后端 tsc+jest 全绿 / 前端 vue-tsc+mock 扫描 0 违规 / 生产部署走 git bundle 流程 / 资金相关必过安全检查清单（CLAUDE.md）

## 四、关键契约与踩坑备忘（集中版·派单时抄进 prompt）

- 服务器：`apps/server/.env`=5433 真库；nest build 需 NODE_OPTIONS=6144；prisma generate 必须 cd apps/server；新表用增量 SQL（勿 db push --accept-data-loss）；部署=git bundle（GitHub 不通）；H5 产线 `api.rebugx.cn/h5/`；admin 产线 `/opt/guoxue/apps/admin/dist`
- SSH 生产有连接频率限制：**一次连接干完所有事**（脚本走 stdin 管道），频繁短连接会触发封禁递增
- 资金铁律：一切分佣/结算走统一结算引擎 SettlementRule 场景（勿新造资金流）；资金动作过 FundApproval；两级计酬红线（COMMISSION 条目≤2 引擎已硬约束）
- 合规四红线 R1-R4 见总体作战计划§一；违禁词/定性话术内置进 AI prompt 而非事后审
- cron 一律 redis.runExclusive 分布式锁 + 幂等设计；AI 调用带降级路径
- 多窗口纪律：贵重中间态尽早 commit；跨窗口"已拍板"必须指到总账条目（防伪造拍板事故重演）
