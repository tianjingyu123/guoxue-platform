# v239 双机验收清单

## 候选与分工

- 版本：1.1.0(239)，由 f380c5e8 后继的本轮独立移动端审计分支生成。
- 包内公开配置：预发布 pre-api / pre-static；禁止使用正式域名包的结果替代预发布验收。
- 本轮包含旧排盘兼容桥、传感器、独立旧支付、短视频首帧、根页返回手势，以及新商城 App 微信支付适配。
- 旧排盘仍由旧系统管理订单、收款、退款、会员及工具权益；Android/iOS 均不转新商城或 Apple IAP。
- 不整合仍在进行的后台 UI 重设计；后台 AI 的 f2d993c5/faecd631 独立改动亦不混入本次客户端故障验收，后续单独合并验证。
- 本轮不包含数据库迁移，不修改旧排盘运行模式、微信功能开关、商户配置或正式 DNS。

## 三道证据门禁

1. 本地代码/模拟：精确记录测试退出码，不把合成 DOM、模拟 SDK 当作真机成功。
2. 新签名包：源码 SHA、公开配置指纹、APK/IPA 哈希、包名、版本、签名及内嵌运行脚本全部匹配；旧 v238 不计入本轮通过项。
3. 真机闭环：同一候选在 iPhone 和 OnePlus 分别录制从入口到结果再返回的连续操作，保留脱敏错误与设备信息；失败立即记录，禁止仅重复入口截图后判绿。

## 双机逐项执行

下列项目初始状态全部为“待新签名包真机复验”。一端通过不能代替另一端。

| 场景/角色 | 操作与通过标准 | 不得替代的证据 |
| --- | --- | --- |
| 安装与冷启动/游客 | 覆盖安装保留现有数据；进程结束后冷启，首页→圈子→首页→发现→我的→工具往返 3 轮；前后台切换 3 次；无白屏/崩溃 | 真实设备版本与连续录像 |
| 圈子/游客与已登录 | 列表纵滑、分类横滑正常；根页左缘右滑回首页；子页仅退一层；弹层、输入框、横向内容不误退 | 根页和子页分别记录，不能仅点顶部返回 |
| 视频/已登录 | 冷启后直接打开第一条，首帧有画面且声画同步；上/下各切 5 条；横/竖素材；暂停/继续；后台恢复 | 第一条必须独立验证，第二条正常不能覆盖首条故障 |
| 视频互动/已登录 | 评论抽屉打开/收起、输入框不遮挡；关闭后继续播放；返回列表位置合理 | 不用真实发布评论代替只读抽屉验收；发表另经批准 |
| 八字/旧排盘账号 | 出生地省市区选择、确认、取消、重复选择；确认后表单值及排盘提交使用所选值 | 必须捕获真实旧页确认回调；合成锚点测试不算修复证明 |
| 奇门/旧排盘账号 | 局数各选项、确认/取消、返回修改，计算入口可达且参数一致 | 不仅证明下拉框能打开 |
| 罗盘/旧排盘账号 | 设备转动至少四个朝向；记录方向数据与指针变化；后台停止/前台恢复；返回后不残留监听 | 真机传感器帧；静态指针图片和方向=0 都不能判绿 |
| 定位/旧排盘账号 | 用户亲自首次允许/拒绝；允许后坐标回填；拒绝给出准确提示；同 URL 重载及切页后不注入迟到位置 | 不要求用户开启不存在的“方向权限”；不保存精确位置到报告 |
| 旧支付/旧排盘账号 | 新 App 走旧交易号→旧接口→微信 SDK；取消返回原旧页；重复点击只拉起一次；前后台及弱网有可理解结果 | 仅记录脱敏旧单状态；不输出签名/令牌，不调用 payOk 假定到账 |
| 新商城支付/受控账号 | 确认服务器有新 App 接口且环境正确，再验 SDK 可用/不可用、取消/查单；iOS 数字权益仍保留新系统 IAP 边界 | 旧排盘支付成功不能证明商城成功；未获资金授权不付款 |
| 微信登录/受控账号 | 先核验当前环境配置与开放平台绑定，开关开放后验授权/取消/返回/既有账号绑定 | 按钮出现不算登录成功；不擅自开启正式开关 |
| 其他共性页面 | 首页、个人中心、课程、古籍、客服、会员、直播：入口、滚动、弹层、返回、刘海/底部安全区各一轮；错误态能重试或退出 | 共性组件测试仅辅助，至少保留每类页面现场证据 |

## 收款与发布边界

- 本地旧支付与商城支付回归均使用合成数据/模拟外部接口，没有真实付款。
- 本轮新云包、设备覆盖和 TestFlight 内测须绑定新的明确候选；不沿用 f380/v238 的上传结果。
- 真实付款/退款须先确认受控资金范围、旧商户与交易归属、新系统测试网关；没有有效测试证明时跳过资金动作并记录阻断。
- App Store 分发规则、正式 DNS 切换、商店审核与公开发布是独立门禁，本清单不代替批准，不隐瞒旧支付功能。
- 未完成项必须保留为待验，不承诺“所有问题已解决”或“所有用户必然满意”。
