## 已实现

1. 新增 `User.interestGuideCompleted`，仅记录账号首次引导已选择或主动跳过，默认 `false`。不挪用通知或其他配置，不改变身份。
2. `GET /auth/me` 与所有统一登录结果返回 `interestCategories`、`interestGuideCompleted`。非空历史兴趣兼容为已完成。
3. `PUT /users/profile` 可单向设置 `interestGuideCompleted=true`；旧客户端保存非空兴趣也完成，编辑清空兴趣不重置。拒绝 `false`、字符串布尔或请求指定其他账号。
4. 视频详情、列表、瀑布流按当前认证账号批量补充点赞/收藏/关注状态。账号状态不写入公共内容缓存；返回新对象，避免串号；详情及列表在共享缓存之外回读当前计数。
5. 视频专属和通用互动入口共用 `VideoInteractionStore`。记录与计数在同一可串行化事务更新，并发冲突最多三次；未知错误不自动重试。
6. “我的点赞”按记录 ID 确定性取消视频点赞时同步计数，并在事务内复核归属。重复取消返回不存在，不反向创建。历史零计数不得扣为负数；目标视频已删除时仍能清理自己的历史点赞。
7. 提交成功后才失效详情/列表/本人收藏缓存；失败不虚报成功。通用入口既有推荐行为记录保留，取消或失败不得记录为新增互动。
8. 客户端兴趣以当前账号资料为准；首次选择或跳过只有在响应账号一致、完成态为真、兴趣数组合法时才水合。登录引导保留白名单站内回跳，网络失败不伪造首次或完成态。
9. 游客入口沿用既有品牌，提高字号/触控热区；个人中心登录文字可点击。App 播放器触摸只由 renderjs 桥处理，带视频和手势标识；重复结束、迟到事件及滑动/长按残留不参与双击。当前没有设备原生双派发时序证据，不能宣称已确认唯一现场根因。
10. 视频互动使用单请求锁、真实服务端状态与计数；迟到详情不得覆盖刚确认的操作。评论键盘只压缩列表、保留标题和关闭按钮，覆盖键盘与系统缩窗只扣一次高度。
