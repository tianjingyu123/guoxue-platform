# 圈子邀请链接与入圈边界（2026-09-22）

本轮检查发现，旧邀请页虽显示邀请码，但分享链接没有带码；预览页把 `code` 传给普通 `/circles/:id/join`，该接口的 DTO 不接收这个字段。因此好友仍需手填且邀请归因不会形成。另有更严重的服务端边界：独立 `/circles/join-by-code` 原来没有限定免费圈，可绕开付费入圈。

已在隔离候选修正：免费圈的 H5 邀请链接和微信原生分享直接指向预览页并携带邀请码；预览页使用专门的入圈接口，服务端在写入前核对邀请码归属、圈子状态、免费类型、禁入状态和圈规确认。限次邀请码在事务内条件占用，用完或过期不建成员。用户尚未确认圈规时，预览页展示真实条文、明确勾选、留存服务端快照后继续原入圈动作。付费圈只分享预览页，好友仍按页面价格付款，不生成或使用可绕过付款的邀请码。现有无到期日的有效码可复用，不重复生成。

本地证据：`tests/release/circle-invite-join-browser.mjs` 使用隔离接口验证失败重试、链接带码、圈规确认与直达圈内；`circle.service.spec.ts` 验证付费拦截、错圈拒绝、圈规闸门、限次占用以及生成边界。所有请求在本地拦截，不涉及真实账号或资金。

待目标环境验收：微信原生分享卡及 H5 微信内回跳、真实圈规配置、免费审批圈的邀请码例外、有限次数并发与历史邀请码数据、付费圈真实付款。服务端和移动端必须同批发布；本轮没有部署，也没有修改真实订单或成员。
