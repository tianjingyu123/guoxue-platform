## 二、P1（功能断裂 · 优先修）

### P1-1 「我的课程」列表恒为空，已购课程完全不显示
- 路由：`/pkg-mine/my-courses/index`
- 现象：页面显示"0 学习中 / 0 已完结 / 暂无学习中的课程"。但该用户**已购《周易六十四卦详解》**。
- 证据：`GET /courses/my?page=1&pageSize=50` 返回 200，`data` 为**数组** `[{orderId, paidAt, amount, course:{...}}]`（确有 1 门课）。
- 根因：`src/lib/mine-data.ts` `getMyCourses()`（约 1760 行）读 `(my?.courses ?? [])`。而 `apiGet`（`utils/request.ts:69`）resolve 的是 `body.data`，此处是**数组**，`my.courses` 恒 `undefined` → 空数组 → 所有已购课程被丢弃。
- 影响：用户花钱买的课在"我的课程"永远看不到（学习入口断）。属经典 adapter 形状不匹配。
- 建议：`const list = Array.isArray(my) ? my : (my?.courses ?? [])`，或改用 `apiGetPaged`。
- 备注：`/pkg-course/learn/index?id=<courseId>` 直连可正常读章节并"继续学习"，说明后端与学习页本身没问题，仅"我的课程"列表 adapter 坏。

### P1-2 「我的圈子」整页为硬编码 mock，零后端调用
- 路由：`/pkg-circle/my-circles/index`
- 现象：页面渲染"八字命理研习社/紫微斗数学院/风水堪舆…（1280人、2.8k获赞、总经验2870）"等丰富数据，看似正常。
- 证据：整页只发出 `GET /system/public/brand-config` 一个请求，**无任何 /circles 调用**；`my-circles/index.vue` 216 行起为静态数组常量（`totalExp: 2870` 等）。真实 `/circles/my` 只有"中医养生实践圈"。
- 根因：该页未接数据层，直接 import 死数据（违反前端数据流铁律）。
- 影响：展示的是虚构圈子，与用户真实圈子无关；"发帖数/获赞/经验"全是假的。
- 建议：接 `/circles/my` 真连 + 三态。
- 连带（见 P2-3）：本页 4 个快捷入口路由全部错误。

## 三、P2（体验/健壮性）

### P2-1 课程播放器直接进入（无 lesson 参数）→ 404「章节不存在」
- 路由：`/pkg-course/player/index?id=<courseId>`（无 `lesson=`）
- 现象：整页停在错误态"章节不存在 / 重试"，body≈7 字。
- 证据：`404 GET /courses/chapters/1/content`——请求了字面量章节 id `1`。
- 根因：`player/index.vue` `onLoad` 默认 `lessonId = options?.lesson || '1'`、`courseId = options?.id || '1'`（残留占位默认）。
- 边界：正常路径 learn→点课时 经路由别名层 `/courses/:id/player` 会带上 `lesson=<真实章节id>`，可正常播放；仅**深链/分享/无 lesson 参数**时命中 `'1'` 默认 → 404。
- 建议：默认值改为空并在无 lesson 时取章节列表首个真实 id，或错误态给出"选择章节"引导。

### P2-2 播放器/学习页「提问」「笔记」为假壳（只弹 toast 不落库）
- 文件：`pkg-course/player/index.vue`（`submitNote`/`submitQuestion`）、`pkg-course/learn/index.vue`（`submitQuestion` 48 行）
- 现象：点提交后 `uni.showToast('问题已提交'/'笔记已保存')`，**无任何 API 调用**，数据不持久化。
- 影响：用户以为提问/记笔记成功，实际什么都没发生。learn 页问答列表是真连（读），但"提交"是假的。
- 建议：接后端问答/笔记写端点，或先隐藏入口。

### P2-3 `/circles/create|stats|activities|badges` 路由塌缩为圈子详情
- 文件：`pkg-circle/my-circles/index.vue`（17/165/171/177 行 `navigateTo('/circles/create')` 等）
- 根因：动态路由 `/^\/circles\/([^/?]+)$/`（router.ts:461）抢先命中，把 `create/stats/activities/badges` 当作圈子 id → 落到 `/pkg-circle/circles/detail?id=create` → 错误页。
- 影响：我的圈子页"创建圈子/数据统计/活动/徽章"四个快捷入口全是死按钮。
- 建议：调用方直接用完整路径 `/pkg-circle/circles/create` 等，或在 ROUTE_MAP 增静态别名（须置于动态 `/circles/:id` 之前）。

### P2-4 圈子帖子详情页缺 circleId 时请求空 circleId → 404
- 路由：`/pkg-circle/circles/post?id=<postId>`（未带 circleId）
- 证据：`404 GET /circles//posts/<postId>`（注意 `/circles//posts` 双斜杠，circleId 为空）→ 页面"加载失败，请重试"。
- 说明：帖子详情依赖 circleId + postId 双参。若从某些入口跳转只带 id 会断。需核对各入口是否都拼了 circleId。
- 建议：无 circleId 时先按 postId 反查，或统一入口带全参。

### P2-5 商城「立即购买」跳过结算页，直接建单
- 文件：`pkg-mall/product/detail.vue` `buyNow`（106 行）
- 现象：SKU 面板"立即购买"→ `createOrder(type=PRODUCT)` 后直接 `navigateTo('/pkg-order/detail/index?id=...')`，**未经结算页选地址/优惠券**。实物商品无收货地址确认环节。
- 对比：另有完整结算页 `pkg-shop/checkout/index`（走地址/优惠券/金额明细，实测 ¥899.90 正确）。两套下单流程双轨不一致。
- 建议：实物商品「立即购买」应先进结算页确认地址，或确认服务端默认地址逻辑可靠。

### P2-6 订单模板复用不当（课程订单显示物流步骤）
- 现象：COURSE 订单（《周易》¥399.9）在订单详情显示"待发货/商家发货/交易完成"实物物流步骤条；订单列表把该课程订单显示为"商品 ¥399 待发货"。
- 影响：虚拟商品（课程）套用了实物发货流程文案，语义错误。
- 建议：按订单 type 区分展示（课程订单不显示物流步骤，展示"立即学习"）。
