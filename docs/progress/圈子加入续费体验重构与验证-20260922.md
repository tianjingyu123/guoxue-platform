## 本批实现

| 路径 | 原问题 | 本批处理 |
| --- | --- | --- |
| 成员身份 | 查询失败返回未加入，可能诱导再次加入或付款 | 加入、详情、续费使用严格查询；失败显示未知与重试；不能将回跳参数作为成员身份 |
| 免费加入 | 详情乐观授予成员状态；预览成功仍需再次点击 | 提交期间防重复；服务端确认成员后解锁；预览替换为圈子详情，减少返回栈 |
| 审批加入 | 审批记录异常可能显示首次申请 | 需要审批且申请记录失败时阻止新申请；已有待审核申请显示进度入口 |
| 登录 | 登录后未明确返回当前圈子 | 使用既有登录回跳存储，预览保留圈子和邀请码，详情保留圈子 |
| 付费加入 | 反复弹权益确认、购买两层；到账未同步仍提示完成支付 | 删除重复权益确认层；预览费用、期限、原有退款说明留在页面；收到已确认付款事件后只查询权益，不再次付款 |
| 支付返回 | 返回详情后权益未同步容易再付款 | `paymentSuccess` 只触发核对状态，不授予权限；核对完成前不再进入购买。此标记不构成支付证明 |
| 到期 | 已过期但 joined=false 的成员可能再次走加入 | 预览与详情导向续费；权益待确认时隐藏续费提醒，避免并列付款入口 |
| 续费 | 自有旧支付分支可能只建单、不调起；吞异常后尝试确认 | 创建订单后替换当前页进入统一收银页，订单金额优先使用服务端值；兑现与业务跳转复用既有收银链路 |
| 续费重复 | 建单成功但跳转失败可能再次建单 | 当前页面保留已创建订单，重试复用；提交中锁定方案/渠道 |
| 续费渠道 | 小程序仍显示支付宝 | 小程序仅展示微信；安卓与普通 H5 默认支付宝，微信内默认微信 |
| 视觉和触达 | 预览/续费仍为旧金红混合样式，小返回键 | 中性画布、系统无衬线字体、清晰选中态、实色吸底栏、44px 主要触达区、微信胶囊预留 |
