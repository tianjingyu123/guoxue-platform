## 主线接收次序

1. 主线单一写入任务先固定 `D:/gx-deploy-91` 当前并行改动的状态；不要直接覆盖正在使用的 3989 服务及其数据库。
2. 当前主线 `release/integration-20260801` 的 `2e458597a` 是本分支祖先；到硬件基线 `4ca9ade61` 之间还有 32 个提交、约 501 个改动路径，其中包含小卜功能前置代码和其他平台工作。2026-09-23 只读快照：候选分支相对主线提交改了 516 个路径，其中 411 个与主工作树未提交内容重叠；不能直接快进、覆盖或只挑后续硬件提交。
3. 硬件基线之后的接续改动共涉及 26 个路径，与主工作树当前改动直接重叠的只有下述 2 个；但这不消除第 2 步的前置代码依赖。前置代码具备后，按本分支 `4ca9ade61..HEAD` 的提交顺序逐个评审；`4484e8e98`、`a4156b9bd`、`7c65d7558` 涉及模拟回放和发送时序，接收并安全切换测试服务后才会改变真机听感。
4. 对 `apps/admin/src/api/xiaobu-ops.ts`、`apps/server/src/modules/voice/voice.module.ts` 与主树未跟踪旧版逐文件合并。候选版分别增加设备运维 API 类型与设备/会话/OTA 控制器及服务注册；主树文件不可直接覆盖。按目标环境重跑 TypeScript、后台类型检查、语音回归；回归数据库只能使用专用隔离库，Redis 使用单独 DB。
5. 在独立预发布环境验证真实 Redis 连接与订阅、两实例设备重连、告警 Webhook 实际送达、设备 OTA 公网地址与证书。记录发起时间、设备尾号、连接实例、告警接收时间；不得以“配置存在”代替可用性验证。

## 按年签约前门槛

这些项目无需商业授权，完成后再开通按年计费接口。真实语音质量与供应商费用只能在签约后的联调阶段验收，不纳入“签约前已完成”的宣称。

- [ ] 安全接收并切换本阶段代码；设备在新版本上复测短句、长句、停顿句的首播时间与断续情况，必要时回退 540 ms 的 Mock 端点阈值。
- [ ] 在设备实际通话期间采集网络时延、服务端下行迟发/背压和设备串口音频队列；定位断续是在服务端发送、Wi-Fi 传输还是设备解码播放。待命时 ICMP 延迟不能代替通话中数据。
- [ ] 用隔离用户与可回滚额度验收余额不足/充值提醒；确认不影响正常用户余额与真实扣费。
- [ ] 在独立预发布环境验收多实例 Redis、告警 Webhook 实际送达、OTA 地址/证书及失败回退；明确 800 台突发连接的入口限制，不写未经验证的容量承诺。

## 暂待外部条件

- 商业语音授权 API：取得供应商正式文档、测试凭据、调用额度与费用规则后，才实现并验收真实 ASR/模型/TTS、中继失败行为与扣费边界。
- 余额不足/充值提醒：在隔离账号与可回滚额度条件下安排一次真机触发，核对屏显、播报、待命和服务日志；不动当前正常用户余额。
- 容量：在独立预发布环境按连接突发、持续会话、供应商延迟分别压测，采集 TCP 队列/拒绝、OTA 与 WS 阶段、进程和数据库指标后再给出容量数值。
