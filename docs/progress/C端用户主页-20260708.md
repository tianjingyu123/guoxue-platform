# C 端公开用户主页后端 + profile.vue 去 mock（20260708）

## 一、方案判定结论

**判定：新增专用公开端点**（二选一中的后者）。

依据（Read 核实）：`user.controller.ts` 的 `GET /users/:id` 虽只挂 `JwtAuthGuard`（非 ADMIN，任意登录用户可调），但 `user.service.getUserById` 的 `select` 返回**大量敏感字段**：

```
phone(maskPhone 掩码), gender, memberLevel, memberExpire, status, roles, station, operator
```

- `memberLevel/status/roles/station/operator` 会把会员等级、封禁状态、角色绑定、驿站/运营商归属暴露给任意陌生人 → 违反 R3 合规红线（隐私最小化）。
- 该端点定位是「登录态用户详情」，不适合作为陌生人可见的公开主页。

因此**不能**让 profile.vue 直连 `GET /users/:id`，改为新增脱敏投影端点 `GET /users/:id/public-profile`。

## 二、改动清单

### 后端 `apps/server/src/modules/user/`

1. **user.service.ts** 新增 `getPublicProfile(userId, viewerId?)`：
   - `user.findUnique` 只 `select { id, nickname, avatar, bio }`（脱敏投影，源头就不查敏感列）。
   - 认证徽章复用 `TeacherCertification`：`status === "APPROVED" && verifiedTitle` 才 `verified=true` 并带 `verifiedTitle`；PENDING/无认证一律 `verified=false` 且**不泄露** verifiedTitle。
   - 统计复用 `getUserStats`（followingCount/followerCount/likeCount）。
   - `isFollowing` / `isMutualFollow`：按 `viewerId` 双向查 `follow`（看自己或未登录时不查关注关系）。
   - `isSelf`：服务端按 viewerId 计算。
   - 用户不存在抛 `BusinessException(USER_NOT_FOUND)`。
   - **严禁返回手机号/生辰/身份证/会员等级/角色/状态/绑定关系**（合规达标）。
2. **user.service.ts** `follow()` 增强：创建关注后反向查一次 `follow`，返回 `{ ...created, isMutualFollow }` → 前端关注后「互相关注」徽章可即时点亮。
3. **user.controller.ts** 新增 `GET :id/public-profile`（`JwtAuthGuard`，传 `req.user?.id` 作 viewer），置于 `:id/stats` 之后、`@Get()` 列表之前（无路由冲突）。

### 前端 `apps/mobile/src/lib/user-profile-data.ts`

4. `userProfileApi.getProfile` 去 mock 改真连：
   - 由「三次拼装（/users/:id + /stats + /is-following）」改为**一次调用** `GET /users/:id/public-profile`。
   - 适配后端聚合响应（verified/verifiedTitle 真连，不再硬编码 `verified:false`；isMutualFollow 真连，不再降级为 false）。
   - `coverImage/level/levelName` 后端仍无 → 前端 `v-if` 诚实降级（页面已处理）。
   - `isSelf` 优先用后端结果，未登录场景用本地 userInfo.id 兜底。

### 后端 spec `apps/server/src/modules/user/user.service.spec.ts`

5. mockPrisma 补 `teacherCertification.findUnique`。
6. 新增 `describe("getPublicProfile")` 6 用例：
