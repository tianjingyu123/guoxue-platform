# IM 好友/通讯录切片 真连 + 单聊死代码清理（2026-07-04）

> 目标：IM 单聊/群聊已上线，好友是最后一块 mock。本切片把好友/通讯录/加好友/好友申请全部去 mock 真连后端 REST，
> 并清理单聊遗留死代码。验收：`vue-tsc --noEmit` + `scan-mock-imports.sh` 全绿；im-data.ts 好友 mock + 单聊死代码清零。

## 一、改动清单

### 后端 `apps/server/src/modules/im/im.service.ts`
好友端点此前为腾讯 REST 原样透传，且 `getFriendList` 用 `sns/friend_get_list` 只传 `From_Account`（缺 `To_Account`/`TagList`，
按腾讯契约属畸形请求），`listPendingFriendRequests` 也不含申请人资料。本次改为**归一化输出**，前端可直接消费：

- 新增导出类型 `ImFriend { userId, nick, avatar, remark }`、`ImPendingRequest { userId, nick, avatar, wording, addTime }`。
- 新增私有方法 `getProfiles(accounts)`：批量 `profile/portrait_get`（`Tag_Profile_IM_Nick` / `Tag_Profile_IM_Image`）补全昵称/头像。
- `getFriendList(userId)` 重写：`sns/friend_get`（拉取好友账号 + `Tag_SNS_IM_Remark` 备注）→ `getProfiles` 补资料 → 返回 `{ friends: ImFriend[] }`。
- `listPendingFriendRequests(userId)` 重写：`sns/friend_get_pendency`（`PendencyType: Pendency_Type_ComeIn`）→ `getProfiles` → 返回 `{ pending: ImPendingRequest[] }`。
- `isFriend()` 同步改为消费新的 `{ friends }` 结构。
- 未改动的端点：`POST /im/friends`（加好友）、`DELETE /im/friends/:toUserId`、`POST /im/friends/approve|reject`、黑名单端点保持原样。

### 前端数据层 `apps/mobile/src/lib/im-data.ts`
- **删除单聊死代码**：`AVATAR` 工具、`AVA_ME`/`AVA_101`、`mockChatTarget`、`mockChatHistory`、`HOUR`、`ChatTarget` 接口，
  以及 `imApi.getChatTarget` / `getChatHistory` / `sendMessage`（单聊已走 TIM SDK，均无引用）。保留 `ChatMessage`/`ChatProduct`/`MessageStatus`/`timToChatMessage`（chat 页在用）。
- **删除好友 mock**：`mockFriendsWithPinyin`、`friendAvatar`、`mockFriendRequests`、`getFriendRequestsData`。
- **类型 id number→string**（对齐腾讯 identifier）：`FriendItem.id`、`FriendRequestUser.id`、`FriendRequestItem.id`。
- **新增纯函数 `pinyinInitial(name)`**：取名称首字拼音首字母（A–Z），中文用 `localeCompare('zh-Hans-CN')` 与边界字比较，英文/数字/符号兜底；用于通讯录分组。
- `groupFriendsByLetter` / `getLetterIndexList` 保留；`searchFriends` 改为纯函数 `searchFriends(friends, keyword)`（在已加载列表中过滤，不再依赖 mock）。
- 新增映射器 `toFriendItem(ImFriendRaw)`、`toFriendRequestItem(ImPendingRaw)`。
- `imApi` 真连：
  - `getFriends()` → `GET /im/friends`，映射 `FriendItem[]`（错误上抛走三态，无 mock 回退）。
  - `getFriendRequests()` → `GET /im/friends/pending`；腾讯无历史故 `processed` 恒空、由页面处理后本地追加。
  - `handleFriendRequest(fromUserId, action)` → `POST /im/friends/approve|reject`（body `{ toUserId }`），失败抛错。
  - 新增 `addFriend(toUserId, remark?)` → `POST /im/friends`；`removeFriend(toUserId)` → `DELETE /im/friends/:toUserId`。
- import 补 `apiDelete`。

### 前端页面
- `pkg-im/im/contacts/index.vue`：新增 `allFriends` 平铺列表；`searchFriends(allFriends.value, keyword)`。（此前已三态齐全、真连 `imApi.getFriends`。）
- `pkg-im/im/friend-requests/index.vue`：`processingIds`/`rejectDialog.requestId`/`goUser` 由 number 改 string；approve/reject/approveAll 加 `try/catch` 错误 toast（API 由「返回 boolean」改为「抛错」）；approveAll 逐条容错累计成功/失败数。
- `pkg-im/im/add-friend/index.vue`：**移除伪造搜索结果 + 伪造添加**（原 `doSearch` 硬编码两个假用户 + `setTimeout` 假 add）。改为「按账号/智玄号发起申请」，`onAdd()` 真连 `imApi.addFriend`（`submitting` 防重复 + 错误 toast），加说明条诚实告知暂无在线搜索。

## 三、剩余卡点 / 待办

1. **未做双账号 e2e 真机验证**：memory 记载 IM 密钥冻结、账号 import 未自动化、生产短信签名失败；本切片无法在本地/生产跑通「加好友→同意→成好友」真链路。
   后端归一化实现严格按腾讯 REST 文档契约编写（`sns/friend_get` / `profile/portrait_get` / `sns/friend_get_pendency`），
   **待 IM 配置就绪后需真机复验字段名与响应结构**（尤其 pendency 的 `To_Account` 是否即申请人、`ValueItem` 是否含 `Tag_SNS_IM_Remark`）。
2. **无公开用户搜索端点**：`GET /users`（keyword）是管理员专用（RolesGuard）。C 端无法按昵称/手机号搜人，故 add-friend 诚实降级为「按账号添加」。
   若要做真正的「搜索加好友」，需新增一个 C 端可用、且经隐私评审的用户搜索端点（涉及数据语义/隐私，属业务规则，需先拍板；未擅自新增）。
3. **在线态诚实降级**：通讯录在线点隐藏（`isOnline` 恒 false）。腾讯 `openim/querystate` 可查，但后端在线态鉴权守卫按好友逐个 `isFriend`（每次 2 次腾讯调用）成本过高，故不做批量在线态；待守卫优化后再接。
4. **invite 邀请页**：纯前端分享（链接/二维码/海报），无 mock import、不违规，本次保留未改。其邀请码目前为占位 `GUOXUE2026`，
   接真实推荐码需 referral 端点（属分销/用户域，另 agent 在用），列为 backlog。
