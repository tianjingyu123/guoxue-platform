## 本轮修复主题

**一类系统性 bug**：service 对**按 id 执行 `update`/`delete`** 时缺少存在性检查 → 操作不存在记录时 Prisma 抛 `P2025` → HTTP **500**（正确应为 **404**）。
**另一类**：用 `updateMany`/`deleteMany` 删改单条记录 → 记录不存在时静默返回 200（**假成功**）。

修复模式（统一）：
```ts
const existing = await this.prisma.<model>.findUnique({ where: { <键> } });
if (!existing) throw new BusinessException(ErrorCode.NOT_FOUND, "<资源>不存在");
```
`BusinessException(ErrorCode.NOT_FOUND)` 全局映射为 HTTP 404（已由 e2e 验证）。

## 审计维度四：NaN/参数健壮性致 500（2026-07-02 续，已修复并提交）

3 域审计，发现一个**系统性根因** + 上百受影响端点（"单测绿但真人崩"典型）。

- **根因**：用户传非法/缺省数值参数（`?page=abc`、`?page=-1`、无效日期）→ NaN/Invalid Date → 进 Prisma `skip/take/where` → 抛 `PrismaClientValidationError`，而 `PrismaExceptionFilter` **只捕 `KnownRequestError`(P2xxx)** → 漏网成 500（应为 400）。约 100+ 列表端点受影响（多为"传非法值才崩"，少数"缺省即崩"）。
- **🔴 P1（`e2dd5657`）paipan 公开排盘 GET**：`/paipan/bazi/calculate`、`/bazi/public` 裸 `@Query` 手拼对象 `as BaziInputDto` **绕过 ValidationPipe**，`?year=abc` 或 public 缺参→NaN 直入排盘引擎→TypeError→500（公开无鉴权、缺参即崩）。加 `parseBaziInt` 校验（calculate 回退默认 / public 抛 400）。
- **✅ 系统性根治（`fdab3403`）**：新增 `PrismaValidationExceptionFilter`（`@Catch(PrismaClientValidationError)` 映射 400 + warn 日志防掩盖真 bug），注册于 `main.ts`；修 `safePagination` 的 NaN bug（`Number.isFinite` 兜底）。一处收敛全部分页-NaN→500。补 filter+分页单测。
- **✅ 日期字段（`eb2116a3`）**：audit/finance/risk-control/shop/system/ai-gateway 的可选日期筛选字段 `@IsString`→`@IsDateString`（非法日期校验阶段返 400）。保留 period(YYYY-MM)与必填排期字段。

决策依据：用户选"全局过滤器兜底 + 修 safePagination + 日期字段一并修"。**未做**逐端点分页归一化（有全局过滤器兜底已足够；safePagination 已修供复用）。
