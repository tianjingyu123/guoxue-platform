## 一、这批已经落地的代码

1. 新增智能体实时语音专用页 `pkg-agent/agent/voice-call`：
   - 独立的语音通话视觉样板，含聆听、思考、说话、重连、结束状态。
   - 实时字幕、情感音色、静音、结束、切回文字对话。
   - H5 麦克风预检、小程序 `scope.record`、Android/iOS 麦克风权限声明。
   - 页面通过统一 `VoiceAgentRuntimeBridge` 接入供应商 SDK；SDK 未装载时发布闸门明确阻断，不制造假通话。
2. 智能体文字页的“语音通话”入口已改为进入专用语音页。
3. 后端已有 `POST /bots/:id/voice-room`，会校验智能体是否开放语音，并由服务端创建临时房间，密钥不下发到客户端。
4. 古籍听书继续统一走后端 TTS，新增：
   - `EmotionCategory`、`EmotionIntensity` 情感表达；
   - `SegmentRate` 断句敏感阈值；
   - 古籍默认 `poetry / 110 / 2`，优先按明确标点断句；
   - 情感、强度、断句参数纳入缓存键，避免串音色。

## 二、语音实时通话：建议正式方案

### 推荐主链路：腾讯 TRTC AI 实时对话

选择理由：

- 同时覆盖 H5、Android、iOS、微信小程序，且项目已有 TRTC UserSig、真人付费通话和腾讯云基础设施。
- 支持低延迟语音、服务端启动 AI、实时字幕、机器人状态、智能打断、降噪和上下文。
- 可以继续使用平台现有大模型和知识库，不必把所有智能体迁入单一供应商。

正式链路：

`客户端进 TRTC 房间 → 后端 StartAIConversation → ASR/VAD → 平台智能体路由与知识库 → 情感 TTS → TRTC 下行音频 → 字幕/状态回调`

当前 Coze `audio/rooms` 可以保留为备选验证链路，但客户端仍需对应 RTC SDK，不能只凭一个房间 Token 完成跨端通话。

### 需要你开通或提供的项目

| 项目 | 需要的值/操作 | 用途 | 注意 |
| --- | --- | --- | --- |
| 腾讯 TRTC 应用 | `TRTC_SDK_APP_ID`、`TRTC_SECRET_KEY` | 房间和 UserSig | SecretKey 只进服务端配置中心 |
| AI 实时对话 | 在 TRTC 控制台开通 AI 实时对话及套餐 | 机器人入会、智能打断、状态回调 | 会产生音频通话、AI 对话、ASR 三部分费用 |
| 语音转文字 ASR | 开通 TRTC 语音转文字 | 用户语音识别、实时字幕 | 小程序字幕需额外 IM 信令通道 |
| 腾讯云 TTS | `TENCENT_APP_ID`、`TENCENT_SECRET_ID`、`TENCENT_SECRET_KEY` | 情感语音、古籍朗读 | 已有基础 TTS 代码；需确认生产账号已开通多情感音色 |
| TRTC 客户端 SDK | Web/H5、微信小程序、Android、iOS | 真实采集、进房、播放、打断 | App 需 DCloud 原生插件或自定义基座 |

## 三、每个语音智能体的角色化要求

统一底层能力，不统一角色表现。每个智能体配置以下可运营字段：

| 配置层 | 示例 |
| --- | --- |
| 角色音色 | 沉静男声、温和女声、书院讲师、诗词吟诵 |
| 情绪策略 | `peaceful`、`story`、`poetry`、`call` 等 |
| 对话节奏 | 回答长度、停顿、追问频率、是否允许打断 |
| 输出模板 | 学习路线、句读卡、诗词意象卡、典故源流卡、礼仪场景卡 |
| 专业边界 | 非本专业问题推荐对应专业智能体；预测类问题导向专业排盘工具 |
| 推荐策略 | 先解决问题，再在明确上下文中推荐一项相关内容；记录展示、点击、转化和拒绝 |

推荐必须遵守：不隐瞒商业关系、不利用用户焦虑、不把普通建议伪装成专业诊断或确定性预测。

## 四、古籍自然朗读、断句与标点

### 数据结构应采用“三层文本”

1. **原始底本层**：保存来源、版本、页码/卷章和未经改写的原文。
2. **编辑校勘层**：保存平台采用的断句、标点、异体字和校注版本，是正式展示与朗读来源。
3. **AI 草稿层**：AI 生成断句、释词、翻译、拼音和停顿建议，必须保留模型、提示词、时间和置信度，经过人工审核后才能升为编辑层。

不能把任一外部 AI 的自动标点直接当作经典定本。古文存在版本、句读和学派差异，必须支持版本并存、编辑审核、用户纠错和回滚。

### 建议开通的外部能力

| 能力 | 建议接口 | 解决的问题 |
| --- | --- | --- |
| 扫描古籍 OCR | 腾讯云 OCR 古籍/通用印刷体能力，必要时另购专业古籍 OCR | 从影印页获得文字和版面坐标 |
| AI 断句/标点 | 平台现有大模型网关，使用专门提示词和检索到的权威校本 | 生成可审核草稿，不直接覆盖原文 |
| 字词读音 | 自建多音字/古音词典 + 人工覆盖表 | 人名、地名、通假字、专有名词读音 |
| 情感朗读 | 腾讯云 TTS 多情感音色；长文本逐句或实时 WebSocket | 诗歌、经史、讲解采用不同语气 |
| 时间戳 | TTS `EnableSubtitle` 或实时合成字幕 | 逐字高亮、笔记定位、断点续听 |

### 朗读上线验收

- 断句单元保留原文锚点，笔记和“回到原文”精确到句。
- 对无标点底本先走编辑层，不把按固定字数硬切当作正式效果。
- 标点、专名、多音字、数字、干支、异体字建立回归语料。
- TTS 失败允许降级到普通音色，但不得朗读错误文本或自动改写原文。

## 五、多端适配与发布闸门

### H5

- 手机：375×667、390×844、430×932。
- 平板：768×1024、834×1194，横竖屏。
- PC：1280×720、1440×900、1920×1080；桌面端保持合理内容宽度，并给商家工作台/库存系统提供更高信息密度。
- 必测：返回/关闭按钮不重叠、内容层手势关闭、弹层滚动锁定、麦克风拒绝后恢复、键盘顶起。

### 微信小程序

- 当前 AppID 已配置，但 `urlCheck:false` 仅适合开发；提审包必须恢复 `true`。
- 配齐 request、uploadFile、downloadFile、socket 合法域名和业务域名。
- 完成隐私保护指引：麦克风、相册/相机、位置、昵称头像、剪贴板等实际用途。
- 预测敏感表达继续按现有条件编译规范裁剪，不影响 H5/App 专业学习内容。
- 真机验证支付、登录、音频后台策略、录音授权、iOS/Android 微信差异。

### App

- 当前 `manifest.json` 顶层 DCloud `appid` 仍为空，这是 App 云打包硬阻塞。
- 需要提供：DCloud AppID、Android 包名与正式签名证书、iOS Bundle ID/证书/描述文件、正式版本号、隐私政策 URL、客服与注销入口、商店截图/图标/启动图。
- TRTC 需原生插件或自定义基座；Android/iOS 麦克风声明已预置，仍需真机授权验收。
- 上架前完成第三方 SDK 清单、个人信息收集清单、权限最小化、账号注销、儿童/未成年人和内容举报流程。
