# 直播板块主播端摸底走查报告（2026-07-11·只读审计·拍板材料）

**总判断：观众端（watch/vertical/horizontal/plaza）是真材实料可沿用；主播端 27 页中约半数是原型过度设计的半成品——「数据读取真连、写操作全假」是普遍模式。最致命的不是页面假，而是三条主链路断点：①主播无法自主开播（接口被锁管理员+无 UI 入口+功能开关未配）②TIM 弹幕群从未创建（imGroupId 全库恒 null，实时弹幕从未生效过）③画质计费只收钱不核销（consumeQuota 零调用点）。**

## ④ 主播端收敛方案建议（27 页 → 8 页）

**开播三件套（核心重塑）**：
1. **竖屏开播台**（create 演进）：创建+画质选档+时长包内联购买已扎实，补「开播」按钮（前提：start 接口放开给房主）
2. **OBS 开播流程页**（stream-config+obs+obs-guide 三合一）：推流码+图文教程+复制真实现，砍假实时监控
3. **直播控制台**（console 重塑）：保留真数据看板+真弹幕流，把假按钮接到现成后端（禁言/秒杀/下播），砍掉无后端的抽奖/优惠券/提词器/连麦（或连麦接 mics 端点）

**经营三页**：
4. **我的直播**（manage 吸收 schedule/host-data）：列表+编辑/删除接现成端点+每场入口进 analytics
5. **数据复盘**（analytics 保留，吸收 host-data 汇总卡）
6. **收益**（earnings 保留）：提现入口指向钱包既有提现

**配套两页**：
7. **时长包购买**（quality-packages 保留）——前提是把 consumeQuota 核销接上
8. **评价管理**（reviews 保留）：补一个回复端点即闭环

**砍掉清单**：theme、team、replay-comment、schedule、host-data、obs（并入）、replay-home（并入 replays）、settings（无后端，砍或降级）；hosts 页待拍板（倾向砍）。观众侧三处小修：preview 预约按钮、replays 点击跳转、vertical 关注接 API。

## ⑤ 风险与依赖

1. **开播权限是第一颗要拔的钉子**：PUT start/end 锁死管理员且全前端无调用——重塑前必须先拍板「主播自主开播（房主校验）还是运营代开」。生产库需确认 live_start feature flag。
2. **推流真验证依赖**：生产 env 需配 LIVE_PUSH_DOMAIN/LIVE_PLAY_DOMAIN/LIVE_PUSH_KEY/LIVE_PLAY_KEY（腾讯云 CSS·转码模板 hd720/hd1080 已建）+ 真机推一路流。
3. **IM 弹幕依赖**：需在 createRoom/startLive 时调腾讯 IM 创建群并回写 imGroupId——一个后端小改动救活三个页面的实时弹幕。
4. **VOD 回放依赖**：需腾讯云直播控制台开启录制模板+配置回调地址；回调验签逻辑已在。
5. **连麦 TRTC**：真连麦是二期工程（需 TRTC 房间创建/user-sig 下发），后端 mics 端点只是麦位占位记录。
6. **计费核销缺口**：consumeQuota 已写好但无人调——建议挂到 LiveDataCollector 每分钟 cron（天然挂载点），否则时长包商业化名存实亡。
7. **迁移地雷**：LiveReview/LiveTeamMember 库有表但 repo 无建表 SQL——保留的能力需补 migration。
