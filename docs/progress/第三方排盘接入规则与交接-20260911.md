# 第三方排盘接入规则与交接

日期：2026-09-11。来源：用户在当前任务连续确认的业务要求及本机代码、安卓微信验证。本文供后续窗口接续，不代表功能已经全部实现或验收通过。

## 最新决策：稳定性优先

先只读调查和独立验证，不切换线上接入、分享方式。若内嵌必须绕过浏览器限制，或容易产生白屏、授权循环、错误盘面、支付异常，则放弃该方案。必须第三方配合时列出具体证据和最小配合项，由用户联系；不要反复要求第三方整套源码。第三方源码不在我们手中。

## 普通用户与登录

- 普通排盘只要求热卜登录，不能因未绑定手机号阻止使用。
- 微信内默认优先微信快捷登录，保留账号登录选项；不代替用户确认微信要求的授权。
- 登录完成自动回到受阻的页面和必要位置，保留参数、分站来源、必要页面状态；所有功能适用，不统一跳首页，不要求用户重新寻找入口。
- 不自动重放付款、创建订单等有副作用操作。取消登录不循环弹出授权。
- 有手机号：使用已有手机号签名接入约定，关联旧账号；不存在时按旧系统支持的流程开户。具体响应和落地效果仍需核验。
- 无手机号：允许走旧系统自己的授权与建号流程，不强迫绑手机，不伪造手机或身份。
- 新系统微信登录不等于旧系统登录。可追求一次点击连续完成，但不能承诺不同公众号首次授权永远只需一次确认。
- 后续绑定手机号：可查询并保存旧账号对应关系，不自动合并旧账号、不迁移旧权益；冲突保留待核对。无手机号期间不要求跨系统权益互通。

## 分站、运营商与归属

- 开通分站或运营商要求绑定手机号，用于核对旧系统推荐人身份。
- 用户确认：旧系统支持账号不存在时自动开户，已有账号可核对或开通推荐人。此为用户提供的能力说明，接口行为尚待验证。
- 保存站长与旧系统推荐人 userid、推荐链接的映射；普通旧用户有 userid 不等于已有推荐人资格。
- 用户从哪个分站点击排盘，就使用该站长的旧系统推荐链接，登录回跳不能丢失来源。
- 是否建立旧系统推荐关系由旧系统决定，不覆盖其已有归属。新旧推荐关系、业务和佣金独立。
- 旧排盘支付、订单、佣金、客服继续由旧系统处理，热卜不接管。

## 分享与页面壳目标

主要分享格式是 H5。重点场景：App 内分享具体排盘，接收人在微信打开后仍有热卜外框、返回热卜首页入口，并显示准确的对应盘面。

- 首次分享必须取得准确且可公开的盘面地址，不分享手机号签名入口或登录凭据。
- 接收人切换盘面后再次分享，不能把第一次地址当作当前地址。
- App 原生容器与 H5 跨域 iframe 能力不同；H5 不能默认读取第三方跳转后的地址、修改其内部按钮。
- 优先调查旧页已有分享链接或消息接口；没有能力证据不得宣称能自动抓取。
- 不因增加外框破坏旧站授权、客服或支付。保留外层首页按钮，不等于旧页内部所有按钮已受控。
