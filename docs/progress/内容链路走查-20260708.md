## P0 — 智能体广场对话全线 502 超时（Coze 集成）

**路由**：`/pkg-agent/agents/index`（广场）→ `/pkg-agent/bots/chat/index?id=<botId>`（对话）；同源问题波及 `/pkg-agent/agent/main`（智玄主入口）与全局客服 FAB。

**操作**：广场任一智能体 → 进对话 → 输入问题 → 发送。

**预期**：真调 AI，返回命理/国学解答（DeepSeek 已恢复）。

**实际**：前端气泡显示「抱歉，回复失败：request:fail timeout」。API 层复现：

```
POST /bots/a0000001-...-001/chat  {query:"你好，请用一句话介绍八字命理"}
  → 502  35.9s  {"errorCode":700003,"message":"COZE对话超时，未获取到响应"}
POST /bots/...-002/chat (紫微斗数) → 502 39.5s  同错误
POST /bots/...-004/chat (六爻)     → 502 36.5s  同错误
```

**判定**：真 bug（P0）。广场 5 个智能体全部 Coze 型（`botId` 均 76xxx）：八字命理精批师 / 紫微斗数分析师 / 合婚匹配顾问 / 六爻占卜师 / 择日通书师——**无一可用**。且 `agent-main`（智玄）与客服（`sendZhixuanMessage`/`sendCsMessage`）走同一 `POST /bots/:id/chat` 路径 → 同样超时。即**平台所有 Coze 型对话入口 100% 失败**。

**范围界定**：DeepSeek 系 AI 全部正常（见下方古籍伴读/点句白话/诗词 AI）；仅 Coze 集成挂了。根因在后端 Coze 调用侧（密钥/配额/网络/bot 配置），非前端。属"后端就绪假象"——`GET /bots` 列表 200、详情 200、页面能开，唯独真发消息即超时。

**证据**：`walk-interact-report.json` 项「智能体对话发消息」`snippet` 含"回复失败：request:fail timeout"；`shots/i-bot-chat.png`；上方 3 次 API 复现。

**建议**：确认 Coze 三方配置是否在生产失效/未配（后台 ThirdPartyConfig）；短期可将广场默认智能体路由到 DeepSeek 自建链路（伴读已证可用），或对 Coze 超时做降级兜底文案（当前是硬失败）。

## P1 — 电子书阅读进度保存 400（静默丢失）

**路由**：`/pkg-ebook/reader/index?id=<bookId>`（阅读器切章/翻页/退出时保存进度）。

**操作**：打开电子书阅读器（正文正常渲染，点句 AI 提示在），`onHide`/`onUnload`/切章触发保存进度。

**预期**：`PUT /ebook/progress/:bookId` 200，记住阅读位置。

**实际**：`400 PUT /ebook/progress/:id`，控制台一条 400。API 复现：

```
PUT /ebook/progress/538d4f06...  {chapterId:"fb68...", progress:12}
  → 400  {"message":["【chapterId】该字段不允许提交，请检查是否填了多余的字段"]}
```

**根因**：
- 前端 `pkg-ebook/reader/index.vue:612` → `ebookApi.saveProgress(bookId, { chapterId, progress })`（`lib/ebook-data.ts:690`）发送 `chapterId`。
- 后端 `apps/server/src/modules/ebook/ebook.dto.ts:154 UpdateProgressDto` **只允许 `progress` / `currentPage`，无 `chapterId`**；全局 ValidationPipe `forbidNonWhitelisted:true` 直接 400。
- 前端调用挂 `.catch(() => {})` → **错误被静默吞掉**，用户无感知，但进度永不落库。

**判定**：真 bug（P1·静默功能断）。对比古籍阅读器 `PUT /classic/progress/:id` 返回 200 正常——仅电子书这条契约错配。

**证据**：`walk-content-report.json` 项 `ebook-reader` api 列表含 `400 PUT /ebook/progress/...` + 一条 400 console error；`shots/c-ebook-reader.png`（正文渲染正常）。

**建议**（两选一）：后端 `UpdateProgressDto` 增补 `@IsOptional() @IsString() chapterId?`（并落库到进度记录，语义更完整）；或前端 `saveProgress` 去掉 `chapterId` 字段。前者更佳。
