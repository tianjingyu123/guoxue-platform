# 微信 H5 排盘内嵌调查结论（2026-09-11）

## 当前结论

完整 H5 内嵌暂不具备发布条件。两节点独立验证页在安卓微信能显示热卜外框，但 p1.php 内部持续空白；不能把 iframe load 或 HTTP 200 当成功，也尚不能断言具体是第三方策略还是授权会话限制。没有证据证明历史 H5 内嵌验收通过，App 原生桥可用不代表 H5 可用。

按用户“有风险则放弃”的要求，本地 iframe 试验已从业务页面撤出，保存在 artifacts/paipan-embed-investigation/index.vue.unverified.txt，仅供调查。未发布线上。

## 已完成的本地候选修改

- 普通入口和分站入口统一经过后端校验，移除微信端绕过新系统登录的分支。
- 普通用户真正无手机号时允许返回旧站网页授权入口；个人中心和站长同步仍使用原规则。旧站授权实际完成情况尚未验收。
- 微信首次登录允许按现有微信登录协议建号，不因来自排盘而强制手机号。
- 登录回跳使用已登记页面清单，修复有效页面未在别名表中时被误判而回首页，保留查询参数。未宣称覆盖滚动位置、表单或第三方内页状态。
- 移除入口页直接整页外跳；复用后端返回的原始地址交接给现有兼容页，不擅自改写签名或分站推荐参数。

注意：现有 H5 兼容页仍是用户点击打开旧站的保底方式，不是内嵌，不满足“始终留在热卜壳内”。不能将上述候选称为完整接入修复，不能直接全量覆盖线上。

## 验证记录

- 29 项前端登录回跳、入口及门禁检查通过。
- 7 项后端入口、推荐参数、站长同步检查通过。
- 配置正式公开地址后的 H5 构建成功；首次缺少公开构建变量被构建器拦截，补齐后通过。
- 没有修改线上服务、数据库、支付配置，没有进行真实开户或支付。

## 必须补齐的第三方契约

1. 微信 H5 可用的内嵌接入方案：现有 p1.php 触发旧公众号 OAuth，需确认如何在不丢失外框的情况下完成授权与会话建立；不得禁用浏览器安全机制或自行代理其登录/支付来试错。
2. 准确盘面公开地址与状态通知：若需在第三方内页跳转后仍分享当前盘面，需要旧页提供约定消息，至少含公开盘面标识或无凭据公开地址。热卜校验消息来源和对应窗口，不接收任意跳转。
3. 首页、返回与分享动作桥：旧页已有 App 桥不能被当作 H5 父子页消息桥；请确认可复用的 H5 协议。无需第三方整套源码。

在上述能力得到证实前，建议放弃自动 H5 内嵌与当前内页抓取；保留既有功能，不制造“有外框但盘面空白”的假完成。若第三方仅支持公开盘面页内嵌，可缩小到分享落地页单独验收，不把登录、支付整站一起嵌入。

## 接口历史核实

原始用户接口说明来自任务“新旧程序切换数据迁移”：partner.php 对不存在手机号返回失败；my.php?mod=member&act=addPartner 才是在微信授权后自动开户。因此保留不存在账号的待授权状态，不删除它盲调 partner.php。后续如第三方升级接口，需以新契约替代旧说明。

权威业务规则见主工作区 docs/progress/第三方排盘接入规则与交接-20260911.md。

## 分站来源丢失修复补充

代码复核发现：承接页只消费一次内存地址，过期后无条件请求普通入口，登录回跳也没有入口参数，会丢失原分站或个人中心目标。候选已修复为：

- 路由仅传入口类型与分站标识，原始签名地址仍只放短期内存。
- 内存交接与入口上下文绑定，不同分站不能串用推荐地址。
- 交接过期、页面刷新或登录返回后，重新请求同一分站/个人中心接口。
- 缺分站标识明确提示，不偷偷退回普通入口；401 由页面呈现登录选择。

新增超时、跨分站隔离、重复消费、个人中心重试及参数转义检查；前端相关检查共 49 项通过。仍未发布，完整内嵌限制不变。
