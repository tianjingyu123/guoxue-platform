# 排盘报告付费交付与工作台体验审计（2026-09-22）

## 用户要完成的事

| 用户 | 任务 | 顺畅路径应当是 |
| --- | --- | --- |
| 爱好者 | 看懂自己的盘、找到依据、继续提问 | 起盘 → 看免费盘面 → 明白报告范围和价格 → 支付 → 直接读报告 → 对具体章节提问 → 学习相关典籍 |
| 从业者 | 快速形成可审核的客户交付物 | 起盘 → 导入工作台 → AI 起草或改写 → 自己校核 → 客户视角预览 → 交付 → 收集客户问题与回访 |
| 已购买用户 | 不中断已开始的工作 | 查原订单到账 → 进入原报告或会员能力 → 历史与对话可继续；网络失败可重试，不能重复收费 |

这三条路径共享排盘记录、报告事实和交付状态，但“平台小卜报告”与“从业者署名交付报告”是两种产品，现有代码也分别在 `paipan` 与 `practitioner` 模块。后续应在工作台建立关联，避免用户以为买了小卜报告就自动生成客户交付件。

## 本轮实证与修复

1. **付款后走丢**：通用支付成功页只有订单和商城入口。现在用服务端核验为已支付的订单类型与 `targetId` 决定主要动作：报告订单进入原报告，工作台会员返回工作台，语音时长回额度页；从报告入口买小卜会员会带回原排盘记录。仍保留订单入口。订单未支付或查询失败时不展示成功服务入口。订单状态和权益生效仍由后端支付回调决定。
2. **微信 H5 回跳再次唤起付款**：支付页原来回跳后直接调用 `startPaying()`。现在为回跳链接加 `paymentReturn=1`，回页只轮询原订单。倒计时结束仍是“确认中”，不是擅自判失败。
3. **从业者会员支付绕路**：工作台原用 Native 扫码弹层，手机用户需跨设备扫码。现改为平台统一收银页，保留服务端订单定价与回调开通；返回工作台及编辑器时刷新会员状态。
4. **交付内容不同步**：工作台 AI 改写后同步更新编辑区章节；改写前先保存老师未提交的改动。交付前若保存失败立即停止；有空白章节时由老师确认是否仍要交付。避免客户读到旧稿或误交空章。
5. **报告对话失败无恢复**：失败的问题可原位重试；新报告不会沿用旧报告的对话缓存。未发送问题原文到行为埋点。
6. **假进度和价格误导**：生成页去掉定时点亮步骤，预检返回后一次展示已核对的事实，保留真正进行中的成书阶段；会员方案列表为空时不再显示“¥0 起”。
7. **漏斗可测**：增加不含姓名、生辰、问题正文的事件：报告权限、购买点击、订单创建、生成开始/完成/失败、提问开始/完成/失败、导入工作台、已付服务继续、工作台会员购买。上报失败不影响用户操作。

## 仍需推进的产品工作（按优先级）

| 优先级 | 工作 | 验收标准 |
| --- | --- | --- |
| P0 | 微信小程序、微信内 H5、外部 H5 的报告购买／会员续费／语音充值联调；支付回调延迟、失败、退款、重复回跳与订单恢复。App 端当前只提示尚不支持在线支付，若作为正式购买端须接入合规支付能力并验收 | 每种状态只兑现一次；付款后能到原任务；已付款但生成失败可免费重试；退款后的权益按规则收回 |
| P0 | 工作台交付页与真实客户预览逐屏对照，报告内容审校与版本留痕 | 老师看到的与客户看到的一致；每章能区分引擎事实、AI 初稿和人工修改；撤回链接立即失效 |
| P1 | 工作台“今日待办”围绕预约、未定稿报告、客户新问题和回访安排，而非泛化 KPI | 从首页一步回到未完成任务；能看到客户关联的盘、报告、问答及后续动作 |
| P1 | 报告阅读中的术语、原典、具体问题与课程/圈子建立相关性连接 | 推荐理由与当前章节相关，能返回阅读位置；避免购买刚结束就推无关商品 |
| P1 | 统一历史：小卜报告、对话、客户交付件、订单在各自页面可互相回到同一任务 | 用户换设备后不用重新输入盘面，已付报告可继续，工作台导入不制造难辨的重复件 |
| P2 | 为专业用户提供门派对照、计算口径、案例批注与团队复核 | 同一盘的依据和争议可追溯；能沉淀可检索的客户案例和学习笔记 |

## 衡量方法与边界

- 漏斗按 `权限页展示 → 点击购买 → 订单创建 → 支付成功 → 报告生成完成 → 首次阅读 → 首次提问 → 次日/七日回访` 测量，分端、用户类型、首购/续费，不混算。
- 同时看支付后到达报告率、生成失败恢复率、交付前预览率、空章交付率、提问成功率、客户回访率、退款与客服原因。转化率提高但退款/投诉上升，不能算体验提升。
- 本机没有代表性的真实用户行为样本，本轮无法声称转化率或满意度已提高。新增埋点要等真实环境验证上报与口径，再做小流量对照；订单数据作为付款真源，埋点只衡量行为。
- [Baymard 结算研究](https://baymard.com/research-articles/current-state-of-checkout-ux)显示不清晰的结算流程会导致用户放弃；其[订单确认页研究](https://baymard.com/checkout-usability/benchmark/step-type/receipt)也指出用户需要明确确认购买并知道下一步。本轮的“先核验订单、再给原任务入口”采用这一原则；具体效果须由本平台数据验证。

## 技术验证边界

本轮在本地工作树完成静态代码审查、7 个订单去向分支验证和移动端类型检查；移动端完整类型检查仍有金口诀、罗盘、梅花及旧 shared 声明相关的既存报错，本轮改动文件无新增报错。从业者报告导入、交付报告和客户问答 3 组 Jest（19 项）通过；支付服务测试因本工作树复用的旧 Prisma Client 缺 `VoiceSession.usageState` 声明，编译阶段未运行。未触发真实支付、付费 AI 调用、生产回调或远端部署；这些必须在匹配的隔离环境里按 P0 场景联调。

## 2026-09-23 补充：支付恢复与结算超时

- 收银页从订单、超时页或 H5 回跳重开时，先只读查询原订单。已支付直接去对应服务的成功页；已取消或退款显示终态；待付且并非渠道回跳时才发起支付。查单异常或状态未知时继续轮询原单，不在未知状态下唤起第二次付款。重试按钮也执行同一核验。用户离开页面后，晚返回的支付参数不再唤起收银台或跳转结果页。
- 订单状态接口缺失 `status` 不再默认成 `PENDING`，避免异常响应被误判为可再次付款。支付轮询遇到已取消或退款订单会结束，并告知真实状态。
- 商城结算页原有前端 15 分钟倒计时发生在创建订单之前，但文案称“支付超时”，到期还会跳到一个没有订单号的支付超时页。现移除这段没有服务端期限依据的倒计时及弹窗；商品和价格仍会在结算时读取，真实订单状态以服务端为准。
- 验证：订单恢复决策 8 个状态用例通过；改动文件 ESLint 0 error（存量样式 warning）；移动端类型检查仍为原有 16 个其他模块错误，改动文件无新增错误。未进行微信真实扣款或异步回调联调，不能将本地分支验证等同于支付端到端验收。
- 报告生成失败的服务端门禁按已购权益或有效会员状态核验，报告内容仅在模型成功后写入；失败后重试不再创建新订单。前端错误态已有原记录重试入口，本次把生成中“请勿离开页面”改为可以从原排盘记录继续查看或重试，避免给用户错误的等待压力。会员到期后仍按服务端当时的权益规则处理。

## 2026-09-23 补充：成功页回调延迟恢复

- 支付成功页的订单查询若暂时未到账或网络失败，新增“重新核验”入口；从订单页返回时自动重新核验原订单。核验只读取服务端状态，不再次发起付款。
- 已取消和已退款订单显示各自真实状态，不用“回调仍在处理”的误导性提示，也不反复展示无效的核验按钮。成功服务入口依然只有在订单确认为已支付后出现。
- 仍需在微信小程序、微信内 H5、外部 H5 用真实支付回调和延迟注入验证多端表现；本地静态与分支检查不能替代真机联调。

## 2026-09-23 补充：工作台交付版本保护

- 客户交付链接原来直接读取报告当前正文，老师交付后继续保存或整份 AI 改写，会让客户在同一链接里看到未经重新预览的新稿。现将链接有效期间的正文设为只读：编辑器禁用修改与改写，服务端保存和改写都用 `shareToken = null` 条件写入，防止并发交付后仍写进新稿。
- 老师需要修订时，先撤回交付链接；撤回后报告回到 `final`，可修改、预览，再生成新链接。交付时统一标记 `delivered`。旧链接撤回即失效，新链接使用新令牌；正式环境仍需验证链接传播与缓存行为。
- 相关服务端 Jest 两组 11 项通过，覆盖交付后拒绝保存、改写拒绝与改写期间发生交付的竞争。编辑器和支付成功页 ESLint 0 error；移动端完整类型检查的其他模块存量错误仍需清理。

## 2026-09-23 补充：从业者会员月底续费

- 从业者会员付款开通与退款后按剩余订单重建权益，原来分别用 `Date.setMonth` 加一个月。1 月 31 日等月底会越过 2 月，导致有效期与用户理解的“按月续费”不符。现共用按 UTC 自然月顺延、目标月不足原日号则取月末的函数，保留原时分秒，付款与退款重建口径一致。
- 4 个边界用例通过，覆盖平年 2 月、闰年 2 月、30 天月份与跨年。支付／退款服务整组 Jest 因本工作树复用的旧 Prisma Client 类型分别缺 `VoiceSession.usageState` 和新增订单类型，在编译阶段停下，未运行到业务断言。尚未在真实支付／退款回调环境跑端到端重建；需要与财务订单和到期通知一起验收。
- 小卜 AI 会员页原默认选第二档，当前默认配置对应年费，容易让用户一进入就面对较高实付金额。现默认选择服务端返回的总支付金额最低档，长期方案保留给用户主动选择；若已手动选档，刷新后仍保留该选择。

## 2026-09-23 补充：返回购买页时恢复待付订单

- 小卜报告、小卜 AI 会员和从业者会员在当前页面会话内保留刚创建的订单。用户从收银页返回再次购买同一标的时，先查原订单：仍待付就回原单继续；已付则刷新报告权限或会员状态；已取消／退款才允许创建新单；查单失败或未知状态不盲目创建第二笔。
- 这减少同一页面反复进入收银台造成的重复待付订单。记录只在当前页面实例中，换设备或重启后不能复用；彻底解决需要服务端按用户、产品、标的、价格和有效期做并发安全的待付订单复用，并核对优惠券、归因和价格变化的语义。
- 三个改动页面 ESLint 0 error；移动端完整类型检查仍为其他模块既有的 16 个错误，改动页面无新增错误。尚未真机模拟微信取消、慢回调和跨端付款。

## 2026-09-23 补充：服务端待付订单复用

- 报告、小卜 AI 会员和从业者会员下单扩展现有的 Redis 创建锁与 PostgreSQL 事务级锁，按用户、订单类型、标的查询原 `PENDING` 订单。相同条件返回原单；无券订单若当前服务端价格与原单金额不同，要求先取消原单；优惠券不同也不另建可扣款订单。同券待付单保留创建时已核销的价格，不再次扣券。
- 从业者会员只接受 `practitioner_pro_monthly` 标的，避免通过更换标的绕开订单锁；工作台旧的 `createProOrder` 辅助函数补齐标的与数量参数。
- 商城下单服务运行时 Jest 全组 72 项通过，包含 9 项数字服务订单恢复场景；为绕过本工作树复用的旧 Prisma Client 对 `VoiceSession.usageState` 的编译报错，临时测试配置只关闭了过期类型诊断。正式类型检查与真实 PostgreSQL 并发、支付回调仍需在匹配的隔离环境验收，不能将这些单元用例等同于端到端支付安全证明。
- 复用返回增加 `reused` 标记，报告与从业者会员购买页分别上报“恢复原单”事件，不把跨设备找回旧单重复计作新订单创建；订单与付款的最终统计仍以服务端流水为准。
