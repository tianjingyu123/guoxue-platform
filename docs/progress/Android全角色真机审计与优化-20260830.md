# Android 全角色真机审计与优化（2026-08-30）

## 1. 目标与结论边界

本轮不再以「页面能打开」作为验收，而以真实角色完成一条业务任务为最小单元。当前仍处于审计与修复阶段，未获得同版本服务端、数据库迁移、客户端和真机证据前，不宣称「全部通过」或「已达上线水平」。

## 2. 新的验收方法

每条证据必须同时绑定：

- 唯一完整 `sourceCommit`；
- 唯一 `releaseId`、服务端双节点版本与数据库迁移状态；
- 客户端版本号、APK SHA-256、包签名和运行域名；
- 设备型号、Android 版本、分辨率和验收时间；
- 账号角色、入口、操作序列、截图/XML/日志和最终状态。

审计按五层递进，任一层失败就不能以下一层的「静态测试通过」代替：

1. **导航与生命周期**：冷启动、热启动、前后台、左缘返回、系统返回、重复进入、异常恢复；
2. **真实任务链**：从入口到结果页，不仅点第一个按钮；
3. **交互完整性**：点击、竖滑、横滑、输入、弹层、键盘、焦点、空态、错误态、加载态；
4. **角色与权限**：普通用户不多权，业务角色能完成工作，未配置能力诚实禁用；
5. **弱网与失败恢复**：超时、401/403/404/5xx、重试、幂等、重复点击和进程重建。

本轮同时新增“版本边界”规则：若手机 `versionCode/sourceCommit`、公网 `releaseId` 与数据库迁移不属于同一冻结候选，测试结果只用于定位问题，不得记为上线通过。这样可以避免新客户端连旧服务端时出现套餐缺失、旧排盘回滚等伪缺陷或伪通过。

- 客户端、服务端、数据库迁移和公网 `releaseId` 必须对齐到同一冻结提交；

- 五个主导航连续切换、排盘工具连续切换、短视频竖滑、支付前确认、评论输入、前后台恢复均通过；

- 支付、评论、开播、发布、审批等外部副作操作仅在明确的动作级授权下执行，不用伪数据代替结果。

## 7. 本轮对“旧排盘是否为根因”的结论与正式口径

结论不是猜测：当前旧排盘接入容器/路由是排盘工具点击无响应、底部导航消失和返回链异常的直接主因。v232 真机同时存在底层原生工具页和上层第三方 WebView；v233 临时隔离旧排盘后，相同设备、账号与服务端下五个代表工具及两种返回手势立即恢复。这一对照实验定位了故障，但不能用“切回原生”规避正式业务要求。

但不能把所有问题都归给旧排盘：

- 会员购买被阻断是预发布数据库套餐未迁移；
- 短视频此前“无法上下滑”包含旧验收方法错误，必须在沉浸播放器内验证；
- 评论“无反应”是缺少定位加输入聚焦的可见反馈问题；
- 最终上线仍需客户端、双节点服务端、数据库迁移和公网制品统一到同一冻结提交。

更晚的用户产品指令固定为：`PAIPAN_MODE=legacy` 时普通用户所有排盘入口统一进入旧排盘，新排盘只对隔离 QA 开放；`PAIPAN_MODE=native` 时才恢复平台原生排盘。因此正式整改必须修复旧排盘承接容器、同源/跨域导航、工具点击、返回链、底部导航承接和异常态，且第三方失败不能泄露或自动回退新排盘。此前“主导航工具强制原生”的未提交方案已撤回，不进入统一候选。

## 8. 审计方法纠偏与新增真机发现

本轮出现过一次测试输入误判：创作中心“收益/设置”最初被记录为点击无响应，复核后发现是截图缩放坐标被错误当作设备原始坐标。改用设备原始 1080×2400 坐标并在每一步读取新截图后，两页均正常打开。该项不是产品缺陷，旧结论已撤销。由此新增以下强制规则：

- 不允许用缩放后的截图坐标直接驱动真机；
- 每次关键点击后必须读取新的页面标题、截图或 UI 层级，不能只按等待时间推断成功；
- 一个按钮失败必须至少用“可访问元素定位/原始坐标/手工复核”中的两种独立方式确认；
- 所有测试按“初始状态—动作—可见反馈—最终状态—是否产生副作用”记录，不能只记录点击动作。

新方法随后发现一个此前遗漏的真实缺陷：个人中心向下滚动时，“我的订单”等正文会进入 Android 时间、挖孔、信号和电量区域。该问题与旧排盘无关，是主导航页面缺少稳定状态栏隔离层。已在 v234 源码增加固定状态栏遮罩，并对发现页搜索栏增加吸顶与安全区隔离；同时新增静态回归，防止滚动内容穿透顶部安全区。该修复已通过构建和自动门禁，但尚未生成并安装签名 v234 APK，因此暂不能记为真机通过。

继续沿买家订单旅程进入“智能客服”后，又发现共享聊天组件顶部导航与 Android 状态栏重叠。原有全局门禁把页面引用 `SimpleChat` 当成了安全区证据，却没有验证组件内部的 `--status-bar-height` 是否真的被运行时赋值，属于“门禁假绿”。现已让共享 `SimpleChat` 从真机 `statusBarHeight/safeAreaInsets/safeArea` 取最大值，并保留 H5 `env(safe-area-inset-top)` 兜底；门禁也改为直接审计组件实现。这一处修复会同时覆盖智能客服和复用该组件的智能体聊天页，仍须随签名 v234 APK 做真机像素复验。

## 11. 最终上线验收不再接受的替代证据

- 不能用“路由存在”替代按钮可点与任务完成；
- 不能用列表滚动替代沉浸视频切换；
- 不能用 H5/模拟器替代 App 真机状态栏、系统返回和生命周期；
- 不能用静态门禁替代签名候选覆盖安装；
- 不能用新客户端连接旧服务端的结果判定最终业务通过；
- 不能把未执行的支付、发布、开播、审批或退款写成通过；
- 不能以单一管理员账号替代游客、普通用户、买家、创作者、圈主、讲师、主播、商家、客服和运营角色。

## 13. v235 候选冻结前门禁与标准纠偏

v235 不再只修“看得见的死按钮”，还复核了决定后续部署的标准和降级契约。复核发现，原迁移审计、生产环境模板和完整上线环境检查仍硬编码“正式默认原生新排盘”的过时口径，且客户端在运行模式探针失败时会把 `unknown` 当成 `native`。这会在网络波动或新环境缺配置时重新向普通用户泄露新排盘，是导致“反复修了又变回去”的标准层根因。

现已统一为以下不打折契约：

- 正式环境必须显式 `PAIPAN_MODE=legacy`；
- 普通用户只在服务端本次明确返回 `legacy` 时进入旧排盘，不再由客户端猜测；
- 只有服务端本次明确返回 `native`，或预发布 QA 白名单授权，才可进入新排盘；
- 探针失败且无十分钟内有效快照时，只展示可重试错误态，不得回退新排盘；
- legacy/native 快照都有十分钟时效，避免陈旧 native 缓存在模式切换后持续泄露。
