## 一句话结论

**开发没有收尾，但缺的不是功能，是"接线"。**

后端和页面大体都是真的，断的是它们之间的连接：前端 484 个页面里 **108 个是孤岛**
（功能做完、后端真连，但全项目没有任何地方能跳转过去），另有 **32 处死链**（点下去统一弹「功能开发中」）。
所以员工的体感是"这个没做、那个也没做"，实际多数做完了，只是没接上。

这解释了为什么"业务流程串不起来、员工测试受打击"。

### 关于角色申请的拍板（2026-07-14）

原设计是"六角色共用一张通用报名表"，但这个设计与业务对不上——六个角色路径本就不同：

- **讲师 / 商家**：资质审核（后端有 提交→查状态→admin审批 完整闭环）
- **站长 / 运营商**：**付费开通**（付款即激活，压根没有审批态）
- **研究院**：入会 + 保证金（完成年度任务可退）
- **线下驿站**：直接建站待审

**拍板：退役统一表，各走各的真流程。** 现已分派到：讲师→teacher-certification、商家→merchant/join、
站长→join-station、运营商→join-operator、研究院→member-apply；线下驿站是唯一保留表单的角色
（后端建站 DTO 本身就是一张申请表），真提交 `POST /offline/stations`。全页零假提交。

## 四、给下一个窗口的执行纪律

1. **先修接线，再做全面走查。** 现在拉员工测，会把上面这些又踩一遍，白白再受一次打击。
2. **接线前必判"现役 vs 退役"**：不是所有孤岛都该接。被 V0 重构取代的旧页要**删**不要接，
   否则一个功能两个页面打架（本轮已剥离 pkg-wallet / pkg-settings 假页）。
3. **退役页必须删 .vue 文件**：只摘 pages.json 无效 —— uni-app build 会扫描 `pkg-*` 目录把路由自动加回来。
4. **每条结论必须亲自打开文件核实。** 本轮 subagent 至少误报 2 条：
   - 说"商城违规商品在前台曝光"（实际早已修好，它引用的是 07-11 的过期报告）
   - 说"实名后端不存在"（实际 identity 模块整套都在）
   照着不核实的结论动手，会白干或改错。
