## 四、给下一个窗口的执行纪律

1. **先修接线，再做全面走查。** 现在拉员工测，会把上面这些又踩一遍，白白再受一次打击。
2. **接线前必判"现役 vs 退役"**：不是所有孤岛都该接。被 V0 重构取代的旧页要**删**不要接，
   否则一个功能两个页面打架（本轮已剥离 pkg-wallet / pkg-settings 假页）。
3. **退役页必须删 .vue 文件**：只摘 pages.json 无效 —— uni-app build 会扫描 `pkg-*` 目录把路由自动加回来。
4. **每条结论必须亲自核实——而且要用生产真实 API / 真库，不能只读代码。** 本轮至少 5 条报告是假的
   （见上文"被证伪"表）。读代码会误判，读旧报告会误判，查错库（容器 5432 那个废库）也会误判。
   反过来说：**真机/真 API 一跑，10 分钟就能挖出读代码半天都发现不了的东西**（短信 Region、搜索历史刷屏重复都是这么抓出来的）。

5. **生产环境速查表**（省得下个窗口再踩）：
   - 真库 = 宿主机 `127.0.0.1:5433`（`PGPASSWORD=guoxue123 psql -h 127.0.0.1 -p 5433 -U guoxue -d guoxue`）；
     容器 `guoxue-pg`(5432) 是**废库**，查它得到的全是空表假象
   - 生产 `.env` 只有 9 行；**真正的密钥在 DB `ConfigSystem` 表**（`third_party.*`，加密存储），
     启动时由 `ThirdPartyConfigLoader.syncToEnv()` 解密注入 `process.env`
   - 测试号 `15383869024` 走短信登录，码要自己塞：
     `sudo docker exec guoxue-redis redis-cli SETEX "sms:code:LOGIN:15383869024" 600 "123456"`
   - **nginx 服务的 H5 目录 = `/opt/guoxue/apps/mobile/h5/dist/`**，不是 `/opt/guoxue/h5`（后者是没人用的旧目录，我发错过一次）。
     ⚠️ H5 是 history 模式，**任何路径都返 200 —— 用 200 验证部署成功是无效的**，要 grep 产物里的新代码
   - **PM2 在 `ubuntu` 用户下**（cluster×4），`sudo pm2 list` 是空的，别加 sudo
   - rebu-server 的 sshd 会**随机掐连接**，单次失败不代表命令失败 —— 要带重试（本轮用 8 次重试封装）；
     大文件走 `base64 -w0 f | ssh host 'base64 -d > f'`（stdin 管道，不受命令行长度限制），scp 会被掐
   - **DNS 要在生产机上用 `getent hosts` 查**，本机 nslookup 超时 ≠ 域名不存在（我因此误判过推流域名）
