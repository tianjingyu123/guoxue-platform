## 五、铁律备忘（每次都要守）
1. 写库**只用** `npx prisma db execute --file xx.sql --schema prisma/schema.prisma`（前台 `dangerouslyDisableSandbox` 连 5433）；**禁 `db push`**（全量同步会误删游离表如 `_quality_snapshot`）。
2. 改 schema/`generate` 前先 `pm2 stop guoxue-api`（避 query_engine dll 锁）；流程：stop → generate → db execute → `nest build` → `pm2 restart` → curl 验证。
3. `VACUUM`/`VACUUM FULL`/`CREATE INDEX CONCURRENTLY` 不能在事务块 → 单条独立成 .sql；`CREATE INDEX`(非并发)/`ALTER`/`CHECK` 可同文件批量。
4. **真机回归我能自测**：pm2 沙箱外连 5433；dev 模式（`NODE_ENV=development`+短信密钥空）验证码进 `pm2 logs`（`[DEV] 验证码: xxx`）。curl 打接口 + mcp 查库。
5. mcp postgres 只读，用于核对；写操作走 db execute。
6. **改数据/删表/加约束前先查根因语义**（血泪教训：PointsProduct stock=-1 是哨兵、ToolRecord 是规划表、金额本应 Decimal）——别凭第一反应当脏数据处理。
7. 加 CHECK 不进 schema（Prisma 不管 CHECK），不影响 schema↔DB 一致性检查；但加列/改类型要同步 schema + generate。
