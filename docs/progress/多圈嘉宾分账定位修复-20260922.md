# 多圈嘉宾分账定位修复

隔离分支：`codex/integrated-live-gift-paipan-pay-20260920`。基线 `ff28d13fd`。本记录与源码、测试同批提交。未部署，未操作真实分账、余额、订单或数据库迁移。

## 问题与修复

管理页已经支持多个圈子，但嘉宾数据接口省略 circleId；后端普通圈主通过 findFirst 选择第一个管理圈子。这使页面圈子与读取、修改的目标可能不一致。

- 管理页、嘉宾页、角色矩阵页均明确传入当前 circleId。嘉宾页等路由参数准备好后才读取；缺少参数在发请求前拒绝，不猜测目标。
- 后端显式目标必须匹配调用者在该圈的 OWNER/ADMIN 身份，禁止用另一圈管理身份操作本圈。保留既有平台 SUPER_ADMIN/OPERATION_ADMIN 跨圈权限。
- 嘉宾身份、分账配置查询及写入继续限定同一个圈子；分账比例与换算规则未变。
- 旧客户端未传目标：仅当管理圈子唯一时兼容；多圈时明确报错要求选择，不再默认取第一个。
- 管理页嘉宾查询失败显示可重试提示，不再静默消失。
