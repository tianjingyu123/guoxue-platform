## 1. 跨簇主题问题（按优先级，这是优化主线）

### P0-A 响应信封契约错位 → 约 18 页列表恒空【最高优先·根因集中】
前端各页用 `data.records || data.data || data.alerts || data.rules || data.predictions || data.tenants || data.list` 等五花八门的键取数，但后端 `ResponseInterceptor` 统一返回 `{ items, pagination }`。键对不上 → 列表恒空、统计卡恒 0。
- finance：WithdrawalApproval / InvoiceList / SettlementList / FundFreeze / ReportList / ReconciliationList（6 页）
- risk：AlertCenter / AppealList / FraudList / RuleList / UserTimeline（5 页，字段名亦错配）
- churn：ChurnList / ChurnActionList / ChurnRuleList（3 页）
- tenant：TenantList / TenantDetail / TenantUsage（3 页）
- 字段名错配（与 schema 不符）：risk/Fraud(riskScore/orderCount)、Appeal(applicant/content)、Rule(level/threshold/conditions)、Timeline(description/deviceInfo)；tenant(recharge amount→quotaAmount、search name→keyword)
- **修复策略**：统一前端取数为 `data.items ?? data.records ?? []`（建公共 unwrap 工具），并按真实 schema 修正字段绑定。集中、性价比最高。

### P0-B 资金 / 审核写操作 假动作或错端点【资金安全】
- `mb/MerchantAfterSales.vue:109`：售后审核调 `handleAfterSale?.()`（不存在），可选链静默跳过仍弹"成功"→ 实际零请求。正确名 `processAfterSale`。
- `shop/RefundList.vue:386`：拒绝退款误调 `orderApi.cancel`（取消订单），应调 `rejectRefund(id,{reason})`，且 rejectReason 被丢弃。
- `commission/WithdrawalList.vue`：**无"打款"按钮**，PAID 终态不可达；审核不显余额/不校验金额（资金流出无风控）。
- `coin/GiftList.vue:384/397/411`：编辑/启停误调 POST 创建端点（重复礼物、status 不持久）；"发礼"走直播赠礼链路扣管理员自己灵石、room 写死 admin、无防重。
- `circles/CircleDetail.vue`：单条问答"退款"误调 `POST /question/admin/refund-expired`（全局批量过期退款）。
- 资金操作普遍无审批流：InstituteFinance 发分红、HuifuConfig 退款、CommissionConfig 改分佣比例、coin/RechargeList 充值直接到账——均直接执行，违背"资金需人工审批/留痕"。

### P0-C 端点 404 / 契约断裂【功能性失效】
- `fortune/FortuneConfig.vue` + `FortuneHistory.vue`：前端走 `/admin/fortune/*`，后端是 `/fortune/admin/*`（前缀顺序反），且 configs/history/share-card 后端未实现 → 两页全 404。
- `im/ImManage.vue`：`getGroupHistory/sendGroupMsg/withdrawMsg` 在 `imApi` 未定义 → 运行时报错；群列表无 listGroups 调用恒空；`api/index.ts:88-106` 多处 URL 用反斜杠 `\im\...` 路径错误。（注：IM 属密钥冻结域，详见决策项）
- churn score→应 calculate；tenant getLogs 404。

### P0-D 数据安全 / 权限闸缺失【安全】
- **隐私明文**（违反安全清单）：UserDetail 手机号+邮箱、UserList 手机号（含导出 CSV）、CapabilityAudit/MemberPurchaseList 手机号、DeviceFingerprint 的 IP/deviceId、tenant 的 apiKey。仅 IdentityAudit 身份证、UserTimeline 手机号已脱敏。
- **敏感操作零权限闸**：项目有 `v-permission` 指令（directives/permission.ts）却全簇未用。封禁/批量封禁/**在 UserDetail 自由授予 SUPER_ADMIN**/实名通过/IP 白名单/群发/task 回滚，对 CUSTOMER_SERVICE 等低权角色全部可见可点，仅靠后端守卫兜底。
- `operator-backend/OperatorDashboard.vue`、`station-backend/StationDashboard.vue`：路由（router/index.ts:1293-1305）**无 meta.roles**，任意登录管理员可进入自管理控制台。

### P0-E Math.random / 硬编码假数据 伪造图表【违禁随机铁律】
- `ai/ContentQuality.vue:556,578`：通过率/评分图表 Math.random 伪造（且这是古籍伴读质量唯一观测页）。
- `SearchAnalytics.vue`：AI 效果 Tab Math.random + 硬编码饼图。
- `users/UserPush.vue`：预估推送人数 Math.random。
- 图表失败回退假数据：GoodsAuditDashboard / FinanceDashboard 柱图假兜底、BannerAdmin / HomepageConfig 回退硬编码、courses/CourseCategoryManage 回退假默认树。

### P1-A RBAC 细粒度权限矩阵形同虚设
RolePermissionManage 可配置权限树、存库、/auth/me 返回 permissions，但**后端无 PermissionsGuard、前端 store 只用 roles**→ 配置不生效。真正执行的是 92 个 controller 的静态 `@Roles` + 静态菜单。那棵权限树目前是装饰品。

### P1-B 审计日志有效性残缺
全局 AuditInterceptor 覆盖写操作，但 `@Auditable` 装饰器零落地 → action 退化为 "POST/PUT" HTTP 方法名，无法按"退款/封禁/审核"语义检索；后端已有导出端点但前端无导出按钮；OperationLogList 无前后值 diff、无回滚。

### P2 品质与规范（全平台横扫）
- **错误态**：约 40+ 页几乎无 error+重试 UI，catch 普遍静默吞错甚至回退假数据 → 加载失败伪装成"无数据"。
- **空态**：仅 78/209 有自定义 el-empty。
- **设计 token**：138/209 含硬编码 #hex，与 var(--token) 混用。
- **操作效率**：列表普遍缺搜索/筛选/排序/导出/批量；多处 pageSize 写死或伪分页。
- **数据可视化**：6 大工作台同质化换皮（同构布局仅换 KPI 标题与图表类型），人均 1 图，**普遍无环比/同比**，无角色专属操作入口（纯只读数字卡）。亮点仅 Cockpit（A-）与 SuperAdmin（服务健康+30s 轮询）。
- 命理 5 页是前台计算器镜像，非真后台管理（无算法/流派配置、付费规则、记录审计动作）。

## 2. 优化执行批次（建议顺序）

- **批次 1 · 数据正确性地基**（P0-A + P0-C 非密钥部分）：统一响应 unwrap 工具，修复 18 页恒空 + 字段错配 + fortune 路径/端点。性价比最高，一改全活。
- **批次 2 · 资金与审核安全**（P0-B + P0-D 资金权限）：修假动作/错端点、补打款终态与金额风控、敏感操作接 v-permission、隐私脱敏。
- **批次 3 · 假数据清除**（P0-E）：删 Math.random 伪造图表，改真数据或诚实空态/降级提示。
- **批次 4 · 设计与三态地基**（P2 横扫）：token 收口清硬编码色、统一 loading/empty/error 三态组件、补空态。
- **批次 5 · 前后台缺口补齐**（P1-C）：按决策范围逐个新建/补全管理页。
- **批次 6 · 审计与权限纵深**（P1-A + P1-B）：@Auditable 落地、操作日志语义化+导出+diff；细粒度 RBAC 是否启用（决策项）。
- **批次 7 · 可视化升级**（P2 可视化）：工作台差异化、环比同比、异常预警、角色专属操作入口。
- **批次 8 · 收口验证**：vue-tsc 全绿、权限矩阵走查、PC/平板适配、最终报告。
