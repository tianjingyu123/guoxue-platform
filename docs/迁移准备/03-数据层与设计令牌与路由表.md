# 数据层 / 设计令牌 / 路由表（迁移地基第三项）

> 目标：把数据来源、设计令牌、路由结构三件地基理清，让页面迁移时只换"壳"不动"魂"。

## A. 数据层归一

### 现状
| 层 | 文件数 | 说明 |
|---|---|---|
| `lib/api/*` | 48 | 业务 API 封装（achievements/fortune/wallet/im/live/mall…），多为 async 函数 + try/catch + mock 兜底 |
| `lib/types/*` | 50 | TS 类型定义，**资产质量高**，迁移可直接复用 |
| `lib/data/*` | 1（daily-verse） | 真正归集的静态数据只有 1 个 |
| 页面内散落 mock | 373 文件 | ⚠️ 绝大多数 mock 硬编码在 page.tsx 里（如 mockCheckInData、成就数组） |

### 风险与策略
- **373 个文件含内联 mock 是最大返工源**。多数 API 已是"先请求真实接口，catch 后用 mock 兜底"的结构（见 certificate/page.tsx），这点很好——迁移时 API 层几乎可直接搬。
- 真正要处理的是**页面内联 mock**：迁移每个页面时，把内联 mock 抽到对应的 `lib/data/<module>.ts` 或直接接 API，UI 只消费数据。
- **类型层（lib/types）整套迁移**：TS 类型平台无关，是迁移的"数据契约"，先整体搬到 Vue3 工程。
- **API 层适配点**：`lib/api-client.ts` 用 localStorage 读 token → 换 storage 封装；fetch → uni.request 封装（保持函数签名不变，只换底层）。

### 建议产物（Vue3 工程）
- `api/`：48 个 API 文件迁移，底层 fetch→uni.request，签名不变
- `types/`：50 个类型文件整体复用
- `data/`：迁移时逐步把页面内联 mock 收敛到此
- `utils/request.ts`：统一请求封装（替代 api-client，含 token 注入、错误处理）

## B. 设计令牌迁移（高保真关键）

### uni-app 迁移方案
- **CSS 变量基本可用**：uni-app（H5/小程序基础库≥2.x）支持 CSS 自定义属性，三层 `:root` 变量结构可保留。
- **单位换算**：原型用 px → 小程序建议 rpx（750 设计稿基准）。但令牌里的颜色/圆角值不受影响，仅布局间距类需 px→rpx。
  - 换算：iPhone6 基准 1px ≈ 2rpx（设计稿 375 时）。需确认设计稿基准宽度后批量换算。
- **暗色模式**：原型用 `.dark` class 切换 → uni-app 用 `@media (prefers-color-scheme: dark)` 或手动 class + theme。小程序需用 `page-meta` 或全局 class 方案。
- **Tailwind**：uni-app 不原生支持 Tailwind v4 `@theme`。两条路：
  1. 引入 `weapp-tailwindcss` / `unocss`（推荐 unocss，支持 presetWind + 自定义 theme，能还原工具类）
  2. 或把工具类转成 SCSS 变量 + 原子类手写
  - ⚠️ 这是迁移决策点：191 个组件大量用 Tailwind 工具类，选 unocss 能最大保真且改动小。
- **字体**：见 02 文档，loadFontFace + 子集化。globals.css 已预留系统字体降级链。
- **关键动画**：globals.css 含 40+ keyframes（太极旋转/金色光晕/直播呼吸灯/飞入购物车/弹幕/礼物飘动等），全部需迁移到 uni 的 CSS animation（rpx 适配），逐条核对时长与缓动。

### 建议产物
- `styles/tokens.scss`：三层令牌（颜色不变，间距 px→rpx）
- `styles/animations.scss`：40+ keyframes 迁移
- `uno.config.ts`（若选 unocss）：theme 映射，还原 bg-brand/text-ink 等工具类
- 字体加载初始化（App.vue onLaunch）

## C. 路由表（128 顶层模块 + 70 动态路由）

### 规模
- 顶层业务模块约 128 个目录，动态路由 `[param]` 70 处。
- Next App Router `app/xxx/[id]/page.tsx` → uni-app `pages.json` 注册 + `uni.navigateTo({url:'/pages/xxx?id=1'})`

### 映射规则
| Next.js | uni-app |
|---|---|
| `app/course/[id]/page.tsx` | `pages/course/detail` + query `?id=` |
| `app/paipan/[toolId]/page.tsx` | `pages/paipan/tool` + query `?toolId=` |
| `router.push('/x')` | `uni.navigateTo({url:'/pages/x'})` |
| `router.replace` | `uni.redirectTo` |
| `router.back()` | `uni.navigateBack()` |
| `useSearchParams().get('id')` | `onLoad(query){ query.id }` |
| 嵌套布局 layout.tsx | uni-app 无嵌套布局，公共部分抽组件或用分包 |
| 底部 Tab（主导航） | `pages.json` tabBar 配置 |

### 分包策略（小程序体积限制）
- 小程序主包≤2MB，总包≤20MB。128 模块必须**分包**：
  - 主包：首页/排盘入口/我的等高频 Tab
  - 分包：商城、圈子、IM、视频、直播、课程、运营商后台、研究院、分站等按模块拆
- 动态路由统一用 query 传参，详情页接 query 后请求数据。

### 建议产物
- `pages.json`：全量页面注册 + tabBar + 分包配置 + 路由表
- `utils/router.ts`：封装 navigateTo/redirectTo/navigateBack，统一 query 处理
- 路由映射对照表（Next 路径 → uni 页面路径），迁移时逐页查表
