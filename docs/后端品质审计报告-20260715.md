## 一、总体结论

**核心底盘已达生产级，但在「越权鉴权、付费闭环、资金边缘用例、自运转 cron、合规声明」上有系统性缺口，尚未整体达到"支撑真实用户规模化上线"标准。**

### 已达生产级（经亲核确认，非臆断）
- **鉴权基线**：162/168 controller 有 @UseGuards；全局 RedisThrottleGuard 限流（30/60s，登录短信 Strict 10/60s）+ 全局 ValidationPipe（注入/字段白名单）；RolesGuard deny-by-default。
- **资金底盘**：扣减全用真 CAS 防并发；支付回调全部先验签后处理并比对金额；提现四眼防自审自批 + 仅渠道 SUCCESS 才标 PAID + payoutRef 幂等。**未发现可被外部直接利用的在线资金 P0。**
- **自运转**：69 个 @Cron 覆盖 ~30 模块，均带 redis 分布式锁/幂等 upsert。
- **数据统计**：全部真实 Prisma 聚合（非写死假数据），日/周报、流失评分、用户标签均有 cron 自运转。
- **AI 工程**：网关抽象（模型路由/语义缓存/预算封顶/多供应商降级）、密钥 DB 加密掩码（非硬编码）、AI 内容 DRAFT+"AI生成"标识。
- **零缺陷参考实现**：teacher / consult-call / crm / mentorship（越权隔离、TOCTOU 原子、加密脱敏均到位）。

### 严重度汇总（8 组合计）
| 级别 | 数量（去重估算） | 说明 |
|---|---|---|
| P0 | 2 | 站长自设 ACTIVE 绕加盟费（**已修**）；商家保证金无条件模拟支付（受"免保证金"现状约束，未在线可利用） |
| P1 | ~35 | 越权/付费闭环/资金边缘/合规/自运转缺口 |
| P2 | ~90 | 命名不一致/计数字段只读不写/缺 cron 兜底/审计留痕缺失等 |

### E. 运维/审计（P1·系统运维组）
- **数据库备份在生产 Linux 跑不起来**（`backup.service.ts:33/37` 用 powershell+CMD 语法，生产是 Ubuntu）+ 无自动备份 + 异地上传未实现 → **数据安全无保障（最优先修）**

- system 域配置版本管理/回滚静默失效（`system.service.setConfig:86` 从不写 ConfigVersion）
- export 导出手机/邮箱/完整银行卡号全明文、零脱敏零审计

## 四、系统性坏味道（跨模块共性·建议专项治理）
1. **计数/收益字段"只读不写"**：interaction 点赞收藏评论数、comment/live 点赞、video 创作者收益提现口径多为死值或错值（真机走查易漏，因前端有兜底显示）。
2. **审核/治理闸门被旁路**：定时发布/草稿发布/悬赏/评论多处跳过内容审核漏斗。
3. **密钥"热生效"承诺不成立**：对构造函数缓存 env 的服务（sms/push/tlssig/cos）改密钥需重启。
4. **付费闭环与资金通道未合拢**：多处"未接真实支付/结算引擎待建"（董事长既定），当前被空表掩盖，引擎落地即暴露。
