# 软性导流 · Coze 智能体配置指南

> 面向：在 Coze 后台配置智能体 prompt 的运营/产品人员
> 目的：让智能体在完成本职回答后，主动识别用户需求并输出**结构化下一步意图**。平台默认优先匹配工具与内容；只有用户明确表达学习、加入或购买意图时，才匹配课程、圈子或商品。

---

## 一、机制总览

```
用户提问 → Coze 智能体回答(本职) + 末尾按协议输出推荐意图标记
         ↓
平台 bot.chat 解析意图标记(从展示文本中自动剥离·用户看不到标记)
         ↓
按 type + 关键词匹配平台真实工具 / 内容 / 服务（最多 2 条）
         ↓
前端:本职回答正常显示 →「需要我为你推荐XX吗？」+[好的,看看][不用了]
         ↓
用户点「好的」才展开真实向导卡 → 点击进入对应页面
```

**关键原则**（与产品定位一致）：
- **不打断**：先把用户问题答好，推荐意图只放在回复最末尾。
- **必须征求同意**：平台前端自动做「先问按钮、同意才展卡片」，你**不需要**在回答里写"需要我推荐吗"这类话术——平台会统一生成。你只需输出**意图标记**。
- **可拒绝**：用户点「不用了」即收起，继续对话。
- **精准**：只在确实识别到相关需求时输出标记。
- **内容优先**：普通咨询优先输出 `article` / `classic` / `video` / `live` / `agent` / `tool`。
- **商业克制**：`course` / `circle` / `product` 必须有明确用户意图；平台还会二次过滤模型擅自给出的商业推荐。

---

## 二、推荐意图协议（核心）

在智能体回复的**最末尾**追加一行标记（用户不可见，平台自动解析并剥离）：

```
<!--RECO:[{"type":"course","query":"八字","reason":"适合初学者系统入门八字"}]-->
```

### 字段说明

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `type` | 是 | `article` / `classic` / `video` / `live` / `agent` / `tool` / `course` / `circle` / `product` | 下一步类型 |
| `query` | 是 | 字符串 | 用于匹配平台内容的**关键词**，尽量用国学主题词（八字/紫微/风水/论语/中医…） |
| `reason` | 否 | 字符串 | 一句话推荐理由，会显示在卡片上（如"系统学习八字命理"） |

### 规则
- 标记必须是**严格合法的 JSON 数组**，否则平台会忽略并退回兜底逻辑。
- **最多 2 条**意图（多了平台只取前 2 条）。
- 仅在确实识别到需求时输出；**无需推荐时不要输出此标记**。
- 标记必须放在**回复最末尾**，前面是正常的本职回答。

---

## 三、在 Coze 后台怎么配

把下面这段加到智能体的 **人设/提示词（System Prompt）** 末尾：

```
【软性导流规则】
当你完成对用户问题的本职回答后，若从对话中识别到用户需要继续阅读、观看、操作、交流或购买，
请在回复的最末尾追加一行推荐意图标记（用户不会看到此标记，平台会自动解析并以"征求同意"方式呈现）：

<!--RECO:[{"type":"article","query":"关键词","reason":"一句话推荐理由"}]-->

要求：
1. 默认优先 article、classic、video、live、agent、tool；只有用户明确说要系统学习、加入交流或购买时，才能使用 course、circle、product；
2. query 用国学主题关键词（八字/紫微/风水/六爻/中医/论语 等），便于平台匹配；
3. reason 是一句话推荐理由；
4. 最多输出 2 条意图；
5. 仅在确实识别到相关需求时输出，否则不要输出此标记；
6. 不要在回答正文里推销，也不要写"需要我推荐吗"——那由平台统一处理，你只输出末尾标记；
7. 不使用恐吓、夸大、制造焦虑或“假装懂用户”的理由；
8. 标记必须是合法 JSON 数组，放在回复最末尾。
```

## 四、示例

**用户**：「我想系统学一下八字，该从哪开始？」

**智能体回复**（正文照常解答学习路径，末尾追加标记）：
```
学八字建议先打基础：先熟悉天干地支与五行生克，再学十神、宫位，最后到大运流年的综合判断。
建议按"基础概念 → 排盘 → 格局 → 实战"的顺序循序渐进……

<!--RECO:[{"type":"article","query":"八字","reason":"先读一篇基础概念"},{"type":"course","query":"八字","reason":"用户希望系统学习"}]-->
```

**用户最终看到**：正文解答（标记已被平台剥离）+ 下方一行征求同意提示。点「好的」后先看到基础文章，再看到明确标价的课程。

**用户明确希望加入同好交流时的例子**：
```
<!--RECO:[{"type":"article","query":"紫微","reason":"先了解基础术语"},{"type":"circle","query":"紫微","reason":"用户希望和同好交流"}]-->
```

## 五、不配会怎样？（平台兜底）

即使你暂时不在 Coze 配置上面的规则，向导推荐**仍能工作**——平台内置了**内容优先兜底**：普通问题先匹配文章，工具/视频/直播等明确意图会进入对应类型；商业内容只响应明确意图。

但兜底是**关键词规则**，精准度不如 Coze 智能体自己的语义判断。**配置 Coze prompt 后，平台会优先采用 Coze 输出的意图**，推荐更贴合对话语境。建议正式上线前完成 Coze 配置。

## 六、平台侧已实现（无需你操作，供理解）

- **解析与剥离**：`bot/recommendation.service.ts` 的 `parseProtocol` 解析 `<!--RECO:...-->` 并从展示文本剥离。
- **兜底**：`fallbackIntents` 在无协议标记时按主题词提取意图。
- **匹配**：`match` 按 `type`+`query` 查询文章、古籍、视频、直播、智能体、课程、圈子、商品或工具注册表。
- **征求同意**：前端 `pkg-agent/agent/chat.vue` 自动做「先问按钮、同意才展卡片」+ 卡片跳转。
- **二次防线**：没有商业意图时，即使模型输出了课程、圈子、商品，平台也会过滤。
