# App 微信登录零影响切换手册

## 目标

在不影响第三方旧系统继续运行的前提下，为新系统启用 App 微信登录。代码、客户端和凭据切换分开进行；任何检查不通过都保持 `client_wechat_app_login=false`。

## 当前门禁

- 客户端内置默认值为关闭，远程配置失败时不展示 App 微信登录入口。
- 服务端在解析 AppID/AppSecret 或调用微信接口前再次检查 `client_wechat_app_login`；关闭时返回 404。
- H5 公众号登录和微信小程序登录不受该开关影响。
- AppSecret 只允许保存到服务端第三方配置，禁止写入客户端、日志、截图和验收报告。

## 推荐路径：复用现有密钥，不重置

这是对旧系统风险最低的路径。

1. 保持 `client_wechat_app_login=false`，先部署服务端和 217 客户端。
2. 让原开发方通过安全渠道确认当前移动应用 AppID，并把现用 AppSecret 交给有权限的运维人员；不要通过聊天、工单截图或代码仓库传递。
3. 只在预发布后台“微信开放平台（APP登录/分享）”卡片保存现有 AppID/AppSecret。
4. 保持开关关闭，检查服务端健康状态和配置掩码，确认密钥未出现在日志中。
5. 在预发布功能开关中把 `client_wechat_app_login` 设为开启、比例 100%，完成真机登录和账号合并检查。
6. 预发布稳定后再为正式环境重复配置和验收；正式 iOS Universal Link 文件未就绪前不得启用正式开关。

复用现有密钥不会使旧系统失效；新旧后台可以同时使用同一移动应用凭据。

## 仅在无法取得现有密钥时：协调重置

重置后旧 AppSecret 无法恢复，因此必须满足以下全部条件才能操作：

- 已确认旧系统确实使用哪个移动应用 AppID。
- 已取得旧系统服务器配置权限、重启权限和回滚负责人联系方式。
- 新旧系统配置页面均已打开并完成管理员登录。
- 新系统代码已部署，但 `client_wechat_app_login=false`。
- 旧系统微信登录基线测试通过，且已安排低峰维护窗口。

切换顺序：

1. 再次确认新系统开关关闭。
2. 在微信开放平台只重置一次 AppSecret，并立即保存到受控密码库。
3. 优先更新旧系统服务器的新 AppSecret并重载服务，立即验证旧系统微信登录。
4. 旧系统恢复正常后，将同一新 AppSecret写入新系统预发布配置。
5. 开启预发布 `client_wechat_app_login`，完成真机登录验收。
6. 观察错误率和登录成功率；异常时立即关闭新系统开关。旧系统必须继续使用新密钥，不能尝试恢复旧密钥。

## 快速启用

1. 预发布第三方配置已保存有效的移动应用 AppID/AppSecret。
2. 管理后台进入“系统设置 → 功能开关”。
3. 创建或更新：
   - key：`client_wechat_app_login`
   - enabled：`true`
   - percentage：`100`
4. 客户端重新进入登录页并拉取远程配置。服务端会立即按同一开关放行接口。

## 快速回滚

只关闭 `client_wechat_app_login`。客户端入口随后隐藏，服务端 App 微信登录接口立即恢复 404；不需要重新构建或回滚数据库。

如果已经重置过 AppSecret，关闭新系统开关不会恢复旧密钥。旧系统必须保留并使用新 AppSecret。

## 禁止切换条件

- 不知道旧系统是否使用同一 AppID/AppSecret。
- 无法更新或重启旧系统后台。
- 无法完成旧系统切换后的微信登录验证。
- 正式 iOS Universal Link/AASA 未通过公网校验。
- 新密钥只能通过非安全渠道传递。
