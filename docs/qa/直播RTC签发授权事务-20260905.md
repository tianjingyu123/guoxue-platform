# 直播 RTC 签发授权事务

## 本轮修改

- rtc-config 透传 HUMAN/AUTOMATION，发流票据禁止自动化领取。
- 同圈锁→房间行锁→账号/角色与麦位共享锁；仅 LIVING 且未下架的房间可签发。
- 主播发布资格和 ACTIVE 资源在同事务重新核对，嘉宾复用主播场次额度，不要求嘉宾取得独立直播发布资格。
- 平台主播豁免取当前数据库中无 bindId 的 SUPER_ADMIN/OPERATION_ADMIN，账号须 ACTIVE；不采用旧 JWT 判断。
- 已获批嘉宾读取被锁定麦位的 AUDIO/VIDEO/MUTED 状态，原有最小权限位逻辑保留。
- CDN 普通播放入口未改，不能把发流授权当作观看授权。
- 同时修复通用 OBS 配置对 TRTC 哈希流名的拆分：使用真实 serverUrl 前缀，不猜平台 UUID 对应字符串。

## 证据

- TypeScript 通过；直播单测 17 suites、313/313。
- 独立完整基线 PostgreSQL：74/74；合成数据库 circle-workflow-pg-2kxS6M，端口 65291，已停止并保留合成数据。
- 新真实数据库用例包括获批麦位、移除后拒绝、主播撤权拒绝本人和嘉宾、自动化拒绝、结束后拒绝，以及账号停用/麦位删除事务持锁时的并发拒绝。

## 未完成边界

本轮未部署、未调用腾讯云、未验证真机。既有票据与已连接媒体不会因本地拒绝续领而自动失效，必须继续接入可信停流/移除媒体连接与资源终结；不得据此宣称撤权可立即断流。
