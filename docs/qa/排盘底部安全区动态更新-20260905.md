# 排盘底部安全区动态更新

## 复现与修复

源码显示安全区只在页面初始化读取；购买栏第一次处理后直接跳过，网页也未监听 resize。合成回归先因缺少 resize 监听失败。

本次仅修改排盘承接页及对应测试：

- 窗口变化重新读取当前系统和原生安全区，允许较大底部值变小或归零。
- 通过既有受信域名校验的注入函数同步新值，触发网页重新布局；不向第三方收银域名注入。
- 网页监听 resize，记录购买栏原始偏移和正文原始 padding；更新时不累计补偿，归零时恢复原数值。
- WeakMap 保存元素状态，不因已移除元素留下强引用。
- 没有安全区且未处理过页面时不改变原页面布局；普通非定位元素不作为购买栏移动。

## 实测范围

- 修改后的排盘返回/布局与分享桥联合回归 53 项通过；后续新增系统重读测试单独通过。
- 四项联合专项曾 67 项通过（包括罗盘）；此后仅补原生 resize 重读接线，再运行上述受影响测试。
- 新增两项动态布局测试验证 34→16→0 的栏位偏移、正文 padding 恢复和普通元素不动；系统重读验证 34→0。
- 移动 vue-tsc --noEmit 退出码 0。

全部是本地源码/合成 DOM 验证，不是已安装签名包的真实布局结论。仍须 Android/iOS 分别验证会员活动页底部购买按钮、弹出键盘、旋转/窗口变化及返回；不得据此称用户反馈已彻底解决。

## 当前设备阻断

爱思投屏唯一返回窗口被工具报告 minimized。依 computer-use 技能执行一次 activate→重新取窗口→截图后仍同样失败，已停止重复 UI 尝试。没有发送分享、没有付款，也没有通过重复云打包绕开缺失的验收。

## 动态页面误改风险复核

新增隐藏栏与视口外元素的合成用例先失败：原条件 `bottom<=4` 接受负值，且矩形只要求大于视口下沿，使原站负偏移隐藏栏和文档下方元素被误抬高。

现要求初次识别时 bottom 在 0..4、矩形下沿距视口下沿不超过 4 像素。已适配栏若后来被原站设置为负 bottom，立即放弃补偿，不重新展开；原始静态元素仍不改。相关返回/布局与分享桥 54 项通过，未重复完整移动构建。此修复只证明不误操作这些合成场景，真实页面可见性与支付确认页仍待同包真机验收。
