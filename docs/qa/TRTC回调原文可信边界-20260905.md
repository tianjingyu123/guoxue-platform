# TRTC 回调原文可信边界

## 为什么调整

咨询资源收尾需要供应商证据，不能把未验签的测试环境请求或被替换的解析对象当成证据。已有守卫在非生产环境缺密钥时跳过验证，且时间窗使用 req.body；业务控制器也直接使用 req.body，未显式绑定已验签原文。

## 已完成

- 所有环境缺密钥均拒绝；保留现有 TRTC_CALLBACK_KEY 与 TENCENT_CALLBACK_KEY 兼容读取，未更改任何实际密钥。
- 时间窗来自原始 JSON 的整数 CallbackTs，不使用另一份可变解析对象；签名仍严格遵循原始字节 HMAC-SHA256/Base64。
- SDKAppId 头须与配置的有效应用 ID 一致，重复头拒绝。
- 验证结果仅写模块私有 WeakMap，包含应用 ID、接收时间、原文 SHA256 和独立解析体。不允许用请求 DTO 或请求对象同名属性冒充。
- LiveController 从该可信记录取独立快照；后续修改快照不污染原记录。重新验证失败先清除旧标记。
- 验签失败日志不再拼接请求 URL，避免查询参数中的秘密进入日志。

## 本地证据

- 守卫及真实 LiveController 单元测试：62/62。
- 本机 Nest/Express HTTP 端到端：6/6。监听仅 127.0.0.1；使用合成密钥，涵盖保留缩进的原始 JSON、无 UniqueId、缺签名、篡改正文、错误应用 ID、过期时间、非生产缺密钥。测试退出后关闭本机服务。
- 相关 diff 检查通过。
- 最终服务端 TypeScript 与 Nest 构建均退出码 0。

## 官方格式与后续边界

[腾讯云房间与媒体回调](https://cloud.tencent.com/document/product/647/51586)说明：新版过滤策略默认不携带 UniqueId；退出房间事件为 104，不能要求它同时产生停止音频/视频事件。后续持久化必须兼容这一格式，并处理乱序和重复事件。

SDKAppId 头是与配置比对的字段，不是 HMAC 原文的一部分。真实验收仍须核对具体应用的回调配置和密钥隔离，不能凭本地测试推定云端配置正确。

本轮未接入咨询退房持久化、未释放任何资源、未部署或更改腾讯云回调配置。可信退房记录、旧票据重入防护和双端真机仍是后续门禁，不能宣称已完成媒体收尾。
