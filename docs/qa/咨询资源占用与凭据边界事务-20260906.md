# 咨询资源占用与凭据边界事务

## 实际接线

`ConsultCallResourceService` 已作为内部 provider 接入 ConsultCallModule，`ConsultCallService.initiate/accept` 实际调用，不是仅有策略函数。

- 发起：同一主库事务内重新核验授权/价格 → 建 WAITING 订单 → 当前授权额度预留并 ACTIVE → 写非敏感票据边界 → 预扣。任何一步失败整笔回滚；名额不足时不调用预扣。只有事务提交后返回票据。
- 接听：重新核验服务者，锁定订单，要求原 ACTIVE 资源绑定的圈子、调用者、服务者、能力、授权版本仍匹配；复用既有资源，不重复计算次数；同事务记录更晚票据边界并认领 WAITING→ONGOING。
- 票据范围核验：映射用户、字符串房间、应用ID、有效期必须匹配本订单；应用范围变更不得覆盖已有边界。不保存UserSig、PrivateMapKey或密钥。
- 取消/超时退款/结束暂不释放ACTIVE，不能以订单状态代替供应商媒体停止证明。历史等待单无资源/边界时不伪造补发，但原取消退款保留。
