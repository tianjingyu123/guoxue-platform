# 咨询短时票据与超时接听

## 本地修复范围

- 发起票据明确使用 1260 秒：最长等待 600 秒、预扣通话 600 秒、连接缓冲 60 秒。
- 接听票据明确使用 660 秒：预扣通话 600 秒和连接缓冲 60 秒。
- 仅实时咨询业务显式传入短窗口；底层签名工具的兼容默认值并未全局修改。
- 接听最终事务更新同时要求 WAITING、创建时间晚于当前时间减 600 秒、创建时间不晚于当前时间；创建时间异常或等待超时均拒绝接通。
- 票据资源边界更新与接听状态更新在同一事务内，最终条件失败不会延长已保存边界，也不会返回新凭据。
- 已签发的历史长票据不追溯缩短。媒体额度仍按记录的最晚有效期及额外 300 秒保护窗核验后归还，不能把订单结束等同于即时释放媒体并发。

## 验证

- 咨询准入、签名工具、预扣到期 worker：3 suites / 57 tests PASS。
- localhost 合成 PostgreSQL：4 PASS / 152 未选中。覆盖正常接听扩展边界、双连接重复接听竞争、等待超时拒绝、未来创建时间拒绝。
- 两项异常接听均确认原票据边界不变、订单仍 WAITING、startAt 为空；未再次扣款，随后取消仅退款一次。
- 单元断言明确验证 1260/660 秒参数，以及最终更新的两个 UTC 时间参数恰差 600000 毫秒。
