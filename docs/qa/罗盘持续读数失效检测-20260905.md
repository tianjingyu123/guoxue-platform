# 罗盘持续读数失效检测

## 补充：首选来源断流后的恢复

新增合成回归先得到 5 通过、1 失败：收到 webkitCompassHeading 后，即使三秒断流失效，仍永久拒绝另一个有效绝对北向来源。现仅在当前有效计时器确认断流时清除 H5 来源优先级，允许绝对来源恢复；相对 alpha 仍拒绝，恢复 webkit 后再次优先，取消的旧计时器不得清除新来源。修复后 H5/App/Harmony 状态及页面读数专项共 15/15 通过。此证据不是签名包或物理北向验收，Harmony 原生数据源仍待接入。

本机只读环境检查已定位 DevEco 的 hdc、hvigor、ohpm 与 sensor API 声明文件；不应再因 PATH 无命令而认定工具未安装。OnePlus ADB 状态为 device，sensorservice 列出了方向与旋转矢量来源，但该清单本身不能证明候选 App 已收到正确北向读数。

## 已确认的问题

共用罗盘适配层原先只在启动时设三秒超时，收到首个有效读数即清除计时器。若之后原生或 H5 传感器停止回调，状态会一直保留 active，页面可能把冻结角度呈现为实时朝向。

## 本次修复

- 每个有效北向读数更新三秒失效计时；非法读数不续期。
- 超时转 unavailable，允许现有页面清除未锁定的传感器读数标识；仍保留监听以接受恢复后的真实读数。
- generation 和计时修订号共同拒绝退出、重入以及已取消计时器的迟到回调。
- 不申请新的系统权限、不生成模拟北向、不将相对 alpha 作为指南针；未改已锁定读数和手动读数的明确标识。
