# 圈子新增迁移顺序修复

## 根因

现有发布链使用 Prisma migrate deploy。Prisma 当前项目所用的目录式 SQL 迁移按字典顺序执行，参考 https://www.prisma.io/docs/orm/v6/prisma-migrate/workflows/baselining 。原候选 manual_add_circle_capability_dispatch 排在 quota_ledger 与 workflow 之前；派发表外键引用额度表，额度表又依赖工作流类型和授权表，因此该候选不能直接依赖原目录顺序部署。

## 本地修改

1. manual_add_circle_capability_workflow → manual_add_circle_capability_01_workflow
2. manual_add_circle_capability_quota_ledger → manual_add_circle_capability_02_quota_ledger
3. manual_add_circle_capability_dispatch → manual_add_circle_capability_03_dispatch

manual_add_circle_platform_direct_grant 保持原名，自然排在上述三个之后。同步两项结构测试及本地 PG 测试的路径。PG 测试改用实际字典排序，不再用人工优先序掩盖此问题。新增顺序断言。
