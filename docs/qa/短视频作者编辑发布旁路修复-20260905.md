# 短视频作者编辑发布旁路修复

## 直接证据

VideoController 的 PUT :id 只有登录与外发红线，调用 VideoService.update。原 UpdateVideoDto.status 为任意字符串，服务层只核对作者后原样更新，作者可提交 PUBLISHED 绕过独立管理审核。此判断来自本地代码，不曾对云端内容实际执行。

## 本批修复

- 作者编辑状态仅接受 HIDDEN；PUBLISHED/PROCESSING/AUDITING 等由独立业务或审核流程处理。
- DTO和服务层双重限制；更新只取 title、coverUrl、status，额外对象字段不进入数据库更新。
- 既有后台编辑表单不提交status，发布/驳回继续走专用审核接口；未修改这些界面或账号权限。

## 验证范围

- 视频及发布红线相关7 suites，147/147 PASS（含6项新增服务层回归）。
- DTO另测8项，覆盖状态拒绝及合法编辑。
- 不包含真实云端操作、真机视频或内容审核供应商验收。

## 待继续

圈内能力新授权尚未接入实际VideoService.create；该路径仍有提交后内存异步审核。不能据此称新能力审批/额度/可靠外发已完整覆盖。管理审核状态与审核台账一致性、发布恢复前的实时授权、媒资精确绑定还需继续收口。

## 后继：管理审核双状态

专用 VideoService.audit 原来只更新 status，未同步 auditStatus；已改为单条更新同时写 PUBLISHED/APPROVED 或 REJECTED/REJECTED，通过时清空旧原因。内部非法action明确拒绝，不静默按驳回处理。

本轮视频相关8 suites，159/159 PASS；服务端TypeScript通过。新增4项断言覆盖通过、驳回、非法动作、不存在记录。本地测试使用模拟Prisma，不能代替线上审核回归。

仍未解决统一 ContentAuditRecord 人审入口与该专用入口的台账协调；AuditService.reviewContent 存在先更新台账再回写业务、回写失败只记日志的旧语义，需要单独收敛事务和并发，不能将本次双字段修复表述为完整审核台账闭环完成。
