# 咨询配置与预扣数值边界

## 根因及修复

原配置写入允许最大 int4 单价，但即时通话按十分钟预扣时，乘积超过 int4 会拒绝。因此存在保存成功、公开入口显示可用、实际发起必然失败的配置。

- 增加共享定价边界：预扣分钟数仍为既有10分钟，不调整计费业务规则。
- 最大可配置正单价为 `floor(2147483647 / 10)`；零价仅表示关闭，不能发起通话。
- HTTP DTO、服务配置内部写入、公开批准投影及通话发起共用边界。负值、小数、非数字、非有限值及超界值均不放行。
- 存量异常价格不生成公开音视频入口；本人仍可读取原值并修正或关闭。批准状态与价格有效性仍分离，未把异常定价当作自动撤权。

## 本地证据

- 定价/DTO、CircleExpertService、ConsultCall准入专项：3 suites、54/54 PASS。
- 本机隔离 PostgreSQL 完整工作流：119/119 PASS。新增真实表测试验证存量超界价隐藏、本人可读、拒绝再次保存、边界价可修正、零价关闭。
- server TypeScript Exit0。无真实预扣、通话、退款或支付操作。

## 边界

数值边界是数据库和现有预扣模型的技术限制，不是运营推荐价，也不代表高额交易已获授权。实际定价审核、真实资金隔离及通话资源闭环仍需完成。

现有规则文档仅定义即时通话计费和可接时段，未明确预约提前量/时区/取消履约规则；下一阶段须用明确的业务契约补齐，不能随意设置一套期限后宣称完成。未部署或修改线上数据。
