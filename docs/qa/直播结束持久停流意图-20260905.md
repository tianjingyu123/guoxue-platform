# 直播结束持久停流意图验收

## 已实现范围

- `LiveService.endRoom` 在结束业务的同一数据库事务中，根据服务器已记录的凭据范围创建停流意图；不接受调用方指定供应商范围。
- 同房间、同供应商仅一条意图；重复结束复用原 operationId。
- 双节点领取通过行锁和版本比较确保单次派发资格。
- 派发租约超时进入 UNKNOWN，不重新入队；迟到回执必须匹配原 operationId。
- 停流回执只表示供应商确认，不作为媒体已停止或额度可释放的证明；ACTIVE 额度继续保留。
- 历史房间没有可信凭据范围时不猜测目标、不释放额度。

## CSS 额度收尾事务（后续实现，取代上节“没有 COMPLETE 接线”的阶段状态）

新增 `LiveMediaCompletionService.completeCss` 与证据决策策略：在同圈锁、媒体锁和房间行锁内核对 ENDED/结束时间、单一 CSS 凭据范围、停流 ACK、ACK 后的新鲜 forbid 查询、禁推期限覆盖凭据有效期，以及无不确定标记/无未闭合连接的断流记录。最新 END 必须落在当前停流请求窗口，查询应发生在 END 之后。曾签发 TRTC 的房间仍等待 TRTC 专属证据，不能只凭 CSS 释放全部资源。

通过时才将额度 ACTIVE→COMPLETED，并在同事务冻结 verification、媒体/凭据版本与额度版本作为 completion 审计。重复收尾只核对原回执、不重复变更；审计写入失败回滚额度与回执。COMPLETED 只归还并发名额，累计使用次数继续计入，不是退还使用次数。
