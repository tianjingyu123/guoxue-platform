# 短视频发布额度实际接线

本地 VideoService.create 已替换原只对 PLATFORM 调用旧授权服务的判断。非管理员投稿无论 CIRCLE_ONLY、PLATFORM、SELF_ONLY 或未传可见范围，均在视频写入的同一个 Prisma 事务中执行新能力授权及额度预留、激活、视频/待审记录写入、持久作者圈子绑定核对和额度完成。

- 圈主使用圈级主体；非圈主以本人为主体，由能力服务验证个人平台直授，不冒用圈主。
- 真人平台管理员保持直接发布路径；AUTOMATION 即使管理员身份也由服务层红线拒绝。
- 额度按成功提交的投稿次数完成，不代表审核通过、内容已公开或外部媒体已处理。
- 任何业务/审核记录/额度写入失败向外抛出，由同一事务回滚。事务提交之后才调用既有异步机审。
- 视频阅读、搜索、列表没有接入发布资格服务。
- VideoModule 已注册投稿事务服务及其额度依赖；CircleModule 已有授权服务导出。

新申请/审批控制器仍未对外注册；直播和问答的业务接线尚未完成，禁止据此声称全部运营闭环通过。候选需要对应的新能力迁移和正确运行规则/授权数据，不能直接覆盖上线使存量发布者突然全部被拒。

本地适配层10项单测覆盖顺序、同事务、个人直授主体、重复请求拒绝、失败/绑定冲突；视频原子审核测试明确模拟此适配层，只证明审核台账原子性。完整额度+视频创建仍需真实隔离数据库集成验证，再做HTTP与后台UI验收。当前请求key由服务端每次生成，不宣称跨HTTP重试幂等。

本轮未部署、未迁移、未改云端或设备。

## 真实数据库集成补验

在 `circle-capability-workflow-pg.integration-spec.ts` 中追加实际 VideoService → 投稿事务服务 → 当前能力授权 → 额度仓储 → 视频/审核台账的完整调用，未 mock 授权、额度或数据库。仅将外部机审调度隔离、将审核可见性固定为待审，以验证待审台账写入。

新增4项通过：圈主申请审批启用后提交，视频/台账/COMPLETED额度与 RESERVE/ACTIVATE/COMPLETE 三张回执存在；撤权后视频与额度零新增；普通MEMBER个人直授且圈子申请条件不达标时投稿成功，仅计个人额度；审核表真实约束失败使视频、额度和回执回滚，未调度机审。
