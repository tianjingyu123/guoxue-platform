# 咨询房间票据接线与未完成边界

## 本轮证据与变更

检查 `ConsultCallService` 额度生命周期时发现更前置的票据问题：原 `buildTrtcConfig` 手写 UserSig，房间号仅作为响应字段，并不包含指定房间的 PrivateMapKey。不能以资格查询通过证明票据只允许进入本次付费通话。

现在复用仓库已锁定的 `tls-sig-api-v2`，输出 UserSig、字符串房间 PrivateMapKey、strRoomId、expiresAt。咨询身份由房间和平台用户映射为32字符内的独立短身份；同一用户不同通话不复用RTC身份。用户UUID仍是平台权限判定依据，不将RTC身份当平台账号。

- VOICE 权限15（创建/进入/收发语音），VIDEO权限63（另加收发视频）；均不开放屏幕分享。
- 房间必须符合实际服务器生成的 `consult_` 加16位十六进制形式；AppId为有效uint32整数，身份、通话类型、有效期严格校验，异常不返回部分票据或记录秘密。
- initiate/accept 使用订单的通话类型，必须同时有UserSig和PrivateMapKey才继续预扣/接听。不是只给前端新增未使用字段。
- 保持既有默认24小时票据期限，上限也限制为24小时。尚未实现安全续签及持久化边界前，不能任意缩短导致等待/通话中失效，也不能把到期当真实媒体停止的证明。
