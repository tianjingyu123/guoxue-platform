# 咨询回调持久化与乱序验收

## 已接入的链路

现有 `/live/trtc/callback` 保留原文守卫，先将咨询房间交给独立 ConsultMediaEvidenceModule，其他房间继续原直播处理。没有新建免验签接口，也没有修改腾讯云回调配置。

ConsultMediaEvidenceService 只能从私有可信请求记录取数据；依原房间查找唯一咨询订单，按圈子锁→订单锁→边界锁核对 SDKAppId 与两名房间隔离身份。证据只写 `ConsultCallMediaBoundary.mediaEvidence`，不改订单、退款、停流意图、签发凭据版本或 ACTIVE 额度。

新增本地迁移 `manual_add_consult_call_media_evidence`：JSONB 证据列及 ConsultCall.rtcRoomId 查询索引。没有远端执行。

## 事件规则

- 兼容新版无 UniqueId 与旧版带 UniqueId；媒体停止不代替退房。
- 只保留应用、房间、映射身份、事件类型/时间、精度、接收时间和原文摘要等白名单字段。不存原始包、客户端 IP、签名或票据。
- 同一事件重投不更新原接收时间或版本，不能借重放伪造新鲜证据。
- 乱序旧进房不能覆盖新退房；新进房或退房后媒体活动恢复为 ACTIVITY_OBSERVED。
- 同毫秒矛盾、混用会话策略、秒精度不足等保持 UNKNOWN。
- 最多 128 条证据，溢出保留原记录并标记 overflow；不丢弃历史后伪装为离线。
- OFFLINE_OBSERVED 只表示观察态，不是额度释放或不可重新进房证明。
