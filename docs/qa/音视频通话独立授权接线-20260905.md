# 音视频通话独立授权接线

## 发现与修复

真实 `ConsultCallService.initiate/accept` 此前仅用圈内 OWNER/PARTNER/GUEST、有效成员与价格作为准入，未读取独立音视频授权，既可能放过未经开通的服务，也会挡住平台直授的普通成员。

本轮将两处新增通话操作接入 `CircleCapabilityService.assertAuthorizationInTransaction`，先取得同圈权限锁，再读取成员和当前价格；VOICE 对应 AUDIO_QUESTION，VIDEO 对应 VIDEO_QUESTION。价格、账号、圈子和成员有效期限制仍保留，只有固定头衔条件交由独立授权策略判定。平台直授仍不绕过账号停用、成员失效等安全条件。

控制器透传真实执行者类型，服务层拒绝 AUTOMATION 发起/接听。取消、超时退款、既有订单结束及申诉路径未加入新的授权要求，避免撤权后无法履约或退款。阅读、观看和文字问答路径本轮未改动。

- 通话服务与准入专项：39/39 通过（资金和 RTC 替身）；补入控制器执行者传递及红线元数据测试后，最终 3 suites、44/44 通过。
- server TypeScript 检查、Nest 生产构建、范围内 diff-check 均 Exit 0。
- 真实 PostgreSQL 全工作流：106/106 通过，新增音频/视频不能混用、直授普通成员通过授权后资金失败回滚、撤权等待单拒接但可取消等测试。
- 隔离实例 PostgreSQL 16.13，360 表，随机端口 58142；目录 `artifacts/local-qa/circle-workflow-pg-X5Qxtu`，合成资料保留，已停止且 postmaster.pid 不存在。
- 没有真实金币扣费、退款、RTC 供应商调用、预发布/生产写入。
