# 队列去重参数接线复核

为圈子能力的可靠业务派发检查既有 QueueService 时，确认 `dedupKey/dedupTtl` 被原样展开到 BullMQ options，但实际安装的 BullMQ 5.77.6 读取 `deduplication.id/ttl`，TTL 单位为毫秒。依据为本地依赖 `dist/esm/types/deduplication-options.d.ts` 与 `dist/esm/classes/job.js`，不是根据文档猜测版本。

本地修复保留 QueueService 调用接口，转换到正确字段；不携带旧无效字段，不擅自提供过期时间；空标识、无标识期限、非正整数期限在入队前拒绝。无去重选项的既有调用保持原行为。

QueueService 单测 19/19 通过，包括精确 options、无默认 TTL 和八类非法参数；这只证明适配层，不代表真实 Redis 并发去重或端到端只执行一次。当前源码未发现其他业务调用 QueueService 时传入这两个选项，不能据此宣称既有线上重复派发事故已被修复。

BullMQ 去重仍不等于 PostgreSQL 业务记录与任务的原子提交，不代替供应商幂等、任务恢复及额度可靠收尾。圈子新接口继续未注册。本次无迁移、无依赖升级、无真实入队、无云端操作。
