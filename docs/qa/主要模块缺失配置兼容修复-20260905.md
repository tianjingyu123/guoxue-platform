# 主要模块缺失配置兼容修复

## 真实根因

只读 GET https://pre-api.rebugx.cn/api/v1/config/client 返回 HTTP 200、schemaVersion=1、environment=staging、revision=15a68b977495a583；七个 client_module_* 字段均不存在，而非管理员明确 false。候选客户端内置默认 false 和旧缓存合成值把全部主要模块误隐藏。候选服务端新增总闸也会把不存在配置当作拒绝业务，存在升级兼容风险。

此前《v243跨端分流实测》所记“当前总开关停用”仅是客户端行为，不能解读为管理员已明确关闭；以此处补充的实际配置证据为准。

## 本地修复及边界

- 客户端不再生成缺失模块键的 false；模块入口缺失时保持旧行为，明确 false 或格式错误仍关闭。
- 新缓存 v3 不读取 v2 合成 false，保留环境与账号隔离；微信登录、小程序分享、其他资格类敏感开关默认仍 false。
- 服务端仅 ClientModuleGuard 使用“缺失时兼容”的参数；普通 FeatureFlagService 调用默认仍 false。明确关闭、灰度、网络错误、角色与业务发布审批均未放宽。
- 未修改任何线上开关、角色、数据库、DNS；未部署。

- 圈子列表→官方圈公开介绍→浏览器返回列表实际通过，不再错误进入停用页；未提交入圈或支付。
