## 后续事务收尾实现

- `ConsultMediaCompletionService` 按圈子锁→订单锁→媒体边界锁执行，核对终态、应用/房间、双方主体、额度绑定、停流受理与最终整房观察。
- 部署侧 `CONSULT_TRTC_CLOSURE_ATTESTATION` 默认空。其语义是人工核验记录：高级权限持续启用、该专用应用仅由本服务签发，时间区间必须覆盖订单创建至核验时点，证据以 SHA256 引用。它不是腾讯云自动回执，不得为让测试或线上通过而凭空填写。
- 满足全部门禁后，同一事务写 COMPLETE 账本回执与边界完成标记；累计用量保留，仅归还并发。重复调用核对同主体原回执，不重复写。
- 有界服务端任务每批最多10条，最多60秒，仅处理已有 ACK 且未完成记录；不调用供应商、不重发移出请求、不发新票据。不是 Codex 定时任务。
- 后台只读投影新增回执核验，完整匹配才显示已归还；没有提供人工强制释放 API。
- 最终单元测试5套72项通过（含后台完成回执反串主体测试），TypeScript与 Nest 构建通过；Compose透传测试2/2。
- 独立 PostgreSQL 16.13 合成库：选定2项通过，其余149项跳过。实际两连接竞争仅一次 COMPLETE；真实账本写后注入失败，事务回滚使额度保持 ACTIVE 且没有完成回执。供应商回应及事件为合成，测试只推进进程 Date，网络计时器不变，电脑与云端时间未改。测试库已停止。

供应商接口边界已查官方资料：`DescribeRoomInfo` 用于历史/对账，官方不建议用于关键业务逻辑；不能把历史列表无记录当作当前房间已空。[官方说明](https://intl.cloud.tencent.com/document/product/647/36754)。`DismissRoomByStrRoomId` 有明确 `FailedOperation.RoomNotExist` 状态，可作为后续精确范围核验方案的研究入口，但本轮未调用、未实现自动二次解散。[官方接口](https://cloud.tencent.com/document/product/647/37088)。

## 保护期后最终核验的后续实现

- 新增内部 `ConsultTrtcFinalProbeDispatcher/Client`。这是额外一次精确房间解散写操作，不是只读查询，也不是重发此前的移出用户请求。必须在保护期后、原停流ACK、专用应用与人工核验记录有效时才能认领。
- 先在同圈锁和订单/边界行锁内写 `finalProbe=DISPATCHING`，提交后才访问供应商；每单至多认领一次。超时或未知结果不重发，租约过期转 UNKNOWN，供原请求调查。
- 仅HTTP成功响应内精确的 `FailedOperation.RoomNotExist` 加有效 RequestId 可归一为 ABSENT。普通成功仅ACK，权限错误/无RequestId/其他错误均UNKNOWN。只保存状态、地域、时间和RequestId，不保存认证原文。
- 账本收尾接受两条路径：保护期后精确解散回调；或保护期后明确ABSENT且不存在时间冲突、错范围、溢出/损坏证据。两条路径均仍要求完整云端权限核验记录，并使用既有同事务COMPLETE回执。
- 后台只读投影显示最终核验状态，UNKNOWN/INVALID提示调查原请求，不提供强制释放按钮。
- 新增隔离 PostgreSQL 两项：两连接仅一次最终请求；ABSENT完成、UNKNOWN保留ACTIVE。与此前两项幂等/回滚合计4项通过，其他149项跳过。供应商为纯替身，未发送真实云请求。测试库正常停止。
- 没有新迁移、没有云端配置变更、没有重复TAT。尚需候选冻结、部署与真实媒体/供应商验收；人工核验记录仍未在云端配置。
- 最终复验：相关8套单元测试127/127，服务端TypeScript、Nest构建、限定文件diff检查均通过。
