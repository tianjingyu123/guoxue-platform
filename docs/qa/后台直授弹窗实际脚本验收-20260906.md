# 后台直授弹窗实际脚本验收

## 发现与处理

源码核对确认已有 `CircleCapabilityList.vue` 和 `CircleDirectGrantDialog.vue`，但直授弹窗未使用已存在的 `createDirectGrantSession`。仅验证独立会话辅助函数不能证明弹窗已具备同样保护。

- 将真实弹窗确认与提交接入会话：目标、最新授权 ID/修订、显示名一致才允许保存确认快照；确认超过 60 秒需重新查询。
- 提交只使用确认会话生成的白名单参数，不从变化中的表单重新取授权对象。失败或结果不明不自动重发；同一次会话不能双击重复授权。
- 组件卸载或弹窗代次变化后，迟到提交结果不能显示成功并关闭另一弹窗。
- 补齐辅助函数最大并发不得超过总额度的验证。此保护不代替服务端同事务权限、对象、修订与额度核验。
- 圈子列表调用后台 `adminCircles`，成员列表调用既有 `circles/:id/members`；已核对实际响应结构为 `{circles,total}` / `{members,total}`，并非凭前端假定。尚未完成浏览器选择、翻页、显示名截断等视觉操作验收。

## 证据

- 新增 `circle-direct-grant-dialog-runtime.test.mjs`：编译实际 SFC script setup，在真实 Vue reactive/watch 下运行，并调用真实会话实现。网络、提示和生命周期挂钩为替身，不对外授权。
- 弹窗 6 项 + 会话 6 项，共 12/12 PASS。覆盖单次保存、过期重查、失败不重发、换对象迟到、异常确认、卸载后迟到。
- 首轮 11/12 原因为测试的两个 VM 使用不同 Error 构造器，跨 realm 的 instanceof 与同一浏览器环境不同；共享 Error 后原断言通过，未放宽过期规则。

## 上线边界

这不是后台运营全链完成。`CircleCapabilityController` 仍未注册到 CircleModule，页面也未作为已开放运营能力发布。仍需完成媒体/额度业务收尾、用户申请启用入口、模块与菜单统一接入、HTTP/数据库及浏览器角色验收。普通阅读不受发布资格控制，平台直授不要求圈子申请门槛的业务规则未改变。

本轮仅本地源码与合成脚本测试，未推送、部署、迁移、修改云端/DNS、真实授权或付款。
