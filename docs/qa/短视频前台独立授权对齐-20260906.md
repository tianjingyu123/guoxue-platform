# 短视频前台独立授权对齐

## 修复

- 新增 JWT 保护、private/no-store 的圈内视频/直播发布资格查询，复用事务内当前主体授权判定。接口只返回圈子、能力和布尔值，不预留额度、不签发媒体凭据、不返回他人授权详情。
- 前台短视频权限检查优先查询新资格，识别平台直授普通成员；旧圈级 canPublish 不再作为新能力授权。平台管理员继续既有身份路径，真实投稿仍由服务端重新核验。
- 申请面板仅复用旧接口的圈子名称列表，不复用其批准结果或门槛。申请、查看进度、本人启用均连接 circle-capabilities。
- 进度来自服务端当前规则，不再补写固定30天/100人等默认门槛，不把圈内帖子称作全部作品；未满足条件不显示申请按钮。
- 原“粉丝1万快速通道”提示改为平台直接授权说明；移除“先发到圈内”的无条件发布暗示。普通阅读不受本改动影响。
- 启用绑定授权 revision；请求结果不明只回读，不自动重发。关闭或切换圈子后丢弃迟到结果，底部面板增加最大高度与滚动。

## 本轮证据

- 授权服务单测40/40；HTTP身份/参数/缓存边界59/59。
- 真实组件脚本及客户端请求适配器9/9：旧批准不放行、直授识别、原因必填、重复点击、启用revision、异常只回读、关闭后迟到响应。
- localhost合成PostgreSQL 2/2，154项未选中：个人直授的资格查询与实际投稿一致，查询不增加账本计数；撤权后查询与投稿均拒绝。
- mobile vue-tsc、server Nest构建、指定文件diff-check通过。未产生迁移、云调用、真实发布或付款。

## 保留缺口

- 尚未验真同包H5/App/小程序交互，不能把组件脚本测试称作真机验收。
- 发布资格查询不保证后续资源额度仍充足，实际提交保留额度与内容审核事务校验。
- 未选圈子时仍依赖既有圈主圈子列表。后续补充已解决历史分页问题，见下节；圈子选择和真实交互仍待同包验证。
- 直播与付费问答的申请/本人启停入口仍需单独对齐；本次不宣称全部前台授权流程已完成。

## 当前授权精确读取补充

- 增加 `GET circle-capabilities/circles/:circleId/current`，JWT与private/no-store保护，主体只从登录态确定，不接受客户端指定其他成员。
- 视频/直播圈主读取圈级授权，普通成员读取个人授权；音视频问答始终读取本人授权，不把圈级记录作为个人提供服务资格。
- 事务内锁定圈子与人员，复核账号及有效成员关系，再以仓储 sequence DESC LIMIT 1 查询；不受后台历史列表分页影响。
- 返回最小状态投影，不包含审计原因、申请事实快照或其他成员信息，不写授权或配额。
- 短视频面板改用此接口，移除“历史超过50条即停止”的临时限制。
- 本轮服务单测42/42（含60条历史和其他成员混合范围）、HTTP61/61（含匿名拒绝、主体伪造拒绝、禁止缓存）、前台脚本9/9通过，server类型检查通过。无云端动作。
