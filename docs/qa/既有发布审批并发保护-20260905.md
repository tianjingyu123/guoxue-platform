# 既有发布审批并发保护

## 实际缺陷

CirclePublishGrantService.approve/reject 原先先读取 PENDING，再仅按 id 更新。管理员旧页面或两人同时操作时，后写入可以覆盖另一人已完成的批准/驳回。

## 修改

保留原资格、批准范围和原因校验；最终 update 的 where 同时要求 id 与 status=PENDING。Prisma P2025 转为明确业务冲突，提示刷新，绝不自动重试；其他数据库异常原样抛出。成功仍返回更新记录，前后台返回结构不变。没有增加普通读者资格门槛。
