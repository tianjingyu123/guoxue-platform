# 删除后恢复入口

发现原列表删除后历史按钮一并消失，数据库虽保留快照，管理员却无直接入口恢复。

现增加超级管理员专用“已删除配置”入口，列表只读主库历史并排除现存标识，不返回指定用户名单；点击历史仍走既有确认与基础指纹回滚，不自动开启。恢复后刷新已删除列表与正常列表。沿用现有 Element Plus 后台样式与明确动作文案，没有引入另一套发布流程。

实测：后台页面脚本 10/10；服务端/HTTP/真实 PostgreSQL 62/62；前后端类型检查通过。真实 PostgreSQL 用例完成删除→发现历史→恢复→已删除列表移除，恢复内容为所选历史值。隔离库 circle-workflow-pg-dHJj4E（localhost:64120）已停止。

尚缺本轮新增弹窗的浏览器视觉与完整真实 API 页面联调，不以脚本测试替代。旧的无历史记录无法从该入口恢复；删除操作本身仍依赖既有审计记录，不能把历史创建时间称为删除时间。未发布、未操作线上。

## 后续真实浏览器操作补验

2026-09-05 使用 CUA 操作 localhost:4187 的真实 FeatureFlagList 组件，后端仍为明确标识的内存合成 API，未连接线上。

1. 点击删除，确认框展示对象、关闭状态、20% 灰度与默认值风险；确认后计数 0→1，正常列表为空。
2. 打开“已删除配置”，发现同一对象；点击“查看历史并恢复”，可见 v1/关闭/20%。
3. 点击回滚再取消，写计数仍 1，记录仍在已删除列表。
4. 再次确认回滚，计数 1→2；正常列表恢复关闭/20%，已删除列表显示“没有可恢复的配置”，历史新增一条（合成 API 的版本号 v3，仅反映模拟 revision，不作为真实数据库版本序列证据）。
