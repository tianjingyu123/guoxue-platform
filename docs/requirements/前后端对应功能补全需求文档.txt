## 热卜国学平台 · 后端管理后台完整需求文档 V1.0

> **文档定位**：后端管理后台开发需求，与前端100个页面形成能力对应  
> **适用对象**：Claude Code  
> **核心原则**：操作最简化、权限清晰化、AI自动化


### 一、总体设计原则

#### 1.1 角色权限原则
- 采用 RBAC 权限模型，按角色分配功能菜单
- 不同角色登录后**仅看到自己有权限的功能**，避免信息过载
- 用户拥有多角色时，权限取并集，提供「身份切换」入口

#### 1.2 操作简化原则
- 所有操作步骤不超过3步到达目标
- 复杂操作提供「一键执行」按钮
- 批量操作统一交互模式（勾选→选择操作→确认执行）
- 关键数据提供可视化图表，减少人工分析

#### 1.3 AI自动化原则
- 能用AI替代的重复性工作，尽量让AI做
- 人工仅处理AI无法判断的异常和决策
- 所有AI处理结果需留存记录，支持人工复核

#### 1.4 前后端能力对应原则
- 前端每个页面的数据和管理操作，必须在后台有对应的管理入口
- 前端每个营销位置，必须在后台有对应的配置项

#### 4.1 方案决策：平台生成推流地址，老师使用第三方工具推流

| 考量维度 | 方案A：后台集成推流 | 方案B：平台生成+第三方推流 |
|:---|:---|:---|
| **技术难度** | 高（需开发全平台推流SDK） | 低（仅集成腾讯云API生成推流地址） |
| **开发成本** | 极高（需适配Win/Mac/iOS/Android） | 低（后端API即可完成） |
| **用户习惯** | 需要学习新工具 | 使用熟悉的OBS等专业软件 |
| **功能丰富度** | 有限（无法媲美专业软件） | 极高（OBS功能全面） |
| **维护成本** | 高（持续适配各平台） | 极低（腾讯云维护） |

**推荐方案**：平台后台生成推流地址，老师使用OBS等第三方工具推流。

#### 4.2 实现要点
- 主播在后台点击「获取推流地址」
- 后端调用腾讯云API生成推流URL+串流密钥
- 前端展示推流地址和密钥，一键复制
- 主播将地址和密钥粘贴到OBS中即可开播
- 支持「重新生成」密钥（旧密钥立即失效）
- 提供OBS配置引导图文教程
