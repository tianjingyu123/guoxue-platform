## 热卜国学平台 · AI智能体技术选型与搭建方案 V1.0


### 一、总体架构：双轨制

平台AI采用**双轨制**架构：

| 轨道 | 适用场景 | 技术方案 | 核心逻辑 |
|:---|:---|:---|:---|
| **自研轨道** | 核心AI能力 | 自建向量数据库 + 自研RAG + 大模型API | 数据在自己服务器，直接调大模型，不走第三方平台 |
| **扣子轨道** | 灵活AI应用 | Coze API + Coze知识库 | 低代码快速搭建，通过API接入平台 |


### 二、技术选型决策矩阵

**核心判断原则**：如果该AI功能涉及平台核心知识资产（圈内内容、课程信息、排盘知识等），且需要严格的数据隔离和低成本高频调用，走自研轨。如果是创意型、玩法型、需要快速迭代验证的，走扣子轨。

| 应用场景 | 选型 | 核心理由 |
|:---|:---|:---|
| **圈主助理** | 🏠 自研 | 圈子专属知识库，需严格数据隔离。未来圈子可达几千甚至几万个，必须摆脱Coze单智能体最多绑定150个知识库的限制 |
| **智能客服** | 🏠 自研 | 回答基于平台知识库，高频调用自研可大幅降低API费用。用户生辰等敏感信息不出服务器 |
| **智能搜索** | 🏠 自研 | 需检索全平台结构化数据（课程/圈子/商品/文章），搜索结果页是独立页面+内容列表，非对话框模式，Coze无法承载 |
| **智能体广场** | 🧩 扣子 | 创意玩法型应用（如“八字脱口秀”、“宝宝起名大师”），需求灵活多变，需快速验证迭代。扣子零代码搭建，半小时可上线一个 |
| **站长助理** | 🧩 扣子 | 本质是文案生成器，功能相对独立，不深度绑定平台知识库，扣子现有模板可直接使用 |
| **AI封面图生成** | 🏠 自研 | 需调用专门文生图模型（如通义万相），通过AI网关路由至对应模型 |
| **AI内容审核(图片)** | 🏠 自研 | 需多模态模型，通过AI网关路由 |
| **AI语音转文字** | 🏠 自研 | 调用腾讯云ASR，通过AI网关路由 |
| **AI文字转语音** | 🏠 自研 | 调用腾讯云TTS，通过AI网关路由 |


### 三、自研RAG方案实现架构

**3.1 整体架构**

```
前端页面（圈主助理对话窗口 / 搜索框 / 智能客服弹窗）
        ↓
平台的统一 AI 网关（/api/v1/ai/{场景名}）
        ↓
┌─────────────────────────────────────────┐
│              AI 网关层                    │
│  1. 鉴权、限流、日志                       │
│  2. 根据场景名 + 配置表 → 路由到对应后端     │
│  3. 格式转换、Fallback 处理               │
└─────────────────────────────────────────┘
        ↓                         ↓
┌───────────────┐          ┌──────────────┐
│  自研 RAG 服务  │          │  Coze API    │
│  (核心AI能力)  │          │  (智能体广场)  │
└───────────────┘          └──────────────┘
        ↓
┌─────────────────────────────────────────┐
│           自研 RAG 服务内部                │
│  1. 向量数据库（Milvus / pgvector）       │
│     - 圈子专属知识库（按circle_id隔离）     │
│     - 平台公共知识库                       │
│  2. 检索模块（向量检索 + 全文检索）         │
│  3. Prompt 模板引擎                       │
│  4. 文档处理管道（PDF/Word/Excel/图片解析） │
└─────────────────────────────────────────┘
```

**3.2 多模型可配置路由体系**

不同AI场景需匹配不同能力的大模型。系统必须支持**每个场景独立配置使用哪个大模型**，且后期可随时调整，无需改动业务代码。

**各场景模型推荐配置**：

| 应用场景 | 推荐主模型 | 推荐备用模型 | 类型 |
|:---|:---|:---|:---|
| **圈主助理**（文本问答） | DeepSeek V4 Pro | DeepSeek V3 | 文本推理 |
| **智能客服**（文本问答） | DeepSeek V4 Pro | 豆包 Pro | 文本推理 |
| **智能搜索**（搜索总结） | DeepSeek V4 Pro | DeepSeek V3 | 文本推理 |
| **AI润色/标题优化** | DeepSeek V4 Pro | - | 创意文本 |
| **AI封面图生成** | 通义万相 V2 | 文心一格 | 图像生成 |
| **AI内容审核-图片** | DeepSeek 多模态 | GPT-5.x Vision | 多模态 |
| **AI课程笔记/字幕** | 腾讯云 ASR | Whisper Large | 语音识别 |
| **AI听书** | 腾讯云 TTS | 阿里云 TTS | 语音合成 |

**模型切换机制**：
- **主备切换**：主模型调用失败或超时（>5秒），自动切换备用模型，记录切换日志
- **灰度切换**：支持按流量比例（如10%用新模型）测试新模型效果，效果达标后全量切换
- **成本预算控制**：按场景设置月度Token预算上限，超出时自动降级到轻量模型

**3.3 圈主助理知识库精细化管理机制**

圈主助理是最复杂的场景。需为每个圈子建立独立知识库，且严格隔离（绝不串台）。

**知识库内容来源与处理规则**：

| 内容来源 | 入库方式 | 去重规则 | 圈主权限 |
|:---|:---|:---|:---|
| **圈主发布的文章** | 自动入库 | 系统自动去重 | 可在知识库管理中移除 |
| **圈主发布的课程** | 自动入库 | 系统自动去重 | 可在知识库管理中移除 |
| **精华帖**（圈主设为精华） | 自动入库 | 系统自动去重 | 可在知识库管理中移除 |
| **热门帖**（点赞≥阈值，可配置） | **候选入库**，需圈主确认 | 圈主确认时系统自动去重 | 圈主手动选择是否加入 |
| **嘉宾/成员发布的帖子** | **手动入库**，圈主点击“添加到知识库” | 点击时系统自动去重 | 圈主完全掌控，可随时移除 |
| **圈主手动投喂**（上传文件） | 实时入库 | 系统自动去重 | 圈主可随时移除 |

**去重机制**：
- **完全重复**：内容MD5哈希值完全相同，直接拒绝录入
- **高度相似**：向量相似度≥90%（阈值可配置），标记为“疑似重复”，推送圈主判断
- **低相似度**：向量相似度<90%，正常录入

**圈主审核后台**：在圈子管理后台增加“知识库管理”模块，包含已入库内容列表（支持搜索、筛选、移除）、待确认内容列表（候选入库+疑似重复）、知识库设置（热门帖阈值、自动入库规则）。


### 四、扣子的定位与使用边界

**扣子负责什么**：
- 智能体广场上的所有AI应用（如“获客文案生成器”、“报告工厂”、“开运好物推荐官”、“白标AI助手”等）
- 站长助理（推广文案生成）

**扣子的接入方式**：
- 在Coze平台为每个智能体创建独立Bot
- 平台后端通过Coze API调用，前端展示对话界面
- Coze返回的SSE流式响应通过平台AI网关转发给前端，前端不直接调用Coze API（避免暴露密钥）


### 五、各场景详细实现方案

**5.1 圈主助理（自研）**

| 环节 | 实现方式 |
|:---|:---|
| **知识库存储** | 自建向量数据库（Milvus/pgvector），每个圈子独立集合/分区，通过circle_id隔离 |
| **知识库更新** | 定时任务自动扫描圈子内容（精华帖/热门帖/文章/课程），自动同步；圈主手动投喂内容实时同步；嘉宾/成员内容需圈主手动确认 |
| **知识库去重** | 内容哈希去重+向量相似度去重（阈值≥90%标记为疑似重复，推送圈主判断） |
| **知识检索** | 用户提问时，根据circle_id在对应圈子向量空间检索+公共知识库并行检索 |
| **回答生成** | 调用DeepSeek V4 Pro，将检索结果和用户问题组合成Prompt，生成回答 |
| **来源标注** | 回答中标注知识来源（如“此回答参考了本圈精华帖《XXX》”） |
| **对话界面** | 前端嵌入圈子主页固定对话窗口，显示AI图标、知识来源、流式输出 |
| **访问控制** | 仅圈内成员可提问，非成员点击时提示“加入圈子后可使用圈主助理” |

**5.2 智能客服（自研）**

| 环节 | 实现方式 |
|:---|:---|
| **知识库** | 自建向量数据库，平台公共知识库（帮助文档、平台规则、使用说明等）+定期同步课程/商品/圈子信息 |
| **回答生成** | 调用DeepSeek V4 Pro |
| **对话界面** | 右下角固定悬浮按钮，点击弹出半屏对话窗口 |
| **转人工** | 用户输入“转人工”或AI识别到无法回答时自动生成工单 |
| **内容推荐** | 回答中可嵌入课程/商品/圈子推荐卡片 |

**5.3 智能搜索（自研）**

| 环节 | 实现方式 |
|:---|:---|
| **搜索引擎** | 自建Elasticsearch索引，同步全平台结构化数据（课程/圈子/商品/文章/电子书/智能体） |
| **搜索结果** | 前端展示独立搜索结果页，包含AI总结卡片（由DeepSeek生成）和各类型内容列表 |
| **与传统搜索区别** | 传统搜索只返回关键词匹配结果，AI搜索额外返回AI生成的总结和建议 |

**5.4 智能体广场（扣子）**

| 环节 | 实现方式 |
|:---|:---|
| **搭建方式** | 在Coze平台为每个智能体创建独立Bot，配置知识库、工作流、人设 |
| **接入方式** | 平台后端通过Coze API调用，前端展示对话界面 |
| **流式输出** | Coze返回SSE流式响应，通过网关转发给前端 |
| **计费** | 可设置免费调用次数，超额需付费或升级会员 |


### 六、数据库补充表设计

在原有Prisma Schema基础上，增加AI知识库管理相关表：

```sql
-- 圈主助理知识库内容表
CREATE TABLE circle_knowledge (
  id BIGSERIAL PRIMARY KEY,
  circle_id BIGINT NOT NULL,
  source_type VARCHAR(30) NOT NULL,
  source_id BIGINT,
  content TEXT NOT NULL,
  content_hash VARCHAR(64) NOT NULL,
  vector_id BIGINT,
  status VARCHAR(20) DEFAULT 'active',
  added_by BIGINT,
  added_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(content_hash, circle_id)
);

-- 圈主手动选择入库记录表
CREATE TABLE circle_knowledge_manual (
  id BIGSERIAL PRIMARY KEY,
  circle_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  target_type VARCHAR(30) NOT NULL,
  target_id BIGINT NOT NULL,
  action VARCHAR(20) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 知识库候选内容表（待圈主确认）
CREATE TABLE circle_knowledge_candidate (
  id BIGSERIAL PRIMARY KEY,
  circle_id BIGINT NOT NULL,
  source_type VARCHAR(30) NOT NULL,
  source_id BIGINT,
  content TEXT NOT NULL,
  content_hash VARCHAR(64) NOT NULL,
  similarity_score DECIMAL(5,4),
  similar_to_id BIGINT,
  status VARCHAR(20) DEFAULT 'pending',
  created_at TIMESTAMP DEFAULT NOW()
);
```

### 八、给 Claude Code 的具体开发要求

1. **统一AI网关**：在Node.js后端实现ModelRouter中间件，所有AI调用统一走 `/api/v1/ai/{场景名}`，根据config_system表中的模型配置自动路由。

2. **向量数据库选型**：建议先使用pgvector（基于现有PostgreSQL，零额外运维成本）。若后期数据量达到千万级向量，可平滑迁移至Milvus。

3. **知识库同步服务**：编写定时任务，每天扫描开通圈主助理的圈子，自动同步精华帖、热门帖、文章、课程到向量数据库。热门帖和嘉宾内容进入候选列表，推送给圈主确认。

4. **去重机制**：在知识库表中增加content_hash字段（MD5哈希，建唯一索引）。编写向量相似度计算逻辑（pgvector余弦相似度），阈值0.9可配置。

5. **圈主审核后台**：在圈子管理后台中增加“知识库管理”模块。

6. **“添加到知识库”按钮**：在帖子详情页、文章详情页的“...”菜单中增加“添加到知识库”按钮，仅圈主可见。

7. **RAG检索模板**：定义标准Prompt模板，确保回答基于知识库内容，无相关信息时如实告知。

8. **Coze Bot管理**：编写Coze Bot的统一管理服务，负责创建、更新、删除Bot。

9. **全量日志**：所有AI调用记录全量日志（场景名、模型名、Token消耗、延迟、费用、成功/失败状态）。
