### 一、安全防护规划（补充至第十一章）

#### 1.1 Web 应用安全

| 防护项 | 方案 | 说明 |
|:---|:---|:---|
| **XSS 跨站脚本** | 所有用户输入输出时必须转义 HTML 特殊字符；前端使用 Content-Security-Policy 头限制脚本来源 | 防止恶意脚本注入 |
| **CSRF 跨站请求伪造** | 后端生成 CSRF Token，前端每次请求携带；关键操作（支付、提现）需二次验证 | 防止伪造用户请求 |
| **SQL 注入** | 使用 Prisma ORM 参数化查询，禁止拼接 SQL 字符串 | ORM 层天然防护 |
| **DDoS 防护** | 接入腾讯云 DDoS 高防包，配置 WAF（Web应用防火墙）规则 | 防大规模攻击 |
| **文件上传安全** | 上传文件必须校验类型（白名单）、大小（≤50MB）、内容（病毒扫描）；存储使用腾讯云 COS 私有桶+签名URL访问 | 防止恶意文件上传 |

#### 1.2 网络安全

| 防护项 | 方案 |
|:---|:---|
| **全站 HTTPS** | 强制 HTTPS，HTTP 请求 301 重定向至 HTTPS |
| **API 签名** | 敏感接口（支付、提现、退款）需额外签名验证，防篡改 |
| **IP 黑名单** | 接口调用频率异常的 IP 自动加入黑名单，Nginx 层直接拦截 |
| **内网隔离** | 数据库、Redis、消息队列仅内网可访问，不暴露公网端口 |

#### 1.3 业务安全

| 场景 | 风险 | 防护方案 |
|:---|:---|:---|
| **刷单** | 虚假订单套取佣金 | 同设备/IP 多账号下单标记风控；订单金额异常波动告警 |
| **薅羊毛** | 新用户福利被批量套取 | 注册需手机号实名；同设备/IP 限制领取次数 |
| **恶意举报** | 竞争对手恶意举报内容 | 举报需登录+填写理由；高频举报同一目标的风控标记 |
| **账号安全** | 盗号、撞库 | 异地登录告警；支持二次验证（短信验证码）；密码强度校验 |
| **支付安全** | 支付回调伪造 | 必须验证微信/支付宝回调签名；回调接口仅允许微信/支付宝官方 IP |

#### 1.4 数据安全

| 防护项 | 方案 |
|:---|:---|
| **传输加密** | 全站 HTTPS + API 敏感字段额外 AES 加密 |
| **存储加密** | 生辰信息、手机号等敏感字段 AES-256 加密存储 |
| **访问控制** | 数据库仅后端服务内网访问；Redis 设置密码认证 |
| **日志脱敏** | 日志中不记录明文密码、手机号、支付信息等敏感数据 |
| **备份加密** | 数据库备份文件加密存储，异地备份 |

#### 1.5 安全审计

- **操作日志**：所有后台管理员操作全量记录（谁、什么时间、做了什么、IP）
- **登录日志**：用户登录记录（时间、IP、设备），支持异常登录告警
- **API 调用日志**：所有接口调用记录，异常调用模式自动检测


### 二、页面加载与性能优化（补充至第十一章）

#### 2.1 首屏加载优化

| 优化项 | 方案 | 目标 |
|:---|:---|:---|
| **小程序包体积** | 主包≤2MB，按业务模块拆分子包；图片资源使用 CDN，不打包进小程序 | 快速下载 |
| **骨架屏** | 首页、列表页、详情页均使用骨架屏，避免白屏等待 | 视觉上更快 |
| **图片懒加载** | 所有列表中的图片使用 IntersectionObserver 懒加载 | 减少首屏请求 |
| **预加载** | 短视频流预加载下一条首帧；排盘结果页预加载 AI 解析 | 减少等待 |
| **缓存策略** | 静态资源（图片、字体、CSS）设置强缓存（1年）；API 数据设协商缓存 | 减少重复请求 |

#### 2.2 页面流畅度优化

| 优化项 | 方案 |
|:---|:---|
| **列表虚拟滚动** | 长列表（帖子、订单、成员）使用 `uni-recycle-view` 虚拟列表，仅渲染可视区域 |
| **防抖与节流** | 搜索输入防抖（300ms）、滚动事件节流（100ms） |
| **动画性能** | 使用 CSS Transform/Opacity 做动画，避免触发重排；复杂动画用 Canvas/WebGL |
| **内存管理** | 页面销毁时释放定时器、WebSocket 连接、大对象引用；避免内存泄漏 |
| **分页加载** | 所有列表查询必须分页，单次最多返回 20 条 |

#### 2.3 网络优化

| 优化项 | 方案 |
|:---|:---|
| **请求合并** | 首页多个数据源合并为单一聚合接口，减少请求次数 |
| **数据压缩** | 后端响应开启 Gzip/Brotli 压缩 |
| **接口超时** | 所有接口设置合理超时（查询 5s、AI 解析 30s），超时返回友好提示 |
| **离线方案** | 已加载过的内容支持离线查看（Service Worker 缓存），断网时展示已缓存内容 |

#### 2.4 图片优化

| 优化项 | 方案 |
|:---|:---|
| **格式** | 优先使用 WebP 格式（兼容性降级为 JPG/PNG） |
| **裁剪** | CDN 支持按需裁剪（指定宽高参数），不加载原图 |
| **压缩** | 上传时自动压缩至合理质量（80%），单张不超过 500KB |


### 三、圈子付费问答 + 音频连麦功能（补充至 4.2 圈子系统）

**功能说明**：成员可向圈主/嘉宾发起付费提问，圈主/嘉宾回答后获得收入。其他成员可付费围观答案。

| 功能点 | 说明 |
|:---|:---|

| **围观** | 已回答的问题可公开展示（默认匿名展示提问者）→其他成员支付较低围观价（如 10 币）查看答案 |

#### 3.2 音频连麦功能

**功能说明**：成员可与圈主/嘉宾进行一对一实时音频通话，按分钟计费。

| 功能点 | 说明 |

| **连麦定价** | 圈主/嘉宾自主设定每分钟价格（虚拟币，如 50 币/分钟 = ¥5/分钟） |
| **发起连麦** | 成员在圈主/嘉宾主页点击“连麦咨询”→选择预计时长（如 10 分钟）→系统预估费用→确认后扣减虚拟币→进入通话 |
| **通话中** | 实时显示已通话时长和已消费金额；通话中可文字发送补充信息 |
| **通话结束** | 按实际通话分钟数结算（不足1分钟按1分钟计）→自动扣减虚拟币→生成通话记录 |
| **余额不足** | 通话中余额即将耗尽时提前 1 分钟语音提示→自动挂断或引导充值续时 |
| **收益分配** | 圈主/嘉宾 70%、平台 30%（可配置） |
| **通话记录** | 双方均可查看历史通话记录（时长、费用、时间） |

### 四、虚拟币体系（新增独立章节）

#### 4.1 虚拟币定义

| 属性 | 说明 |
|:---|:---|
| **名称** | 暂定“国学币”或“热卜币”（可配置） |
| **与人民币比例** | **10:1**（10 币 = ¥1） |
| **最小充值单位** | ¥1 = 10 币 |
| **充值档位** | ¥6 = 60 币、¥18 = 180 币、¥68 = 680 币、¥198 = 1980 币、¥648 = 6480 币（档位可后台配置） |
| **有效期** | 永久有效，不清零 |
| **提现** | 不支持提现（虚拟币仅用于平台内消费） |
| **退款** | 虚拟币充值不支持退款（符合行业惯例）；因平台原因导致的服务失败可退等值虚拟币 |

#### 4.2 虚拟币充值

| 功能点 | 说明 |
|:---|:---|
| **充值入口** | 个人中心→我的钱包→充值；各支付场景余额不足时自动引导充值 |
| **支付方式** | 微信支付、支付宝 |
| **到账** | 支付成功后虚拟币**立即到账**，推送通知提醒 |
| **充值记录** | 用户可查看历史充值记录（金额、币数、时间） |

#### 4.3 虚拟币消费

| 功能点 | 说明 |
|:---|:---|
| **消费场景** | 付费入圈、付费提问、围观答案、音频连麦、直播打赏、智能体付费调用 |
| **消费确认** | 每次消费前弹出确认框，显示消费金额（币数）和折算人民币金额 |
| **消费记录** | 用户可查看历史消费记录（场景、币数、时间、对象） |
| **自动扣款** | 连麦等按时长计费场景，系统每分钟自动扣款，实时更新余额 |

#### 4.4 虚拟币安全

| 防护项 | 方案 |
|:---|:---|
| **防刷** | 充值回调必须验证签名；同一用户连续充值风控标记 |
| **防篡改** | 虚拟币余额仅存储在后端，前端不传递余额字段；消费操作后端直接扣减 |
| **事务一致性** | 虚拟币扣减与业务操作（如提问成功）在同一数据库事务中，防止扣币但服务未生效 |
| **审计日志** | 所有虚拟币变动全量记录（用户ID、变动类型、币数、余额、时间、关联订单号） |

#### 4.5 虚拟币在收入分配中的处理

| 场景 | 分配方式 |
|:---|:---|
| **虚拟币消费** | 用户消费的虚拟币，按对应场景的分佣比例，折算为人民币计入各角色收益账户 |
| **站长推广虚拟币消费** | 用户通过分站链接进入并进行虚拟币消费，站长按对应场景分佣比例获得人民币佣金 |
| **结算** | 各角色收益以人民币形式结算，虚拟币仅用于前端用户消费体验 |

| **paid_question** | 付费问答表 | id, circle_id, asker_id, answerer_id, question, answer, price_coin, peek_price_coin, status, created_at |

高并发与代码安全（补充 PRD 章节）
一、高并发架构要求
当前规模：600万用户，10万日活
目标承载：支持未来3-5年增长至千万级用户，峰值并发10万+

核心设计原则：水平扩展、无状态、分层缓存

1. 前后端分离，API 无状态
后端服务不存储用户会话状态

认证使用 JWT Token，每次请求携带

后端可水平扩展（加机器即可提升承载能力）

2. 多级缓存策略
缓存层级	技术选型	适用数据	过期策略
CDN缓存	腾讯云CDN	静态资源（图片、视频、小程序包）	按版本号更新
API网关缓存	Nginx/OpenResty	首页信息流热门内容、排盘结果公共部分	5-30分钟
应用层缓存	Redis	用户会话Token、临时推荐关系、排盘去重标记、分站品牌配置	按业务场景设定
数据库查询缓存	Redis	热门圈子信息、课程详情、商品详情	数据更新时主动失效
缓存更新策略：采用 Cache Aside 模式，数据库更新后主动删除缓存，下次查询时重建。

3. 数据库层面
读写分离：主库写、从库读，从库至少2个

连接池：使用 PgBouncer 管理数据库连接池，防止连接数爆炸

索引优化：高频查询字段必须建索引（已在数据模型章节标注）

分页查询：所有列表查询必须分页，禁止全量拉取

慢查询监控：接入慢查询日志，超过200ms的查询自动告警

4. 高并发场景特殊处理
场景	并发风险	解决方案
排盘计算	峰值时段大量用户同时排盘	排盘计算独立部署为微服务，可独立扩容；结果缓存（同参数排盘24h内返回缓存）
AI解析	调用DeepSeek/Coze API有速率限制	请求队列（Redis Queue）+ 限流器 + 缓存优先（同排盘+同分析类型24h内返回缓存）
直播观看	大量用户同时涌入直播间	使用腾讯云CDN分发，平台仅管理直播间状态；弹幕消息通过腾讯云IM处理
秒杀/拼团	瞬时流量洪峰	Redis库存预减 + 消息队列异步下单 + 防超卖校验
首页信息流	每次刷新都查询数据库	推荐结果预计算+缓存；首屏数据CDN边缘缓存
5. 限流与降级
接口限流：使用令牌桶算法，单用户同一接口调用频率限制（如排盘接口：非会员5次/天+可配置）

服务降级：高峰期自动关闭非核心功能（如历史排盘记录查询、数据看板），优先保证核心链路

熔断机制：第三方服务（腾讯云、Coze、DeepSeek）调用失败时自动熔断，返回兜底数据或友好提示

6. 异步处理
以下场景使用消息队列异步处理，不阻塞主流程：

订单支付回调后的积分发放

佣金分账计算

AI解析内容存储

用户行为数据埋点写入

推送通知发送

内容审核结果回调处理

消息队列选型：建议使用 Redis Stream（轻量）或 RabbitMQ

二、核心代码安全要求
核心资产识别：

排盘算法（八字、紫微等）：平台核心竞争力

AI解析逻辑（与DeepSeek交互的提示词）

分佣计算规则

推荐排序算法

用户敏感数据处理逻辑

1. 核心代码必须放后端
代码类型	存放位置	说明
排盘算法	🔒 仅后端，绝不放在前端或小程序包中	前端只传参数，后端计算后返回结果
AI解析提示词	🔒 仅后端，存储在环境变量或配置中心	前端不可见
分佣计算逻辑	🔒 仅后端，定时任务执行	前端只展示计算结果
推荐排序算法	🔒 仅后端，推荐服务独立部署	前端只接收排序后的内容列表
用户鉴权逻辑	🔒 仅后端，中间件层统一处理	前端只携带Token
2. 代码混淆与加密
后端代码：Node.js后端使用 javascript-obfuscator 混淆，部署前构建混淆包

前端代码：uni-app构建时自动压缩混淆，微信小程序端由平台自带加密

配置文件：数据库密码、API密钥、支付密钥等敏感配置必须使用环境变量，不得硬编码在代码中

3. API接口安全
身份校验：所有API（除登录/注册外）必须携带JWT Token，中间件统一校验

参数校验：所有入参使用Prisma/Zod进行类型和范围校验，防止恶意参数

频率限制：敏感接口（排盘、AI解析、支付）单用户调用频率限制

防重放：支付回调接口使用Nonce+Timestamp防重放攻击

HTTPS：全站强制HTTPS，杜绝明文传输

4. 数据安全
生辰信息（八字输入参数）：AES-256加密存储

手机号：脱敏展示（138****8888），存储时可选加密

密码/密钥：使用bcrypt/scrypt哈希存储，绝不存明文

数据库访问：后端使用最小权限的数据库账户，禁止root直接操作

5. 排盘服务独立部署（核心保护）
排盘算法作为平台核心竞争力，建议独立为微服务：

text
[前端] → [API网关] → [排盘微服务] → [Redis缓存]
                      ↓
                 [排盘算法模块]
                      ↓
                 [PostgreSQL]
独立部署：排盘服务与主业务服务隔离，可独立扩缩容

接口最小化：仅暴露计算接口，算法逻辑完全不对外

调用审计：每次排盘调用记录操作者、时间、IP，异常调用自动告警

代码隔离：排盘算法仓库与其他业务代码仓库独立，仅核心开发者有访问权限

6. 防逆向与防破解
小程序端：微信平台自带代码保护，前端不发核心逻辑

App端：uniapp打包时开启代码混淆，核心逻辑一律走后端API

H5端：前端代码混淆，核心计算不在浏览器执行

API响应：返回给前端的排盘结果不包含中间计算过程，仅返回最终结果
