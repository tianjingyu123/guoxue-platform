## 热卜国学平台 · AI技术应用需求文档 V1.0

> **文档定位**：平台AI能力的系统规划与开发需求  
> **适用对象**：Claude Code  
> **核心原则**：**内容有人味儿（AI仅辅助），管理少用人（AI自动化+可监控）**


### 一、总体设计原则

| 原则 | 说明 |
|:---|:---|
| **AI辅助创作，不替代创作** | 用户始终是内容的创造者，AI只提供建议、润色、优化，不主动生成发布内容。平台禁止“AI全自动生成并发布”的行为 |
| **管理自动化，人只做决策** | 重复性审核、分类、统计等管理工作尽量由AI完成，人工只处理AI无法判断的异常和关键决策 |
| **可监控、可纠正** | 所有AI行为和输出结果必须可追溯、可审计。运营人员可在后台随时查看AI做了什么，并可手动纠正 |
| **有人情味的知识平台** | AI生成的内容必须标注“AI辅助”标签，让用户清楚知道哪些是人的智慧、哪些是AI的辅助。鼓励真人创作，AI退居幕后 |

| **人不做什么** | AI不自动修改原文，不自动发布。用户必须手动确认是否采纳建议 |

## 《AI技术应用需求文档 V1.0》补充章节：多模型可配置路由体系


### 一、设计目标

平台不同的AI应用场景，需要匹配不同能力的大模型。系统必须支持**每个场景独立配置使用哪个大模型**，且后期可随时调整，无需改动业务代码。

**为什么不能一个模型通吃：**

| 场景类型 | 模型需求 | 适合的模型类型 | 为什么 |
|:---|:---|:---|:---|
| **文本推理/分析**（圈主助理、智能客服、搜索总结） | 强推理、长上下文、中文能力强 | DeepSeek V4 Pro | 推理能力强，成本低，中文语境最优 |
| **多模态识别**（图片内容审核、视频标签识别） | 视觉理解、OCR、视频帧分析 | DeepSeek多模态模型、GPT-5.x多模态版 | 能"看见"图片内容，识别文字和场景 |
| **封面图生成**（AI封面图建议） | 文生图、风格可控、国风素材丰富 | 国产绘图模型（如文心一格、通义万相） | 国风素材丰富，成本可控 |
| **语音转文字**（课程笔记、连麦字幕） | 高准确率ASR、支持方言 | 阿里云/腾讯云ASR、Whisper | 中文识别率高，行业成熟 |
| **文字转语音**（AI听书、语音播报） | 自然发音、多音色、情感表达 | 腾讯云TTS | 多种音色可选，国学场景适配 |
| **文案生成/润色**（标题优化、脚本生成） | 创意能力强、语言流畅 | DeepSeek V4 Pro 或 豆包 | 中文创意写作表现好 |


### 二、多模型路由架构设计

**2.1 统一AI网关**

所有AI场景不直接调用具体的模型API，而是通过平台的统一AI网关 `/api/v1/ai/{场景名}` 进行调用。网关层负责根据后台配置，将请求路由到对应的大模型。

```
前端业务代码
      ↓
/api/v1/ai/search      /api/v1/ai/customer_service     /api/v1/ai/cover_gen
      ↓                        ↓                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                      统一 AI 网关 (Model Router)                 │
│  1. 根据场景名查配置 → 获取对应模型                                │
│  2. 转换请求格式 → 适配不同模型API                                │
│  3. 路由请求 → 调用目标模型                                       │
│  4. 统一日志记录 → 调用量/延迟/费用/成功率                        │
└─────────────────────────────────────────────────────────────────┘
      ↓                        ↓                              ↓
 DeepSeek V4 Pro          扣子 API                    通义万相 API
（文本推理）            （智能体广场）                （封面图生成）
```

**核心优势**：
- 业务代码只调用自家网关，不绑定任何模型厂商
- 模型更换时，只需在后台修改配置，无需改动业务代码或前端
- 可按时段、按任务类型、按成本预算自动选择合适的模型
- 按任务复杂度动态调度至轻量/旗舰模型，实践后可降低约60%的成本

### 三、运营后台配置界面

在运营后台「系统设置 → AI模型配置」模块，提供可视化的模型配置界面：

**3.1 场景-模型映射表**

| 配置项 | 说明 | 示例 |
|:---|:---|:---|
| **场景名称** | 对应业务场景标识 | `circle_assistant`（圈主助理） |
| **默认模型** | 该场景首选的大模型 | `deepseek-v4-pro` |
| **模型提供商** | API提供方 | `deepseek` |
| **Temperature** | 生成随机性 | `0.3`（精确）/ `0.5`（均衡）/ `0.8`（创意） |
| **最大Token数** | 单次回答长度上限 | `2048` |
| **备用模型** | 主模型异常时自动切换 | `deepseek-v3` |
| **优先级** | 调用优先顺序 | `1`（最优先） |
| **状态** | 启用/停用 | `启用` |

**3.2 支持的操作**
- 新增场景-模型映射
- 修改已有场景的模型配置
- 停用/启用某个场景的AI能力
- 查看每个模型的调用统计（调用量、延迟、费用、成功率）
- 批量导入/导出配置


### 四、模型切换与故障转移机制

**4.1 主备切换**
- 当主模型（如 DeepSeek V4 Pro）调用失败或超时（如超过5秒），自动切换到备用模型（Fallback Model）
- 切换后记录日志，运营后台可查看切换原因和频率
- 通过智能 Fallback 机制，可实现 SLA 级别的容灾，确保业务连续性

**4.2 灰度切换**
- 支持按一定流量比例（如10%用新模型，90%用旧模型），测试新模型效果
- 效果达标后逐步提升新模型流量比例，直至全量切换
- 灰度期间可随时回滚

**4.3 时段路由**
- 支持按不同时段配置不同模型。例如：
  - 高峰期（19:00-23:00）：使用成本较低的模型（如 DeepSeek V3）分流
  - 非高峰期：使用旗舰模型（如 DeepSeek V4 Pro）

**4.4 成本预算控制**
- 按场景设置月度Token预算上限
- 超出预算时自动降级到轻量模型
- 通过网关层的“模型路由+订阅配额管理”，实践后可降低约60%的Token成本


### 五、模型选择决策矩阵

以下帮助你快速判断每个场景应该选择什么类型的模型：

| 判断维度 | 决策方向 |
|:---|:---|
| **任务类型** | 文本理解/推理→DeepSeek；图像理解→多模态模型；图像生成→文生图模型；语音→ASR/TTS |
| **响应速度要求** | 实时对话→低延迟模型（如DeepSeek V4 Pro）；异步任务→可用批量处理降低成本 |
| **输出质量要求** | 核心业务→旗舰模型（如DeepSeek V4 Pro）；辅助功能→轻量模型（如DeepSeek V3） |
| **成本预算** | 高频调用→选择性价比最高的模型（如DeepSeek V3）；低频调用→可用旗舰模型 |
| **数据安全** | 涉及用户隐私→必须走自研API网关，不直接调用第三方；非敏感→灵活选择 |


### 六、给 Claude Code 的技术实现要求

1. **统一AI网关中间件**：在Node.js后端实现 `ModelRouter` 中间件，根据 `config_system` 中的配置自动路由请求到对应模型
2. **模型适配器模式**：每个模型厂商（DeepSeek/阿里云/腾讯云/Coze）实现独立的Adapter，负责请求格式转换和响应解析
3. **故障转移**：主模型失败时自动切换备用模型，记录切换日志
4. **调用全量日志**：每次模型调用记录：场景名、模型名、请求Token数、响应Token数、延迟、费用、成功/失败状态
5. **后台配置界面**：提供可视化的模型配置页面，支持增删改查、灰度切换、主备设置
6. **成本监控告警**：按场景设置月度Token预算，超出阈值自动告警并可自动降级为轻量模型

## AI智能体技术选型与搭建方案

> 本章节明确平台所有AI应用场景的技术选型、实现路径和搭建思路，以及圈主助理知识库的精细化管理机制。

### 十、总体架构原则：双轨制

平台AI采用**双轨制**架构：

| 轨 | 适用场景 | 技术方案 | 核心逻辑 |
|:---|:---|:---|:---|
| **自研轨** | 核心AI能力（圈主助理/智能客服/智能搜索/古籍问答） | 自建向量数据库 + 自研RAG + 大模型API | 数据在自己服务器，直接调大模型，不走第三方平台 |
| **扣子轨** | 灵活AI应用（智能体广场/站长助理） | Coze API + Coze知识库 | 低代码快速搭建，通过API接入平台 |

**核心判断原则**：如果该AI功能涉及平台核心知识资产（圈内内容、课程信息、排盘知识等），且需要严格的数据隔离和低成本高频调用，走自研轨。如果该功能是创意型、玩法型、需要快速迭代验证的，走扣子轨。

### 十一、技术选型决策矩阵

| 应用场景 | 选型 | 核心理由 |
|:---|:---|:---|
| **圈主助理** | 🏠 自研 | 圈子专属知识库，需严格数据隔离，每个圈子独立。未来圈子可能达几千甚至几万个，必须摆脱Coze知识库数量上限（单智能体最多绑定150个） |
| **智能客服** | 🏠 自研 | 回答全部基于平台知识库，高频调用，自研可大幅降低API费用。用户生辰等敏感信息不出服务器 |
| **智能搜索** | 🏠 自研 | 需检索全平台结构化数据（课程/圈子/商品/文章），搜索结果页是独立页面+内容列表，非对话框模式，Coze无法承载此交互 |
| **智能体广场** | 🧩 扣子 | 创意玩法型应用（如"八字脱口秀"、"宝宝起名大师"），需求灵活多变，需快速验证和迭代。扣子零代码搭建，半小时可上线一个 |
| **站长助理** | 🧩 扣子 | 本质是文案生成器，功能相对独立，不需要深度绑定平台知识库 |
| **AI古籍智能问答** | 🏠 自研 | 国学经典知识库是平台核心资产，需自建向量库精细化管理 |
| **AI封面图生成** | 🏠 自研 | 需调用专门文生图模型（通义万相），通过AI网关路由 |
| **AI内容审核(图片)** | 🏠 自研 | 需多模态模型，通过AI网关路由至DeepSeek多模态 |
| **AI语音转文字** | 🏠 自研 | 调用腾讯云ASR，通过AI网关路由 |
| **AI文字转语音** | 🏠 自研 | 调用腾讯云TTS，通过AI网关路由 |

### 十二、自研RAG方案实现架构

```
前端页面（圈主助理对话窗口 / 搜索框 / 智能客服弹窗）
        ↓
平台的统一 AI 网关（/api/v1/ai/{场景名}）
        ↓
┌─────────────────────────────────────────┐
│              AI 网关层                    │
│  1. 鉴权、限流、日志                       │
│  2. 根据场景名 + 配置表 → 路由到对应后端     │
│  3. 格式转换、Fallback 处理               │
└─────────────────────────────────────────┘
        ↓                         ↓
┌───────────────┐          ┌──────────────┐
│  自研 RAG 服务  │          │  Coze API    │
│  (核心AI能力)  │          │  (智能体广场)  │
└───────────────┘          └──────────────┘
        ↓
┌─────────────────────────────────────────┐
│           自研 RAG 服务内部                │
│  1. 向量数据库（pgvector / Milvus）       │
│     - 圈子专属知识库（按circle_id隔离）     │
│     - 平台公共知识库                       │
│  2. 检索模块（向量检索 + 全文检索）         │
│  3. Prompt 模板引擎                       │
│  4. 文档处理管道（PDF/Word/Excel/图片解析） │
└─────────────────────────────────────────┘
```

**向量数据库选型**：初期使用 pgvector（基于现有 PostgreSQL，零额外运维成本）。后期数据量达千万级向量时可平滑迁移至 Milvus。

**圈主助理知识库隔离方案**：用户提问时，系统根据 `circle_id` 在对应圈子的向量空间内检索，绝不跨越到其他圈子。同时并行检索平台公共知识库，两部分结果合并后发给大模型。

### 十三、圈主助理知识库精细化管理机制

#### 13.1 知识库内容来源与处理规则

| 内容来源 | 入库方式 | 去重规则 | 圈主权限 |
|:---|:---|:---|:---|
| **圈主发布的文章** | 自动入库 | 系统自动去重 | 可在知识库管理中移除 |
| **圈主发布的课程** | 自动入库 | 系统自动去重 | 可在知识库管理中移除 |
| **精华帖**（圈主设为精华） | 自动入库 | 系统自动去重 | 可在知识库管理中移除 |
| **热门帖**（点赞≥阈值，可配置） | **候选入库**，需圈主确认 | 确认时系统自动去重 | 手动选择是否加入 |
| **嘉宾/成员发布的帖子** | **手动入库**，圈主点击"添加到知识库" | 点击时自动去重 | 完全掌控，可随时移除 |
| **圈主手动投喂**（上传文件） | 实时入库 | 自动去重 | 可随时移除 |
| **通用知识库**（平台级） | 平台统一维护 | - | 无权修改 |

#### 13.2 去重机制

| 去重类型 | 判断方式 | 处理规则 |
|:---|:---|:---|
| **完全重复** | 内容哈希值（MD5）完全相同 | 直接拒绝录入，提示"该内容已存在于知识库中" |
| **高度相似** | 向量相似度 ≥ 90%（阈值可配置） | 标记为"疑似重复"，推送圈主判断：覆盖旧内容 / 保留旧内容 / 两者都保留 |
| **低相似度** | 向量相似度 < 90% | 正常录入 |

**技术实现**：内容哈希存储于 `content_hash` 字段并建唯一索引；向量相似度使用 pgvector 余弦相似度计算（异步处理，避免阻塞入库）。

#### 13.3 圈主审核与管理权限

圈主是圈主助理知识库的唯一管理者，拥有以下权限：

| 权限 | 说明 | 操作入口 |
|:---|:---|:---|
| **添加到知识库** | 对任何圈内内容可手动加入 | 帖子/文章详情页"..."菜单 |
| **从知识库移除** | 已入库内容可移除 | 圈子管理后台 → 知识库管理 |
| **查看知识库内容** | 已入库内容列表 | 圈子管理后台 → 知识库管理 |
| **查看待确认内容** | "疑似重复"或"候选入库"内容 | 圈子管理后台 → 待确认列表 |
| **配置自动入库规则** | 热门帖点赞阈值、是否自动将精华帖入库 | 圈子管理后台 → 知识库设置 |

#### 13.4 "添加到知识库"按钮展示逻辑

| 内容类型 | 按钮展示位置 | 展示条件 |
|:---|:---|:---|
| 圈主自己的文章/课程 | 发布时自动入库，不展示按钮 | - |
| 精华帖 | 设为精华时自动入库，不展示按钮 | - |
| 热门帖（点赞≥阈值） | 帖子详情页"..."菜单 | 未入库显示"添加到知识库"；已入库显示"已加入知识库 ✓" |
| 嘉宾/成员帖子 | 同上 | 同上 |
| 任何已入库内容 | 同上 | 圈主可见"从知识库移除" |

#### 13.5 知识库内容同步服务

| 同步来源 | 同步方式 | 去重处理 |
|:---|:---|:---|
| 圈主发布文章 | 发布时即时同步 | 自动去重后直接入库 |
| 圈主发布课程 | 发布/更新时即时同步 | 自动去重后直接入库 |
| 精华帖 | 设为精华时即时同步 | 自动去重后直接入库 |
| 热门帖（达阈值） | 每日定时扫描 | 自动去重后进入**候选列表**，待圈主确认 |
| 嘉宾/成员帖子 | 圈主点击"加入知识库"时触发 | 自动去重，圈主手动确认 |
| 圈主手动投喂 | 上传时即时解析 | 自动去重后直接入库 |

### 十四、扣子的定位与使用边界

**扣子负责**：智能体广场上的所有AI应用（如获客文案生成器、报告工厂、开运好物推荐官、白标AI助手等）+ 站长助理。

**接入方式**：在 Coze 平台为每个智能体创建独立 Bot → 平台后端通过 Coze API 调用 → 流式响应通过 AI 网关转发前端（前端不直接调用 Coze API，避免暴露密钥）。

**扣子限制认知**：
- 单个低代码智能体最多可绑定 150 个知识库
- 基础版知识库空间仅 1GB，专业版默认 10GB
- 基础版每个工作流每天最多试运行 500 次

CREATE TABLE circle_knowledge (
  id BIGSERIAL PRIMARY KEY,
  circle_id BIGINT NOT NULL,          -- 所属圈子ID
  source_type VARCHAR(30) NOT NULL,   -- 来源类型：article/post/course/file/manual
  source_id BIGINT,                   -- 来源内容ID
  content TEXT NOT NULL,              -- 知识库文本内容
  content_hash VARCHAR(64) NOT NULL,  -- 内容MD5哈希值，用于去重
  vector_id BIGINT,                   -- 向量数据库中对应的向量ID
  status VARCHAR(20) DEFAULT 'active', -- active/removed/pending
  added_by BIGINT,                    -- 添加人ID（圈主ID或系统自动）
  added_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(content_hash, circle_id)     -- 同一圈子内内容哈希唯一
);

-- 圈主手动选择入库记录表
CREATE TABLE circle_knowledge_manual (
  id BIGSERIAL PRIMARY KEY,
  circle_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,            -- 操作人（圈主）
  target_type VARCHAR(30) NOT NULL,   -- 目标类型：post/article
  target_id BIGINT NOT NULL,          -- 目标ID
  action VARCHAR(20) NOT NULL,        -- add / remove
  created_at TIMESTAMP DEFAULT NOW()
);

-- 知识库候选内容表（待圈主确认）
CREATE TABLE circle_knowledge_candidate (
  id BIGSERIAL PRIMARY KEY,
  circle_id BIGINT NOT NULL,
  source_type VARCHAR(30) NOT NULL,
  source_id BIGINT,
  content TEXT NOT NULL,
  content_hash VARCHAR(64) NOT NULL,
  similarity_score DECIMAL(5,4),      -- 与已有内容的最高相似度
  similar_to_id BIGINT,               -- 疑似重复的目标内容ID
  status VARCHAR(20) DEFAULT 'pending', -- pending/confirmed/rejected
  created_at TIMESTAMP DEFAULT NOW()
);
