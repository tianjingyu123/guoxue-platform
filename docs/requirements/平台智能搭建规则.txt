## 给 Claude Code 的指令：AI智能体技术选型与搭建方案（完整版）


请仔细阅读以下内容，并在现有需求文档中补充「AI智能体技术选型与搭建」章节。以下内容明确了平台所有AI应用场景的技术选型、实现路径和搭建思路，以及圈主助理知识库的精细化管理机制。

### 一、总体架构原则：双轨制

平台AI采用**双轨制**架构：

| 轨 | 适用场景 | 技术方案 | 核心逻辑 |
|:---|:---|:---|:---|
| **自研轨** | 核心AI能力 | 自建向量数据库 + 自研RAG + 大模型API | 数据在自己服务器，直接调大模型，不走第三方平台 |
| **扣子轨** | 灵活AI应用 | Coze API + Coze知识库 | 低代码快速搭建，通过API接入平台 |


### 二、技术选型决策矩阵

**核心判断原则**：如果该AI功能涉及平台核心知识资产（圈内内容、课程信息、排盘知识等），且需要严格的数据隔离和低成本高频调用，走自研轨。如果该功能是创意型、玩法型、需要快速迭代验证的，走扣子轨。

| 应用场景 | 选型 | 核心理由 |
|:---|:---|:---|
| **圈主助理** | 🏠 自研 | 圈子专属知识库，需要严格数据隔离，每个圈子的知识库独立。未来圈子可能达到几千甚至几万个，必须摆脱Coze知识库数量上限（单智能体最多绑定150个知识库） |
| **智能客服** | 🏠 自研 | 回答全部基于平台知识库，高频调用，自研可大幅降低API费用。用户生辰等敏感信息不出服务器 |
| **智能搜索** | 🏠 自研 | 需检索全平台结构化数据（课程/圈子/商品/文章），搜索结果页是独立页面+内容列表，非对话框模式。Coze无法承载这种交互 |
| **智能体广场** | 🧩 扣子 | 创意玩法型应用（如"八字脱口秀"、"宝宝起名大师"），需求灵活多变，需要快速验证和迭代。扣子零代码搭建，半小时可上线一个 |
| **站长助理** | 🧩 扣子 | 本质是文案生成器，功能相对独立，不需要深度绑定平台知识库。扣子现有模板可直接使用 |
| **AI封面图生成** | 🏠 自研 | 需要调用专门的文生图模型（如通义万相），通过AI网关路由至对应模型 |
| **AI内容审核(图片)** | 🏠 自研 | 需要多模态模型，通过AI网关路由至DeepSeek多模态模型或GPT-5.x Vision |
| **AI语音转文字** | 🏠 自研 | 调用腾讯云ASR，通过AI网关路由 |
| **AI文字转语音** | 🏠 自研 | 调用腾讯云TTS，通过AI网关路由 |


### 三、自研RAG方案的实现架构

**3.1 整体架构**

```
前端页面（圈主助理对话窗口 / 搜索框 / 智能客服弹窗）
        ↓
平台的统一 AI 网关（/api/v1/ai/{场景名}）
        ↓
┌─────────────────────────────────────────┐
│              AI 网关层                    │
│  1. 鉴权、限流、日志                       │
│  2. 根据场景名 + 配置表 → 路由到对应后端     │
│  3. 格式转换、Fallback 处理               │
└─────────────────────────────────────────┘
        ↓                         ↓
┌───────────────┐          ┌──────────────┐
│  自研 RAG 服务  │          │  Coze API    │
│  (核心AI能力)  │          │  (智能体广场)  │
└───────────────┘          └──────────────┘
        ↓
┌─────────────────────────────────────────┐
│           自研 RAG 服务内部                │
│  1. 向量数据库（Milvus / pgvector）       │
│     - 圈子专属知识库（按circle_id隔离）     │
│     - 平台公共知识库                       │
│  2. 检索模块（向量检索 + 全文检索）         │
│  3. Prompt 模板引擎                       │
│  4. 文档处理管道（PDF/Word/Excel/图片解析） │
└─────────────────────────────────────────┘
```

**3.2 圈主助理的知识库隔离方案**

圈主助理是最复杂的场景。需要为每个圈子建立独立的知识库，且严格隔离（绝不能串台）。

**方案：一个主智能体 + 多个圈子专属向量库（命名空间隔离）**

- **向量数据库层**：使用 Milvus 或 pgvector，为每个圈子创建独立的集合（Collection）或分区（Partition）。每个圈子有唯一的 `circle_id`，作为向量数据的命名空间标识。
- **检索层**：用户提问时，系统根据 `circle_id` 在对应圈子的向量空间内检索，绝不跨越到其他圈子。同时并行检索平台公共知识库（通用帮助文档等），两部分结果合并后发给大模型。
- **大模型层**：通过统一AI网关调用 DeepSeek V4 Pro，将检索到的知识和用户问题组合成 Prompt，生成最终回答。属于同一个主智能体的"大脑"，但每次检索的知识库内容不同。


### 四、圈主助理知识库精细化管理机制

#### 4.1 知识库内容来源与处理规则

圈主助理的知识库由以下来源组成，每个来源有不同的处理规则：

| 内容来源 | 入库方式 | 去重规则 | 圈主权限 |
|:---|:---|:---|:---|
| **圈主发布的文章** | 自动入库 | 系统自动去重（同内容不重复录入） | 圈主可在知识库管理中移除 |
| **圈主发布的课程** | 自动入库 | 系统自动去重 | 圈主可在知识库管理中移除 |
| **精华帖**（圈主设为精华） | 自动入库 | 系统自动去重 | 圈主可在知识库管理中移除 |
| **热门帖**（点赞≥阈值，圈主可配置） | **候选入库**，需圈主确认 | 圈主确认时系统自动去重 | 圈主手动选择是否加入 |
| **嘉宾/成员发布的帖子** | **手动入库**，圈主点击"添加到知识库" | 点击时系统自动去重 | 圈主完全掌控，可随时移除 |
| **圈主手动投喂**（上传文件） | 实时入库 | 系统自动去重 | 圈主可随时移除 |
| **通用知识库**（平台级） | 平台统一维护 | - | 圈主无权修改 |

#### 4.2 去重机制设计

**4.2.1 去重维度**

| 去重类型 | 判断方式 | 处理规则 |
|:---|:---|:---|
| **完全重复** | 内容哈希值（MD5）完全相同 | 直接拒绝录入，提示"该内容已存在于知识库中" |
| **高度相似** | 向量相似度 ≥ 90%（阈值可配置） | 标记为"疑似重复"，展示已有内容和待录入内容供圈主判断。圈主确认后：覆盖旧内容（以新为准）/ 保留旧内容（拒绝新内容）/ 两者都保留（圈主手动标注差异） |
| **低相似度** | 向量相似度 < 90% | 正常录入 |

**4.2.2 去重流程**

```
内容提交（自动/手动）
      ↓
  计算内容哈希值（MD5）
      ↓
┌───┴───┐
│ 哈希值已存在？ │
└───┬───┘
    ↓是          ↓否
 直接拒绝     计算与已有内容的向量相似度
 提示重复           ↓
            ┌──────┴──────┐
            │ 相似度 ≥ 90%？ │
            └──────┬──────┘
              ↓是          ↓否
          标记"疑似重复"   正常录入
          推送给圈主判断
```

**4.2.3 去重的技术实现**

- 内容哈希：对文本内容取 MD5，存储在知识库表的 `content_hash` 字段中，建唯一索引
- 向量相似度：使用 pgvector 的余弦相似度或欧氏距离计算，阈值可配置
- 异步处理：高相似度判断改为异步任务执行，避免阻塞入库流程

#### 4.3 圈主审核与管理权限

**4.3.1 圈主的专属权限**

圈主是圈主助理知识库的唯一管理者，拥有以下专属权限：

| 权限 | 说明 | 操作入口 |
|:---|:---|:---|
| **添加到知识库** | 对于任何圈内内容（帖子/文章/评论），圈主可见"添加到知识库"按钮 | 帖子详情页、文章详情页的"..."菜单中 |

| **查看知识库内容** | 查看知识库中所有已入库内容的列表 | 圈子管理后台 → 知识库管理 |
| **查看待确认内容** | 查看系统自动推送的"疑似重复"或"候选入库"内容 | 圈子管理后台 → 知识库管理 → 待确认列表 |
| **配置自动入库规则** | 设置热门帖的点赞阈值、是否自动将精华帖加入知识库等 | 圈子管理后台 → 知识库设置 |

**4.3.2 "添加到知识库"按钮的展示逻辑**

| 内容类型 | 按钮展示位置 | 展示条件 |
|:---|:---|:---|
| 圈主自己发布的文章 | 文章发布时自动入库，不展示按钮 | - |
| 圈主自己发布的课程 | 课程发布时自动入库，不展示按钮 | - |
| 精华帖 | 设为精华时自动入库，不展示按钮 | - |
| 热门帖（点赞≥阈值） | 帖子详情页"..."菜单 + 圈子内容列表长按菜单 | 圈主可见；内容尚未入库时显示"添加到知识库"；已入库时显示"已加入知识库 ✓" |
| 嘉宾/成员发布的帖子 | 同上 | 同上 |
| 任何已入库内容 | 同上 | 圈主可见"从知识库移除" |

**4.3.3 圈主审核工作流**

```
圈主进入知识库管理后台
      ↓
┌─────────────────┐
│  知识库内容列表   │  ← 已入库内容，支持搜索、筛选、移除
└─────────────────┘
      ↓
┌─────────────────┐
│  待确认内容列表   │  ← 系统自动推送的候选内容和疑似重复内容
│  - 候选入库内容   │     圈主可逐条确认或批量确认
│  - 疑似重复内容   │     圈主可选择覆盖/保留/双保留
└─────────────────┘
      ↓
┌─────────────────┐
│  知识库设置      │  ← 配置自动入库规则
```

基于以上规则，知识库同步服务需做以下调整：

### 五、扣子的定位与使用边界

**5.1 扣子负责什么**

- 智能体广场上的所有AI应用（如"获客文案生成器"、"报告工厂"、"开运好物推荐官"、"白标AI助手"等）。
- 站长助理（推广文案生成）。
- 这些应用的特点是：功能相对独立、不深度绑定平台核心数据、需要灵活配置和快速上线。

**5.2 扣子的接入方式**

- 在 Coze 平台上为每个智能体创建独立的 Bot。
- 平台后端通过 Coze API 调用这些 Bot，前端展示对话界面。
- Coze 返回的流式响应通过平台AI网关转发给前端，前端不直接调用 Coze API（避免暴露密钥）。

**5.3 扣子的限制认知**

- 单个个人用户或企业成员最多可创建 1000 个知识库。(该限制指按用户维度计算的总知识库数量上限，而非按空间计)
- 单个低代码智能体最多可绑定 150 个知识库。
- 基础版知识库空间仅 1GB，不支持扩容，专业版默认 10GB。
- 基础版每个工作流每天最多试运行 500 次。

### 八、给 Claude Code 的具体开发要求

1. **统一AI网关**：在Node.js后端实现 `ModelRouter` 中间件，所有AI调用统一走 `/api/v1/ai/{场景名}`。根据 `config_system` 表中的模型配置自动路由。

2. **向量数据库选型**：作为起步方案，建议先使用 pgvector（基于现有PostgreSQL，零额外运维成本，适合初期数据量级）。若后期数据量达到千万级向量，可平滑迁移至 Milvus。

3. **知识库同步服务**：编写定时任务，每天扫描开通圈主助理的圈子，自动同步精华帖、热门帖、文章、课程到向量数据库。热门帖和嘉宾内容进入候选列表，推送给圈主确认。

4. **去重机制实现**：在知识库表中增加 `content_hash` 字段（MD5哈希值，建唯一索引）。编写向量相似度计算逻辑（pgvector余弦相似度），阈值 0.9 可配置。疑似重复内容推送圈主判断，圈主可选择覆盖/保留/双保留。

5. **圈主审核后台**：在圈子管理后台中增加"知识库管理"模块，包含：已入库内容列表（支持搜索、筛选、移除）、待确认内容列表（候选入库 + 疑似重复）、知识库设置（热门帖阈值、自动入库规则）。

6. **"添加到知识库"按钮**：在帖子详情页、文章详情页的"..."菜单中增加"添加到知识库"按钮，仅圈主可见。已入库内容显示"已加入知识库 ✓"，点击可移除。新增 `circle_knowledge_manual` 表，记录圈主手动选择入库的内容。

7. **RAG检索模板**：定义标准Prompt模板：`你是一个名为"圈主助理"的AI助手，专注于回答关于本圈子的内容。请根据以下知识库内容回答问题。如果知识库中没有相关信息，请如实告知。\n\n知识库内容：\n{检索结果}\n\n用户问题：{question}`。

8. **Coze Bot管理**：编写Coze Bot的统一管理服务，负责创建、更新、删除Bot，以及同步知识库内容到Coze。

9. **全量日志**：所有AI调用记录全量日志，包括场景名、模型名、Token消耗、延迟、费用、成功/失败状态。


### 九、数据库补充表设计

在原有Prisma Schema基础上，增加知识库管理相关表：

```sql
-- 圈主助理知识库内容表
CREATE TABLE circle_knowledge (
  id BIGSERIAL PRIMARY KEY,
  circle_id BIGINT NOT NULL,          -- 所属圈子ID
  source_type VARCHAR(30) NOT NULL,   -- 来源类型：article/post/course/file/manual
  source_id BIGINT,                   -- 来源内容ID
  content TEXT NOT NULL,              -- 知识库文本内容
  content_hash VARCHAR(64) NOT NULL,  -- 内容MD5哈希值，用于去重
  vector_id BIGINT,                   -- 向量数据库中对应的向量ID
  status VARCHAR(20) DEFAULT 'active', -- active/removed/pending
  added_by BIGINT,                    -- 添加人ID（圈主ID或系统自动）
  added_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(content_hash, circle_id)     -- 同一圈子内内容哈希唯一
);

-- 圈主手动选择入库记录表
CREATE TABLE circle_knowledge_manual (
  id BIGSERIAL PRIMARY KEY,
  circle_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,            -- 操作人（圈主）
  target_type VARCHAR(30) NOT NULL,   -- 目标类型：post/article
  target_id BIGINT NOT NULL,          -- 目标ID
  action VARCHAR(20) NOT NULL,        -- add / remove
  created_at TIMESTAMP DEFAULT NOW()
);

-- 知识库候选内容表（待圈主确认）
CREATE TABLE circle_knowledge_candidate (
  id BIGSERIAL PRIMARY KEY,
  circle_id BIGINT NOT NULL,
  source_type VARCHAR(30) NOT NULL,
  source_id BIGINT,
  content TEXT NOT NULL,
  content_hash VARCHAR(64) NOT NULL,
  similarity_score DECIMAL(5,4),      -- 与已有内容的最高相似度
  similar_to_id BIGINT,               -- 疑似重复的目标内容ID
  status VARCHAR(20) DEFAULT 'pending', -- pending/confirmed/rejected
  created_at TIMESTAMP DEFAULT NOW()
);
```
