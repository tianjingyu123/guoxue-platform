# AI 协作运营闭环增量审计（2026-09-02）

## 范围与隔离

本批基于 `f2d993c5a127cb42d46a45bb5d3baabe24889dda`（上游 `f380c5e8dfecdceb3e654781d900a7f328cbb8f2`），只处理后台 AI 协作、决策账本与运营巡检。使用独立工作树，不改客户端、登录支付、排盘、数据库结构、依赖锁或部署资源；没有执行云端写入或预发布业务写验收。

## 已修复

| 缺口 | 本批处理与验收边界 |
| --- | --- |
| 提案创建、人工审核、效果回收与决策账本分步写入 | 使用同一 Prisma 事务；状态条件写入防并发覆盖；账本独立入口禁止单独处理协作关联决策 |
| 回滚未抢占，重复点击可能重复运行 | 原子进入 `rolling_back`；失败进入 `rollback_failed` 保留原证据，不自动重试；强制记录回滚原因 |
| 真实动作成功后通知失败会被误记为执行失败 | 业务状态与事件通知分离；通知失败留错误日志，不覆盖真实执行成功状态 |
| 未执行也能评分，自动化可自行验收 | 只接受完成后的整数评分；首次反馈原子写入并同步账本；反馈与通用协作执行增加真人红线守卫 |
| 协作没有生产执行器 | 注册 `ops.run_inspection`；仅接受低风险且仅有 `handlerKey` 的计划；执行五项诊断、生成报告和人工待办，不通过此入口修复聚合或执行任意命令 |
| 手动巡检与定时巡检可能重叠 | 共用 `ops-inspection` 分布式互斥锁，锁不可用不降级并发执行 |
| 页面只有状态，缺乏可操作验收 | 提供反馈表单、审核备注、验收人、执行证据、失败/回滚状态；诊断结果使用中文摘要，技术证据折叠；关联账本引导回协作页 |
| 模型置信度容易被误当成准确性 | 明示只是自评置信度，不代表准确率或实际效果，不作为自动切换模型依据 |

### 自动化的真实边界

- 本批没有把通用协作执行接口改为无人审批入口。低风险高置信度仍只是自动批准；执行必须由真人超管触发、且存在真实白名单处理器。
- 已有每日巡检调度仍可按 `automation_enabled` 对原两项聚合白名单进行补跑；本批协作处理器显式设置 `allowAutoFix: false`。
- 巡检是规则驱动自动化，不应宣传成模型已经具备自主经营能力。发现异常、生成报告，不等于异常已经解决。
- 巡检报告不是业务变更，没有可撤销的业务效果，因此不伪造回滚能力。
