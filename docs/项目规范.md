# 项目规范（总纲）

> 本规范是项目的最高治理文件。任何人（包括不同 V0 账号、Claude Code、后续协作者）
> 在本项目新增页面、改造功能、迁移代码时，**必须遵循本规范**，以保证产出质量与风格的长期一致。
> 核心目标：**让同样的高质量结果可被任何人、在任何时候、稳定复现。**

## 一、项目结构约定（强制）

项目永远保持「**一个原型文件夹 + 一个 Vue3 文件夹**」的双轨结构：

```
项目根/
├─ prototype/        # React/Next.js 高保真原型（设计与交互的唯一真相来源 SSOT）
├─ vue3/             # uni-app 全端工程（最终交付物，从 prototype 1:1 高保真转化而来）
└─ docs/             # 规范、流程、经验、对接说明（本目录，跨两端共享）
```

> 说明：当前仓库根即为 `prototype/` 的内容（历史原因）。正式启动 Vue3 时，
> 按 `06-工程结构迁移说明` 将原型归入 prototype/，新建 vue3/。在此之前，原型 = 仓库根。

**铁律**：
- 原型（prototype）是**设计与交互的唯一真相来源**。任何视觉/交互标准以原型为准。
- Vue3 是转化产物，**必须 100% 高保真还原原型**，不得自由发挥。
- 新增功能时：**先在原型实现并验收 → 再按标准流程转化到 Vue3**。两端始终对应。
- docs/ 跨两端共享，是经验与规范的沉淀地，只增不弃。

## 三、设计规范（高保真红线）

1. **配色**：仅用项目设计令牌（故宫红 `#c41e3a` / 珠宝金 `#c9a96e` / 宣纸 / 墨色 + 角色专属色）。
   严禁引入令牌外的颜色，严禁出现紫色/violet（角色色除外）。改背景必改前景以保证对比度。
2. **字体**：标题=思源宋体（font-serif），正文=思源黑体（font-sans）。最多两种字族。
3. **国风调性**：宣纸底 + 鎏金描边 + 印章元素。任何页面不得脱离国风（历史教训：welcome 深蓝星空、证书深蓝背景均属偏离，已修正）。
4. **布局**：移动优先；flexbox 优先，复杂二维才用 grid；间距用 gap，不混用 margin/padding+gap。
5. **图标**：统一图标库，禁用 emoji 作图标。
6. **峰值时刻品牌露出**：高光时刻（证书/小结/勋章/里程碑）必须带品牌露出 + 扫码进入平台入口（复用 PlatformEntry 母版）。

## 四、工程规范

1. **母版优先**：能用母版（components/common/*）就不重写。新场景优先扩展母版而非另造。
2. **数据驱动**：组件靠 props/数据渲染，不硬编码文案到逻辑里；品牌信息统一引用 `lib/brand.ts` 的 BRAND 常量。
3. **类型先行**：复用 lib/types 的类型定义作为数据契约。
4. **纯函数渲染**：canvas 等绘制逻辑写成平台无关纯函数，平台差异收敛到适配层。
5. **可复用封装**：跨页通用能力（storage/request/share/canvas/scroll 等）封装成 utils/composables，不在页面内重复实现。

## 五、质量与验收规范

1. **基准截图**：每个页面/母版改动前后用 agent-browser 截图，作为像素验收标尺。
2. **浏览器验证**：涉及 UI/交互的改动必须在真实浏览器（或真机）验证，编译通过 ≠ 验收通过。
3. **类型检查**：每次改动跑 tsc --noEmit 确认无类型错误。
4. **日志排查**：runtime 问题查 v0_debug_logs.log，注意区分新旧时间戳。

## 六、协作与交付规范

1. **提交规范**：feat/fix/docs(scope): 标题 + 要点列表 + 浏览器验证结论 + Co-authored-by 落款。
2. **分支规范**：永不直接推 main；在功能分支提交并推送。
3. **阶段性对接文档**：每完成一个阶段，更新 `04-ClaudeCode对接说明.md`，让 Claude Code 能据此做前后端对接与联调。
4. **经验沉淀**：每遇到坑或形成可复用做法，写入 `经验沉淀.md`，确保换人/换账号也能复现。

## 七、本规范要求的固化项（来自项目方明确要求）

- ✅ 永远保持 原型文件夹 + Vue3 文件夹 双轨结构。
- ✅ 后期新增页面也按「先原型 → 标准流程转化 Vue3」执行（见 05 文档）。
- ✅ 持续沉淀经验/工具/规范/流程到 docs/，使不同 V0 账号能产出同等质量。
- ✅ 阶段性为 Claude Code 生成对接说明，便于前后端对接联调。
- ✅ 尽量产出可复用的规范与组件，便于平台功能按标准扩展。
