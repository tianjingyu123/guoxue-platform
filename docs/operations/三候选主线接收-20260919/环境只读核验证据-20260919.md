## 管理端、启动产物和代理拓扑

- 两节点运行产物均包含 `trust proxy`、`ValidationPipe` 和 `api/v1` 标记；源码确认 `trust proxy = 1`，全局 `ValidationPipe` 使用 `whitelist: true`、`transform: true`。
- 管理端生产 base 为 `/admin/`，API base 为 `/api/v1`；Nginx 有 `/admin/` 和 `/api/` 挂载，静态根为 `/var/www`。
- 服务容器只暴露容器网络 `3000/tcp`，没有主机端口映射；Nginx 是唯一主机入口，发布 `80/tcp`。
- Nginx 只信任 `100.64.0.0/10` 的 `X-Forwarded-For`，启用递归真实 IP，并在转发时把 `X-Real-IP`、`X-Forwarded-For` 重写为解析后的 `$remote_addr`。
- 最近 2000 条访问日志的聚合分类：国学2 loopback 36、private 143、public/proxy 1821；国学1 loopback 35、private 0、public/proxy 1965。未保存或输出原始 IP、URL。
- 代码层事实：通用守卫先判断基础设施 IP 白名单，再判断用户白名单，命中会跳过计数。因此不能声称所有登录用户一定不受白名单影响。
- 针对反馈联系方式、正文和截图明文接口，接收分支新增 `SensitiveRedisThrottleGuard`，强制按用户计数，基础设施和用户白名单均不能绕过；这部分尚未部署。
