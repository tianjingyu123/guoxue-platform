## 本轮新增适配

环境核验确认通用限流守卫的基础设施 IP 和用户白名单会先于 userId 计数放行。为避免反馈明文接口因部署拓扑或内部来源绕过附加限流，本轮新增专用 `SensitiveRedisThrottleGuard`：

- 联系方式、正文原文、截图三个明文接口强制按已认证用户计数；
- 基础设施 IP 白名单和用户白名单均不能跳过该计数；
- 其他登录、验证码、AI 等原有严格限流行为不变；
- 新增两项单元验证，覆盖内网 IP 和用户白名单场景。

同时新增可复用的两节点只读审计脚本；脚本不读取业务行数据和密钥，不执行写入。

用户继续推进后，按报告中的推荐方案完成业务边界收口：

- 客服可按需查看联系方式和正文原文，逐次审计；截图仅 `SUPER_ADMIN`、`OPERATION_ADMIN` 可看，管理端同步隐藏客服截图入口；
- `general_chat` 改为仅 `SUPER_ADMIN`、`OPERATION_ADMIN` 可调用，普通用户请求在供应商调用前返回 403；专用 AI 场景不受影响；
- 本次发布继续使用现有正式域名，`gx.yrydai.com` 不纳入本批切换。
