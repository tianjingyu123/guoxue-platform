# 全平台推荐内容目录与圈子知识采集方案（2026-09-23）

状态：架构方案 + 隔离代码候选。未迁移数据库、未启动向量化、未调用付费 Embedding、未合入或部署。基于 `codex/ai-guide-intent-20260922`。本文件中的规模与性能指标均为待实测目标，不是正式环境结论。

## 先分清两种“进入”

1. **进入可发现目录**：所有有合法展示资格的内容都应有一条统一元数据记录，供智能体、搜索、首页等入口召回。包括文章、课程、视频、古籍、圈子、商品、公开帖子、公开直播/回放、平台内容、已审核智能体和工具入口；但并非每次回答都推荐所有类型，也不表示把私有或付费正文公开。
2. **进入回答知识库**：只有圈主授权、来源可追溯、内容有事实/方法价值且通过去重与审核的片段，才可作为圈主助理的依据。聊天记录、打卡、纯情绪表达、广告、未经核实的个人断言不能因“发在圈里”而自动成为知识。

目录负责“找到哪里看”，知识库负责“依据什么回答”。两者保留来源链接，但索引、权限和生命周期分别管理。

## 当前代码盘点与主要缺口

| 链路 | 现状 | 缺口 |
| --- | --- | --- |
| 全局搜索 | Article、Course、Product、Circle、Video、User、ClassicBook、Content 八类，审核/公开过滤口径不完全一致 | Post、LiveRoom、智能体/工具尚无统一导览入口；中文整句主要靠 `ILIKE` 回退 |
| AI 内容导览 | 从搜索结果转成古籍、文章、课程、圈子、Content 五类可点击卡片 | 视频、直播、商品等尚未接入；商业类型仍需按意图与权限节制展示 |
| 推荐向量 | Article、Video、Course、Product、Circle、Classic 六类，Redis 单 JSON 数组存储 | 缺 Content/Post/Live 等；全量读取与重写随数据增长变慢；部分公开条件原先缺失 |
| 圈主助理知识 | 圈文章、精华帖、课程自动同步；近期帖/嘉宾帖进候选；MD5 和向量阈值去重；有质量评分字段 | 自动采集缺实质内容门槛；精确哈希与候选哈希口径有漂移；质量分通常入库后才算；近似重复被直接跳过，无法审阅差异；内容编辑后的旧候选快照尚无版本校验 |

本候选先收紧向量候选的公开/审核/删除/隔离条件，修复限额中断时误删未扫完向量；圈子知识自动采集跳过明显闲聊、短内容转待审；手动采集及候选确认重新核对圈子归属和源状态。它们是底线修复，不等于目录建成。

## 统一内容目录：建议数据契约

新增独立的 `ContentCatalog`（名称待主线确认），以 `(sourceType, sourceId)` 唯一，保留原业务表为事实来源，不复制交易状态或正文。最小字段：`scope`（平台/圈子/分站）、`circleId/stationId`、`visibility`、`auditStatus/sourceStatus`、`title/summary/cover`、`tags/topicIds`、`contentFormat`、`creatorId/teacherId`、`commercialType`、`canonicalTarget`、`sourceUpdatedAt/sourceHash`、`indexedAt/indexVersion`。许可与版权状态单列，古籍仍复用已审核商用许可口径。向量单独建版本化索引，记录模型、维度、文本版本；旧向量不直接冒充新模型结果。

入目录前必须具备可访问详情页和可判定权限。平台级公开推荐只取已发布、审核通过、未删且可公开的记录；圈内内容仅在已授权成员的圈内上下文检索；付费课程/商品可展示经审核的标题、简介和价格标识，不能把付费正文灌入公开问答。下架、改权限、撤销授权时先停止召回，索引异步清理并对账。

内容创建/审核/修改/下架通过事件或 outbox 增量更新目录，定时对账只修漏项；先做一次**只读覆盖率报告**，按类型统计源内容数、可索引数、缺标题/摘要/封面/标签数、索引缺失/过期数和无详情页数。没有这份报告，不承诺“全平台都已进入推荐”。

## 召回与排序

先按身份、圈子、分站、审核、版权、上下架、有效期做硬过滤，再混合关键词与语义召回，最后按问题意图、主题、内容质量、新鲜度和多样性排序；答案依据与“继续看”卡片分开。课程、商品、圈子等商业入口必须有用户意图或明确披露，不用热度压过正确答案。模型只看已过滤候选的安全摘要和来源 ID，点击详情再由业务接口二次校验权限。

数据库效率先以真实 `EXPLAIN (ANALYZE, BUFFERS)` 和数据规模判断。PostgreSQL 官方文档将 GIN 列为全文检索的优选索引类型，部分索引可只覆盖可发布子集；但当前中文 `simple` 分词效果需样本实测。pgvector 官方文档说明 ANN 的过滤在索引扫描后执行可能降低召回，需考虑过滤列索引、部分索引或分区；这些均为候选选型，不能在未确认数据库扩展、数据量和费用前直接上线。参考：

- https://www.postgresql.org/docs/current/textsearch-indexes.html
- https://www.postgresql.org/docs/current/indexes-partial.html
- https://github.com/pgvector/pgvector#filtering

## 圈主助理的知识采集三道门

| 判定 | 示例 | 处理 |
| --- | --- | --- |
| 可入知识 | 圈主原创讲解、审核文章、课程大纲与讲义、精华帖中可复用的方法/事实，来源可核对 | 通过圈归属、状态、授权、实质内容与去重后入库；记录来源和版本 |
| 待人工复核 | 简短但可能有价值的古文解释、嘉宾观点、近期高质量帖子、与现有知识相似但角度不同的内容 | 给圈主/运营看原文、来源、相似目标与差异；决定合并、保留两条或拒绝 |
| 不采集 | “你好”“哈哈”“谢谢老师”、打卡、单纯提问、广告/引流、隐私与未授权内容、已删除或驳回内容 | 不进入回答依据；必要时进入审核/投诉流程，不能仅靠长度或模型打分放行 |

去重分三层：同源 ID + 版本避免重复同步；规范化文本哈希拦截完全相同；相似度只提出“疑似重复”，不能自动认定观点相同。审核结果必须可追溯，修改已采纳知识应重审并使旧向量失效。现有 `qualityScore` 的长度、来源、引用符号只能辅助排序，不能证明观点正确或版权合规。助理回答应能追到圈内已批准的知识条目；证据不足时明示通用知识，不能捏造圈主立场。

## 圈子知识地图：把采集成果变成可感知体验

建议名称为**圈子知识地图**，实现形态是可点选/拖动的力导向关系图，而非把每条知识全文都做成一颗星。节点分三层：主题簇 → 知识点 → 已审核来源；连线必须有明确语义（前置学习、原文与解读、同一主题、课程与讲义、问答与依据），不能仅凭向量相似就画成“知识关系”。每个节点可追到圈主确认的来源，避免外观很强却内容空泛。

- **圈外加入页**：展示圈主选择公开的主题簇、公开课程/文章示例及真实可核对的覆盖范围；点开可看简介与来源类别，私密问答、付费讲义正文和成员信息不出现。此处是“专业能力预览”，不是绕过付费墙。
- **圈内成员页**：可搜索主题、拖动、点开知识点、查看授权来源，并一键把该知识点作为上下文询问圈主助理。助理回答回链到来源，形成“看地图 → 问问题 → 看依据 → 继续学”的闭环。
- **移动端体验**：首屏先给可读的精选主题图，只有手势操作时才布局/高亮；密集图谱按主题分层展开，永不一次画出全圈所有节点。提供等价列表视图、键盘/触屏可用入口和减少动态效果。H5 可评估 D3 力导向布局；Android nvue、微信小程序是否能用同一渲染方案必须分别实测，不以桌面浏览器代替。参考 https://d3js.org/d3-force 、https://d3js.org/d3-drag 和 https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion 。

落地前置：知识条目有稳定来源 ID、权限、主题标签和审核状态；关系边有类型、生成方式、审核状态和版本；对外聚合只使用标记可公开的节点。先做一圈受控样本的图谱和加入页原型，验证用户能否在三次操作内找到一项真实知识及对应课程/问答，再决定是否扩大。当前仅有概念示意，尚未接平台真实知识数据或新建接口。

## 实施顺序与验收

1. **P0 数据与权限审计**：运行只读覆盖率、抽查各类型公开/圈内/下架样本；修复搜索、推荐、知识链路的准入条件。通过：同一内容在各入口的可见口径一致，跨圈和下架样本零暴露。证据放 `artifacts/ai-content-catalog/eligibility/`。
2. **P1 目录与采集规范**：确定字段与标签词表，发布/审核表单补齐主题、难度、受众、摘要、来源/版权；以可回滚迁移创建目录，先只读回填、对账，不切流。通过：每类源内容数、可索引数、缺失数可追踪；抽样目标页可打开。证据放 `artifacts/ai-content-catalog/backfill/`。
3. **P2 检索与知识审核**：增量事件、目录混合召回、圈知识候选复核、版本与撤回；先影子流量比较，不让模型看未授权正文。通过：同一固定问集比较 Precision@4、Recall@20、空结果率、跨圈泄露数、p95 延迟和索引滞后。阈值以现有基线与产品目标共同定，不凭空宣布达标。证据放 `artifacts/ai-content-catalog/evals/`。
4. **P3 小流量验收与持续改进**：Android/H5/微信端验证卡片、返回路径、内容权限和“少打扰”展示；记录曝光、点击、继续阅读、无关推荐、投诉及撤回率，按圈/类型分层看。任何正式切流、数据库迁移、索引扩展与 Embedding 费用须主线统一安排。
