# 退出文件采集与落盘验真

本批在上一冻结源码96ef90f56276dcf5e0d3b131d41b7072a5a8997e、归档3c35b11ca1d4928493dae27d871f66b8803f7cd7之上独立增加维护用HTTP下载工具及公共退出格式验真模块。上一批33套及恢复包保留原字节，不将新工具测试结果回写旧报告；服务端、客户端页面、schema及迁移均不修改。

## 采集范围

`scripts/ops/managed-exit-download.mjs`只GET已经由本应用管理员建立的V3快照。它先通过现有`/api/v1/lease/context`核客户ID、应用ID及CUSTOMER_ADMIN，再读取`/exports/:id`总清单，顺序读取22类的全部`/exports/:id/pages/:collection/:page`。结束前重新读取总清单及context，核快照未变、授权仍有效，再从磁盘独立读取总清单、分页及附件验真。

不登录、不刷新令牌、不建立新快照、不自动重试或跨源重定向；只允许明确HTTPS源站，合成本机试点允许127.0.0.1带端口HTTP。ACTIVE服务端正常记录下载审计；FROZEN时下载已建快照的响应说明没有新增审计，不能把GET宣称数据库绝无写入。采集前需要客户管理员的既有有效快照及受限配置，不读网页登录Cookie或平台环境变量。

输入配置只保存在调用者受限文件，字段为`origin/customerId/applicationId/clientKey/accessToken/exportId/downloadToken`，来自已授权源站及既有快照回执。命令示例只给路径：

```text
node scripts/ops/managed-exit-download.mjs 受限目录/下载配置.json 受限目录/新的退出目录
node scripts/ops/managed-exit-verify.mjs 受限目录/新的退出目录/manifest.json 受限目录/新的退出目录
```

Windows使用PATH中的PowerShell 7实际核每个配置文件及目录ACL，只接受当前用户、SYSTEM和Administrators的Allow规则；权限无法读取直接拒绝，不依赖Windows无效的mode设置。Linux配置600、目录700，并核所有者为当前用户或root。符号链接、目录联接及已有输出目录拒绝，不覆盖或递归删除历史数据。新文件请求fsync并重新读取验真；退出数据和下载配置都不入Git，不打印凭据或响应正文。

## 成功与失败

总清单必须包含完整22集合、连续分页、500行普通页及1行附件页；累计最多100000行、128MiB载荷。HTTP按解压后实际读取限制：context 64KiB、manifest 8MiB、分页4MiB；载荷仍按原服务端单页2MiB、PNG/JPEG附件512KiB约束。UTF-8和JSON必须完整，附件Base64必须规范且原字节SHA匹配。响应若回显认证或下载凭据立即拒绝保存；HTTP错误正文不读取。

每个新目录先记录`download-status.json`的IN_PROGRESS。清单或分页缺失、篡改、凭据回显、容量超限、断网、授权失效等保留FAILED及实际已写页数，不生成完成结论；即使全部分页已落盘，最终远端复核失败仍是FAILED。成功文件包括`manifest.json`、`managed-集合-页号.json`和VERIFIED回执。命令失败不自动重发，已有服务端事实与部分下载保持可查；再次执行须维护侧核清后使用新目录。
