# 旧排盘真实分享缺陷与修复（2026-09-27）

范围：隔离接收工作树的 App 分享代码、当前公网 H5 分享承接页、已安装的本地 Android 250 测试包。后续临时静态页已在两节点 H5 共享卷生效；未部署累计业务候选、修改数据库或真实用户资料。

## 真实复现与版本边界

- 在 OnePlus 9R 的 Android 249 包中，旧八字排盘输入页选择“微信好友（热卜链接）”后，原生接口返回失败，未进入微信联系人选择。原代码对 `uni.share` 的 `type: 0` 图文消息只传入链接、标题、摘要，漏了官方接口要求的 `imageUrl`。这是明确的源码缺项。
- 改用“系统分享公开链接”，经用户授权向其备用测试账号发送一次，微信显示“已发送”。消息以长网址文本呈现，且同一网址出现两次。源码把网址同时放在系统分享 `href` 与 `content`；Android 分享面板会附加 `href`。该次是发送请求成功，不能算接收端链路验收成功；没有重复发送。
- 打开已发送网址时，微信先提示“无法确认该网页的安全性”；用户反馈继续后显示“分享链接无效”。只读请求确认线上 H5 返回 HTTP 200，但实际加载的分享页脚本 `pkg-common-legacy-paipan-share-index.qLdNCHyM.js` 中，允许的第三方查询参数未包含 `ruid` 或 `act`。已发链接的第三方目标含数字 `ruid`，因此线上旧脚本拒绝。隔离候选源码的校验已包含数字 `ruid`，且定向测试覆盖。**HTTP 200 不代表承接页业务成功；目前公网版本落后于本地候选。**
- 这次发的是未填写出生资料时的工具入口，不是个人排盘结果。个人结果、微信接收端卡片、朋友圈及登录回跳均未据此通过验收。

## 隔离修复

- 微信图文分享加入包内 120×120 PNG 缩略图，6,704 B；不依赖第三方图片地址，也不将私有盘面截图作为缩略图。
- 系统文字分享正文去掉重复的网址，只由 `href` 提供一次链接；系统分享仍只是备选文字通道，不能当作图文卡片。
- `node --test tests/release/mobile-legacy-paipan-share.test.mjs`：25/25；移动端 `vue-tsc --noEmit` 通过；App 和 H5 构建退出 0，App 产物含缩略图及调用引用。本地 H5 分享页脚本 `pkg-common-legacy-paipan-share-index.CgaI5a65.js` SHA-256 `333D4E6936DC3BBBD029F9A872DB1CE3899E90B8151E0BB4865F10125113925A`，包含数字 `ruid` 与 `act` 校验；公网旧脚本仍不包含。

## 2026-09-27 承接页修复候选

- 线上旧 H5 脚本拒绝数字 `ruid`，直接整包替换又会改变大量尚未发布的 H5 页面。新增独立静态承接页 `apps/mobile/public/pkg-common/legacy-paipan-share/index/index.html`，由 `build:h5` 后置脚本放入正式 H5 产物同一路径。它只接受白名单第三方 HTTPS 公开工具/盘面地址及允许的查询参数，保留数字 `ruid`，拒绝登录、订单、鉴权等地址。
- 曾有 Android 微信内跨域 iframe 空白的项目记录，因此该承接页校验后使用顶层 `location.replace` 打开第三方网页；原站微信 OAuth 可在顶层完成。页面另提供“继续打开排盘”作为跳转失败时的手动入口。此设计不能替代微信接收端实际点击验收。
- 本轮构建产物中静态页 SHA-256 `7b2ece311425d821dd50f8c59c2d3bc4b3139eed3809317b21d269ac7ee8091f`；分享定向测试 27/27、H5 正式构建通过。变更前双节点无该静态页，公网旧 SPA 显示“分享链接无效”。
- 两节点 Nginx 使用 `/h5/` 静态文件优先路由；运行容器分别有镜像内 `/app/h5-dist` 和共享卷 `/app/h5-dist-shared`。原计划两处同步，经首节点验证镜像目录只读，因此改用共享卷临时承接并记录重启回退风险；正式固定包仍须包含源码中的静态页。热修不等于正式候选整体发布。
