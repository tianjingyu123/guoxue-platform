# 旧排盘真实分享缺陷与修复（2026-09-27）

范围：隔离接收工作树的 App 分享代码、当前公网 H5 分享承接页、已安装的本地 Android 249 测试包。未部署、未更改线上配置或真实用户资料。

## 真实复现与版本边界

- 在 OnePlus 9R 的 Android 249 包中，旧八字排盘输入页选择“微信好友（热卜链接）”后，原生接口返回失败，未进入微信联系人选择。原代码对 `uni.share` 的 `type: 0` 图文消息只传入链接、标题、摘要，漏了官方接口要求的 `imageUrl`。这是明确的源码缺项；补齐后能否在该签名包与微信开放平台配置下成功，仍需匹配新包真机复验。
- 改用“系统分享公开链接”，经用户授权向其备用测试账号发送一次，微信显示“已发送”。消息以长网址文本呈现，且同一网址出现两次。源码把网址同时放在系统分享 `href` 与 `content`；Android 分享面板会附加 `href`。该次是发送请求成功，不能算接收端链路验收成功；没有重复发送。
- 打开已发送网址时，微信先提示“无法确认该网页的安全性”；用户反馈继续后显示“分享链接无效”。只读请求确认线上 H5 返回 HTTP 200，但实际加载的分享页脚本 `pkg-common-legacy-paipan-share-index.qLdNCHyM.js` 中，允许的第三方查询参数未包含 `ruid` 或 `act`。已发链接的第三方目标含数字 `ruid`，因此线上旧脚本拒绝。隔离候选源码的校验已包含数字 `ruid`，且定向测试覆盖。**HTTP 200 不代表承接页业务成功；目前公网版本落后于本地候选。**
- 这次发的是未填写出生资料时的工具入口，不是个人排盘结果。个人结果、微信接收端卡片、朋友圈及登录回跳均未据此通过验收。

## 隔离修复

- 微信图文分享加入包内 120×120 PNG 缩略图，6,704 B；不依赖第三方图片地址，也不将私有盘面截图作为缩略图。
- 系统文字分享正文去掉重复的网址，只由 `href` 提供一次链接；系统分享仍只是备选文字通道，不能当作图文卡片。
- `node --test tests/release/mobile-legacy-paipan-share.test.mjs`：25/25；移动端 `vue-tsc --noEmit` 通过；App 构建退出 0，产物含缩略图及调用引用。这些是源码与构建验证，**不是**新包原生分享验收。

## 发布前剩余动作

1. 先按正式固定包流程把包含数字 `ruid` 校验的 H5 分享承接页发布到最终入口；发布后从微信重新打开受控测试链接，确认不再显示“分享链接无效”，并核实微信安全提示是否仍存在。不得为了让旧版通过而删除分站推荐来源。
2. 用包含本修复的正式同签名候选 App 真机测试“微信好友（热卜链接）”是否呈现带缩略图的卡片、卡片点击是否到正确工具/结果。若原生接口仍失败，检查微信开放平台移动应用包名、签名与分享能力；不能以系统文字分享替代卡片验收。
3. 用不含个人资料的合成盘面核验结果分享，再由真实接收端验证；微信安全提示及域名可信度需要单列处理。通过前不在朋友圈发布测试内容，也不对外宣称旧排盘分享已完成。

参考：DCloud 官方 `uni.share` 文档明确图文 `type: 0` 的 `href` 和 `imageUrl` 均为必填；HTML5+ 系统分享仅支持文字/图片模式。原始截图仅留本机受控验收目录，不入库。
