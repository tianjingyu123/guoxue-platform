# 旧课程复用旧主体点播：代码核查与最小交接（2026-09-23）

状态：只读源码核查，未登录新旧腾讯云，未读课程数据，未上架、迁移或发起真实播放。此项与 AI 推荐/星图的隔离代码候选分开验收。

## 已核实的现有能力

- 新平台课程由 `Course` 记录课程身份、所属圈子/上传人、售价、可见范围和审核状态；`CourseChapter` 记录章节顺序、`mediaUrl`、时长和免费试看。服务端章节接口由 `CourseLearningService.addChapter` 保存 `mediaUrl`，取章节内容时检查试看、免费、作者或购买权益。
- 现有 `VodService.genPlayerSignature` 使用**当前配置的** `VOD_SUB_APP_ID` 与播放密钥签名；代码没有按章节区分旧主体/新主体的 VOD 子应用，也没有在 `CourseChapter` 中保存旧账号 FileId 和来源账号。
- 后台通用 `ImportService` 的 `course` 类型只批量建课程元数据、直接写 `auditStatus: APPROVED`，不导入章节或媒资，不做旧 ID 去重和权益核对；**不能拿它直接做旧课正式上架**。
- 因此“先沿用旧账号媒资”目前最直接的隔离试点是：新平台创建课程/章节元数据，章节 `mediaUrl` 指向经过验证可持续访问的旧账号播放地址。视频文件仍在旧账号，不是转存到新账号。若旧地址需动态签名、会过期或受域名防盗链限制，不能直接把一次性的 URL 固定写入章节；需先核对旧账号播放配置，再设计双来源播放解析，不把新账号密钥误用于旧账号资源。

## 实施前最小资料

1. 一份可导出的课程—章节对应清单：旧课程 ID、课程名、教师、章节 ID/标题/顺序、旧 VOD FileId 或稳定播放地址、时长、封面、课程简介、售价/免费试看。先给一门受控样本课即可，不需一次性交全量。
2. 新平台要承载首批课程的虚拟圈主用户 ID、圈子 ID，以及首批课程的公开范围、审核与售价决定。旧平台购买权益是否迁移应单独确认；不能因为课程视频可播就自动给用户新增购买权益。
3. 旧账号只读核验途径：可查媒资 ID、播放域名、访问控制和地址是否长期有效。网页登录可用于人工核对，但不等于官方 API 已鉴权；不要求提供密钥到聊天或仓库。新账号也只需先核对现有 VOD 配置，不需要把旧视频重新上传。

## 接收顺序

先只读核对一门样本课的媒资与播放规则，再在隔离数据环境创建虚拟圈主名下的课程/章节映射，验证游客、免费试看、未购买和已授权账号各自的播放边界，并观察地址过期后的行为。通过后做批量导入的去重、回滚及逐课对账；正式上架与权益变动须另行授权。结果保存 `artifacts/legacy-course-vod/`：脱敏映射、旧/新媒资归属、测试设备与构建 SHA、播放与鉴权结果、导入前后计数和回滚记录。任何真实密钥不入证据目录。

当前停止条件：尚无旧课清单、旧账号可验证播放规则、虚拟圈主/圈子 ID，不能声称可以自动完成上架；也不把一次性可播 URL 当作长期方案。
