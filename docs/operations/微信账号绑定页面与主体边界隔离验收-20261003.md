# 微信账号绑定页面与主体边界隔离验收（2026-10-03）

本批只做隔离候选、测试及接收准备。源码提交 `26aa29c55ed309f154164057822eb196bd49d947`；测试脚本去除正式域名硬编码提交 `fd488b9bfd820f839808a4dc3df2e810ca12813f`。完整 CI 和官方四端构建状态以本记录后续追加的实测为准，不由本机通过推定。没有部署、生产迁移、真实授权、账号绑定写入、真实通知或付费打包。

## 实际行为

- 微信绑定复用受 JWT 保护的 `/auth/bind/wechat`，不调用微信登录接口替代绑定，不替换热卜令牌、不合并其他账号。小程序取临时 code；APP 使用 `onlyAuthorize` 且遵守现有远端开关；H5 仅在微信内提供授权入口。
- H5 准备授权后由用户点击“继续微信授权”同步进入顶层微信页面，保留此前 XWeb 的实际经验。回调固定回本站绑定页；随机状态仅使用一次，10 分钟内有效，校验发起账号，URL 中的 code/state 随即清理。取消清理尝试，不保存手机号或授权票据。
- 新页面的绑定、解绑请求携带发起账号；服务端实际主体始终来自 JWT。授权期间切换账号或重试使用另一账号会被拒绝。旧客户端省略新字段仍兼容，但不能因此宣称旧客户端也具备新保护。
- 成功后重新加载服务端绑定列表；身份冲突、取消、网络失败显示可理解的结果，不能只在本地改成已绑定。解绑失败保留原状态；明确提示微信解绑覆盖该用户各微信客户端，QQ/Apple 解绑后暂不能重新绑定。
- 移除无依据的“绑定送积分”“绑定两个账号即安全”承诺。QQ/Apple 没有新绑定接口，不因已有登录接口而标为完成。
- 登录/绑定授权状态不能被残留的支付回跳会话接管，保留支付自身的回跳逻辑。

## 失败与修复，不删原记录

1. 初版完整 CI 的域名门禁指出新浏览器测试硬编码正式域名。`fd488b9bf` 改成按请求类型提供合成响应，所有非本地请求仍先截断；未增加域名豁免或降低审计标准。初版官方失败任务 `111152242229` 日志保留。
2. 浏览器脚本最初错误依赖开发模式全局 uni、随后缺合成 CORS 响应；改用 SDK 实际 H5 存储格式和离线响应后重新通过。这些是测试夹具修正，不当作产品 bug 修复数量。
3. 本机完整门禁最初发现旧的未补丁 braces；本隔离树执行冻结依赖恢复后，补丁新增行的 CRLF 造成实际文件字节摘要仍不同。LF 归一化摘要与既定补丁一致，但没有据此放宽字节校验或宣称本机完整门禁通过。最终由 Linux 干净安装的完整 CI 复验。恢复只作用于本工作树，没有生成主工作区 Prisma 客户端。
