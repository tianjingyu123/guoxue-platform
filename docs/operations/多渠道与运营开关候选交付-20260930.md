## 已实现的行为

### 渠道版本

`AppVersion` 按 `applicationId + platform + channelId` 隔离查询、活动槽、版本/构建去重、发布、退役、回退和最低支持线。事务锁及唯一索引限制同渠道并发活动版本；另一渠道不会因发布而退役。可选更新有稳定账号灰度和指定用户；强制最低支持线不被可选更新灰度阻断。

新构建写入公开安装选择器，更新查询通过登记表解析渠道，不猜手机品牌。不带选择器的旧客户端只查 legacy；未知选择器和直接自报渠道不跨渠道回退。更新提示忽略记录按应用/渠道/原生构建/资源版本隔离。

**信任边界：clientKey 是公开选择器，并非安装证明或保密凭据。** 持有其他有效选择器的请求可以声称另一渠道；本候选没有原生签名验真/安装证明系统。渠道规则用于分发和运营裁决，不能替代用户认证、租户权限、购买权益或全局安全防线。涉及必须防伪的商店审核隔离，接收前还需可信原生身份方案和实测。

### 运营开关

复用既有 FeatureFlag、角色权限、红线门禁、审计与 ConfigVersion 历史。状态包括未开放、开放、维护、只读；渠道规则只能收窄全局状态。单项 emergencyDisabled 和全局 client_emergency_close 优先关闭；老全局 MD5 灰度桶保持不变，避免升级重新抽签。

后台可保存不生效的草稿，选择已登记渠道、原生构建和模拟用户进行预览，由超级管理员发布；发布和历史回退记录操作者 ID 与原因。编辑预览后的字段会取消当前草稿发布按钮，需重新保存预览。既有受权限保护的直接开关接口继续保留，并非所有管理接口都被改成审批草稿接口。

服务端带 FeatureFlag 的业务接口从主库读取裁决，缓存失败不会放行。READ_ONLY 允许 GET/HEAD、阻止写入；统一 MEMBER 建单还检查 member_purchase。未登记请求使用各渠道限制的保守交集。防线只覆盖已有装饰器和此次补上的会员建单，不宣称无装饰器的全部历史接口均受此开关控制。

客户端默认关闭直播开播、会员购买、商家入驻、商城结算；缓存按环境、应用、选择器、原生/资源版本、账号和认证修订隔离。登录退出立即重置、刷新；旧请求成功或失败均不能覆盖新账号。TTL 到期收窄写业务开关并通知 Vue 订阅；后台/系统暂停定时器时，下一次业务读取仍按实际时间判过期。服务端即时裁决与页面同步是不同路径，TTL 不等于推送。

首页“全部功能”商家入口响应配置更新；统一导航阻止新结算、入驻、开播及 OBS 入口。搜索结果经同一导航进入这些页面也受限制。历史订单、退款、客服、已购课程和既有权益阅读保留原有权限规则；未做整个搜索索引下架或所有详情页面封锁。

### WGT 安全基础

新增独立 ResourceRelease，资源版本与原生构建分开。严格清单绑定产品/应用/Android 平台/渠道/包名/runtimeAppId、资源版本、原生构建范围、原生指纹、精确字节数、SHA-256、签名 keyId 和有效期。发布、停发及服务端回退有权限、审计和同渠道事务锁。默认缺少可信公钥、许可或原生恢复证据时拒绝发布。

构建工具绑定完整源码 SHA、独立渠道输出目录和构建锁。ZIP 门禁拒绝截断、越界/重叠、危险路径、重复文件、软链接、加密、ZIP64、原生文件及缺失 manifest。原生边界门禁纳入 manifest、依赖锁、SDK 输入、原生插件内容和渠道身份源文件；原生输入变化必须完整包。离线签名只接受仓库外 Ed25519 私钥；此次未创建或使用生产私钥，测试密钥只存在合成进程内存。

客户端提供 NativeResourceBridge 契约和编排：下载到临时文件、大小/哈希/签名验证、原子暂存、持久化状态、冷启动再次检查停发/灰度/兼容性、健康确认。支付、直播、录制、上传期间不切换；不在前台自动重启。

**本候选没有生产原生桥接器，也未接入 App.vue 自动下载/安装。** 新 JS 无法启动时的恢复必须在 JS 之前由完整原生包实现；普通 plus.runtime.install 与 JS 超时不构成此证明。当前只有原生模拟契约测试，不能据此开启 WGT。服务端回退只改变以后提供的资源，不让已安装的新资源降级；已装设备的恢复由未来经过真机验收的原生层完成。

当前签名资源协议仅允许 Android web-resources，iOS/Harmony 暂不启用。不要把注册页证据文字、技术可安装、模拟测试或商店政策一般说明当成具体应用的许可。

## 数据库接收与回退边界

1. 先评审候选两个代码工作包及最终证据工作包；接收后在主线自己的同源码依赖中重新生成 Prisma Client，不复制本工作树 node_modules/dist。
2. 在真实预发布备份副本检查历史同渠道版本/构建重复、原有 activePlatformKey 唯一索引与活动记录；重复会明确阻塞迁移，不能删除历史记录来静默通过。本次合成库升级不代表真实全库迁移已验收。
3. 迁移把旧活动键从 platform 改为 application:platform:legacy；新服务按该范围加锁。旧服务仍写 platform 键且按整个平台发布，**不能在多渠道启用后与新服务混写，也不能直接回滚旧二进制**。预发布须协调服务版本和迁移，暂停版本写入后验证。
4. 运营列为增量、旧布尔语义保留；新表可先空置。接收不必登记假商店身份，更不必开启 WGT。
5. 若新服务有问题，先停发新渠道、冻结版本管理写入，保留数据/审计/备份，用评审后的前向修复恢复；不要删除新表或把多个渠道活动键强行改回 platform。回退到旧代码前必须独立制定范围合并与数据恢复方案。
6. 真实完整包核验每渠道包名/证书/链接/版本和安装身份、渠道标签与账号切换，然后才逐渠道灰度。legacy 继续作为历史客户端兼容槽。
