## 已实现的行为

### 渠道版本

`AppVersion` 按 `applicationId + platform + channelId` 隔离查询、活动槽、版本/构建去重、发布、退役、回退和最低支持线。事务锁及唯一索引限制同渠道并发活动版本；另一渠道不会因发布而退役。可选更新有稳定账号灰度和指定用户；强制最低支持线不被可选更新灰度阻断。

新构建写入公开安装选择器，更新查询通过登记表解析渠道，不猜手机品牌。不带选择器的旧客户端只查 legacy；未知选择器和直接自报渠道不跨渠道回退。更新提示忽略记录按应用/渠道/原生构建/资源版本隔离。

**信任边界：clientKey 是公开选择器，并非安装证明或保密凭据。** 持有其他有效选择器的请求可以声称另一渠道；本候选没有原生签名验真/安装证明系统。渠道规则用于分发和运营裁决，不能替代用户认证、租户权限、购买权益或全局安全防线。涉及必须防伪的商店审核隔离，接收前还需可信原生身份方案和实测。

### 运营开关

复用既有 FeatureFlag、角色权限、红线门禁、审计与 ConfigVersion 历史。状态包括未开放、开放、维护、只读；渠道规则只能收窄全局状态。单项 emergencyDisabled 和全局 client_emergency_close 优先关闭；老全局 MD5 灰度桶保持不变，避免升级重新抽签。

后台可保存不生效的草稿，选择已登记渠道、原生构建和模拟用户进行预览，由超级管理员发布；发布和历史回退记录操作者 ID 与原因。编辑预览后的字段会取消当前草稿发布按钮，需重新保存预览。既有受权限保护的直接开关接口继续保留，并非所有管理接口都被改成审批草稿接口。

服务端带 FeatureFlag 的业务接口从主库读取裁决，缓存失败不会放行。READ_ONLY 允许普通 GET/HEAD、阻止写入；签发新直播凭据的 GET 明确标记为写行为。统一 MEMBER 建单检查 member_purchase；新商家申请、编辑、提交、保证金支付和签约受入驻开关约束，既有申请阅读保留。创建直播间和领取新开播凭据受开播开关约束；已经 LIVING 的直播间允许续取凭据，仍保留原服务的所有者/管理员授权。未登记请求使用各渠道限制的保守交集，不宣称全部历史接口均已加装饰器。

客户端默认关闭直播开播、会员购买、商家入驻、商城结算；缓存按环境、应用、选择器、原生/资源版本、账号和认证修订隔离。登录退出立即重置、刷新；旧请求成功或失败均不能覆盖新账号。TTL 到期收窄写业务开关并通知 Vue 订阅；后台/系统暂停定时器时，下一次业务读取仍按实际时间判过期。服务端即时裁决与页面同步是不同路径，TTL 不等于推送。

首页“全部功能”商家入口响应配置更新；统一导航及直接 uni.navigateTo/redirectTo/reLaunch 阻止新结算、入驻、开播及 OBS 入口。首次深链等待首个页面建立后检查，避免首屏初始化竞态。搜索结果经这些导航进入页面也受限制。历史订单、退款、客服、已购课程和既有权益阅读保留原有权限规则；未做整个搜索索引下架或所有详情页面封锁。

### WGT 安全基础

新增独立 ResourceRelease，资源版本与原生构建分开。严格清单绑定产品/应用/Android 平台/渠道/包名/runtimeAppId、资源版本、原生构建范围、原生指纹、精确字节数、SHA-256、签名 keyId 和有效期。发布、停发及服务端回退有权限、审计和同渠道事务锁。默认缺少可信公钥、许可或原生恢复证据时拒绝发布。

构建工具绑定完整源码 SHA、独立渠道输出目录和构建锁。ZIP 门禁拒绝截断、越界/重叠、危险路径、重复文件、软链接、加密、ZIP64、原生文件及缺失 manifest。原生边界门禁纳入 manifest、依赖锁、SDK 输入、原生插件内容和渠道身份源文件；原生输入变化必须完整包。离线签名只接受仓库外 Ed25519 私钥；此次未创建或使用生产私钥，测试密钥只存在合成进程内存。

第二阶段提供真实 Java ResourceStore/ResourceRuntime、UTS Application.onCreate 钩子和 Native.js 桥接器，已接入 App.vue 下载、验证、暂存及排队。原生冷启动复检签名、原始包哈希、渠道/基座、停发和账号灰度；文件日志同步、健康备份树摘要和原子目录切换用于启动前恢复。基座身份改变拒绝沿用旧日志；完整包升级和 SDK 资源释放的状态迁移仍需单独验证。详见 `apps/mobile/native/resource-updater/README.md`。

支付、TRTC 直播/预览、RecorderManager、上传实际生命周期接入忙状态；原生再检测活跃录音。账号 JWT 仅由本 App 传入，AndroidKeyStore 加密后用于冷启动复检；不提取网页登录凭据。App 全局错误及未处理拒绝会阻止健康确认；至少前台观察 65 秒，原生另核验 60 秒。前台仅排队，下次冷启动切换，不自动重启。

**原生源码、AAR 和 UTS 转译已验证，正式 DCloud APK 的启动前恢复尚未真机验收。** 不把 JVM 进程/文件验证当成 Android provider、Keystore、目录同步或 SDK 启动时序验证。当前原生配置 enabled:false，服务端也默认拒绝 WGT。服务端回退只改变以后提供的资源，已安装资源恢复依靠经过完整包验证的原生层；普通 plus.runtime.install 与 JS 超时不是恢复证据。

### 公钥与准入管理

后台新增 WgtControlPanel，`/system/wgt/admin` 复用 ConfigVersion 历史、角色、红线及审计。运营/超级管理员可查看并提交根公钥签名的待审证据；仅超级管理员可以登记/撤销资源公钥、审批最新证据、启用或禁用。旧证据不能替代最新证据审批，禁用在同一范围锁内停发全部 ACTIVE 资源；撤销公钥后查询和发布拒绝该密钥资源，但不自动改变历史资源记录的状态。

服务端 `WGT_CONTROL_PUBLIC_ROOTS` 只接受 Ed25519 SPKI 公钥。完整包固定根公钥，资源公钥在该根下轮换，撤销的 keyId 不可复活；更换完整包固定根必须重新建立完整包基线。公开 `/system/wgt/trust/:clientKey` 仅返回已登记应用的有效公钥授权，无缓存；它不提供安装证明。

必须显式配置 `WGT_DEPLOYMENT_ENVIRONMENT`。合成证明仅在 NODE_ENV=test 且部署环境=test 时可用；非测试环境要求 release-native、正式安装包摘要、编译器/运行时匹配、证书/身份及全部恢复用例。官方来源 URL 只做 HTTPS 格式检查，具体应用的政策许可由根签名和人工审批负责，不宣称系统已自动核验商店许可。

当前自动 WGT 加 Native.js 协议在 OPPO、荣耀、三星、Google Play、Apple 渠道被服务端、原生和构建器共同阻止；其余渠道也须独立许可与完整包证据。不能将此结论泛化为全部远程 JS 都违规，也不能把 OPPO 规则自动当成一加/realme 的已核实规则。官方来源和核验限制见 `商店渠道审核与资源更新矩阵-20260930.md`。

当前签名资源协议仅允许 Android web-resources，iOS/Harmony 暂不启用。不要把注册页证据文字、技术可安装、模拟测试或商店政策一般说明当成具体应用的许可。
