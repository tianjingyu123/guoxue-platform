# 圈子知识宇宙 3D 选型与隔离样例（2026-09-23）

## 结论与边界

上一版平面关系图不是最终效果。本轮选择 `3d-force-graph@1.80.0` 制作独立 H5 体验样例：真实 WebGL 三维力导向布局、动态关系粒子、光晕、缓慢环绕、拖拽缩放、点选具体知识点的卡片。样例入口：`prototypes/knowledge-universe-3d/index.html`，本地用静态服务访问。数据是 24 个演示概念和人工演示连线，不对应真实圈子、课程或知识库事实；没有部署、没有改动现有加入页。

这不是可上线成品。初版点击时出现 `Cannot read properties of undefined (reading 'x')`；通过浏览器异常堆栈定位到 3D 控制器处理节点拖动与视角拖动的指针事件交接。样例无需拖动单颗节点，关闭 `enableNodeDrag` 后，浏览器复测点选、镜头聚焦和拖动视角均无该异常。光晕模块仍提示多实例 Three.js，正式工程应统一 Three.js 版本并打包，不能沿用演示的双 CDN 引入方式。

## 选型（只比较三项）

| 方案 | 适配情况 | 判断 |
| --- | --- | --- |
| [3d-force-graph](https://github.com/vasturiano/3d-force-graph) | 原生 JS、Three.js/WebGL，H5 可独立使用；官方有粒子、镜头、bloom 样例 | 本轮视觉样例采用；禁用不需要的节点拖动 |
| [three-forcegraph](https://github.com/vasturiano/three-forcegraph) | 更底层的 Three.js 对象，需自行搭建相机、控制器、渲染及后处理 | 灵活但实现和维护成本较高，作为未来替换备选 |
| [ECharts GL](https://github.com/ecomfe/echarts-gl) | 图表生态较成熟，但三维知识宇宙的定制表现与官方示例不如上述方案直接 | 不用于本轮样例 |

选型依据是当前 Vue/uni-app H5 技术栈、官方效果能力和集成成本，不把 GitHub 星数等同于性能或稳定性。`3d-force-graph` 与 Three.js 代码均为 MIT 许可，正式打包须保留许可声明；MIT **不授权任何课程、插画、字体或知识素材**。样例只用了系统字体、CSS 效果与手写演示文字，没有第三方商业视觉素材。正式数据要单独核对内容公开许可及来源。

## 真实圈子数据接入边界

源码核查发现现有 `CircleKnowledge` 保存的是知识库原文/分块，字段 `scope=circle|global` 表示检索范围，不是“允许在圈外展示”的授权。`KnowledgeEntity` 是跨圈共用实体，摘要在抽取时可能被不同来源覆盖；`KnowledgeEdge` 虽有 `knowledgeId`，也没有独立的公开审核状态。现有 `classic/knowledge` 查询未做圈子公开摘要筛选，因此**不能直接作为圈子加入页的数据源**。本轮未调用线上接口、未读取真实圈子内容，也未修改该接口。

另有一项需主线单独安全核查：源码中 `ClassicKnowledgeController` 原查询没有局部身份守卫，当前全局守卫只有限流和红线闸；`KnowledgeGraphService` 的实体抽取可来自任一 `active` 圈子知识。若正式库已有私有圈子抽取结果且此路由可访问，存在摘要/关系越界展示的风险。这是**源码推断，未进行线上可达性或数据实测**；不要以此直接宣称已发生泄露。本隔离分支先将整组旧查询限制为 `SUPER_ADMIN` / `OPERATION_ADMIN`，没有向公众开放新图谱。仓库源码检索未发现平台前端调用该路由，但外部调用方未知，主线合入前须评估兼容性。

安全候选验证：`classic-knowledge.controller.spec.ts` 3 项通过（守卫和角色元数据、普通角色拒绝、平台管理角色通过）。尝试运行服务端整体 `tsc --noEmit` 未通过，输出存在大量与本改动无关的 Prisma 生成类型和 `@guoxue/shared/paipan` 解析错误；本轮未重新生成共享 `node_modules` 中的 Prisma Client，也不把全量编译标成通过。旧查询权限变更未部署，线上风险尚未验证或消除。

建议建立独立的“圈外知识星图”已审核快照，而非由前端过滤私有数据。每个可展示节点至少要有 `circleId`、具体知识点名称、短摘要、来源知识条目、公开授权状态、审核人/时间、撤回状态；每条关系要有两端节点、关系类型、来源证据和审核状态。服务端只返回当前圈子审核通过且授权公开的短摘要与关系，不返回 `CircleKnowledge.content`、会员课程全文或私密答疑。源内容删除、撤权或圈子状态变化时，快照立即失效。

链路建议：知识采集 → 去重与具体概念提取 → 圈主/平台审核公开范围与素材权利 → 生成限量快照 → 圈外只读展示。首屏建议限制精选节点和边，再按点选展开；不能把全部知识库无上限送给浏览器。真实数据接入前须先确认公开范围、审核责任和撤回操作入口。

### 本轮追加：默认空白的公开快照候选

隔离分支新增 `CircleKnowledgeShowcaseNode` / `CircleKnowledgeShowcaseEdge` 表结构候选和只读 `GET /circles/:circleId/knowledge-showcase`。迁移**尚未执行**，没有导入、复制或发布任何真实知识，也没有把接口接到加入页。新记录默认 `DRAFT`；节点发布须有人工审核、公开权利确认和来源知识，关系发布须有审核与证据。查询还实时要求圈子为 `ACTIVE`、来源知识为 `active`、未撤回，只返回最多 40 个知识点的名称/短摘要和 80 条已审核关系；不返回知识库原文。无合格节点时返回空图，浏览器端不承担私有数据过滤。

本轮**新运行**：`circle-knowledge-showcase.service.spec.ts` 3/3 通过，覆盖空图、关系端点过滤和服务端 SQL 公开闸门；`prisma validate` 通过（仅解析 schema，使用本地占位数据库 URL，未连接数据库）。这些是模拟/静态验证，**不代表真实数据库迁移成功、接口端到端可用或真实内容公开授权完成**。全量服务端类型检查仍受前述既存生成类型/共享包错误阻断，未标记为通过。

## 接入建议

1. 节点点选异常已在样例中规避；正式接入时仍须统一 Three.js 依赖并测 FPS、内存、首屏和切后台销毁。大型知识库不能把全部节点一次绘出，需限量精选、按关系展开与聚合。
2. 数据层以**具体知识点**为节点，边记录关系类型、证据来源和审核状态。圈外加入页只读取标记为公开展示且取得授权的摘要，绝不直接暴露会员课程全文、私密问答或未审核推断。
3. 加入页只给一段自动演示和轻量点选，真正检索仍走文本/列表入口；动效减少、WebGL 不支持、低端设备、nvue 和小程序走可访问的静态卡片降级。
4. H5 性能和真实内容接口完成后，再由主线决定是否集成。当前不建议直接接入正式加入页，更不代表发布验收通过。

## 撤回

视觉样例未接入产品页面；不引用 `prototypes/knowledge-universe-3d/` 即无线上影响。旧图谱的管理员权限收紧也只在隔离分支，未发布；若主线评审不接受该兼容性变更，可单独撤回 `classic-knowledge.controller.ts` 及其测试。新增快照迁移仅是源码候选，**没有执行数据库迁移或线上部署**；主线不采纳时不应用该迁移、不注册公开控制器即可撤回。
