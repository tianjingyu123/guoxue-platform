- 基线 `ca1df63da`；分支 `codex/ai-reading-cards-20260922`。此候选与 `codex/ai-quota-reliability-20260922` 并列隔离，主线需分别评审接收。

- 视觉沿用现有暖白、深墨与朱红；回答主字号 32rpx，正文 30rpx。没有给寒暄附加图像或大面积装饰。内容封面来自平台记录，无封面时使用类型印记。

## 伴读与点句解读追加候选（同一隔离分支）

- 伴读的旧人设曾要求“一般 400–600 字”并每轮延伸追问，与全平台短答规则冲突。现改为单句先一句白话、复杂题才补依据，寒暄和单句释义不强行追问。并把客户端固定 220 字截断改为自然断句；找不到安全断句就不截断，详情可键盘展开。
- 根据已定角色谱，古籍伴读服务端角色为“小简”（“小卜 AI”团队成员）；页面标题、开场和登录提示同步为“小简”，消除界面与模型自称不一致。通用“小卜”入口不变。
- 点句翻译维持原 JSON 协议，但提示词要求单句白话直达、只有易错字词才给注释（单句最多两条）。`promptVersion` 从 `translate-v1` 提升至 `translate-v2`，避免旧缓存掩盖新提示词；旧缓存不删除，下次按需请求才可能重新生成。此变化可能增加上线初期模型调用量，主线需评估额度与发布时间。
- 阅读器默认显示前两条字词注释，更多内容可展开；听书半屏抽屉复用可读回答组件，所选句解读不再默认要求“含义、背景与要点”全讲。
- 本轮新运行：移动端纯逻辑检查通过；六个相关 Vue SFC 脚本/模板定向编译通过；服务端古籍服务、伴读、文本派生资产 3 套件 52 项通过。服务端这组测试为绕过仓库现有 Prisma Client/schema 不一致而关闭了 ts-jest 类型诊断，不能计为类型检查通过。没有重新运行 H5 整包构建：上一轮同一工作树已实测因排盘共享包路径解析错误而失败，未修复该构建基线。
