# 服务器、数据库与域名迁移手册

适用范围：API、H5、管理端、小程序、App、PostgreSQL、Redis、对象存储、直播、点播、支付、物流和第三方回调。

原则：先并行预部署，再隔离验收，最后短暂停写切流；旧环境至少保留 72 小时。禁止在 DNS 切换当天删除旧服务器、旧数据库或旧对象存储。

## 1. 迁移工单必须记录

- 新服务器：云厂商、地域、系统版本、CPU、内存、磁盘、内外网 IP、SSH 用户。
- 新数据库：PostgreSQL 版本、地址、端口、库名、TLS、备份和恢复策略。
- Redis：地址、端口、TLS、持久化方案，是否允许清空短期会话。
- 新域名：API/H5、管理端、CDN、直播推流和播放、点播。
- 对象存储：Bucket、地域、CDN 域名、CORS、防盗链及旧文件保留策略。
- 第三方平台：微信、支付、物流、IM、直播、VOD、短信、邮件和 AI 服务。

密钥、密码和私钥只能进入服务器私有配置，不得提交到 Git。

## 2. 新服务器预部署

1. 将 DNS TTL 提前降低到 300 秒。
2. 上传已经通过门禁并记录提交 SHA 的项目版本，不允许服务器自行拉取不确定分支。
3. 执行服务器准备脚本：

   ```bash
   sudo DOMAIN=api.example.com LETSENCRYPT_EMAIL=ops@example.com \
     DATABASE_MODE=prepare bash docker/setup-server.sh
   ```

4. 首次执行会生成私有生产配置并安全退出；填写真实值后复核权限：

   ```bash
   chmod 600 docker/.env.production
   ```

5. 完整校验环境和发布配置：

   ```bash
   pnpm release:gate:full
   docker compose \
     -f docker/docker-compose.yml \
     -f docker/docker-compose.prod.yml \
     --env-file docker/.env.production config -q
   ```

6. 通过 hosts 或预览域名验证证书、H5、管理端和 API；正式 DNS 尚未切换时不得修改旧生产。

`release:gate:full` 不只是环境审计：它还会执行全仓静态检查、类型检查、共享算法包与服务端测试、16 套排盘/历法逐值回归，以及 Server、Admin、H5、微信小程序和 App 生产构建。任何一步失败都不得继续部署。

客户端公网变量在构建时固化，切换域名后必须重新构建 H5、小程序和 App：

- `VITE_API_URL` 必须等于 `PUBLIC_API_URL`，不要包含 `/api/v1`，客户端请求层会自动追加。
- `VITE_PUBLIC_H5_URL` 必须等于 `PUBLIC_H5_URL`，用于分享链接、海报和跨端跳转。
- `VITE_PUBLIC_ASSET_ORIGIN` 必须等于 `PUBLIC_ASSET_ORIGIN`，历史兜底图片会在构建时统一改写到该对象存储/CDN。
- 构建完成后必须检查 H5 与管理后台产物不再包含旧域名，再上传 H5 并重新提交小程序与 App 安装包。
- GitHub `production` Environment 必须同步设置同名 Variables：`VITE_API_URL`、`VITE_PUBLIC_H5_URL`、`VITE_PUBLIC_ASSET_ORIGIN`；缺失时发布任务会失败闭合。

`DATABASE_MODE` 只允许：

- `prepare`：只准备主机，不初始化数据库，默认且最安全。
- `restored`：确认已经从旧库恢复并完成校验后使用。
- `empty`：仅明确创建全新空库时使用，并同时提供 `CONFIRM_EMPTY_DATABASE=YES`。

## 3. PostgreSQL 全量迁移

### 导出

```bash
export SOURCE_DATABASE_URL='postgresql://旧库连接'
export MIGRATION_BACKUP_DIR='/secure/backups/guoxue-migration'
bash scripts/migration/export-postgres.sh
```

导出物包含 custom-format dump、SHA-256、public 表行数、数据库版本、扩展和 Prisma 迁移清单。脚本不会修改源库。

### 恢复

只允许恢复到新建空库：

```bash
export TARGET_DATABASE_URL='postgresql://新库连接'
export BACKUP_FILE='/secure/backups/guoxue-migration/xxx.dump'
export RESTORE_CONFIRM='新数据库名'
bash scripts/migration/restore-postgres.sh
```

目标 public schema 已存在业务表时脚本会拒绝执行，不得绕过保护。

### 核对

```bash
export TARGET_DATABASE_URL='postgresql://新库连接'
export SOURCE_COUNTS_FILE='/secure/backups/guoxue-migration/xxx.table-counts.tsv'
bash scripts/migration/verify-postgres.sh
pnpm --filter @guoxue/server exec prisma migrate status
```

必须确认：

- 所有 public 表精确行数一致。
- `vector`、`pg_trgm`、`pg_stat_statements` 可用。
- Prisma 迁移状态正常。
- 用户、订单、支付、退款、课程、古籍、圈子、文章、视频、直播、库存、采购、物流和售后抽样一致。

## 4. 最终停写窗口

1. 公告 10–30 分钟维护窗口。
2. 旧站停止下单、支付、退款、发货、库存调整、内容发布、积分及佣金写入。
3. 停止旧站 BullMQ 与定时任务，避免双消费者。
4. 执行最终导出、恢复和逐表计数核对。
5. 新环境只启动单实例，完成迁移状态和业务冒烟。
6. 全部通过后才切 DNS。

如要求零停机，必须另行完成 PostgreSQL 逻辑复制或云 DMS/DTS 演练，不能临时启用未经验证的复制。

## 5. Redis、会话和队列

- 缓存、验证码和短期会话可从空 Redis 启动。
- 如需减少强制登录，保留相同 `JWT_SECRET` 和 `JWT_PREVIOUS_SECRETS`。
- 支付补偿、退款、佣金和物流任务切换前后必须核对待处理数量。
- 幂等键或分布式锁依赖 Redis 时，必须先判断是否允许丢失；不允许时迁移 RDB/AOF。
- 旧、新消费者不得同时处理同一队列。

## 6. 第三方回调清单

所有 URL 都应以新的 `PUBLIC_API_URL` 为基准：

| 系统         | 配置项                         | 路径                                        |
| ------------ | ------------------------------ | ------------------------------------------- |
| 微信支付     | `WECHAT_PAY_NOTIFY_URL`        | `/api/v1/shop/pay/notify`                   |
| 微信退款     | `WECHAT_PAY_REFUND_NOTIFY_URL` | `/api/v1/shop/refund/notify`                |
| 支付宝       | `ALIPAY_NOTIFY_URL`            | `/api/v1/shop/alipay/notify`                |
| 银联         | `UNIONPAY_NOTIFY_URL`          | `/api/v1/shop/unionpay/notify`              |
| 汇付         | `HUIFU_NOTIFY_URL`             | `/api/v1/huifu/notify`                      |
| 快递100      | `KUAIDI100_CALLBACK_URL`       | `/api/v1/shop/logistics/kuaidi100/callback` |
| 腾讯 VOD     | 控制台回调                     | `/api/v1/videos/vod/callback`               |
| 腾讯直播     | 控制台回调                     | `/api/v1/live/callback`                     |
| 腾讯直播审核 | 控制台回调                     | `/api/v1/live/audit/callback`               |
| 腾讯 IM      | 控制台回调                     | `/api/v1/im/callback`                       |

还要更新微信网页授权和小程序合法域名、支付授权目录、App Universal Link/App Link、COS/CDN CORS、防盗链、短信/邮件/AI 的出口 IP 白名单。

## 7. 切流前验收

```bash
export PUBLIC_API_URL='https://新API域名'
export PUBLIC_H5_URL='https://新H5地址/'
export EXPECTED_ORIGIN='https://新H5域名'
bash scripts/migration/smoke-test.sh
```

人工验收至少覆盖：

- 登录、刷新登录态、搜索、客服、消息、举报和投诉。
- 首页、发现、圈子、工具、个人中心。
- 课程购买、商品下单、支付回调、退款、库存、采购、发货、物流和售后。
- 古籍阅读/听书、文章、视频、直播、智能体和语音通话。
- 分享卡片、海报二维码、微信打开、小程序跳转和 App 深链。
- 管理端、商家端、从业者工作台。
- H5 手机/平板/PC、小程序和 App 真机。

## 8. DNS 切换与回滚

先切 API/H5，观察 15–30 分钟，再切管理端/CDN。持续观察 5xx、登录、CORS、数据库连接、慢查询、队列积压、支付/退款回调、IM、直播和 VOD。

以下任一情况应立即评估回滚：

- 支付、退款或订单出现错账、重复入账。
- 表计数或关键业务抽样不一致。
- 大面积登录失败、证书/CORS 错误。
- 核心回调持续失败且 15 分钟内无法修复。

回滚只恢复 DNS 和旧站写入，不得用旧库覆盖新库。切流期间的新数据要单独导出、对账和补偿。

## 9. 旧资源下线条件

- 新 DNS 稳定超过 72 小时。
- 所有第三方回调验证成功。
- 新库完成自动备份和至少一次恢复演练。
- 订单、支付、退款、佣金、库存和物流连续三天对账正常。
- 旧数据库、对象存储和日志完成不可变归档。
- 负责人书面确认回滚窗口结束。
