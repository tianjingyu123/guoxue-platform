## 问题与修复

分享页使用 `https://gx.yrydai.com/h5/`，但原 Android Manifest 仅登记 `api.rebugx.cn`，站内 `parseAppEntryLink` 也仅接受 API 域名。因此即使公开关联文件配置正确，H5 分享链接仍缺少原生接收和安全路由的完整链路；这是独立于手机 `legacy_failure` 的代码缺口。

本次在两份 Android Manifest 中为正式 H5 增加独立 `autoVerify` 过滤器，继续使用既有主 Activity 别名，范围限定 HTTPS 和 `/h5/`。解析器从构建时 `VITE_PUBLIC_H5_URL` 提取精确可信主机，仅允许配置为 HTTPS 默认端口和 `/h5/`；既有 API 回跳保留。伪域名、URL 凭据、异常端口、越界/编码分隔路径和可复用敏感凭据继续拒绝。旧排盘承接结果页与圈子分享普通参数可映射回站内路由，页面及后端权限仍须校验。

iOS Associated Domains 声明补 `applinks:gx.yrydai.com`，既有 API 域声明和微信 OAuth/分享/支付的 `https://api.rebugx.cn/h5/` UniversalLinks 均保留。**这不是签名描述文件、Team ID、微信平台登记或 iOS 真机通过的证明。**按 [Android 官方说明](https://developer.android.com/training/app-links/add-applinks)，域名须在原生 Manifest 中声明并完成关联验证；公开 `assetlinks.json` 200 不能代替系统验证。
