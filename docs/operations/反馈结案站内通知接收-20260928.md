## 闭环与权限边界

后台把工单从其他状态改成 `resolved` 时，必须重新填写面向用户的回复。服务端先按原状态做条件更新，成功后才用 `FEEDBACK_RESOLVED:<反馈ID>:<本次更新时间>` 建站内通知；并发失败、重复结案和推荐负反馈信号不发通知。通知正文只提示去“我的反馈”查看，不复制反馈正文、联系方式或回复。通知失败仅记录告警，不撤销已完成的结案，但**尚无失败补偿任务**，不能写成可靠送达。

历史 `Feedback.result` 原本是内部处理备注。本批仅将新结案时带明确版本标记的回复返回给反馈本人；旧备注、处理中备注和回退原因均不作为用户回复。管理端列表/详情里的处理备注继续按既有规则脱敏；状态流转表单不预填旧备注，避免将内部信息或脱敏串误存为公开回复。移动端“我的通知”和 IM 消息中心两处通知点击均进入“我的反馈”的历史页，该接口按当前登录用户 ID 查询；此项是源码与定向测试结论，尚无线上跨账号真机验收。
