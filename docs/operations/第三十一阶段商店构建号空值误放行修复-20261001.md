## 问题与修复

原脚本对旧构建号直接使用 `Number`：Android／鸿蒙 null 或空字符串可能被当成 0，布尔值和数组也可能变成整数；iOS 的原 null／空字符串排除仍不能阻止空白、布尔值及数组。候选号超出 JavaScript 安全整数范围时也可能被当成合法版本。

独立修复提交 `d6b7775312b77078580fcca576afeecb24f1d742`，起点 `5bb4550d6e9442f2c30dbb9b5174baf5f49008e0`，仅修改：

- `scripts/release/audit-store-readiness.mjs`
- `tests/release/audit-store-readiness.test.mjs`

候选和三端基线先统一验证：接受正安全整数数字或十进制数字字符串；拒绝缺失、空白、布尔值、数组、零占位、负整数、字符串指数／十六进制／小数写法及不安全候选整数，再执行严格大于比较。有效数字和字符串基线保持兼容，候选号等于线上旧号不能作为升级。该校验是仓库发布输入约束；没有据此声称鸿蒙／iOS 的全部平台版本规则一致。[Android 官方版本说明](https://developer.android.com/studio/publish/versioning)明确要求正整数 versionCode，系统以此保护覆盖升级／降级。
