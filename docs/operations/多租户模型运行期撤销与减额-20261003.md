# 多租户模型运行期撤销与减额

本批继续用户要求先完成其他工作、最后协调主窗口接收。在既有独立候选中补齐模型授权的运行期核验，不使用真实客户、供应商账号或付费调用；两个用户指定虚拟主体的前批证据保留。源码只修改本任务工作树，既有schema及143个迁移目录未改。

## 实现行为

此前供应商签名及预算只在启动时读取，维护侧撤销或减额后旧进程继续用旧记录。本批将运行期就绪、预算及实际派发改为重读同一绝对路径受限文件，每次验证客户、空间、认证密钥、签名、有效期及明确调用授权。文件损坏、客户条目删除、篡改预算或撤销返回未就绪，不缓存旧授权、不继承平台环境变量。

模型、官方端点和供应商密钥指纹仍固定于启动配置；即使轮换登记有合法签名，旧进程也拒绝继续，需要明确重启。启动时没有客户登记的进程不会自动开通通道。签名提高预算可在既有进程生效，须来自实际授权；本批提高只使用合成测试预算。

预留事务提交后、HTTP派发前，重新取得客户预算锁并核当前签名和全客户持久总次数/未确认名额（包括本次预留）。不符合减额后上限则ABORTED，不调用供应商，累计次数保留。预留、派发检查都是客户级锁，不占锁等待外部服务。完整答复返回后及数据库提交前再次核授权，撤销则回滚助手正文和完成审计，保留ABORTED结果事实。

已经通过最后授权检查并派发到供应商的请求无法撤回；维护文件替换与外部HTTP不是跨系统原子事务。撤销会阻止后续授权检查通过和在途答复提交，不承诺已派发请求未计费。完整历史同键仍可查询，UNKNOWN不自动补发或释放，ABORTED仍计累计次数。

维护侧必须单写并原子替换同一路径文件。本批实际验证同机三个进程共用同一受限文件，未证明不同主机/容器的配置副本同步、配置指纹一致性门禁或生产运维窗口。受限文件保留现有ACL，密钥不进聊天、Git或公开报告。

## 专项与错误处理

专项使用三个真实Nest进程、真实本任务PostgreSQL及共享签名文件，HTTP为loopback供应商替身。覆盖两个旧进程减额、PG触发器暂停已经检查旧预算的预留后减额、显式签名提高额度、同时撤销、历史重放、删除条目不影响另一客户、篡改及损坏配置、在途撤销不保存答复、固定密钥轮换拒绝。

首个探针因Prisma无法反序列化锁函数void返回值提前退出，不计通过。已清除测试触发器、恢复原合成授权并核本任务进程归零；修正为执行锁语句，并给并行同步任务安装拒绝处理，避免异常跳过finally。最终证据使用冻结后完整回归，早期探针与清理摘要单列，不改写历史结果。
