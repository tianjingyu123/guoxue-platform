## 业务边界复核与修正

- 支付成功通知只在订单支付处理及 `ORDER_PAID` 外发箱写入成功后调用，幂等键 `ORDER_PAID:<orderId>`；通知异常被记录，不反向改变已提交的支付状态。支付事务失败时不会走此调用。
- 退款完成通知只在退款 CAS、权益及相关语音冲正事务提交后调用，幂等键 `ORDER_REFUNDED:<orderId>`。原候选存在通知抛错让已完成的退款接口报错的问题；本轮改为记录失败并保留退款成功结果。重复退款确认会用同一幂等键补尝试；事务失败不发完成通知。
- 通知先落站内记录，再读取外部推送偏好。原候选若“落库成功、偏好读取失败”会释放 Redis 幂等锁，重试可能生成第二条；本轮将落库后的推送准备失败降为告警，保留已落库结果和幂等锁。
- `FAIL/CLOSED/ABNORMAL` 退款回调继续只发送“退款未完成”语义。通知内容不含金额、手机号或支付流水。详情查询条件包含 `id + userId`，本轮补了跨用户访问的单测；点击后的具体订单/售后接口仍须依靠资源自身权限测试。
