# 证书生命周期与 CDN 安全配置决策清单

更新时间：2026-08-01
适用环境：历史预发布 `pre-api.rebugx.cn`、`pre-static.rebugx.cn`，以及待接入的新正式域名

> 本文不记录密码、Secret、私钥、证书正文或对象内容。所有变更先在预发布验证，旧生产域名不在本清单的自动变更范围内。

## 1. 已确认现状

- CLB 的 HTTPS 监听器绑定 `pre-api.rebugx.cn` 临时证书，公网实际证书有效期为 2026-07-30 至 2026-10-28。
- CDN 域名 `pre-static.rebugx.cn` 已启动并完成 CNAME，源站为北京 COS 私有 Bucket，私有源回源已开启；公网实际证书有效期为 2026-07-30 至 2026-10-28。
- 两张公网证书均为 TrustAsia DV RSA 证书，仅覆盖各自精确域名。
- Prometheus 已对两张证书持续采集实际公网到期时间，当前剩余约 88 天。
- 证书告警为互斥三级：60～30 天准备权限与方案，30～14 天执行续期、验证和部署，14 天内启用人工签发与部署兜底；企业微信继续接收告警。
- CDN 防盗链、IP 黑白名单、IP 访问限频、Token 鉴权、UA 规则和区域访问控制均未启用；当前没有证据表明已配置用量封顶。
- COS 运行时使用 CVM 实例角色；角色具备业务所需的对象操作权限，但不能读取 CLB、CDN、SSL、云监控或 Bucket 管理配置，符合最小权限原则。
- CDN 当前按流量小时结算，控制台未显示可抵扣流量包；今日预发布用量很低，不能据此估算正式流量包。

## 2. 已核实的供应商规则与上线口径

- 腾讯云免费证书在到期前 30 天开放“快速续期”，实质是重新申请新证书，不是无人值守自动续费；新证书签发后仍需重新部署。
- 只有域名 DNS 托管在腾讯云解析时，腾讯云才支持自动添加 DNS 验证记录；使用其他 DNS 服务商时必须人工添加验证记录。
- 付费证书可配置自动续费，但余额、域名验证、签发和部署仍可能需要人工介入；未取得公网握手证据前不得判定续期完成。
- 腾讯云证书托管仅在目标云资源和证书均满足条件且已实测时，才可作为自动部署能力；新服务器、新域名和新账号必须重新验收。
- 标准自建部署可使用项目已有的 Let's Encrypt 路径；腾讯云 CLB/CDN 部署则按证书控制台、DNS 验证和云资源绑定流程执行。两条路径不得混用证据。

正式域名接入时必须在基础设施清单记录：证书供应商与类型、DNS 托管方、验证方式、部署目标、续期责任人、人工兜底责任人和公网验收地址。没有这些信息时，证书门禁保持未完成。

## 3. 历史预发布证书时间线

| 阶段 | 内部截止时间 | 必须完成的工作 |
| --- | --- | --- |
| 续期/替换准备 | 2026-08-29 前 | 确认证书类型、覆盖域名、DNS 与证书控制台权限、部署责任人；创建变更单 |
| 正式替换 | 2026-09-28 前 | 将新证书分别绑定 CLB HTTPS 监听器与 CDN 域名，并完成公网验收 |

上述日期只适用于历史预发布证书，不可直接复用为新域名的上线证据。新正式证书应优先选择能够由公司账号持续管理且与实际 DNS、CLB/CDN 或自建入口兼容的方案；免费、付费、精确域名、多域名或通配符证书均需按实际成本、覆盖范围和续期自动化能力评估，不得只凭“免费”或“覆盖面大”作决定。

## 4. 续期与替换执行顺序

1. 在选定的证书供应商完成重新申请或续费、域名验证和签发，不上传或转发私钥到聊天工具。
2. 先在预发布 CLB 的 HTTPS:443 监听器替换 `pre-api.rebugx.cn` 证书。
3. 验证 H5、管理后台、API、Socket.IO、HTTP→HTTPS 跳转和移动端登录。
4. 再在 CDN 的 `pre-static.rebugx.cn` HTTPS 配置中替换证书。
5. 验证静态资源 200、缓存响应头、跨域和 COS 私有回源。
6. 用公网握手读取 `subject`、SAN、颁发机构和 `notAfter`；不能只凭控制台显示“已部署”判定成功。
7. 确认 Prometheus 两条 `probe_ssl_earliest_cert_expiry` 时序均更新到新到期时间，三级旧证书告警全部保持非触发状态。
8. 保留旧证书到新证书稳定运行 24 小时后，再决定是否删除未绑定证书；删除前必须重新核对绑定资源。
9. 若任一自动续费、自动 DNS 验证或证书托管条件未满足，立即切换人工签发与部署兜底，不得等待自动流程自行恢复。

## 5. CDN/COS 安全策略取舍

### 当前不直接开启

- **Referer 防盗链**：APP、小程序、下载器或分享链接可能不携带 Referer，直接开启可能造成图片、音视频或附件大面积 403。
- **Token 鉴权**：需要服务端签名 URL、客户端刷新和过期重试配套，不能只在 CDN 控制台单边开启。
- **IP 限频**：移动运营商和企业 NAT 会让大量用户共用出口 IP，未取得真实流量分布前容易误伤。
- **硬性用量封顶**：达到阈值会主动停止服务，应先确定可接受的月度预算、日峰值和告警联系人。

### 建议上线前完成

- COS 继续保持私有读写，CDN 继续使用私有源回源；禁止改为公有读写来解决临时访问问题。
- COS 生命周期仅清理未完成的分片上传；用户上传的图片、音视频、课程和附件不得设置统一自动过期。
- 评估为新对象开启 SSE-COS 服务端加密；上线前用上传、CDN 回源、下载和删除闭环验证兼容性。
- CDN 先设置费用/流量异常告警，再根据真实一周流量决定资源包和是否增加硬封顶；启用任何可能产生费用的日志、WAF 或安全产品前单独确认。
- 若后续决定启用 CDN Token 鉴权，必须先完成服务端签名、APP/小程序/H5 兼容和旧版本灰度，再在 CDN 开启。

## 6. 待新资源接入后填写的决策

- 证书供应商、免费或付费、精确域名/多域名/通配符方案，以及预算和发票主体。
- 新正式域名的 DNS 托管方；若不在证书供应商托管，指定人工 DNS 验证责任人与应急登录方式。
- CLB/CDN 或自建入口是否满足证书托管/自动部署条件，并记录一次真实续期演练的公网证据。
- CDN 月度预算、异常告警阈值和达到预算后是“只告警”还是“停止服务”。
- 是否为 COS 新对象启用 SSE-COS，以及未完成分片上传保留 7 天是否可接受。
- 是否购买 CDN 流量包、WAF 或 CLS 七层访问日志；这些均可能产生新增费用。
