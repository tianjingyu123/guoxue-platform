第三方失败日志和指标仅保留接口名称、安全整数错误码或固定分类。ErrorInfo、响应正文和原始网络异常不进入日志、指标或上层异常；客户端保留 THIRD_IM_FAILED 业务码，改为通用中文提示。超时／网络／解码失败分类固定，私信异步审核失败保留已发送结果。五类 WebSocket 推送入口继续捕获失败，不记录可能含消息的异常对象。

请求日志、RequestContext 的 path、慢请求告警和 5xx 告警只保留 URL 路径，去掉查询参数与片段。IM 请求异常只记录安全类别，开发环境也不展开其异常堆栈。未改原请求 URL、查询参数、回调验签、消息内容或异常响应中的 path 字段。JSON 中的 `imErrorLogAndTraceContextOnlySafeCategory` 仅指应用错误日志／RequestContext，**不表示 OpenTelemetry span 已脱敏**。

## 复现与本轮验证

修复前固定来源上仅新增测试文件：最终完整捕获的 28 项模块隐私断言全部按预期失败。模块修复后，真实 HTTP 复现进一步检出请求 URL／告警泄露：8 项中 7 项按预期失败，错误签名拒绝的 1 项原本就通过。两组最终复现均无跳过，汇总脚本正常结束。
