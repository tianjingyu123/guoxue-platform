## 许可预检修正

第一轮提交 `68a9e02d3fcb0178551f86096f1ed0da603306a4` 的 [运行 36899048986](https://github.com/tianjingyu123/guoxue-platform/actions/runs/36899048986) 在安装前失败。辅助程序手工将 XML 正文赋给 License 对象，遗漏 SDK 的 JAXB 文本适配器，造成标准许可未接受的误报。失败回执与日志完整保留，未安装镜像、没有核心通过结论。

修正后使用官方 `SchemaModuleUtil.unmarshal` 和 `AndroidSdkHandler.getAllModules()` 取得 SDK 实际 License 对象，再调用 `License.checkAccepted`。XML 原文摘要仍单独保留，不用手工改写许可摘要或重新接受协议。本机及托管环境实测一致：

此前预览许可原文 SHA-256 `4812a1e9...` 对应未归一化的 XML 正文，可继续用于原文核对；旧辅助程序计算的 `e0f3013...` 不作为 SDK 实际接受摘要，旧 Phase22 手工赋值接受入口不得继续使用。未来若明确接受预览许可，须对官方加载器返回的实际 License 对象操作并回读，另存新回执。

本轮标准许可确认已不再需要；未执行任何接受操作。AOSP 官方包引用既有标准许可，因此完成这两项测试没有接受 Google APIs 预览许可。Google APIs/x86_64 的 API31/32 镜像仍未安装、未运行核心，不计作该镜像变体覆盖。

## API31 官方元数据差异

官方目录声明 AOSP API31 修订 5，归档 `x86_64-31_r05.zip` 内 `source.properties` 的 `Pkg.Revision` 却为 3。本轮通过官方 HTTPS Range 只读获取该 ZIP 中央目录和此成员，CRC 校验通过，成员 SHA-256 为 `df7aad3e6bba94fc964fb919ed88a082e3f828fc2981fcf33b466dbfa0da5922`，与作业采集文件逐字节一致。因此分别记录“目录修订 5”和“归档属性声明 3”，不将属性 3 误写为目录修订 5。

这次元数据查询没有下载整份镜像，也没有独立复算整包 SHA-1；不作整包复算结论。镜像实际安装由官方 sdkmanager 完成，API31、default、x86_64 和运行设备身份均已核实。API32 目录及属性均为修订 2。
