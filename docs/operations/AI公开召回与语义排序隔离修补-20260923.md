# AI 公开召回与语义排序隔离修补（2026-09-23）

状态：`codex/circle-knowledge-universe-3d-20260923` 隔离候选，未合入、未部署；以下仅是源码和模拟测试结果，非正式内容库验收。

## 本轮修补

1. 全局视频搜索的 FTS 与 ILIKE 两条路径，统一要求 `PUBLISHED`、`APPROVED`、`PLATFORM` 且非私密，和视频公共瀑布流的准入一致。原路径只检查 `PUBLISHED`，可能返回圈内或私密视频的标题与播放地址。
2. 语义候选补齐文章/课程/圈子/平台内容的软删除过滤，以及课程的全平台可见、视频的公开审核/非私密过滤。语义搜索仍限现有五类，不宣称全平台类型已覆盖。
3. AI 内容导览按实时发布状态检索，不读取 120 秒旧缓存。自定义权重检索也不再复用无权重缓存；**该阶段**普通搜索仍保留缓存。后续隔离补丁见下文。
4. 语义初筛的问题和候选均用同一种本地向量。外部重排时把问题与候选标题一起调用同一 Embedding 模型，避免跨向量空间直接比较；先按初筛分数选 Top 20 再重排。
5. 内容向量增量更新改为按目标 ID 精确读取，避免只查最近 1000 条导致早期上架内容无法更新；仍复用审核、公开与版权门禁。
6. 新增 `apps/server/scripts/audit-ai-content-coverage.ts` 只读盘点入口：按文章、课程、视频、商品、圈子、平台内容、古籍分别输出总数、可公开数、标题/简介/封面/标签缺失数；帖子和直播仅报总数，公开条件未统一前不推断可推荐量。不读正文、用户资料，不写库，不调用 Embedding。运行前必须核对目标数据库身份与只读账号，并传 `--read-only`；本轮未连任何真实数据库。
7. AI 内容导览增加短视频卡：只有明确找视频/演示的意图才加入；卡片只从前述公开过滤后的搜索结果生成，导航到现有短视频详情页。移动端同步加类型标签与目标路径白名单；普通知识问答不自动塞视频卡。
8. 商品卡只在明确找商品/商城/选购时从已上架、未删除的公开搜索结果加入；显示商品类型和检索时价格快照，最终价格与可购买性以详情页为准。退款、订单和投诉问题仍由原有抑制规则拦截。
9. 零命中主题补检只把当前问题允许展示的类型算作命中；无关视频或商品不能阻断古籍/文章的主题补检。

## 剩余验收入口

1. 在受控只读内容库准备每类公开、圈内、私密、未审核、软删除样本；分别调 `/search?type=video`、语义搜索和 `/search/guide`。通过：任何不合资格样本的 ID、标题和地址均不出现；公开样本可打开。脱敏结果存 `artifacts/ai-content-catalog/eligibility/`。
2. 固定匿名化查询集，比较修补前后的相关性、Precision@4、空结果率和 p95 延迟；Embedding API 的模型、维度、调用量及费用按受控测试环境记录，不以单元测试代替效果评估。证据存 `artifacts/ai-content-catalog/evals/`。
3. 后续隔离补丁已关闭普通搜索的 Redis 结果缓存，并给搜索、语义、导览响应设置 `Cache-Control: no-store`；但正式代理/CDN、详情页二次鉴权和其他推荐链路缓存尚未验收，不能宣称全平台撤权即时生效。由于每次搜索都重查数据库，主线合入前须对真实数据量测 p95 延迟、QPS 和数据库负载；不达标应改用可靠的按内容变更失效机制。
4. 只读覆盖率工具的结果存 `artifacts/ai-content-catalog/eligibility/`，记录脱敏的数据库环境标识、源码 SHA、执行时间、各类型计数；不保存连接串或账号口令。工具当前不统计目录/向量索引缺失数，因为统一目录尚未建成且 Redis 向量库存储方式待替换；不能把“可公开数”当成“已进入推荐数”。
5. 本地星图样例 HTTP 检查返回 200 且页面包含 `3d-force-graph`，但浏览器控制通道两次返回 `nodeRepl.fetch request failed`，没有获得交互或视觉证据；Android 真机、微信小程序和正式运行包仍未覆盖。

## 后续隔离补丁：普通搜索撤权缓存边界

普通 `/search` 曾在未带自定义权重的单类型查询中复用 120 秒 Redis 结果，可能短时返回已撤下的标题/地址。本候选取消该结果缓存的读取和写入，所有类型均执行当前公开 SQL；`fresh` 参数暂保留以兼容已有调用。新增单测确保伪造的旧 Redis 撤权结果不会返回。**新运行**搜索/控制器/导览/语义相关 Jest 实际匹配 5 套件 60 项通过，均为模拟数据库与缓存。搜索结果的及时性仍取决于数据库状态，尚未实测正式代理、真实库性能或其他推荐服务缓存。
