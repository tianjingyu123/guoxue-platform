# 隔离业务旅程验收手册

## 目标

在新服务器、新数据库和新域名完成部署后，用可回滚、可追溯的真实业务请求证明关键链路可运行，而不触发真实支付、短信、退款、回调、发货或物流订阅。

验收工具只允许访问同一 API 源下的 `/api/v1/`，远程环境必须使用 HTTPS。所有写入都要求 `QA_` 前缀、命令行双重确认以及清理步骤。

## 分层执行

### 1. 公共只读旅程

```powershell
corepack pnpm release:verify-business-journeys -- --spec config/release/business-journeys.example.json --api-origin https://pre-api.example.com --journey public-readiness --release-id release-20260803-001 --report artifacts/release/business-public.json
```

### 2. 登录只读旅程

令牌只通过当前进程环境变量传入，不写入仓库或报告：

```powershell
$env:QA_USER_TOKEN = '<QA 用户令牌>'
$env:QA_MERCHANT_TOKEN = '<QA 商家令牌>'
corepack pnpm release:verify-business-journeys -- --spec config/release/business-journeys.example.json --api-origin https://pre-api.example.com --journey authenticated-user --release-id release-20260803-001 --report artifacts/release/business-user.json
corepack pnpm release:verify-business-journeys -- --spec config/release/business-journeys.example.json --api-origin https://pre-api.example.com --journey merchant-operations --release-id release-20260803-001 --report artifacts/release/business-merchant-read.json
```

### 3. 商家采购单闭环

前置数据必须是专用 QA 商家、已启用的现有供应商和该商家的在售测试商品；供应商名称、商品名称或 SKU 必须以 `QA_` 开头，便于数据库与审计日志检索。旅程只创建草稿采购单并取消，禁止提交和收货入库。

```powershell
$env:QA_MERCHANT_TOKEN = '<QA 商家令牌>'
$env:QA_MERCHANT_PRODUCT_ID = '<QA 商家的测试商品 ID>'
$env:QA_MERCHANT_SUPPLIER_ID = '<QA 商家的已启用供应商 ID>'
$env:QA_MERCHANT_SUPPLIER_NAME = '<以 QA_ 开头的供应商名称>'
$releaseId = 'release-20260803-001'
corepack pnpm release:verify-business-journeys -- --spec config/release/business-journeys.write.example.json --api-origin https://pre-api.example.com --journey merchant-purchase-order-cycle --release-id $releaseId --allow-write --confirm-write "QA_WRITES:$releaseId" --report artifacts/release/business-merchant-write.json
```

### 4. 用户待付款订单闭环

前置商品必须是专用 QA 实物商品，商品名称或 SKU 必须以 `QA_` 开头，并至少保留 1 件可售库存。QA 用户不能是商品所属商家。旅程创建待付款订单后立即取消，库存应被服务端回补；不得调用任何支付接口。

```powershell
$env:QA_USER_TOKEN = '<QA 用户令牌>'
$env:QA_SHOP_PRODUCT_ID = '<专用 QA 商品 ID>'
$releaseId = 'release-20260803-001'
corepack pnpm release:verify-business-journeys -- --spec config/release/business-journeys.write.example.json --api-origin https://pre-api.example.com --journey customer-order-cycle --release-id $releaseId --allow-write --confirm-write "QA_WRITES:$releaseId" --report artifacts/release/business-order-write.json
```

脚本会在写入前读取并核验商品、供应商名称必须以 `QA_` 开头；任一 ID 指向普通业务资源时会在创建订单或采购单前阻断。订单取消后还会复核商品库存与下单前一致。

## 放行标准

- 健康接口返回的 `releaseId` 必须等于本次发布标识，不得为 `unversioned`。
- 每份报告 `success` 必须为 `true`，主流程和清理步骤均为 `PASS`。
- 取消请求完成后必须重新读取采购单或订单，确认服务端持久化状态确为 `CANCELLED`。
- 允许保留带 `QA_RELEASE_ACCEPTANCE` 的已取消记录作为审计证据，但不得存在待付款、待收货或库存净变化。
- 不得出现支付流水、短信发送、退款、回调、发货、物流订阅或真实通知。
- QA 令牌、业务 ID 和报告文件不得提交到 Git。

## 迁移后的最低证据集

1. 公共、登录用户和商家只读报告。
2. 商家采购单创建与取消报告。
3. 用户订单创建与取消报告。
4. 同一发布标识的健康检查、构建摘要、数据库基线、备份可恢复性和回滚演练记录。
