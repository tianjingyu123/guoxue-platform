# 微信支付新账套替换清单

## 结论

当前旧订单全部是测试数据，不存在旧商户号退款、查单或对账责任，因此生产系统只保留一套微信支付配置。新商户资料写入原配置键 `third_party.wechat_pay`，不增加双账套路由和订单账套字段。

旧服务器作为开发测试环境：

- 日常自动化和本地开发使用 Mock，不连接真实支付；
- 发布前的支付联调使用新商户号做受控小额真实支付和退款；
- 不再使用旧商户号制造新的测试交易。

微信支付 APIv3 没有通用独立沙箱，生产接口也禁止压测。参考：[微信支付最佳安全实践](https://pay.wechatpay.cn/doc/v3/merchant/4012073699)。

## 需要交接的资料

| 资料 | 是否需要 | 后台字段 | 说明 |
| --- | --- | --- | --- |
| 与商户号绑定的 AppID | 必需 | 绑定 AppID | 小程序、公众号或 APP 的 AppID，必须已与新商户号绑定 |
| 商户号 | 必需 | 商户号 | 新商户号 `mchid` |
| APIv3 密钥 | 必需 | APIv3 密钥 | 商户平台自行设置的正好 32 字节字符串，不是证书密码 |
| 商户 API 证书序列号 | 必需 | 证书序列号 | `apiclient_cert.pem` 对应序列号，不是 `PUB_KEY_ID_...` |
| 商户 API 私钥 | 必需 | 商户私钥 | `apiclient_key.pem` 完整 PEM 内容；严禁通过聊天、邮件或代码仓库传递 |
| 微信支付公钥 | 新商户默认必需 | 微信支付公钥 | 商户平台下载的 `pub_key.pem`，用于验证微信响应和回调 |
| 微信支付公钥 ID | 公钥模式必需 | 微信支付公钥 ID | 与 `pub_key.pem` 成对，格式 `PUB_KEY_ID_...` |
| APIv2 密钥 | 不需要 | 无 | 本项目只调用 APIv3；不要为了本项目额外启用 APIv2 |
| `apiclient_cert.pem` 文件内容 | 后台无需粘贴 | 无 | 妥善归档；后台只需其序列号和配套私钥 |

新申请商户号通常默认使用微信支付公钥模式。只有商户平台已明确切换为“平台证书模式”时，微信支付公钥和公钥 ID 才能同时留空。APIv3 的商户请求仍必须由商户 API 私钥签名。参考：[APIv3 概述](https://pay.wechatpay.cn/doc/v3/merchant/4012081606)、[申请商户 API 证书](https://pay.wechatpay.cn/doc/v3/merchant/4012072428)。

## 新域名回调

后台会按当前 `PUBLIC_API_URL` 给出推荐值，应填写：

- 支付回调：`${PUBLIC_API_URL}/api/v1/shop/pay/notify`
- 退款回调：`${PUBLIC_API_URL}/api/v1/shop/refund/notify`
- 商家转账回调：`${PUBLIC_API_URL}/api/v1/payout/wechat/transfer-notify`

三个地址都必须是公网 HTTPS、无需登录、不能经 301/302 跳转到旧域名。支付和退款下单时会把对应地址直接传给微信。

## 后台替换步骤

1. 先确认新服务器 `ENCRYPTION_KEY` 已安全备份；该密钥用于解密后台保存的第三方配置。
2. 进入“系统 → 第三方配置 → 支付 → 微信支付”。
3. 把商户号、APIv3 密钥、证书序列号、商户私钥、微信支付公钥和公钥 ID 全部填写为新账套值。敏感字段显示为掩码时，粘贴非空新值即可覆盖；不能保留代表旧值的掩码。
4. 使用页面给出的三个当前域名推荐回调，覆盖旧域名。
5. 保存。后台会把所有非空新值覆盖到原 `third_party.wechat_pay` 配置并立即热同步，不会新建第二套账套。
6. 保存后敏感字段只显示尾号掩码；数据库中整张配置使用 `ENCRYPTION_KEY` 加密存储。

## 上线前闭环验证

至少完成一次：

1. 新商户号创建 JSAPI 小程序支付单；
2. 使用白名单测试用户完成小额真实支付；
3. 确认新域名回调验签、解密、商户号校验成功，订单只入账一次；
4. 发起全额退款；
5. 确认退款查询和退款回调收敛为成功；
6. 重放同一支付/退款回调，确认幂等；
7. 按实际首发端补测公众号 JSAPI、H5、Native、APP；未首发的端不阻塞本次切换；
8. 核对微信商户平台交易、系统订单、退款记录和财务金额一致。

任何一步失败都不要开放真实用户支付。商户私钥、APIv3 密钥和 `ENCRYPTION_KEY` 不得出现在截图、日志、工单、Git 或聊天记录中。
