# 旧排盘全 H5 壳内复核（2026-09-27）

## 目标与当前边界

用户目标是从进入排盘、微信授权、填写资料、查看结果，到分享当前结果和返回热卜，全程留在热卜 H5 外壳。此前“只要拿到第三方真实地址，不需要第三方配合即可完成”是过度承诺。地址只能决定最初加载什么，不能赋予热卜对跨域子页及其后续跳转的控制权。

当前线上分享临时修复让链接可打开：热卜承接页校验地址后顶层跳至 `www.yrydai.com`。它解决“分享链接无效”，但不满足全程保壳；不得称为内嵌完成。

## 本轮隔离实测

- 在两台新上线节点的 H5 共享卷临时安装相同测试页 `https://gx.yrydai.com/h5/qa/legacy-frame-20260927/index.html`，页面 SHA-256 `fb5f26a19758be5c0964b872fb65ce0a927a166794411bcd7591541395fd6d8e`。国学2 `inv-d96n6vgt89`，国学1 `inv-e96n7dg23c`，均成功且 Nginx 文件哈希一致；只测试公开入口，不读取账号、盘面或支付信息。
- 在隔离浏览器打开该页，热卜外框正常；内嵌 `www.yrydai.com/p1.php?mod=bazi&ruid=5` 实际跳到 `open.weixin.qq.com/connect/oauth2/authorize`，浏览器显示“请在微信客户端打开链接”。切换 `www.yrydai.cn/guide.php?mod=index&act=guoxue` 后，同样跳至旧公众号 OAuth。此结果证明两个公开入口并非可直接操作的免授权内页；普通浏览器结果不能代替微信真机结论。
- 点击测试页“检查当前分享地址”，得到“跨域：热卜 H5 无法读取切换后的真实盘面地址”。这是页面自身执行跨域读取所得结果，不是仅凭推测。即使已经拿到某次打开时的公开链接，也不能据此自动得到用户在第三方页面中继续操作后的当前结果链接。
- 2026-09-11 已有 Android 微信真机记录：热卜外框可见，第三方 `p1.php` 内部持续空白，未形成可操作盘面。本轮没有获得新的微信真机嵌入成功证据，也没有重做该项测试。不能用隔离浏览器中的 OAuth 错误替代微信端失败原因诊断。
- 本轮测试页已按固定 SHA 只删除自身文件。国学2 `inv-d96ngjg958` / `invt-d96ngjg959`、国学1 `inv-e96nh20mn3` / `invt-e96nh20mn4` 均成功退出 0。没有改变正式分享页、镜像、数据库或第三方网站。

## 可独立完成与最小依赖

热卜可独立完成外壳页面、公开入口白名单、分享卡片外观、外壳自己的返回按钮和登录前后的热卜路由恢复；可以对已知的公开结果 URL 生成热卜承接链接。以上不能解决子页 OAuth、子页内部返回/分享动作，以及切盘后准确获取当前结果 URL。

若坚持全部流程留壳，至少要从第三方取得两项可验证能力：

1. 微信 H5 中可嵌入的授权后入口或等效会话交接，使排盘页在热卜外框中真正可填写、可出结果；若第三方禁止或破坏嵌入，必须由其提供支持方案。
2. 子页向热卜父页主动发送当前公开结果地址或盘面 ID、分享与返回动作（例如受限来源的 `postMessage` 协议）；热卜校验来源与窗口后生成分享链接。无需第三方交付整套源码。

没有这两项实测通过前，不把 iframe 试验切到正式业务，也不通过反向代理第三方登录、OAuth、支付或修改浏览器安全策略来伪装同源。`yrydai.com` 腾讯云接入备案通过后，还需单独复测微信域名提示和正式 H5 链路；备案结果本身不能改变跨域权限。

参考：MDN 对跨源 iframe 的访问限制及 `postMessage` 跨源通信说明，见 https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy 与 https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage 。
