## 可独立完成与最小依赖

热卜可独立完成外壳页面、公开入口白名单、分享卡片外观、外壳自己的返回按钮和登录前后的热卜路由恢复；可以对已知的公开结果 URL 生成热卜承接链接。以上不能解决子页 OAuth、子页内部返回/分享动作，以及切盘后准确获取当前结果 URL。

若坚持全部流程留壳，至少要从第三方取得两项可验证能力：

1. 微信 H5 中可嵌入的授权后入口或等效会话交接，使排盘页在热卜外框中真正可填写、可出结果；若第三方禁止或破坏嵌入，必须由其提供支持方案。
2. 子页向热卜父页主动发送当前公开结果地址或盘面 ID、分享与返回动作（例如受限来源的 `postMessage` 协议）；热卜校验来源与窗口后生成分享链接。无需第三方交付整套源码。

没有这两项实测通过前，不把 iframe 试验切到正式业务，也不通过反向代理第三方登录、OAuth、支付或修改浏览器安全策略来伪装同源。`yrydai.com` 腾讯云接入备案通过后，还需单独复测微信域名提示和正式 H5 链路；备案结果本身不能改变跨域权限。

参考：MDN 对跨源 iframe 的访问限制及 `postMessage` 跨源通信说明，见 https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy 与 https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage 。

## 具体结果地址的单独可行性判断

用户转述第三方称：排盘页无需手动登录，具体盘面分享时会显示该盘面地址。对此应拆开判断：

- **App 发起分享**：现有 App 子 WebView 桥在用户点击分享时可读取其当前 `window.location.href`，再通过公开地址白名单生成热卜分享承接链接。这个环节不依赖 H5 父页跨域读取，已有源码实现。前述“无法读取当前盘面地址”专指独立浏览器里的跨域 H5 iframe 父页，不应扩大为 App 也无法取得地址。
- **接收者查看固定结果**：若第三方给出的具体结果地址无需旧站会话即可展示真实盘面，且其最终页面允许在微信 H5 iframe 中渲染，那么可以把这个固定地址嵌入热卜分享页；此时不需要父页追踪盘面切换，也未必需要第三方新增消息桥。此方案只证明“分享结果页保壳”，不自动证明从头填写、切换盘面、站内支付和第三方内部返回均保壳。
- **当前样例不可充当验证证据**：对历史示例 `https://www.yrydai.cn/p1.php?id=1` 的无会话只读请求为 HTTP 200、响应体 0 字节；`.com` 同路径返回 302 到旧公众号微信 OAuth。带微信 User-Agent 的对照结果相同。`id=1` 可能并非有效真实盘面，不能据此否定第三方所说的真实结果链接，也不能宣称结果页可嵌入。

下一步需用不含敏感资料的真实测试盘面**完整分享地址**做接收端验证：无旧站会话访问应有可见盘面；微信内 iframe 应真正渲染结果；分享链接仍为热卜域名；返回应回热卜而非旧站；重复打开不能要求额外登录。只有这组验证通过才切换正式分享承接页。若实际结果仍跳 OAuth 或空白，则保持现有可打开链接，不伪称保壳。

用户倾向先在热卜完成最短授权，再自动进入旧盘面，减少重复登录；用户表示旧站可按手机号匹配或立即创建普通用户，此项列为待真机核验的新信息。现有小程序登录页已经实现由用户点击的 `getPhoneNumber` 手机号一键登录，并在成功后回原页面；微信 H5 使用微信 OAuth 快捷登录。现有 `/legacy-paipan/entry` 要求热卜 JWT，但 `client=h5` 固定返回旧站 `.com/p1.php` 网页授权入口，即使热卜账号已有手机号也**不会**调用 App 专用签名入口；`client=app` 才由服务端给 `.cn/guoxueApp.php` 生成手机号签名，且只约定 `go=tool/my`，未约定结果 `id` 直达、在微信 H5 中完成旧站会话、或 `.cn` 与 `.com` 跨站会话打通。因此仅增加热卜登录不能证明白屏已解决，也不应把手机号或签名拼入可转发链接。当前第三方 `mobileUser.php` 是查询，`partner.php` 不存在用户时失败；自动开户仅有 `addPartner` 微信授权入口的明确说明，尚无 `guoxueApp.php` 对普通新用户自动开户的验收证据。

独立无会话只读对比：`.com/p1.php` 结果地址跳微信授权；同盘 `.cn/p1.php` 返回 200 但正文 0 字节；`.cn/app_p1.php` 只返回极短 HTML，不能据 200 判定盘面可用。后续最短路径需第三方明确并验证：热卜服务端已登录手机号如何换取**该结果 ID** 的免二次授权、可内嵌会话或短期公开分享地址；新手机号是否自动创建；会话在 `.cn/.com` 间如何落地；首次微信接收者是否可显示并保壳。取得契约后，在隔离 QA 上做“无旧站会话 → 热卜快捷登录 → 原分享盘面”真机验收。普通用户是否绑定手机号仍遵守既定规则，不因当前方案改为全平台强制准入。

### App 本机号码一键登录可行性（2026-09-27）

当前 `apps/mobile/src/manifest.json` 的 App OAuth 仅有 Apple、微信；登录页提供微信/Apple、短信验证码和密码，没有运营商本机号码 SDK；服务端只有短信、微信、Apple 和**微信小程序专用** `miniPhoneLogin`，没有 App 一键取号验证入口。故现有 App 包不能直接弹出本机号码授权。DCloud 官方 uni-app 方案 `univerify` 可支持 App：需给本应用开通一键登录服务及 uniCloud，启用 App 原生 OAuth 模块，在可用手机上预取号并展示运营商授权页，收到凭证后通过 uniCloud 服务端换手机号，再交本平台账号服务按手机号匹配或创建；客户端提交的手机号本身不能作为登录凭据。此服务的开通、审核、计费、原生重新打包以及双卡/无 SIM/移动数据不可用时的回退均需作为正式验收条件。未查询到本项目已有 uniCloud 服务空间或 `univerify` 配置，因此不在正式登录页显示无效按钮，也不为实验消耗真实计费次数。

实现时复用现有手机号哈希查找、并发创建与身份冲突保护，禁止手机号账号与另一微信账号静默合并；保留微信、短信登录回退和用户主动确认协议。取号凭证仅交服务端校验，手机号不进浏览器 URL、日志或可分享地址。授权后由现有统一回跳回原排盘/订单位置，不额外落首页；但**App 一键登录只解决热卜账号问题**，仍须验证旧站签名入口能建立旧站会话并落到指定结果页。DCloud 文档：`https://uniapp.dcloud.net.cn/univerify.html`。

本轮另外修复小程序登录授权层重复的协议勾选：快捷层保留一处，普通登录表单保留一处用于关闭快捷层后的登录方式。相关定向测试 3/3、移动端类型检查、App 与小程序本地构建通过；小程序构建产物主包 1.58 MB、最大分包 `pkg-paipan` 1.68 MB，保守上传估算 1.87 MB（此数不是官方上传实测）；未上传或发布新包。
