## 行为与边界

两套 Nginx 模板用原始 `$request_uri` 的命名捕获生成不含查询参数的日志路径；日志请求行保留方法、编码路径、协议，继续保留状态码、字节数和耗时。Referer 日志字段固定为 `-`。实际 URI、请求头、反代、重定向、验签规则不改。

追踪拦截器只记录清理后的 URL，失败状态不存异常原文，也不存用户 ID。导出代理显式复制 ReadableSpan 的公开字段，继续保留 trace/span ID、父关系、路由、状态码、时间、链接结构和错误状态；不修改 SDK 原始 Span。官方导出器的回调、刷新和关闭继续透传。

已列 URL 属性去除用户名、密码、查询和片段；移除查询/片段属性、异常 message/stack、状态 message、已列请求/响应 body、用户 ID 和凭据字段。生产入口已把该代理接入 BatchSpanProcessor。追踪启动/关闭失败日志也不展开原异常。

这一规则不是任意数据的全局脱敏保证。**Nginx 错误日志的原始请求上下文仍需处理**；User-Agent、IP、自定义 span 名称、事件名称、资源、SQL/Redis 内容、OTel 自动日志和指标及历史日志都没有完成全面审计。错误详情从追踪移除后，排障须使用状态码、路由、耗时与 trace ID。
