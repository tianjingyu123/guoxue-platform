# 反馈明文审计先行修复

旧反馈联系方式、正文和截图入口依靠全局异步审计：响应发出后审计失败只记警告，无法保证每次明文访问留痕。新增失败模拟在旧源码3失败/2通过，确认明文可先于审计结果发出。

本批为 `Auditable` 增加可选 `requireSuccess`，只在上述三个敏感查看入口开启。读取结果后先等待审计落库，成功才返回原结果；失败返回503与通用重试提示，不发明文、不输出数据库错误。不改普通业务的异步审计约定，支付、退款主事务仍不会因审计日志失败而被阻断。权限、独立限流及脱敏详情保持原状。

新增5项验证真实入口装饰器、失败不发明文、延迟落库不提前响应、业务失败不写成功审计及普通事务不阻断；与原拦截器3项一起8/8通过。审计内容不含返回明文、请求体或查询参数。日志在 `artifacts/release-audit-20260927/audit-sensitive-before.log` 与 `audit-sensitive-after.log`。

最终同版Linux HTTP故障注入与恢复重试另记，单元测试不替代实际入口验收。可独立撤回本提交；不涉及schema、生产迁移、真实用户查看或通知。
