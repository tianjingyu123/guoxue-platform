# 语音智能体与古籍音频服务开通清单

> 更新日期：2026-08-02  
> 适用范围：新服务器、新数据库、新域名迁移后的 H5、微信小程序、Android、iOS 生产环境。  
> 原则：先完成受控验收再开放入口；密钥不进 Git、不进聊天记录、不下发客户端。

## 一、采购结论

### 必须开通

| 能力           | 推荐服务                               | 用途                                         | 必须提供或登记                                            |
| -------------- | -------------------------------------- | -------------------------------------------- | --------------------------------------------------------- |
| 实时音频房间   | 腾讯云 TRTC                            | 用户与 AI 的低延迟语音通话、打断、状态同步   | `TRTC_SDK_APP_ID`、`TRTC_SECRET_KEY`、应用责任人          |
| AI 实时对话    | TRTC AI 实时对话                       | 机器人入房、ASR、智能打断、字幕与状态回调    | 套餐/计费开通证明、回调域名、验收证据编号                 |
| 实时语音识别   | 腾讯云 ASR                             | 边说边出文字、最终句确认、实时字幕           | CAM 最小权限角色或 `TENCENT_SECRET_ID/KEY`、地域、引擎    |
| 流式语音合成   | 腾讯云 TTS 流式文本语音合成            | 大模型逐步输出时边生成边播放，降低首字等待   | 地域、生产可用音色、情感/语速参数白名单                   |
| 长文本语音合成 | 腾讯云 TTS 长文本语音合成              | 古籍章节、有声书等离线音频生成               | 回调地址、结果下载任务、失败重试与费用告警                |
| 音频存储与分发 | 腾讯云 COS + CDN；需要媒资管理时接 VOD | 保存审核后的章节音频、字幕和时间轴           | `COS_BUCKET/REGION/CDN_BASE`，需要时提供 `VOD_SUB_APP_ID` |
| 内容安全       | 平台已有文本/音频审核链路              | 用户语音转写、智能体输出和公开音频的风险控制 | 审核服务开通、策略版本、人工复核责任人                    |

腾讯云官方说明中，AI 实时对话以 TRTC 房间为通道，支持第三方 LLM/TTS，并提供实时字幕、机器人状态、智能打断和服务端回调。其费用至少包含音频通话、AI 实时对话和语音转文字三部分，采购时必须同时设置预算与告警，不能只购买 TRTC 时长。

### 可选能力

| 能力                         | 何时采购                         | 风险控制                                       |
| ---------------------------- | -------------------------------- | ---------------------------------------------- |
| 专属/复刻音色                | 首批角色化语音通过通用音色验收后 | 必须取得声音权利人书面授权，保留撤回与下架流程 |
| 高级降噪、回声消除、弱网优化 | 真机质量数据表明基础能力不足时   | 先以真实机型和网络数据决策，不按宣传页盲购     |
| 录音与质检                   | 付费咨询、争议仲裁确有需要时     | 双方明确同意、限定保存期、加密、权限审计       |
| 多语种/方言                  | 有明确内容和用户规模后           | 每种语言单独建立准确率与敏感词回归集           |

### 暂缓

- 数字人、实时视频形象和自动生成头像：不影响首版语音价值，成本与审核复杂度高。
- 未授权的声音克隆、名人音色和“高度相似”角色音色。
- 把所有古籍一次性全量合成：先做高访问章节，按实际播放率扩容。

## 二、正式链路

```text
用户麦克风
  → TRTC 房间
  → 实时 ASR / VAD
  → 平台智能体路由、知识库与工具调用
  → 结构化回复（文字、卡片、动作）
  → 流式 TTS
  → TRTC 下行音频
  → 客户端字幕、聆听/思考/说话/打断状态
```

服务端负责签发短期 UserSig、启动/停止 AI 对话任务、保存计费与回调状态；客户端只能取得短期票据。`TRTC_SECRET_KEY`、CAM 密钥和模型密钥不得进入前端包。

## 三、需要你开通或交付的资料

### 腾讯云控制台

- TRTC 应用及 SDKAppID；SDKSecretKey 由运维写入生产配置中心。
- AI 实时对话和语音转文字服务的开通状态、套餐、并发上限及费用告警。
- TTS 通用/流式与长文本服务；确认首批角色实际可用的音色 ID、情感类型、语速范围。
- COS 存储桶、地域、正式 CDN 域名；如使用 VOD，再提供正式子应用 ID。
- AI 实时对话、长文本合成、审核服务的 HTTPS 回调域名与签名/鉴权方案。
- 一个最小权限 CAM 角色；生产 CVM 优先使用实例角色，避免长期静态密钥。

### 客户端与应用商店

- 微信小程序 AppID、主体、类目、`request/socket/uploadFile/downloadFile` 合法域名。
- DCloud AppID、Android 包名与签名证书、iOS Bundle ID 与证书/描述文件。
- TRTC/音视频 SDK 或 DCloud 原生插件所需 License、License URL/Key（如供应商要求）。
- 隐私政策、麦克风用途说明、第三方 SDK 清单、账号注销和内容举报入口。

### 不得通过聊天交付

- SecretKey、SecretID、私钥、证书密码、API V3 Key、签名文件。
- 这些资料只允许由授权运维写入配置中心或受控密钥库；交接表只登记责任人、指纹和证据编号。

### 正式候选包证据文件

供应商能力开通不等于客户端已经可用。正式候选包生成后，由发布人员复制
`config/release/store-release-evidence.example.json` 到仓库外受控路径，逐端填写候选包路径和 SHA-256、真机型号、系统版本、验收人和证据编号；不得把截图、密钥或证书正文写入该文件。门禁会重新读取候选包并计算 SHA-256，填写的哈希与实际文件不一致即阻断。Android 与 iOS 都必须实际完成麦克风授权和双向通话，鸿蒙必须用正式签名候选包覆盖安装线上旧版。

```bash
pnpm release:audit-store -- --strict \
  --release-id "$RELEASE_ID" \
  --evidence "/受控路径/store-release-evidence.json" \
  --report "release-evidence/$RELEASE_ID/store-readiness.json"
```

门禁会同时要求 `manifest.json` 存在可识别的 TRTC/RTC/voice/audio 原生插件配置、证据文件的 `releaseId` 与当前发布一致、双端候选包哈希有效，以及鸿蒙签名基线和覆盖安装证据同时通过。添加任意无关原生插件、只修改 `signingProfileVerified` 或复用上一批次证据均不能放行。

## 四、古籍断句、标点与自然朗读方案

### 文本必须分三层

1. **原始底本**：保留来源、版本、卷章页码与未经改写的原文，只读保存。
2. **编辑校勘本**：保存正式展示采用的断句、标点、异体字、通假字和校注版本。
3. **AI 草稿**：保存模型、提示词版本、生成时间、置信度和差异，不得直接覆盖前两层。

### 处理流水线

```text
权威底本/扫描页
  → OCR 与版面还原（仅扫描本需要）
  → 字符规范化和卷章节锚点
  → 大模型生成断句、标点、专名和停顿草稿
  → 规则/词典/对照版本校验
  → 编辑抽检或逐章审核
  → 发布校勘版本
  → SSML/停顿/多音字表
  → TTS 生成音频与时间轴
  → COS/CDN 缓存与版本绑定
```

古文断句和标点没有必要再采购一个“自动断句接口”作为权威来源。平台现有大模型网关足以生成可审核草稿，真正必须补的是：权威底本、版本化编辑台、专名/多音字词典、抽检规则和回滚能力。AI 输出必须以差异稿进入审核，不能直接修改原文。

### 朗读质量门槛

- 诗歌、经史、讲解分别配置音色、语速、停顿和情感策略，不能全站共用一个模板。
- 无标点底本不得按固定字数直接切句并作为正式朗读。
- 长章节使用长文本异步任务，生成结果及时转存 COS；供应商临时结果地址不能作为永久播放源。
- 逐句高亮、笔记定位和断点续听使用稳定的句子锚点与时间轴，不用易变化的数组下标。
- TTS 失败可降级普通音色，但不得自动改写原文或朗读未经审核的 AI 标点稿。
- 每批至少抽检：专名、多音字、异体字、数字、干支、朝代、人名、地名和长句停顿。

## 六、受控上线验收

1. 使用一个测试用户和一个测试智能体完成真实通话，保存任务号、房间号哈希、回调证据和账单明细。
2. 验证重复回调、网络闪断、强制退出、麦克风撤权、服务端超时后均能正确停止任务和计费。
3. 设置日预算、并发上限、单次最长时长、异常费用告警和自动熔断。
4. 验证日志只保存脱敏用户 ID、配置指纹和错误码，不记录密钥或无必要的原始音频。
5. 古籍首批选择 3 种文体、每种至少 3 章，完成人工朗读质量抽检后再逐步扩容。
6. 将验收责任人和证据编号登记到私有基础设施接入清单 `externalEndpoints.mediaDelivery`。
7. 将 Android、iOS、Harmony 候选包真机结果登记到仓库外 `store-release-evidence.json`，并生成与同一 `releaseId` 绑定的商店准备度报告。

## 七、当前代码映射

| 配置                                       | 当前用途                          |
| ------------------------------------------ | --------------------------------- |
| `TRTC_SDK_APP_ID`、`TRTC_SECRET_KEY`       | 房间票据与实时语音发布门禁        |
| `TENCENT_SECRET_ID`、`TENCENT_SECRET_KEY`  | ASR、TTS、审核等腾讯云通用服务    |
| `TENCENT_ASR_REGION`、`TENCENT_ASR_ENGINE` | 实时/文件识别地域和中文 16k 引擎  |
| `TENCENT_TTS_REGION`                       | 后端 TTS 地域                     |
| `COS_BUCKET`、`COS_REGION`、`COS_CDN_BASE` | 音频、字幕和时间轴持久化分发      |
| `VOD_SUB_APP_ID`                           | 需要媒资管理与转码时的 VOD 子应用 |

现阶段代码已有语音专用页面、服务端 `POST /bots/:id/voice-room`、TRTC UserSig 基础能力和后端 TTS。正式开放仍依赖供应商服务开通、客户端原生 SDK/插件和多端真机验收。
