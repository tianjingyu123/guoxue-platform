# 热卜国学平台 — 容量规划与资源预留预案

> 更新时间：2026-05-15 | 适用阶段：全生命周期

## 一、数据增量模型

### 1.1 单条记录平均大小

| 数据类型 | 平均大小 | 索引倍数 | 实际占用 | 备注 |
|---------|---------|---------|---------|------|
| 排盘记录 (PaipanRecord) | 2KB | ×1.5 | 3KB | JSON resultData 占大头 |
| AI 分析记录 (AiAnalysisRecord) | 3KB | ×1.2 | 3.6KB | 分析全文较长 |
| 订单记录 (Order) | 0.5KB | ×2.5 | 1.25KB | 索引较多（11个） |
| 用户行为日志 (UserBehaviorLog) | 0.3KB | ×1.3 | 0.4KB | 轻量事件记录 |
| 行为数据 (UserBehavior) | 0.3KB | ×2.0 | 0.6KB | 4个复合索引 |
| 聊天记录 (BotChatLog) | 2KB | ×1.2 | 2.4KB | query+response |
| 用户表 (User) | 0.5KB | ×2.0 | 1KB | 含关联关系 |
| 音视频元数据 | 0.2KB | ×1.5 | 0.3KB | 文件本体在 COS |

### 1.2 按用户规模的数据增量预估

| 指标 | 1万用户 | 5万用户 | 10万用户 | 50万用户 | 100万用户 |
|------|---------|---------|---------|---------|----------|
| 日活用户 (DAU) | 1,000 | 5,000 | 10,000 | 50,000 | 100,000 |
| 日均排盘次数 | 5,000 | 25,000 | 50,000 | 250,000 | 500,000 |
| 日均订单 | 100 | 500 | 1,000 | 5,000 | 10,000 |
| 日均行为日志 | 50,000 | 250,000 | 500,000 | 2,500,000 | 5,000,000 |
| 日均 Bot 对话 | 500 | 2,500 | 5,000 | 25,000 | 50,000 |

### 1.3 数据量累计预估

| 时间节点 | 排盘记录 | AI 分析 | 订单 | 行为日志 | Bot 聊天 | **总计（含索引）** |
|---------|---------|---------|------|---------|---------|------------------|
| 1 个月 (1万用户) | 0.45 GB | 0.54 GB | 3.75 MB | 6 GB | 0.36 GB | **≈ 8 GB** |
| 3 个月 (3万用户) | 4.05 GB | 4.86 GB | 34 MB | 54 GB | 3.24 GB | **≈ 70 GB** |
| 6 个月 (10万用户) | 27 GB | 32 GB | 225 MB | 360 GB | 21.6 GB | **≈ 480 GB** |
| 12 个月 (50万用户) | 270 GB | 324 GB | 2.25 GB | 3.6 TB | 216 GB | **≈ 4.6 TB** |

> **关键发现：行为日志是存储大户，占总量的 75%+。必须优先做冷热分离 + 时序数据库迁移。**

## 二、资源规格与预留

### 2.1 各阶段服务器规格

| 阶段 | 用户规模 | 应用服务器 | 数据库规格 | Redis 规格 |
|------|---------|-----------|-----------|-----------|
| **P0 (当前)** | < 1,000 | 2C4G ×1 | 2C4G 50GB SSD | 1C2G |
| **P1** | 1K–10K | 4C8G ×2 | 4C8G 200GB SSD (主) + 2C4G (只读) | 2C4G Cluster |
| **P2** | 10K–100K | 8C16G ×4 | 8C16G 1TB SSD ×2 (主+从) + ClickHouse 4C8G | 4C8G Cluster ×3 |
| **P3** | 100K–500K | 16C32G ×8 | 16C32G ×2 (分片) + ClickHouse 8C16G | 8C16G Cluster ×6 |
| **P4** | 500K+ | 自动伸缩 | 分布式集群 (Citus/自建分片) + 专用搜索集群 | 16C32G Cluster ×N |

### 2.2 资源预留比例（铁律）

```
所有生产环境资源必须按以下比例预留余量，任一指标触达阈值立即启动扩容：

┌──────────┬────────────────┬─────────────────────┐
│  指标     │  告警阈值       │  扩容完成期限        │
├──────────┼────────────────┼─────────────────────┤
│  CPU     │  P0-2: 60%     │  达标后 48h          │
│          │  P3-4: 50%     │  达标后 24h          │
├──────────┼────────────────┼─────────────────────┤
│  内存     │  P0-2: 70%     │  达标后 48h          │
│          │  P3-4: 60%     │  达标后 24h          │
├──────────┼────────────────┼─────────────────────┤
│  磁盘     │  65% 黄色告警   │  达标后 72h 扩容     │
│          │  75% 红色告警   │  达标后 24h 扩容     │
│          │  85% 紧急冻结   │  立即停止写入        │
├──────────┼────────────────┼─────────────────────┤
│  连接数   │  70% 告警      │  达标后 48h          │
│          │  85% 拒绝新连接  │  立即处理            │
├──────────┼────────────────┼─────────────────────┤
│  带宽     │  70% 告警      │  达标后 72h          │
└──────────┴────────────────┴─────────────────────┘
```

### 2.3 资源预留计算公式

```
实际采购资源 = 当前峰值需要 × (1 + 预留比例)

预留比例阶梯：
  P0-P1: ×1.5  (当前用 100G → 买 150G)
  P2:     ×2.0  (当前用 500G → 买 1TB)
  P3+:    ×3.0  (当前用 2TB → 买 6TB，含分片余量)
```

## 三、扩容触发流程 (SOP)

### 3.1 自动触发流程

```
┌─────────────┐    ┌──────────────┐    ┌─────────────┐
│ 监控指标超标  │ → │ 企业微信告警   │ → │ 自动创建扩容  │
│ (Prometheus) │    │ (P0/P1分级)  │    │ 工单/通知CTO  │
└─────────────┘    └──────────────┘    └─────────────┘
                                               │
                    ┌──────────────────────────┘
                    ▼
┌─────────────┐    ┌──────────────┐    ┌─────────────┐
│ 确认扩容方案  │ → │ 执行扩容操作   │ → │ 验证 + 关闭   │
│ (CTO审批/自动)│    │ (按预案执行)   │    │ 告警         │
└─────────────┘    └──────────────┘    └─────────────┘
```

### 3.2 各类资源扩容方案

**数据库扩容（最快 15 分钟，最长 2 小时）**

| 操作 | 停机时间 | 前置条件 | 风险 |
|------|---------|---------|------|
| 增加只读副本 | 0 | 主库 WAL 归档已开启 | 无 |
| 磁盘扩容 (云盘) | 0-5 分钟 | 云厂商支持在线扩容 | IO 短暂抖动 |
| 规格升级 (CPU/内存) | 5-15 分钟 | 提前预约维护窗口 | 短时不可用 |
| 分片扩展 (加新分片) | 0 | 分片键设计已完成 | 数据迁移耗时 |

**Redis 扩容**

| 操作 | 停机时间 | 方案 |
|------|---------|------|
| 内存扩容 | 0 | 在线纵向扩容 |
| 加节点 (Cluster) | 0 | `redis-cli --cluster add-node` 在线迁移 slot |
| 迁到更大规格 | 1-5 分钟 | 主从切换 + 数据预热 |

2. **冷数据归档到低频存储**：90 天前数据从 SSD → 机械盘 / 对象存储归档

### 5.2 扩容预测告警

```sql
-- 按当前 7 天增速预测磁盘满时间
WITH daily_growth AS (
  SELECT
    date_trunc('day', now()) - interval '1 day' * generate_series(0, 6) AS day,
    pg_database_size('guoxue') / 1073741824.0 AS size_gb
  FROM pg_database_size('guoxue')
)
SELECT
  (current_size / NULLIF(avg_daily_gb, 0))::INT AS days_until_full_65pct
FROM (
  SELECT
    pg_database_size('guoxue') / 1073741824.0 AS current_size,
    -- 计算 65% 阈值对应的剩余空间
    (total_disk * 0.65 - pg_database_size('guoxue') / 1073741824.0) AS remaining_gb,
    avg(pg_database_size('guoxue') / 1073741824.0) OVER () AS avg_daily_gb
);
```

## 六、数据归档与清理策略

### 6.1 冷热分离时间线

```
数据写入 → 热区 (SSD, 高频读写)
   │
   ├─ 排盘记录: 30天 → 温区 (SSD, 只读)
   │             90天 → 冷区 (归档, 按需加载)
   │            365天 → 对象存储 (压缩, 历史查询慢)
   │
   ├─ 行为日志: 7天 → ClickHouse 热区
   │            30天 → ClickHouse 温区
   │            180天 → 对象存储 (Parquet 格式)
   │
   ├─ Bot 聊天: 30天 → 温区
   │            365天 → 对象存储
   │
   └─ 订单: 90天 → 温区
            3年 → 归档 (合规要求)
```

### 6.2 清理任务 Cron 定义

```bash
# 每日 02:00 执行冷数据迁移
0 2 * * * /opt/guoxue/scripts/archive-cold-data.sh

# 每周日 03:00 执行过期数据清理
0 3 * * 0 /opt/guoxue/scripts/purge-expired-data.sh

# 每月 1 号 04:00 生成容量趋势报告
0 4 1 * * /opt/guoxue/scripts/generate-capacity-report.sh
```

## 七、特殊场景预案

### 7.1 节假日前扩容

春节/国庆/元旦前 3 天，资源规格临时提升 1 档（按历史峰值 ×2 预留），节后 3 天降回原规格。

### 7.2 营销活动扩容

活动期间（如双十一促销、国学讲座直播）：
- 提前 7 天升级数据库到下一档
- Redis 增加 1 个节点
- 应用服务器扩容至 2 倍
- 活动结束 72h 后缩容

### 7.3 突发流量（热点事件）

如某个排盘结果被传播/某篇内容爆红：
- **L1 自动拦截**：Redis 限流 + 缓存预热热门八字
- **L2 手动扩容**：5 分钟内增加应用实例
- **L3 熔断降级**：非核心功能（行为日志、推荐刷新）暂时关闭
