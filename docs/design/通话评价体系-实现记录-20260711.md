## 二、后端端点（consult-call 模块·全走原生 SQL）

| 端点 | 权限 | 规则 |
|---|---|---|
| `POST /consult-calls/:id/rate` | 登录·仅通话发起方 | 仅 ENDED·仅一次·结束后 24h 内；rating 1-5（DTO+service 双层校验）、tags ≤5 个、comment ≤200 字；原子 UPDATE `WHERE ratedAt IS NULL` 防并发重复评 |
| `POST /consult-calls/:id/dispute` | 登录·通话双方任一 | 仅 ENDED·仅一次·24h 内；只落 PENDING 记录，**资金零触碰** |
| `GET /consult-calls/expert-stats?expertIds=a,b` | 登录 | 好评率=rating≥4 占比（整数百分比）+评价数；**无评价的达人不返回**（前端据此不渲染·不编数）；最多 50 个 id |
| `GET /consult-calls/admin/disputes?status=` | SUPER_ADMIN / OPERATION_ADMIN | 申诉队列（默认 PENDING·join 双方昵称·分页） |
| `POST /consult-calls/admin/disputes/:id/resolve` | SUPER_ADMIN / OPERATION_ADMIN | 仅 PENDING→RESOLVED/REJECTED，只记结论+备注+处理人；**不动任何余额/流水**，退款由人工走现有金币退款审批流 |

评价/申诉字段随 `GET /consult-calls/my` 自动返回（`SELECT c.*`），call-end 页无需新单条端点。
