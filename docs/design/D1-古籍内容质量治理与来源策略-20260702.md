## 一、现状摸底（2026-07-02 · 本地库实测，生产库同源同量级）

**规模真相：库里不是"62 部"，是 17,389 部 / 465,637 章**（殆知阁全量早已注入且**全部 PUBLISHED 对用户可见**；"62 部"只是做过精修导读/书单的名著子集）。

| 质量维度 | 实测数据 | 说明 |
|---|---|---|
| 空壳章节 | **115,874 章（24.9%）正文 < 50 字** | 大量只有标题/残句；另有 78,737 章仅 50-200 字（部分为诗集单首属正常） |
| 空壳书 | **184 部书 70% 以上章节 < 100 字**（其中 119 部是 ≥20 章的大部头） | 典型=《红楼梦》：525"章"每章仅 24 字（只有回目对联，正文全丢） |
| 微型残书 | 1,007 部全书总字数 < 2,000 | 多为残卷/单篇误立为书 |
| 重复版本 | **172 组书名重复，413 部卷入** | 如《论语》同时存在 80 章版与 3 章残缺版，versionGroupId 未有效使用 |

SQL 量不出来的（需抽样人工/AI 比对）：底本权威性（如通行本 vs 善本）、缺卷（书该有 40 卷只爬到 20 卷）、OCR 错字率、简繁混杂、无标点文本比例。

**结论：问题根源 = 未经清洗的殆知阁全量直接 PUBLISHED。**用户感知的"缺失版本、内容缺失、非权威"全部得到数据印证。

## 二、治理原则（拍板）

1. **质量优先于数量**：宁可 500 部精品，不要 1.7 万部垃圾。
2. **测试阶段动作**：只做清洗（隐藏劣质书）+ 来源锁定 + 管道与标准建设；**不做大规模新导入**。
3. **正式上线动作**：云服务器部署时按锁定来源大面积导入，一步到位。
4. 商用合规：来源必须允许商用；古籍原文公版，但**现代点校/译注成果可能受保护**（法律结论见 §三）。

## 三、法律红线与来源对比（2026-07-02 联网调研定稿）

### 3.1 法律红线（比选源更优先）

**古籍原文属公有领域，但现代点校本（分段/标点/校勘/注释/译文）在中国司法实践中受著作权保护**——中华书局诉国学时代案（北京一中院终审）：二十五史点校作品具独创性受保护，判赔 17 万+停止侵权。商用结论：

| 内容类型 | 商用风险 |
|---|---|
| 古籍白文（无标点原文） | ✅ 公有领域，安全 |
| 自研标点/译注（AI 生成+人工审校） | ✅ 安全，且形成**自有版权资产** |
| 采集他人现代点校本（出版社整理本/商业库导出） | 🔴 有直接判例，禁止 |
| 开源社区标点文本（MIT/CC） | 🟡 许可可商用，但警惕"实际抄自出版社点校本"的上游污染（殆知阁典型隐患） |
| 爬取国学大师等聚合站 | 🔴 双重风险（盗采商业库+爬取行为本身），禁用 |

### 3.2 来源结论（完整对比表见调研报告，此处为决策要点）

- **殆知阁（现用）**：★★ 质量差有口碑实锤（繁转简丢字/夹注错乱/无底本/校对差）+上游污染合规隐患 → **只降不增，逐步替换**
- **🌟 kanripo 漢籍リポジトリ**（京都大学）：9000+ 部、每书一 GitHub repo、**底本明确（四部丛刊等善本转录）**、CC BY-SA 4.0 **明确可商用** → **扩展书目主力源**
- **🌟 识典古籍**（北大-字节）：1.9 万部、权威底本（四部丛刊/百衲本二十四史）、粗校/精校分级、免费不限复制，但批量商用再分发需函询 → **最优质免费源，函询成本低值得谈**
- **维基文库**：CC BY-SA 可商用有 dump，质量参差 → 只取有扫描校对（ProofreadPage）标记的条目作补充
- **chinese-poetry**（诗词）：MIT 可商用，但宋词约 1/5 有校对疑点（issue 实锤）→ 引用需锁旧版+抽检
- **CBETA**（佛典）：学术级质量，但**条款限非营利，商用须事先书面同意** → 发授权函后才能用（现库 4,368 部"释"部书需排查来源！）
- **ctext.org**：禁批量抓取、商用未授权 → 只作人工校对参考基准
- **书格**：影印 PDF 无文本层 → 作底本书影/对照素材
- **中华书局古联（籍合网）**：正版整理本唯一合法数字来源，有对外数据授权先例（荀子大模型 20 亿字语料）→ **付费授权首选谈判对象**（报价需商务接洽）；爱如生/雕龙/鼎秀为备选比价，无公开数据授权产品优先级低

## 四、分阶段方案（定稿）

### P0 测试阶段·止血清洗（可立即执行·不花钱）
- 空壳书（184 部短章占比≥70%）、微型残书（1,007 部 <2,000 字）→ status 改 DRAFT 下架（保留数据不删）
- 重复版本 413 部 → 每组保留最完整一部（章节数×总字数综合），其余 DRAFT 并挂 versionGroupId
- 精修 62 部名著保持 PUBLISHED 白名单保护
- **停止扩大殆知阁书目**（管道保留但不再执行全量导入）
- 清洗脚本要求：幂等、只改 status 不删数据、白名单机制、执行前导出备份清单
- ClassicBook 增加「底本/校对状态」元数据（source 已有，补 sourceEdition 底本版本+proofStatus 校对分级）——把"质量优先"变成用户可感知卖点

### P1 测试阶段·标准与管道 V2
- 上架标准五维：完整性（卷章齐全）/底本可溯源/标点质量/元数据齐全（author/dynasty/intro）/来源合规
- 导入管道 V2：来源→格式转换→机器校验（长度/章节/字符集）→评分→人工抽检→分级 PUBLISHED
- 核心书目（top 阅读量经典）以 kanripo 白文为基+自研 AI 标点译注+人工审校 → 形成自有版权整理层（竞争壁垒）
- **合规排查**：现库"释"部 4,368 部若源自 CBETA 需先取得书面同意，否则一并 P0 下架

### P2 正式上线·规模导入（云服务器部署时一步到位）
- 第 1 层核心经典 50-100 部：自建精修（kanripo 白文+ctext/书格影像三方核校+自研标点译注）
- 第 2 层扩展数千部：kanripo 整体引入（保留 CC BY-SA 署名脚注）+ 维基文库有校对标记条目
- 第 3 层佛典：CBETA（授权函取得后）
- 第 4 层差异化付费内容：古联数据授权（谈判结果而定）+ 识典古籍函询结果
