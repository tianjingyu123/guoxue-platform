## 〇、定位与重点（先读）

**线下驿站 = 平台的「线下服务终端」：线上引流、线下交付。** 平台把线上用户导到本地的实体教学点（驿站），完成线下课程、面授、沙龙、师承等**线下交付**。

**本板块重点在 B 端——驿站运营者后台。** 一个驿站主要在这里经营一个实体教学点：**排课 → 招生 → 到店核销 → 选用讲师 → 卖驿站商品 → 结算**。C 端只是学员"找驿站、报名线下课、到店签到"的轻链路。

**现状**：10 页 C 端 B 端混在一起、职责不清；师资预约页语义冲突；驿站对外主页与详情重复。**本次推翻重做前端**，把 C 端 / B 端切干净，B 端做成完整的线下经营闭环。后端能力很完整（报名/签到核销/驿站商品/师资排期预约/订单/结算/从签约讲师库入驻），只重 UI 与交互。

> **与「书院研究院」的衔接**：研究院把优秀会员签约成讲师后进讲师库；**驿站在 B 端"从签约讲师库选用讲师"**（本委托 B5）——这是研究院→驿站闭环的驿站侧落地。研究院里那些"师资需求/人才库"的概念，正确的家在这里，不在研究院。

## 一、角色

| 角色 | 说明 |
|---|---|
| **学员（C 端）** | 找驿站、报名线下课、到店签到核销、看驿站师资与商品。 |

## 二、页面架构总览（10 页 → 重构为 11 页·C/B 切干净）

### 砍并原则
- **C 端 / B 端彻底分开**（现状混杂）：C 端 4 页轻链路，B 端 7 页经营闭环。
- **合并重复**：驿站对外主页（station-home）并入驿站详情（station-detail）。
- **拆解语义冲突页**：teacher-booking 拆成 → C 端"驿站师资展示"（并入详情）+ B 端"师资管理与预约"（B5）。
- **承接研究院移交**：B5 师资管理内含"从签约讲师库选用讲师"。

## 三、核心：B 端线下经营闭环 + 到店核销（本委托灵魂）

### 3.1 线下经营闭环（B1→B7 串起来）
驿站运营者的主动线：**B3 排课 → C 端招生 → B4 到店核销 → B5 安排讲师 → B6 卖商品 → B7 结算**。B1 工作台把这条线的"待办 + 数据"聚合呈现。请把 B 端设计成一个**顺手的线下经营工作台**，不是零散页面堆砌。

### 3.2 到店核销（C4 ↔ B4 双向·重点出稿）
- **C 端 C4**：学员报名线下课后，生成**到店核销凭证**（二维码 + 6 位核销码 + 场次/时间/地址）。
- **B 端 B4**：运营者**扫学员二维码 / 输核销码**完成到店核销（sign-in），名单实时标"已到店"。
- 两稿都要出：C 端凭证态、B 端核销操作态（扫码/输码 + 核销成功反馈）。

### 3.3 从签约讲师库选用（B5·研究院闭环落地）
- B5 里一个"选用签约讲师"入口 → 拉起**平台签约讲师库列表**（signed-lecturers）→ 选中 → 该讲师入驻本驿站（from-signed）。
- 已入驻讲师显示在驿站师资列表，可排期/被预约。
- V0 出：签约讲师库选择弹窗 + 已入驻师资列表。

## 四、数据能力边界（都是现成后端，画的元素要能对上）

- **驿站**：stations（列表/discover/my/:id）、:id/home、my/brand（改品牌）、:id/revenue-dashboard（营收看板）、:id/audit（平台侧，不画）。
- **线下课**：courses（列表/CRUD/:id）、:id/register、:id/my-registration、:id/cancel、courses/sign-in（核销）、:id/registrations（名单）、:id/reviews（评价）。
- **师资**：stations/:id/teachers（驿站师资）、teachers/:teacherId/availability（可约时段）、stations/:id/teacher-bookings（预约·create/confirm/cancel）、**stations/:id/teachers/from-signed（从签约讲师库入驻）**、signed-lecturers（签约讲师库·institute 端点）。
- **商品**：stations/:id/products（CRUD）。
- **订单/结算**：stations/:id/orders（CRUD）、stations/:id/settlements（生成/查看/settle）。
- **禁止画的能力**：驿站装修楼层器、线上直播、复杂 BI（后端无·本次不做）。

## 六、视觉规范
全站统一 token：宣纸白 #FAF8F5 页底、卡片白 #FFFFFF、朱红 #C41E3A（主按钮/激活/价格）、金 #C9A96E（价值强调/营收/等级）、文字 #2C2C2C/#6E6E73/#999、圆角 18px·胶囊 999px、页边距 20px。
- C 端偏"温暖在地服务感"（地址/导航/到店），B 端偏"高效经营工作台"。
- 核销码/排期日历/结算单用清晰实色卡片与状态标签；克制留白、国学雅致、禁荧光渐变与娱乐贴纸感。
- ⚠️ 禁同色系底字；封面图上文字必须有渐变衬底。

## 七、技术兼容（安卓微信 X5 内核）
1. 封面/比例用 padding-top 方案（不用 aspect-ratio，稿内标注比例）。
2. 不用 writing-mode 竖排。
3. 排期日历、核销扫码、结算单用实色卡片，毛玻璃不承载关键信息。
4. 扫码核销、预约确认、结算发放等写操作交互由我方实现，V0 只出视觉与态。

## 八、交付格式
1. 纯 HTML 静态稿，390px 移动端宽，稿内 HTML 注释标数据来源与交互（注释即规格）。
2. 交付清单：
   - **C 端**：C1 发现驿站 / C2 驿站详情 / C3 线下课报名 / **C4 我的报名·到店签到凭证**。
   - **B 端**：B1 驿站工作台 / B2 品牌资料 / B3 课程排期管理 / **B4 招生与核销（核销操作态）** / **B5 师资管理（含从签约讲师库选用）** / B6 驿站商品 / B7 订单与结算。
   - 附《后端待办清单.md》（若发现缺口列出）。
3. **两阶段**：先线框级信息架构稿（重点确认 C/B 切分、B 端经营闭环、到店核销双向）→ 确认 → 视觉稿。**B 端线下经营闭环 + 到店核销（第三节）是本委托灵魂。**
