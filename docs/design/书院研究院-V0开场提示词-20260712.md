你好，帮我设计一个**移动端 H5**（390px 宽，纯静态 HTML 稿，稿内用 HTML 注释标数据来源与交互）的「**书院研究院**」板块。完整规格见附件《书院研究院板块-V0设计委托书》，这里先讲清最关键的几点，请务必先理解再动手：

**一、定位（这是一条漏斗，别做成"卖课书院"）**
书院研究院 = 平台的「**精英师资筛选培养体系**」。一条主线：
**付费准入（会费 1 万/年·交钱即进不审核）→ 自主申请分享 → 完成月/季/年任务→年度退会费（不申请者纯学习、不退）→ 平台评估签约成讲师 → 进线下驿站讲师库授课。**
会费本质是"可退押金"，"完成任务才能退费"这个诱因是整个体系的发动机，设计里要讲清楚。

**二、三个「别做偏」（原型虚构过，务必避免）**
1. 别做**讲师自主申请入库表单**——讲师是平台签约遴选制（观察评估后签约），不是填表自荐；相关页只做"遴选机制说明 + 路径引导"。
2. 别做**师资需求大厅 / 人才库 / 讲师评分打分**——那是线下驿站的事，不属研究院。
3. 别把付费准入做成**复杂审核门槛**——交钱即进，真正的筛选在后面的"任务+评估+签约"。

**三、核心是「我的会籍中心」（重点设计）**
一页承载会员自服务：会籍卡（角色/状态/讲师等级徽章）+ **申请分享开关** + 月/季/年任务进度 + 单任务提交完成 + **年度退费按钮**（未满足条件灰置+差距提示）+ 分红记录。把"入会→任务→退费→签约"路径做得一目了然。

**四、要砍要合（别照搬旧的 19 页）**
按委托书收敛成 10 页 + 移交 4 页：4 个错配页（teacher-pool/teacher-demand/demand-create/demands-create）属线下驿站，删掉移交；展示页合并（讲师/排行、成员/委员会、内容/讲座、活动列表/详情）。

**五、流程**
**分两阶段**：先出**线框级信息架构稿**（重点让我确认定位主线不跑偏 + 砍并结构 + 会籍中心转化路径）→ 我确认后 → 再出视觉稿。

具体每页简章、数据能力边界、视觉 token 全在委托书里。**入会→会籍→退费路径是灵魂，请重点打磨；别再造虚构的师资打分/需求大厅。**
