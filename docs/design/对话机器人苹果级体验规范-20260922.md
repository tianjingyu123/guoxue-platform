# 对话机器人苹果级体验规范

日期：2026-09-22  
适用范围：移动端对话机器人、智能体广场、对话历史、语音通话、额度续费、推荐承接，以及排盘解读、客服助理、圈主助理、古籍伴读等对话型场景。

## 目标

让用户在任何一个对话入口都能迅速理解三件事：当前助手能做什么、下一步应该做什么、完成后还能得到什么。体验以苹果产品常见的清晰层级、直接操作、连续反馈和克制视觉为参考，保留热卜的文化品牌识别，不复制苹果的具体界面或素材。

本轮优先解决：

1. 入口分散：广场、历史、详情和语音入口的主次关系不一致。
2. 反馈断点：加载、失败、额度不足、语音不可用和结束后的承接没有统一状态。
3. 视觉噪声：大面积色块、重复按钮和强阴影影响阅读，推荐卡与对话内容抢夺注意力。
4. 连续性不足：从推荐、语音和续费返回后容易丢失上下文，用户需要重新寻找原来的内容。

## 设计原则

### 1. 一屏一个主任务

每个页面只保留一个最重要的主动作：对话页是发送，智能体详情页是开始对话或语音，历史页是继续上次对话，语音结束页是继续追问。其它动作降级为文字链接、次按钮或菜单。

### 2. 信息先于装饰

标题、状态、价格和可操作范围使用清晰的系统无衬线字体；说明文字不低于全局 caption 令牌；推荐卡先显示标题和理由，再显示装饰图标。禁止用低对比度文字承载关键状态。

### 3. 克制的层级

页面底色使用中性浅灰，内容使用白色表面，品牌色只承担选择、确认和重要提示。圆角采用 12/18/24rpx 三档，阴影使用低透明度和大模糊，不用多层彩色发光制造层级。

### 4. 直接操作

操作靠近它影响的对象：智能体卡片上直接语音，历史记录行上直接续聊，额度提示上直接续费。主要动作的触控区域不小于 44px，支持键盘/辅助技术的 role、label 和 focus-visible。

### 5. 连续性

路由前保存会话、滚动位置和来源；返回后恢复原页面上下文。推荐内容、语音结束摘要和额度续费都必须提供明确的“回到刚才的位置”路径，不让用户重新猜入口。

### 6. 每个状态都可理解

统一提供 loading、空状态、重试、网络恢复、额度不足、权限不足和功能暂不可用状态。文案说明发生了什么、用户现在能做什么；不伪造价格、能力或已连接的语音运行时。

### 7. 轻量动效

默认动效 160–240ms，使用 ease-out；只用于确认点击、列表出现和状态切换。尊重 prefers-reduced-motion，减少位移和呼吸动画。动效不能阻止发送、返回或重试。

### 8. 信任与隐私

推荐说明来源和用途，不在对话卡片中泄露不必要的支付、联系方式或用户数据。额度显示以服务端返回为准；语音运行时未接入时，明确提示“语音服务尚未连接”，不能显示成已连接。

## 页面交互地图

### 对话页

顶部只保留返回、助手身份和一个语音入口；会话区按消息层级显示，推荐内容不压过回答。输入栏固定在安全区内，发送后立即进入“已发送/生成中”状态；失败时在原消息位置重试，不清空输入。

### 智能体广场

搜索是首要入口，分类和推荐是辅助导航。卡片先显示“能帮你做什么”，再显示价格、标签和直接语音。点击卡片进入详情，点击语音只进入通话页，不绕路经过重复确认。

### 对话历史

按今天、昨天和更早分组；每行保持头像、名称、最后一句和时间，语音助手额外提供一个 44px 语音按钮。搜索无结果时保留清除和回到广场的动作。

### 语音通话

进入后先显示能力和隐私说明，再进入单一的“开始通话”主动作。真实运行时不可用时，直接展示原因和文字替代入口；结束后展示时长、摘要和“继续文字追问/发现更多内容”，并回传来源，不能把失败伪装成通话成功。

### 额度与续费

额度不足在发送动作附近即时提示，展示剩余额度、服务价格（有服务端数据才展示）和一个“立即续费”动作。支付完成后回到原会话并自动恢复输入上下文；价格缺失时显示“价格以支付页为准”，不展示 0 币。

### 推荐承接中心

推荐卡最多一个视觉重点；卡片标题、推荐理由和单一动作必须在首屏可见。动作名称随内容类型变化，但位置和触控尺寸保持一致。进入内容后保留“回到对话”的轻量返回路径。

## 实施顺序

1. **P1 共用基础**：统一令牌、推荐卡、历史列表、空/错误/加载状态。
2. **P2 核心入口**：对话页、智能体广场和详情页的层级、输入栏、语音入口。
3. **P3 连续服务**：语音状态、结束承接、额度续费恢复和推荐回跳。
4. **P4 配套页面**：排盘解读、客服助理、圈主助理、古籍伴读等场景的专属提示和返回路径。

## 验收标准

- 首屏能看到当前任务和唯一主动作；主要按钮可见、可读、可点击。
- 网络失败、额度不足、语音不可用均有可理解的恢复动作。
- 进入语音、续费或推荐内容后能回到原会话，不丢失输入和上下文。
- 主要文字与背景达到可读对比度，点击区域不小于 44px。
- 移动端类型检查、微信小程序构建和服务端相关测试通过。
- 真实 RTC、真实支付渠道、真机多型号兼容和线上推荐效果另行验收，不把模拟运行时写成已上线。

## 本轮边界

本规范不引入新的 RTC/支付供应商，不改变额度扣减、收费规则、权限模型和生产部署流程；只改进信息层级、视觉一致性、状态反馈和已有能力的入口承接。
