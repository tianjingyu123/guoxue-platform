# T2 五角色工作台与智能商业顾问 — 设计方案 V1（待逐节探讨）

> 2026-07-03 · 七日冲刺 D2 交付物 · 基于五角色工作台现状侦察（成熟度基线见附录A）
> 目标：把五大角色的工作台从「数据展示型仪表盘」升级为「诊断-建议-执行-反馈」的智能商业伙伴，
> 让圈主/讲师/站长/运营商/驿站老板的日常经营离不开平台。

---

## 〇、三个核心判断

1. **最便宜的跃升是「接上做了不展的能力」**：圈主趋势图/成员流失预警/待回复队列、驿站库存告警/待确认预约/开课提醒/双排行榜——后端端点全部存在，前端整块没接。P0 零新后端即可让五个工作台观感升一级。
2. **智能商业顾问必须是一个统一引擎，而非五套逻辑**：五角色的「诊断→建议→执行→反馈」结构完全同构，差异只在指标源和建议库。做成配置驱动的 AdvisorEngine，一次建设五处复用，且规则可后台运营（这正是「工具+数据+AI」护城河的落地形态）。
3. **归因链路刚打通，站长漏斗有了数据地基**：分享 ref→点击(page_view)→注册(ReferralRelation)→下单(Order.referrerId) 全链路自今日起有真实数据，站长「推广作战中心」的转化漏斗从空想变为可实现。

## 一、统一智能商业顾问引擎（AdvisorEngine）

### 1.1 三层架构

```
指标层 DataProbe     诊断层 RuleEngine + AI          行动层 InsightCard
──────────────      ─────────────────────          ─────────────────
复用现有 dashboard    AdvisorRule 配置表逐条评估      工作台建议卡片：
端点 + TrackEvent  →  命中 → 生成 AdvisorInsight  →  事实陈述 + 建议文案
聚合，无新采集        （AI 把结构化事实润色为个性        + 一键执行动作
                      化建议，可降级为模板文案）        + 已读/采纳/效果回访
```

### 1.2 数据模型（两张新表）

```prisma
/// 顾问规则（后台可运营）：一条规则=一类经营问题的检测器
model AdvisorRule {
  id          String  @id @default(uuid())
  roleType    String  // CIRCLE_OWNER / LECTURER / STATION_MASTER / OPERATOR / STATION_OFFLINE_OWNER
  ruleKey     String  @unique // 如 circle_activity_drop / station_low_conversion / stock_low
  metric      String  // 检测指标标识（DataProbe 支持的探针名）
  condition   Json    // { op: "drop_pct"|"lt"|"gt", threshold: 30, windowDays: 7 }
  severity    String  @default("INFO") // INFO / WARN / CRITICAL
  suggestion  String  // 模板建议文案（含 {{占位符}}；AI 关闭时直接使用）
  actions     Json    // [{ label:"发起话题讨论", type:"NAVIGATE", target:"/pkg-circle/..." }, { type:"API", endpoint:"..." }]
  enabled     Boolean @default(true)
  updatedAt   DateTime @updatedAt
}

/// 顾问建议实例：每日 cron 按规则对每个主体评估生成，工作台拉取
model AdvisorInsight {
  id         String   @id @default(uuid())
  ruleKey    String
  roleType   String
  subjectId  String   // 主体ID（圈子ID/分站ID/驿站ID/讲师userId/运营商ID）
  severity   String
  facts      Json     // 结构化事实 { metric, current, baseline, deltaPct }
  content    String   // 最终建议文案（AI 生成或模板渲染）
  actions    Json
  status     String   @default("OPEN") // OPEN / READ / ACTED / DISMISSED / EXPIRED
  actedAt    DateTime?
  feedback   Json?    // 效果回访：{ metricAfter, deltaAfterPct }（7天后 cron 回填）
  createdAt  DateTime @default(now())
  @@index([roleType, subjectId, status])
  @@index([ruleKey, createdAt])
}
```

### 1.3 端点与调度

- `GET /advisor/insights?roleType=&subjectId=`：工作台拉取 OPEN 建议（各工作台首屏「经营顾问」卡）
- `POST /advisor/insights/:id/read|act|dismiss`：状态流转（act 记录采纳，供效果回访与规则命中率统计）
- Cron 每日 6AM：逐角色逐主体评估规则 → 生成 Insight（同主体同规则 7 天内不重复打扰）
- Cron 每日 7AM：对 7 天前 ACTED 的建议回填 feedback（指标变化）→ 形成「建议有效性」数据，反哺规则调优
- **AI 层**：DeepSeek 把 facts 渲染为个性化文案（带主体名称/具体数字/语气），失败或关闭时回退 suggestion 模板。成本控制：仅对命中规则的主体调用，结果落库不重复生成。

### 1.4 每个角色的首发规则库（各 4-6 条，示例）

| 角色 | 规则示例（metric → 建议 → 动作） |
|---|---|
| 圈主 | 活跃成员环比降 >30% → 「发起一个八字案例讨论激活氛围」→ 跳发帖；待回复提问 >3 条 → 跳答疑；付费转化率 < 同规模圈子均值 → 建议调整入圈权益说明 |
| 讲师 | 课程完课率 <40% → 建议拆短章节；新评价含差评 → 跳回复；粉丝周增 >20% → 建议趁热发布新课/开直播 |
| 站长 | 素材点击多但注册少（漏斗断层）→ 建议更换落地内容；锁定用户 7 日未消费占比高 → 建议分享限时优惠券；本月收益环比降 → 推荐本周热销品去推广 |
| 运营商 | 沉寂站长（30 天零业绩）>N → 生成唤醒任务清单；新站长 7 日未出首单 → 建议一对一辅导（附话术）；团队活跃率 < 50% → 建议发起团队竞赛 |
| 驿站 | 库存 < 阈值 → 跳补货；待确认讲师预约 → 跳处理；3 日内开课报名 < 50% 座位 → 建议分享招生海报 |

## 二、五角色工作台升级方案

> 通用结构：顶部「今日宜忌/每日一签」轻栏（复用 wannianli 模块·休闲融入）→ 经营顾问卡（AdvisorInsight）→ 核心 KPI → 趋势 → 待办/预警 → 快捷动作。

### 2.1 圈主 → 圈子运营中心（P0 即可大幅升级）
- **接入即有**：近 30 天趋势图（getTrends 已存在）、成员流失预警（getChurnWarning）、待回复提问（getPendingQuestions）。
- 新增：收入构成环形图（已有 revenue 数据重新可视化）、圈子健康度分（活跃率×发帖率×付费率合成，前端计算）。

### 2.2 讲师 → 讲师品牌中心（双身份合并）
- 合并 teacher-dashboard（课程）与视频创作者中心为统一「品牌中心」首页：**影响力指数**（浏览/粉丝/评分/学员数加权合成，前端可算）+ 双身份数据分区。
- 一键生成讲师品牌海报（复用 poster 体系 + 认证 verifiedTitle）。
- 补销售统计的后端缺口（video sales 恒 0）列入 P2。

### 2.3 站长 → 推广作战中心（漏斗是灵魂）
- **新端点 `GET /track/funnel?ref=me`**：基于 TrackEvent + ReferralRelation + Order 聚合「分享点击 → 注册 → 首单」三步漏斗（数据自归因链路上线日起累积）。
- 客户分层（锁定用户按消费频次/金额分 高价值/待激活/流失风险 三层，后端聚合）。
- 保留已有：趋势图/结算倒计时/自购已省。

### 2.4 运营商 → 团队作战指挥中心
- **团队健康度评分**：活跃站长率 × 人均月产出 × 新人首周激活率 合成（后端聚合端点）。
- 沉寂唤醒任务：dormant 预警从「诚实降级」变真实（30 天零 StationEarning 的站长清单 + 一键发送鼓励消息/分享素材包）。
- 新站长孵化漏斗：注册→建站→首单 转化。

### 2.5 驿站 → 门店经营中心（P0 纯接入）
- **接入即有**：库存预警（getStockAlerts）、待确认预约（getPendingBookings）、即将开课（getUpcomingCourses）、课程/商品排行（getRankings）——全部后端已备，纯前端工作。
- 新增：到课率统计（签到数/报名数，已有数据可算）。

## 三、实施分期

| 期 | 内容 | 成本 | 产出 |
|---|---|---|---|
| **P0 接入即有** | 五工作台接入全部「做了不展」端点 + 今日宜忌轻栏 | 纯前端，无新后端 | 观感与实用性跃升一级 |
| **P1 顾问引擎 MVP** | 两张表 + cron + 模板文案 + 建议卡组件；先上**站长+驿站**（规则最可量化） | 后端中等 | 「诊断-建议-执行」闭环跑通 |
| **P2 AI 个性化 + 漏斗** | DeepSeek 文案 + /track/funnel + 客户分层 + 效果回访 | 中等 | 「生意参谋」成型 |
| **P3 扩展** | 圈主/讲师/运营商全量规则 + 团队健康度 + 影响力指数 + 每日简报推送 | 中等 | 五角色全覆盖 |

## 四、任务拆解（可派普通模型执行）

1. **P0-a** 驿站工作台接入 4 组既有端点（stock-alerts/pending-bookings/upcoming/rankings）+三态
2. **P0-b** 圈主工作台接入 trends/churn-warning/pending-questions + 健康度分
3. **P0-c** 五工作台顶部「今日宜忌」轻栏组件（复用 wannianli API）
4. **P1-a** AdvisorRule/AdvisorInsight 建表（manual-sql）+ advisor 模块（评估 cron + 三个端点 + 单测）
5. **P1-b** 站长/驿站首发规则各 5 条种子 + 工作台「经营顾问」卡组件
6. **P2-a** /track/funnel 聚合端点 + 站长漏斗可视化
7. **P2-b** AI 文案渲染接入（AiGateway 现有通道）+ 效果回访 cron
8. **P3** 其余三角色规则库 + 团队健康度 + 影响力指数
