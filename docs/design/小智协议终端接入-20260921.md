# 小智协议终端接入（第一阶段·隔离测试）

> 2026-09-21。合作模式：**热卜主业务、小智协议终端**——小智硬件只负责拾音、播放和协议通信；
> 用户、圈子、智能体、记忆、权限、用量、额度、计费和审计都在热卜。协议适配层接入热卜自己的服务端，
> 不部署完整独立的小智开源服务端。语音能力前期不直接接大模型，预存采购小智调教好的语音通话服务包（商业 API 未到位）。

## 1. 链路

```
小智硬件 ──OTA(HTTP)──▶ 热卜 /api/v1/xiaozhi/ota/        设备身份（MAC→HMAC）、激活码、连接令牌、终端核对
        ──WebSocket──▶ 热卜 /api/v1/xiaozhi/ws           握手鉴权 → hello → 以绑定用户身份开硬件会话
                                                          → 供应商设备中继（VOICE_PROVIDER.openDeviceStream）
                                                          → 语音识别 / 对话 / 语音合成（语音通话服务包，待商业 API）
```

## 3. Mock 与真实供应商的验证边界

- Mock（`XIAOBU_VOICE_PROVIDER=mock`，生产环境注册表拒绝启用）只做**回放**：把用户刚说的 Opus 帧原样送回设备；
  识别文本、字幕都标「模拟」，会话 `providerIsMock=true`、用量 `usageState=mock`，不进真实用量统计。
- Mock 的「说完」判断是粗略规则（小帧≈静音，连续 700ms 视为说完，单段最长 6 秒），真实服务由供应商做 VAD。
- 默认供应商 `unavailable`：设备能连上、完成 hello，随后收到「待开通/暂未开放」提示并断开，**不建会话、不伪造对话**。
- App 发起的硬件会话口径不变：设备未经真实供应商激活一律显示「待开通」；只有协议终端接入层在 Mock 下显式放行。

## 4. 用户、设备、圈子与会话权限方案

- **设备唯一标识**：固件 `Device-Id` 请求头（物理 MAC），规范为 12 位大写十六进制，台账只存 `HMAC(XIAOBU_DEVICE_PEPPER)` 与末四位。
- **登记**：设备必须先进热卜台账。未登记设备 OTA 只拿到热卜地址（令牌为空、无激活码）——连不上热卜，**也不会回退官方云**。
  后台「小卜硬件台账 → 终端上报」可看到型号/芯片/固件（不含明文 MAC 与网络信息）并一键登记（MAC 不经过前端）。
- **绑定**：已登记未绑定的设备 OTA 拿到 6 位数字激活码（`XIAOZHI_ACTIVATION_CODE_LENGTH` 可设 4—8），设备逐位播报；
  用户在 App「我的硬件」输入完成绑定。激活码 10 分钟有效、用后即废、只存 HMAC，每用户 10 分钟最多试 10 次。
- **解绑/转赠/停用/重新绑定**：沿用现有状态机（条件更新、绑定代次 +1）。连接令牌绑定「设备+代次+用户」，
  任一变化旧令牌立即失效；设备每次开机取新令牌，旧令牌作废。
- **新用户不能读取原用户历史**：会话按 (设备, 绑定代次, 用户) 隔离（契约测试已覆盖转赠场景）。
- **凭据不明文落库或写日志**：令牌、激活码只存哈希；日志只有 MAC 末四位（已检查联调日志）。
- **设备权限不替代用户权限**：握手时校验绑定用户状态；会话以绑定用户身份走热卜会话编排（额度、上下文、幂等键、审计）。
- **圈子私有知识**：设备不直接挂共享智能体；圈子场景仍由热卜按成员身份判断，
  在供应商能安全传递用户身份到 MCP 之前只开放公开知识（沿用 `knowledgeAccess: public_only_until_verified_identity`）。
- **MCP**：设备 hello 宣告的 `mcp` 能力第一阶段不使用；热卜知识走服务端受控检索。

## 5. 需要的设备操作（请决策人配合）

1. **核对设备信息**：型号/板卡名、芯片、固件版本、当前服务器。设备屏幕「关于/版本」或配网页可见；
   改好 OTA 地址后，后台「终端上报」会自动显示芯片、板卡、固件版本。
   决策人 09-21 更正：设备开机报 **6 位**激活码、支持小智官方，即当前连的是官方 xiaozhi.me（默认 OTA `https://api.tenclass.net/xiaozhi/ota/`）。
2. **进配网页改测试服务器地址（不刷固件）**：开源参考板为「开机启动阶段按一下 BOOT 键」进入配网模式（厂商板可能不同），
   手机连设备热点 `Xiaozhi-XXXX`，打开 `http://192.168.4.1` →「高级 / Advanced」→「Custom OTA URL」填：
   `http://192.168.110.155:3989/api/v1/xiaozhi/ota/`（本机 WLAN 地址，联调时服务端需在运行），保存后重启。
   - 依据配网组件源码：开源固件 **v2.4.1（2026-08-04）起**显示该输入框；配网组件 v3.2.0 默认隐藏，中间版本可能看不到。
   - **回退**：同一页面清空该字段保存，设备即恢复默认服务器；只改设备 NVS 设置，不动固件。
3. **同一 WiFi**：设备连与本机相同的 WiFi（本机 192.168.110.155，防火墙关闭）。
4. **配网页没有该输入框时**：先不要刷机。单独评估：用 `esptool read_flash 0 ALL 原厂固件备份.bin` 整片备份并保存，
   确认芯片型号与分区，再决定是否刷开源固件；回退为 `esptool write_flash 0 原厂固件备份.bin`。刷机需决策人另行批准。

## 6. 需要的测试密钥与商业 API 条件

- 第一阶段 Mock 验证**不需要任何密钥**。
- 语音通话服务包（商业 API）到位后需要：接入文档（鉴权、会话签发/结束、音频流通道、用量回调与签名、能力清单）、测试账号与测试密钥、
  设备/智能体映射方式。测试密钥只放本机或隔离环境变量，不打印、不提交、不写前端。
- 需供应商明确回答的能力（`VoiceProviderCapabilities`）：sessionIssue、sessionEnd、usageCallback、callbackSignature、
  userIdentityToMcp、agentConfigPush、deviceBinding、memoryControl、answerCompleteness、audioRecording、**deviceAudioRelay**（本次新增）。

## 7. 商业 API 到位后的最短联调步骤

1. 新建 `provider/xiaozhi-commercial.provider.ts` 实现 `VoiceProvider`：probe / issueSession / endSession / parseUsageCallback / **openDeviceStream**；
   按文档填能力清单，没有证据的一律 `unknown`。
2. `voice-provider.registry.ts` 按环境变量启用；密钥只从环境变量读。
3. 用 `xiaozhi-sim.js` 在本机隔离环境跑通（模拟设备 + 真实服务包）；再用真机按 §5 跑握手、对话、打断、静音、重连。
4. 验证用量回调入账与停费确认；再评估打开 `chargeUsers`。
