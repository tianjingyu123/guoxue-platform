# 小卜硬件出厂自检方案

> 2026-09-22。量产款还没选定（见《小卜硬件选型评测清单》），本方案按目前的开源固件与热卜后台能力写。换板型后只需要改分区偏移和固件文件。
> 原则：**自检环境与正式环境隔离**。工位用独立 WiFi、独立热卜服务（模拟供应商，只做回放）和独立库，不碰正式台账与用户。
> **设备身份 = MAC + 设备 ID**（固件 NVS `board/uuid`，请求头 Client-Id）。MAC 可被空中嗅探、同批连号，热卜只认 MAC 的话别人能冒充设备或抢先激活；
> 所以设备 ID 由工厂生成并写入设备、随清单登记进正式台账，登记即锁定身份。工具：`scripts/xiaobu-factory-nvs.py`。

## 1. 整体流程（每台约 2 分钟）

```
烧录量产固件 ─→ 写自检 NVS（生成设备 ID，MAC+设备 ID 进清单）─→ 自检（配网/上报/激活码/按键回放）─→ 写出厂 NVS ─→ 贴标 ─→ 正式台账批量登记
```

| 步骤 | 做什么 | 检的是什么 | 通过标准 |
| --- | --- | --- | --- |
| 1 烧录 | 写合并镜像（引导 + 分区表 + 量产固件 + 资源） | Flash、串口 | esptool 写入并校验通过 |
| 2 写自检 NVS | `xiaobu-factory-nvs.py station`：读 MAC、生成设备 ID，写「设备 ID + 工位 WiFi + 自检服务地址」，`mac,client_id` 记入当批清单（返工重测沿用原 ID） | 芯片身份 | MAC 不重复 |
| 3 上电联网 | 设备自动连工位 WiFi，访问自检服务 | WiFi 天线、网络栈 | 自检后台「终端上报」30 秒内出现该台，芯片/板型/固件版本与本批一致 |
| 4 激活码 | 设备屏显并**逐位播报** 6 位激活码；质检员在自检 App 账号输入 | 喇叭、屏幕 | 听得清、屏上清楚，输入后绑定成功 |
| 5 按键回放 | 单击按键，对着设备说「一二三四五」，松开等回放 | 麦克风、按键、喇叭、编解码 | 回放清晰无杂音；服务日志该台「上行 ≥ 30 帧、≥ 1 轮」 |
| 6 写出厂 NVS | `xiaobu-factory-nvs.py final`：按清单写「只含设备 ID」的 NVS（去掉工位 WiFi 与自检地址）；解绑自检账号。**不能整片擦 NVS**——设备 ID 会丢 | — | 设备回到出厂配网状态（热点 `ReBu-XXXX`） |
| 7 贴标 | 标签印 MAC 末四位与批次号 | — | — |
| 8 正式登记 | 当批**通过**的清单行（`MAC,设备ID` 两列）用后台「登记设备 → 批量」导入正式台账，登记即锁定身份 | — | 成功数 = 通过数；台账「设备身份」列为「出厂锁定」 |

失败的机器直接进返修，不进正式台账。

## 2. 工位环境

- **WiFi**：独立 2.4GHz 热点（如 `ReBu-QC-01`），只接自检服务，不通外网
- **自检服务**：热卜服务端同一版本、模拟供应商（`XIAOBU_VOICE_PROVIDER=mock`）、独立库；启动方式同本机联调的 `run-server.sh`
- **自检 App 账号**：每个工位一个质检账号，只用来输激活码绑定
- **自检库的台账**：未登记的设备拿不到激活码，所以要在自检前把设备登记进**自检库**。两种做法：每写完一台自检 NVS 就把清单新增行导入；或让自检库对未登记设备走后台「终端上报 → 一键登记」

## 3. 自检 NVS 与出厂 NVS

开源固件读 NVS 命名空间 `wifi` 里的 `ota_url`，为空时才用编译进去的正式地址（`main/ota.cc` 的 `GetCheckVersionUrl`）；
设备 ID 读 `board/uuid`，为空时才自己随机生成（`boards/common/board.cc`）。
所以量产固件编译时就写**正式地址**，工位只用 NVS 临时改到自检服务，最后换成只含设备 ID 的出厂 NVS。不需要两套固件。

| | 自检 NVS（station） | 出厂 NVS（final） |
| --- | --- | --- |
| `board/uuid` 设备 ID | ✓（新生成，或沿用清单） | ✓（同一个） |
| `wifi/ssid`、`wifi/password` 工位热点 | ✓ | — |
| `wifi/ota_url` 自检服务地址 | ✓ | — |

- 工具：`scripts/xiaobu-factory-nvs.py`（需 ESP-IDF 自带 Python；`make` 只生成镜像不碰设备，便于核对）
- 分区：xmini-c3（`partitions/v2/16m_c3.csv`）NVS 在 `0x9000`、大小 `0x4000`；其他板型用 `--nvs-offset/--nvs-size` 按其分区表
- 工位 WiFi 密码只从环境变量 `XIAOBU_QC_WIFI_PASSWORD` 读，不进命令行历史、不打印
- 已验证（2026-09-22）：两种镜像用 ESP-IDF `nvs_tool` 解析，键值与上表一致；工具经 esptool 4.x/5.x 只读读取真机 MAC 一致。**写设备（station/final）尚未在真机上跑**——样机 NVS 里有办公 WiFi，写入会覆盖，待决策人同意或换空白样机再测

> 自检后抽检几台，确认开机是 `ReBu-XXXX` 配网热点，且后台台账「设备身份」为「出厂锁定」。

## 4. 热卜侧已具备的能力

| 能力 | 位置 |
| --- | --- |
| 终端上报（芯片/板型/固件，不含明文 MAC） | 后台「小卜硬件台账 → 终端上报」 |
| 批量登记（每行「MAC,设备ID」，最多 500 台，逐条回报，只回显末四位；带设备 ID 即登记时锁定身份） | 后台「登记设备 → 批量」；接口 `POST /admin/xiaobu/devices/batch` |
| 设备身份锁定与重置（冒充的请求拿不到令牌/激活码/固件；机主 App「重新认证」、后台「重置身份」） | 台账「设备身份」列；运行概况「身份不符」计数 |
| 运行概况（近 24h/7d 联网、正在对话、固件分布、每日开机检查/连接/鉴权失败/结束原因计数） | 后台「运行概况」；接口 `GET /admin/xiaobu/terminals/overview` |
| 激活码绑定 | App「我的小卜硬件」输入 6 位数字 |
| 回放（模拟供应商，原帧回放） | 自检服务 `XIAOBU_VOICE_PROVIDER=mock` |
| 连接日志（上行/下行帧数、轮数、结束原因） | 服务日志「小智终端断开：设备 …XXXX 原因 … 上行 N 帧 下行 N 帧 N 轮」 |

## 5. 以后可以再提速（未做）

- **免输激活码的自检模式**：自检库里当批设备开机上报即自动绑定到工位账号，省掉第 4 步的人工输入（喇叭/屏幕改为只听看）。需要在服务端加「仅自检环境生效」的开关，正式环境必须关闭
- **自动判定回放**：自检服务记录每台的上行帧数与音量，后台直接出「通过/不通过」清单，免看日志
- 量产固件若加闪存加密、安全启动：烧录步骤要改（加密后 NVS 需用加密方式生成），且**会永久烧写芯片熔丝**，上线前单独评估并由决策人确认

## 6. 注意

- 自检服务与正式服务的设备序列号密钥（`XIAOBU_DEVICE_PEPPER`）可以不同：两边台账各自登记，互不影响
- 不要把工位 WiFi 密码、自检服务地址写进量产固件源码
- 当批清单（MAC + 设备 ID）等同设备凭据，只在内部流转、导入后妥善保管；后台与接口都不回显完整 MAC 与设备 ID
- 设备 ID 在设备 NVS 里是明文：拿到实物的人可以读出来。这是「拿到设备 = 拥有设备」的正常边界；要防实物被拆读，需闪存加密（见 §5）
