## 二、状态机（#10/#12）

```
警告 WARNING(ACTIVE, expiresAt=+90天)
  ├─ cron 每小时：expiresAt<now → EXPIRED（90 天自动清零·静默）
  ├─ 创建时若 累计生效警告≥threshold(默认3) 且无生效禁言 → 自动建 MUTE(auto=true, 7天) + 双通知
  └─ 申诉成立 → REVOKED（不再计入累计）

禁言 MUTE(ACTIVE, expiresAt=+1/3/7/30天)
  ├─ 发帖(checkPostGate)/评论(comment.service) 链路拦截：ACTIVE 且未到期 → 403
  ├─ cron 每小时：到期 → EXPIRED + 通知「禁言已解除」
  ├─ 圈主提前解除 → LIFTED
  └─ 申诉成立 → REVOKED

移出 REMOVE（仅圈主·须理由）
  ├─ removeBanRejoin=true → ACTIVE=禁入（createMembership/Tx 两个加入咽喉点拦截）
  ├─ removeBanRejoin=false → 直接落 EXPIRED（仅记录在案）
  ├─ 圈主解除禁入 → LIFTED；申诉成立 → REVOKED（不自动恢复成员关系，需自行重新加入）
  └─ 💰资金硬红线：删成员+记状态+通知为止；付费剩余费用按既有圈子退款流（CircleRefund 双审核）另行结算，本批不动钱

申诉 CircleAppeal(PENDING, deadlineAt=+48h)
  ├─ 前置：本人·处理后 72h 内·每处理仅一次·REVOKED 不可诉·申诉期间处理照常生效
  ├─ 平台裁决（SUPER_ADMIN/OPERATION_ADMIN·不经圈主）：UPHELD→violation REVOKED+清记录 / REJECTED→维持·说明同步
  └─ cron 每小时：超 48h 未裁 → 自动 UPHELD（reviewerId="system"）——按「48 小时答复」承诺，平台失职不由成员承担（⚠️此为实现决策·可拍板改为仅告警升级）
```

三个 cron 均 `@Cron(EVERY_HOUR)` + `redis.runExclusive`（锁名 `circle_governance_expire` / `circle_governance_appeals`·多实例防重复）。

## 三、权限矩阵（#8）

- 定义：`governance/circle-governance.constants.ts` `CIRCLE_PERMISSIONS`（9 项·默认位取自设计稿）+ 纯函数 `resolvePermission(role,key,overrides)`。
- 铁律：圈主恒全权；锁定项 `member.remove` / `funds.manage` 非圈主恒拒（覆盖位抬不动·「能禁言的不能碰钱」）；其余按 `CircleGovernanceConfig.rolePermissions` 覆盖，缺省回落默认。
- 接入点（最小侵入·`CircleSharedService.checkPermission` 新方法）：
  - `circle-post.service` 删帖(非作者)→`content.moderate`；置顶/加精→`content.pin`
  - `circle-core.service` 公告增删→`announcement.manage`
  - `circle-membership.service` removeMember→`member.remove`（⚠️行为变化：原 checkAdmin 允许管理员/合伙人，现按设计稿仅圈主）
  - `growth.service` 入圈申请列表/审批→`member.approve`（默认管理员✓合伙人✗·原先合伙人可审）
