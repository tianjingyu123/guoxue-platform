# 小智商业 API 适配边界与字段映射

日期：2026-09-21。状态：**热卜侧接口已定、供应商侧全部待商业文档**。本文不描述小智商业 API 的真实形态——签约前没有文档，任何字段名、鉴权方式、回调格式都不得猜测。

代码位置：`apps/server/src/modules/voice/provider/`

| 文件 | 作用 |
| --- | --- |
| `voice-provider.types.ts` | 热卜需要供应商提供的能力（接口定义、错误码、能力清单） |
| `unavailable-xiaozhi.provider.ts` | 默认：暂未开放；不发任何请求、不产生费用 |
| `mock-xiaozhi.provider.ts` | 仅测试：契约/权限/页面测试；生产环境拒绝启用；恒 `isMock=true` |
| `voice-provider.registry.ts` | 按 `XIAOBU_VOICE_PROVIDER` 选择；`xiaozhi` 目前仍回退为暂未开放 |

## 1. 替换方式（商业 API 到位后）

1. 新建 `xiaozhi-commercial.provider.ts`，`implements VoiceProvider`，`id = "xiaozhi"`、`isMock = false`。
2. 在 `voice-provider.registry.ts` 的 `wanted === "xiaozhi"` 分支返回它（读取它自己的配置，密钥只从环境变量读，不进代码与日志）。
3. `probe()` 如实返回能力：**只有联调证实的能力才写 `supported`**，其余保持 `unknown`。页面与运营面板据此显示。
4. 实现 `parseUsageCallback()`：按真实文档校验签名、解析事件；不能校验的一律抛 `BAD_CALLBACK`。
5. 会话编排、额度、页面、后台**都不需要改**。

## 2. 接口与字段映射

「热卜侧」列是已实现的字段；「小智侧」列全部待商业文档，填写时附文档出处与日期。

### 2.1 签发会话 `issueSession(IssueSessionRequest) → IssueSessionResult`

| 热卜侧字段 | 含义 | 小智侧对应 | 备注 |
| --- | --- | --- | --- |
| `correlationId` | 热卜会话关联 ID（`VoiceSession.requestId`） | 待文档 | 需供应商在回调中原样回传；不支持时靠 `providerSessionId` 关联 |
| `idempotencyKey` | 同一会话签发的幂等键 `issue:<sessionId>` | 待文档 | 供应商不支持幂等时，编排层已保证同一请求号只调一次 |
| `agentRef` | 热卜侧角色（`xiaobu`/圈子角色 ID/设备角色） | 待文档：智能体 ID 映射 | 映射表由适配器维护，页面不感知 |
| `userRef` | 用户化名 `u_<HMAC>`，不传热卜用户 ID 原值 | 待文档 | 需要稳定密钥 `XIAOBU_USER_REF_SECRET`（≥32 字符） |
| `scene` | 场景 | 待文档（可能无对应，仅作上下文） | |
| `context` | 最小上下文（≤4000 字，已脱敏） | 待文档：上下文/记忆注入方式 | 不下发出生信息、手机号、笔记、完整聊天记录 |
| `maxSeconds` | 本次时长上限 | 待文档 | 供应商不支持上限时，由服务端超时清理兜底 |
| `tier` | lite / standard | 待文档：档位/模型选择 | 圈子档位以平台审核版本为准 |
| `deviceRef` | 硬件会话的设备引用 | 待文档：商业固件设备映射 | |
| 返回 `providerSessionId` | 供应商会话 ID | 待文档 | 存 `VoiceSession.providerSessionId` |
| 返回 `clientCredential` | 端上临时凭据（不透明） | 待文档：临时凭据签发 | **不落库、不写日志**，只返回给发起者 |
| 返回 `expiresAt` | 凭据过期时间 | 待文档 | |

### 2.3 用量回调 `parseUsageCallback(headers, rawBody) → VoiceUsageEventInput[]`

入口：`POST /api/v1/voice/provider-callbacks/:providerId/usage`（无登录态，靠签名；未启用的供应商一律 404）。

| 热卜侧字段 | 小智侧对应 | 备注 |
| --- | --- | --- |
| `eventId` | 待文档 | 与 `provider` 组成唯一键，重复到达只处理一次 |
| `providerSessionId` / `correlationId` | 待文档 | |
| `usedSeconds` | 待文档：计费时长与取整口径 | **供应商没给就是 `null`，不补 0** |
| `isFinal` | 待文档 | 非最终事件只刷新心跳 |
| `answerCompleteness` | 待文档 | 没有就是 `unknown` |

原始回调体只存 SHA-256（可能含用户语音转写），不存原文。

### 2.3.1 用户输入/语音活动 → 空闲计时（1 分钟无新输入自动结束）

决策人 2026-09-21 定：通话 1 分钟没有新的输入即结束（用户告知小智开源服务端也按「无语音即断开」处理）。热卜侧已实现：

- 会话字段 `lastInputAt`，接通时置为接通时刻；`POST /voice/sessions/:id/input` 刷新（只报「有输入」，不传语音/文字内容，5 秒内重复上报只记一次）。
- 端上页面到点主动挂断（`reason=idle_timeout`）；服务端清理任务在「空闲秒数 + 15 秒」后兜底结束并请求供应商停止。
- 秒数在 `voice_billing_config.idleTimeoutSeconds`，默认 60，限 15–600。

真实适配器要做的映射（**字段名待商业文档，不猜**）：

| 热卜侧 | 小智商业侧 | 说明 |
| --- | --- | --- |
| `recordInput(userId, sessionId)` | 待文档：用户语音活动/识别结果事件 | 有此事件就映射过来刷新计时；端上 SDK 的「检测到说话」回调调页面的 `markInput()` |
| `endReason=idle_timeout` | 待文档：供应商因无语音主动断开的结束原因 | 供应商先断开时，以其结束/用量回调收尾，结束原因映射为 `idle_timeout` |
| 空闲秒数 | 待文档：供应商侧无语音断开时长是否可配 | 两边不一致时以较短者为准，需在联调时核对 |

## 3. 错误码约定

| 适配器抛出 | 编排层处理 | 用量状态 |
| --- | --- | --- |
| `UNAVAILABLE` | 会话失败，释放预留 | none |
| `REJECTED` | 会话失败，释放预留，提示稍后重试 | none |
| `TIMEOUT` | 会话失败，释放预留；**供应商侧是否已建会话未知** | unknown（进异常清单待对账） |
| `RATE_LIMITED` | 失败、可重试 | none |
| `BAD_CALLBACK` | 回调返回 401，不入账 | — |
| 其他 | 视同 `UNKNOWN` | unknown |

## 4. MCP 身份边界

`XiaobuMcpServer.handle(raw, identity)`：官方云接入点目前恒为 `{ verified: false }`。
身份绑定工具（`search_circle_knowledge`）在未验证时不出现在 `tools/list`，硬调用返回 `-32001`；
身份只接受服务端基于供应商能力解析的结果，**不接受工具参数里自报的 userId/circleId**。
商业 API 能传已验证身份后，只需在 `xiaozhi-mcp-bridge.service.ts` 把解析出的身份传给 `handle()`。

## 5. 不要做的事

- 不用网页登录 Cookie 构造请求，不逆向私有接口。
- 不把模拟器的回调格式当成小智格式。
- 不在代码里放任何测试令牌、虚构生产地址。
- 不把 `unknown` 能力在页面上显示成“已开通”。

## 6. 签约前资料索取与验收问题（2026-09-23 补充）

下表是热卜需要供应商**提供或书面回答**的内容，不代表小智现已支持。取得正式文档后逐项填写文档版本、页码或接口链接、测试结果；没有证据的能力继续保持 `unknown`。年费开通时点由决策人控制，当前不为索取资料而启用付费接口。

| 主题 | 请供应商提供或回答 | 热卜侧验收依据 |
| --- | --- | --- |
| 测试入口与鉴权 | 正式 API/SDK 文档、测试环境、凭据申请与轮换、权限范围、请求签名、限流与并发规则；是否能在年费生效前取得不计费的联调条件 | 用最小只读调用确认身份、权限和返回格式；密钥只在受控环境中使用，不进日志或仓库 |
| 会话签发与恢复 | 签发、查询、结束接口；临时端上凭据的有效期；请求超时后能否按幂等键或关联号查询真实会话状态；`maxSeconds` 是否由服务端强制执行 | 同一幂等键重复签发不会产生两条计费会话；8 秒签发超时后的状态可核对，不能把未知当作失败 |
| 停费确认 | 主动结束、设备断线、静音、超时后的计费终点；结束接口何时返回“已停费”，失败时如何查询或补偿 | 结束请求按热卜当前 5 秒超时约束测试；未拿到停费确认时保持 `unknown` 并进入对账，不声称已停费 |
| 设备音频中继 | 是否允许热卜服务端转发终端双向音频；输入/输出编码、采样率、声道、帧长、二进制封装、缓冲上限；是否支持当前终端上行 Opus 16 kHz、单声道、60 ms 帧，输出能否被终端直接播放 | 用真机验证连续对话、打断、断线重连和至少一次长句；若格式不兼容，先评估转码代价与设备固件改动，再决定产品方案 |
| 流式事件与时延 | 用户开始/停止说话、识别文本、首段回复音频、后续音频、回答结束和错误事件；供应商提供测试条件、首音频 P50/P95、抖动及并发限额 | 记录从说完到首播、下行帧间隔和设备播放队列；Mock 回放的约 1 秒听感不能代替真实 ASR/模型/TTS 指标 |
| 用量回调与验签 | 回调原始字节签名算法、时间戳/重放保护、密钥轮换、`eventId`、会话关联号、最终事件、重试顺序和失败重发策略；是否有按会话查询用量接口 | 伪造/篡改回调被拒绝；重复、乱序和迟到事件不重复扣费；无法匹配的事件进入异常清单，不丢弃审计线索 |
| 计费口径与对账 | 开始计费点、暂停/静音/等待 MCP/断线是否计费、取整单位、最小计费量、失败会话、账单明细和争议处理；能否提供测试账单样本 | 对照供应商账单核对 `usedSeconds` 与热卜额度结算；缺失真实时长写 `null`/`unknown`，不得补 0 或把模拟用量当真实费用 |
| 错误码与重试 | 鉴权失败、额度不足、限流、参数错误、供应商不可用、请求超时、流中断、回调验签失败的真实错误码；哪些允许同幂等键重试 | 映射到 `VoiceProviderErrorCode`，特别区分明确拒绝与“可能已建立会话”的超时；保留关联号以便查询和对账 |
| 身份、数据与删除 | 用户化名引用能否随 MCP 调用传递并由热卜验证；音频/转写/长期记忆的保存期限、删除接口与导出方式；角色、提示词和音色的生效边界 | 未验证身份不开放圈子私有知识；未取得明确能力及授权前不录不存实时音频，不宣称可删除供应商侧记忆 |
