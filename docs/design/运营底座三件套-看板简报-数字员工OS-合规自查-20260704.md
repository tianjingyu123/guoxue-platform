## 一、数据看板 + 每日运营简报

### 1.1 指标体系（以生态飞轮为纲，不堆虚荣指标）
- **北极星双指标**：周活从业者数（工作台周活）· 交易线月 GMV
- **飞轮转化仪表**（增长页）：L0→L1 工具用户次日回访率 / L1→L2 内容用户课程转化 / L2→L3 认证转化 / L3→L4 角色转化 / 触点漏斗（曝光→点击→成交·分触点）
- **收入八线仪表**（收入页）：各线日/月新增（会费类：新签+续约率；交易类：GMV+佣金）——直接对应总设计测算表，**看板即军令状进度条**

## 二、数字员工运营 OS（CLAUDE.md 承诺兑现·上线后无人值守的地基）

### 2.1 四大件
1. **任务池 OpsTask**（状态存 DB 不存脑内）：id/type(巡检|修复|审核|运营动作)/priority/status(pending|in_progress|completed|needs_review)/executor(CLAUDE|人名)/payload Json/result Json/needsApproval——数字员工与真人从同一池取任务、完成/转交全记录
2. **一键接管开关**：`POST /system/automation/toggle`（SUPER_ADMIN）→ SystemConfig `automation_enabled`；**数字员工的一切写操作前置检查此开关**（关=只读模式）；开关变更审计+通知
3. **操作审计与回滚**：复用 AuditLog，补 `executor` 字段（CLAUDE 标识）；关键操作（配置改动/下架/退款类）落 `rollbackPayload`，admin 一键撤销
4. **每日巡检 cron**：健康检查全项/错误率突增(G4数据)/资金对账结果(settlement-reconcile)/超时订单/慢查询 Top——产出巡检报告进任务池：**白名单内自动处置**（重跑失败 cron/清理过期缓存·处置动作本身审计），白名单外建 needs_review 工单转人工

### 2.2 权限边界（CLAUDE.md 既定·落成代码）
高风险操作（退款/删用户数据/改价格策略/资金）**永远** needsApproval=true 走人工；数字员工角色与真人同权限体系配置（RoleType 加 DIGITAL_EMPLOYEE）。

### 2.3 任务包（2 批）
| 批 | 内容 | 验收 |
|---|---|---|
| OS-P1 | OpsTask表+CRUD+automation_enabled开关+写操作守卫(装饰器@RequireAutomation)+AuditLog补executor/rollback | 关开关→数字员工写操作全 403·审计完整 |
| OS-P2 | 巡检cron+白名单处置+needs_review工单+admin任务池页 | 造异常→巡检发现→分级处置端到端 |
