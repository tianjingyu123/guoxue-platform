# 圈子苹果级体验重构规范

日期：2026-09-22
适用范围：圈子广场、圈子详情、内容流、发帖入口、我的圈子、圈主助理与圈主管理入口。

## 目标

把圈子从“功能入口集合”重构为一条连续的社区体验：用户先理解一个圈子能带来什么，再用最短路径加入、浏览、参与和继续探索。视觉参考苹果产品的清晰层级、直接操作、连续反馈和克制动效，保留热卜的文化气质，不复制苹果的具体界面或素材。

首屏只回答三个问题：

1. 这里是什么圈子，适合谁；
2. 现在有什么值得看；
3. 下一步最值得做什么。

## 核心路径

```text
发现圈子 → 看懂价值 → 预览内容 → 加入/申请/付费
        → 进入圈内首页 → 阅读/评论/发动态
        → 圈主助理、课程、直播、橱窗等按需展开
        → 从消息、分享或推荐回到原位置
```

普通成员的主路径是“阅读和轻互动”；圈主、管理员的运营动作集中到管理中心。发布、治理、收益和退款仍沿用现有后端权限与审计边界，不在本轮改变业务规则。

## 交互原则

### 一屏一个主动作

广场的主动作是“看看圈子”，详情页在未加入时是“加入/申请加入”，已加入时是“发动态”。搜索、分享、管理和退出降为次级动作，避免多个红色按钮竞争注意力。

### 状态先于装饰

加入、审核、付费、加载、失败、空内容、权限不足和续费临期都要在原位置给出说明及恢复动作。文案说明发生了什么和用户可以做什么，不能用空白、灰色按钮或没有反馈的跳转代替状态。

### 直接操作与连续性

点击圈子卡进入预览，点击加入完成加入或进入支付，成功后直接进入圈内首页；点击发动态直接打开编辑器；从助理、课程、直播和商城返回时保留圈子与滚动位置。主要触控区域不少于 44px，页面操作不能被微信胶囊按钮遮挡。

### 克制的视觉层级

页面使用中性浅灰画布和白色内容表面，品牌色只用于主动作和重要状态。圆角为 12/18/24rpx 三档，阴影低透明度、大模糊，内容卡片优先展示标题、来源和下一步，不用大面积渐变和装饰抢占阅读空间。

### 助理是圈内导航，不是悬浮广告

圈主助理在详情页身份区以一张能力卡出现，明确“能回答什么”。移除重复悬浮球，阅读区域只保留一个带文字的发布按钮。出处、会话恢复、语音入口必须依据实际链路逐一验收，未验证前不在入口文案中承诺。

## 信息架构

### 圈子广场

- 顶部：标题、圈子个人中心；下方固定三个分区“我的圈子 / 发现圈子 / 圈内动态”。微信小程序预留胶囊安全边界。
- 登录成员默认进入我的圈子，游客默认进入发现。搜索位于分区内容顶部。
- 我的圈子：纵向回访列表，名称可读、整行进入；创建圈子作为列表后的次级入口。
- 发现圈子：分类只承担筛选，卡片按“主题、活跃度、加入方式、查看详情”排列。
- 圈内新鲜事：只展示已加入圈子的真实内容，点击内容回到原圈子和帖子。

### 圈子详情

- 顶部身份卡：封面、名称、定位、成员、圈主和管理入口。
- 助理能力卡：进入本圈已有文字对话页。来源与上下文恢复按后续完整服务链验收。
- 内容带：直播、课程、橱窗有真实数据时才出现，无数据不留空壳。
- 栏目：推荐、精华、文章、问答；每个栏目有独立空态和回到推荐出口。
- 底部动作：游客加入通栏；成员带文字的发动态按钮。助理在正文身份区，无双悬浮球。

### 我的圈子

顶部先给“继续参与”的聚合信息，然后按“我创建/管理的”和“我加入的”分组。管理动作只在有权限的圈子卡上出现；搜索、筛选和空态均提供明确出口。

## 分阶段实施

1. P1：统一令牌和高频页面层级；广场、详情、帖子卡、我的圈子先完成。
2. P2：把发帖、助理、搜索、加入和返回状态串成连续路径。
3. P3：管理中心、治理、审核、收益页面按同一套信息层级收口。
4. P4：在真实数据可用后接入圈主观点、课程、直播和橱窗的个性化推荐。

## 方案复核与取舍

最初方案试图在旧首页增加一张大引导卡。复核发现它会重复搜索与创建入口，并使老用户更晚看到自己的圈子，已在实现前后复核阶段移除。最终采用分区结构，让回访、发现、阅读分别有明确位置。

以内容本身作为视觉焦点：发现页大封面帮助判断主题，回访页紧凑列表帮助快速进入，帖子页留下连续阅读空间。只有发现页强调封面；每一层不重复铺大卡、渐变和装饰标签。

字体优先使用平台中文无衬线字体；正文左对齐，标题和辅助信息使用既有字号阶梯。无真实封面时使用已有 SmartCover，避免空白或引入不必要的图片包。

```text
圈子入口                       圈内阅读                       圈主管理（后续）
圈子                  个人中心  返回     圈名          分享     返回       圈主管理
我的圈子 | 发现 | 圈内动态      圈子简介 / 成员 / 圈主          待处理事项
搜索圈子                       问问圈主助理                   入圈申请 / 内容审核

或发现封面 → 预览              内容、图片、评论               收益与履约
或圈内近期动态                 内容、图片、评论               规则与设置
创建圈子（次级）                                    发动态     风险操作独立说明
```

| 圈内阅读、助理、资源承接 | 内容优先，资源打开本圈列表，只有一个发布悬浮动作 | 首轮代码候选；本地 H5 验证 |

| 发帖与内容详情 | 草稿、键盘、附件失败、审核状态、退出挽回形成闭环 | 本机草稿隔离/自动保存、发布防重与返回、评论按需输入已完成候选；附件真机、审核及云端草稿恢复仍待完整验收 |
| 我的圈子与个人事务 | 按角色浏览，申请、退款、创作状态易找到 | 多圈管理入口、查询失败恢复、回访刷新已完成本地候选；真实审核与售后链仍待验收 |

| 助理配套 | 当前圈子上下文、可信来源、推荐理由、语音能力、续费回原会话 | 入口接线完成，服务全链未验收 |

通过门槛是用户任务，不是截图数量：已加入圈子一次点击进入；普通成员一次点击打开发帖；待审申请直接查看进度；同一付款不重复确认；失败后可以恢复；320px 页面没有横向溢出；按钮实际触达区不少于 44px。真实支付与审核后的权限必须独立实测。

## 已识别的既有断点

- 详情页搜索入口实际指向圈子搜索，本轮已更正读屏名称；真正圈内全文检索不能靠改标题冒充接入。
- getJoinStatus 旧调用默认回退 joined=false；5d61fb0a2 的加入/续费路径已使用严格读取与“暂无法确认”状态。其他旧调用不可自动视为都已完成改造。
- 动态聚合当前只取前 6 个圈子各 2 条内容，本轮如实说明范围，不声称为全量消息中心。
- 圈内课程/商品查询当前限制 6 条，本轮资源抽屉是接口返回的近期资源，完整分页留待独立收口。

参考：[Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines)、[Navigation and search](https://developer.apple.com/design/human-interface-guidelines/navigation-and-search)。参考的是信息层级和导航原则；热卜的三端实现仍需各自验收，不能以“苹果级”作为已达标的技术结论。

## 验收标准

- 用户在首屏能读懂圈子定位，并能在两次操作内进入预览或已加入圈子。
- 未加入时只有一个加入主动作，已加入时只有一个发动态主动作。
- 助理、分享、课程、直播和商城返回后保留圈子上下文。
- 所有加载、失败、空内容和权限状态均有可执行出口。
- 主要按钮和系统胶囊不重叠；关键文字对比度可读；主要触控区域不少于 44px。
- 不改变现有支付、退款、治理、权限、通知和内容可见范围；真实设备和线上数据另行验收。
