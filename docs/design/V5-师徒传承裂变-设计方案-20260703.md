# V5 师徒传承裂变 — 设计方案

> 2026-07-03 · 裂变库 V5 · 自主拍板 · 合规红线 R1（传销）是本设计的第一约束

## 一、合规隔离（拍板·最重要）

侦察建议"复用 ReferralRelation(referrerType=MENTOR)"——**否决**。ReferralRelation 已进 commission/settlement 计酬链路，师徒混入会让徒弟消费触发师父分销佣金 = 踩 R1 传销红线。

**铁律：师徒荣誉体系与分销计酬体系物理隔离。**
- 师徒关系用**独立表 Mentorship**，完全不碰 ReferralRelation/commission/settlement
- 传道值 = 纯荣誉整数（UserGrowth.mentorshipPoints），**不可兑换现金/国学币/任何财物**（只上荣誉榜）
- 师徒**单层不嵌套计酬**：师父的师父不因徒孙得任何东西（连荣誉都不传递）——彻底切断层级
- 拜师不产生任何资金关系；徒弟消费与师父零财务关联

## 二、数据模型

新表 `Mentorship`（manual-sql）：
- id / mentorId / discipleId / status(ACTIVE|GRADUATED) / mentorshipPoints(Int·该徒累计贡献的传道值) / disciplePledge?(拜师寄语) / createdAt / graduatedAt?
- @@unique([discipleId])（一人一师·徒弟唯一）· @@index([mentorId]) · 无 FK（裸 String 惯例）
- UserGrowth 加 `mentorshipPoints Int @default(0)`（师父累计传道值·荣誉总和·冗余便于榜单）

## 三、传道值规则（纯荣誉）

徒弟成长 → 师父得传道值（后台可配基准）：
- 徒弟每日打卡 → 师父 +2
- 徒弟学分每满 100 → 师父 +5（在 addExp 钩子里检测徒弟跨百）
- 徒弟晋升功名等级 → 师父 +20
- 徒弟出师 → 师父 +50 一次性
所有加值在 UserGrowth.mentorshipPoints 与 Mentorship.mentorshipPoints 双写（后者留归属明细）。**无任何现金/币映射。**

## 四、出师

徒弟达到条件（学分≥1000 或功名≥举人·可配）→ 可申请/自动出师 → status=GRADUATED → 双方各得出师成就卡（师父 mentor_graduate 成就 / 徒弟 graduated_disciple 成就）+ 师父 +50 传道值。出师后师徒关系保留为荣誉记录，徒弟可再拜新师（一人一师约束按 ACTIVE 计，GRADUATED 不占位）。

## 五、端点契约（新 mentorship 模块或挂 user-growth）

1. `POST /mentorship/invite`（登录·师父）→ { inviteToken, shareUrl }（独立 token·非分销 ref·7天过期）
2. `GET /mentorship/invite/:token`（公开）→ { mentorNickname, mentorLevel, mentorTitle, discipleCount }（师父展示·招徒）
3. `POST /mentorship/accept`（登录·徒弟）body { token, pledge? } → 校验：无 ACTIVE 师父+token有效+不能拜自己 → 建 Mentorship(ACTIVE) → 返回 { mentorshipId, mentorNickname }
4. `GET /mentorship/my-mentor`（登录）→ 我的师父 { mentorNickname/level/title, since, myContributedPoints } 或 null
5. `GET /mentorship/my-disciples`（登录·师父）→ 徒弟列表 [{ discipleNickname, level, status, contributedPoints, since }] + 汇总 { totalPoints, activeCount, graduatedCount }
6. `POST /mentorship/graduate`（登录·徒弟自主出师·满条件）→ 校验条件 → status=GRADUATED+双方成就+师父+50 → { success }
7. `GET /mentorship/ranking`（公开）→ 传道值荣誉榜 TOP N [{ mentorNickname, mentorshipPoints, discipleCount }]

## 六、传道值钩子接入

user-growth.service 的 onCheckin/addExp/等级晋升处，检测该用户是否有 ACTIVE 师父（查 Mentorship discipleId=本人），有则给师父双写传道值。钩子 catch 自吞不影响主流程。

## 七、前端

- pkg-mine/mentorship（师徒中心）：我的师父卡 + 我的徒弟列表 + 招徒邀请分享（useShare 带 token）+ 传道值荣誉榜入口 + 出师按钮（满条件）
- 成长中心 achievements 页加「师徒传承」入口
- 拜师落地页（点邀请链接 → 见师父招徒卡 → 拜师寄语 → 拜师）——可复用 accept 弹层或独立页

## 八、裂变闭环
师父招徒分享（传道值荣誉驱动·想收更多徒弟涨传道值上榜）→ 新/老用户拜师 → 徒弟成长反哺师父荣誉 → 出师双方成就卡再传播。全程零现金，纯荣誉与文化传承叙事，R1 安全。
