# 后台管理端体验标准 V1.0（头部对标 · 2026-07-18）

> 董事长要求：后台管理对标一线主流品牌管理后台（有赞商家后台 / 飞书管理后台 / 微信公众平台 / 抖店 / Stripe Dashboard 的操作范式），
> 让非技术的运营、财务、客服**看一眼就懂、点一下就对、危险操作拦得住、该有的按钮一个不少**。
> 并拍板：**人工工作区和 AI 自动化工作区要分开**（第三节，信息架构总纲）。
> 本文档是后台管理端（apps/admin·Vue3+Element Plus）的**唯一验收标准**，与移动端
> 《全平台体验标准-头部对标-V1.0-20260717.md》同宗；每个页面出厂前逐条过第十节红线。

---

## 一、后台"反人性化"的五大病灶（董事长原话拆解 · 诊断框架）

修任何页面前先对照自查，命中一条即不合格：

1. **代码思维**：把数据库原样端给人看——大写英文枚举（PENDING/WITHDRAW）、裸 UUID 占满列、
   ISO 时间生肉、金额以"分"直出、JSON/技术堆栈报错。运营要的是"待审核 · 5分钟前 · ¥1,280.00"。
2. **按钮不全**：对象能看不能改、能单个不能批量、能查不能导出、详情缺返回/编辑入口、
   审核弹窗里看不到被审内容本体。一个业务对象的**全生命周期操作必须在它的管理页闭环**。
3. **交互逻辑断裂**：筛选不生效、翻页丢筛选态、保存后列表不刷新、跳转 404、
   状态机顺序错（未通过审核就能上架）、操作无 loading 无结果反馈。
4. **功能重复/多余**：同一业务多个菜单入口、老原型遗留僵尸页、死菜单（点开"开发中"）、
   同名不同页（两个"任务池"）。**一个业务只有一个入口**。
5. **质感失守**：三态缺失（白屏/裸空表/console 吞错）、Element Plus 默认样式裸奔、
   表格列宽随缘、弹窗里再套弹窗、密度失衡。

## 二、对标基准（一线管理后台的共同范式）

| 范式 | 对标出处 | 硬要求 |
|---|---|---|
| 列表页九件套 | 有赞/抖店商品列表 | 筛选栏+重置 · 关键词搜索 · 状态 Tab 或下拉 · 时间范围 · 分页(带总数/可改页容量) · 批量操作栏 · 导出 · 列表刷新钮 · 行内操作组 |
| 审核工作流 | 微信公众平台内容审核 | 待审队列默认置顶 · 审核弹窗内呈现**被审内容本体** · 通过/驳回一步可达 · 驳回理由必填(可选常用理由) · 批量通过 · 审核后自动跳下一条(连续审核模式) |
| 数据看板 | Stripe Dashboard | 指标卡带同比/环比 · 趋势图可选时间粒度 · 图表可下钻到明细列表 |
| 危险操作 | 阿里云控制台 | 分级确认(见第七节) · 影响范围预告("将影响 1,203 名用户") · 操作留痕可查 |
| 详情页 | 飞书审批详情 | 面包屑+返回 · 关联对象可点跳(用户→用户详情/订单→订单详情) · 时间线(操作历史) |

## 三、顶层信息架构：人工工作区 与 AI 自动化工作区分离（董事长拍板 2026-07-18）

**原则：人做决定的地方和 AI 自动干活的地方，是两个工作区，不混排。**

### 3.1 两区定义

- **人工工作区**（默认区·运营/财务/客服/审核员每天上班的地方）：
  工作台 · 审核中心 · 内容运营 · 电商 · 用户与会员 · 财务 · 线下与生态 · 排盘工具 · 数据看板 · 系统配置。
  这里只出现**需要人看、人点、人拍板**的功能。
- **AI 自动化工作区**（数字员工车间·AI 自动执行+人监督兜底）：
  现"🤖AI与数字员工"18 项全部划入，另收编散落各区的 AI 自动化项：
  古籍AI维护 · AI复审/协作审核 · 合规扫描 · 哨兵告警 · 刷单识别/异常检测 · 流失预测与自动挽回 ·
  AI内容生成/种子内容 · 智能客服 · 任务池(系统/运营两个同名池合并归位) · AI模型路由/RAG/知识库 ·
  用量统计/调用监控/对话日志。

### 3.2 分区判据（新功能归区就问这三句）

1. 这个页面的主角是"人点按钮"还是"AI 在跑、人来看"？前者人工区，后者 AI 区。
2. 页面主体是执行队列/日志/用量/模型配置吗？是 → AI 区。
3. AI 产出需要人拍板吗？拍板动作放**人工区对应业务页**（如 AI 审核建议出现在审核中心，
   一键采纳），AI 的运行过程和配置留在 AI 区。

### 3.3 两区衔接的三条硬规矩

1. **AI 建议 → 人工确认**：AI 区的任何自动结论进入人工区时必须标注"AI 建议"来源+置信度，
   人工可一键采纳/驳回；绝不允许 AI 结论伪装成人工态直接生效于资金/封禁/下架类操作。
2. **可追溯**：AI 自动执行的每个动作在 AI 区有执行记录，在人工区相应对象的时间线上留痕
   （"由 AI 自动通过 · 2026-07-18 03:12"）。
3. **可兜底**：每类 AI 自动化必须有"暂停自动化/转人工"开关，放在 AI 区该功能的显眼位。

### 3.4 落地形态

侧边栏顶部加**工作区切换**（人工工作区 ⇄ AI 自动化工作区，Element Plus el-segmented 或双 Tab），
切换后侧边菜单整树切换；默认进入人工工作区。菜单重组随 Z 区推进落地，动菜单前列迁移清单亲核。

## 四、数据显示规范（"代码思维"的直接解法）

1. **枚举必翻译**：所有 status/type/method 字段渲染为中文 + `el-tag` 色语义
   （成功=success绿 · 进行/待处理=warning橙 · 失败/拒绝=danger红 · 中性=info灰）。
   全局字典统一维护（`lib/enums.ts` 一处翻译，禁止各页自写映射漏一半）。
2. **时间人性化**：列表用"MM-DD HH:mm"，悬浮 tooltip 给完整"YYYY-MM-DD HH:mm:ss"；
   24h 内加相对时间（"5分钟前"）。禁止 ISO 串/Unix 时间戳直出。
3. **金额**：后端分 → 前端元，`¥1,280.00` 千分位两位小数；资金列**右对齐**；
   收入绿/支出红（或 +/- 前缀）；汇总行加粗。
4. **长 ID**：列表内截断显示前8位 + 悬浮全文 + 点击复制（成功 toast"已复制"）；
   ID 列不做第一列、不占大宽度。
5. **人指代人**：凡出现 userId 处显示 昵称(手机尾号4位)，点击跳用户详情；订单号同理可跳。
6. **数量单位**：大数千分位；百分比统一 1 位小数；空值显示"—"不显示 null/undefined/0 混用。

## 五、列表页规范（九件套逐条）

1. 顶部筛选卡：关键词 + 状态 + 时间范围起步；改筛选即查询或"查询"钮，必配"重置"。
2. 筛选/分页状态入 URL query（刷新/回退不丢态；从详情返回回到原页原筛选）。
3. 分页：el-pagination 带 total/sizes/jumper；翻页保筛选。
4. 批量：需要逐行同操作的列表必须多选 + 批量操作栏（审核类=批量通过；禁止批量驳回不填理由）。
5. 导出：数据型列表配导出钮（后端有端点则接，无则记后端清单，钮不上假的）。
6. 行内操作：≤3 个用文字按钮组；>3 个收进"更多"下拉；危险操作红色靠右。
7. 表格：关键列 min-width 防挤压；长文本 show-overflow-tooltip；图片列缩略图点击大图预览。
8. 空态：人话 + 引导动作（"暂无待审核内容，去看看已通过的？"）；筛选后空态提示"换个筛选条件"。
9. 刷新：列表右上角刷新钮；审核队列类页面给自动刷新间隔或新任务提醒。

## 六、表单与弹窗规范

1. 必填标星、失焦即时校验、错误定位到字段；提交钮 loading 且防重复提交。
2. 成功 = toast + 关弹窗 + 列表刷新且**保持当前筛选页码**；失败 = 具体人话原因（不甩 code）。
3. 有改动未保存时关闭弹窗/离开页面要确认；表单弹窗宽度适配内容，禁止弹窗内滚动嵌套弹窗。
4. 复杂配置用分步或分组卡片；说明文案写在字段旁（placeholder 不当说明书用）。

## 七、危险操作分级（后台一键影响全平台，比 C 端更严）

| 级别 | 适用 | 拦截 |
|---|---|---|
| L1 普通确认 | 删除草稿、取消置顶 | el-popconfirm 一次确认 |
| L2 理由必填 | 驳回、下架、封禁 | 弹窗 + 理由必填（常用理由可选）+ 确认 |
| L3 影响预告 | 批量操作、规则变更、开关切换 | 确认框写明影响范围与数量 + 确认 |
| L4 四眼/复核 | 资金支出（退款/提现/调账）、账号注销 | 发起人≠审批人 · 二次审批流 · 全程留痕 |

资金与权限端点改动逐处双查（铁律5）；任何 L2+ 操作写入操作日志且对象时间线可见。

## 八、三态与反馈

1. 加载：区域 v-loading（骨架屏优先于全屏转圈）；> 1s 的操作必有 loading 态。
2. 空态：人话 + 引导（见五-8）；**禁止裸的"No Data"**。
3. 错误：接口错 = el-result/alert + "重试"钮；catch 里禁止只 console.error 吞掉；
   报错文案人话（"加载失败，请重试"），技术细节收进折叠或日志。
4. 所有写操作有结果反馈（成功/失败 toast），页面数据随之刷新，禁止"点了没反应"。

## 九、菜单与导航规范

1. **一个业务一个入口**：重复功能合并（订单管理 vs 统一订单中心、三处提现审批、两个任务池
   ——审计确认后合并或明确分工重命名）。
2. 无死菜单：点开是"开发中"/空白/永远空列表的菜单项，要么补齐要么下架。
3. 命名口径统一：动宾或名词短语，同类同构（"XX管理"/"XX审核"），禁止中英混排和内部代号。
4. 一级分组 ≤ 9 个（米勒定律），按使用者工作流组织而非代码目录。
5. 深层页有面包屑，详情页有返回且返回保列表态；当前菜单项高亮正确。
6. 角色可见性：菜单按角色过滤（审核员不见财务），入口与路由权限一致，防"点得到进不去"。

## 十、验收红线（每页出厂检查清单）

1. 无大写英文枚举/裸ID/生肉时间/以分计的金额直出
2. 该对象增删改查+状态流转+批量+导出按钮齐全（或已入后端清单并注明）
3. 筛选真联动、翻页保态、操作后列表自动刷新
4. 危险操作按第七节分级拦截，驳回类理由必填
5. 三态齐全，无 console 吞错，无"点了没反应"
6. 无重复入口、无死菜单、无假按钮（点了只 toast 不调 API）
7. 详情可回、关联对象可跳、面包屑正确
8. AI 相关：自动结论标"AI 建议"+可采纳/驳回；AI 页面归 AI 工作区（第三节）
9. `npx vue-tsc --noEmit` EXIT 0
10. 真机截图走查过 + 交叉复检零新发现
