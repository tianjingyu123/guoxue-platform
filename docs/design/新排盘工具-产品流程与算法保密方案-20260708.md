# 新排盘工具：产品流程与算法保密方案

> 定位：董事长秘密自研、用于**硬切换替代第三方老排盘系统**的新一代排盘工具设计稿。
> 两个战略目标同时服务：①承接老用户（用回收的生辰**重算历史盘**，无感迁移）②新的**付费解读变现**。
> 编制：2026-07-08（原稿因上个对话工具污染未落盘，本次重建）。本文为产品流程 + 算法保密 + 防蹭防破解的落地规格，可直接交付开发。
> 配套：《排盘系统硬切换-数据主权回收与无感迁移方案-20260708》。

## 一、第一原则：算法保密靠"服务端运行"，不是靠"付费墙"

**铁律：核心算法只在服务器运行，前端（小程序/H5/APP）永远只收到「算好的结果/报告」，拿不到任何算法逻辑。**

- 前端代码可被用户下载、反编译——**任何放在前端的算法，加密也只是拖时间，终会被破解**。
- 付费墙是第二层（控制谁能拿到结果）；服务端运行是第一层（控制谁能看到算法）。**两层缺一不可，第一层更根本。**
- 做到这一点，蹭客/破解者看到的永远是「答案」，不是「解题过程」。

### 什么才是真正要保密的（火力集中点）
| 层次 | 是否保密 | 说明 |
|---|---|---|
| 基础排盘规则（干支/四柱/五行生克/星曜落宫） | ❌ 无需保密 | 公开的传统知识，任何命理书都有，保不住也无必要 |
| **独家格局判断 / 评分模型** | ✅ 重点保密 | 同一个盘怎么给结论——这是核心资产 |
| **AI 解读 prompt 工程 + 知识库** | ✅ 重点保密 | 新工具最值钱、最该锁死服务端的部分 |
| **多流派综合推演逻辑** | ✅ 重点保密 | 独家算法 |

**结论：把保密投入集中在"独家判断/解读层"，不要浪费在通用排盘层。**

## 二、产品流程（付费漏斗）

采用「先付费 → 校验 → 服务端排盘 → 付费报告」主线，符合董事长算法保密诉求；补一道信任缓解降低盲付流失。

```
用户选工具/服务
   ↓
【信任缓解】展示「样例报告」或一句话极简结论（不泄露独家判断层）
   ↓
下单付费  ← 收入在最前锁定
   ↓
填写信息（出生年月日时/性别/出生地；合盘含对方）
   ↓
【信息校验·三层】不合格 → 提示补充/纠正（此时未触发算法，不浪费）
   ↓
服务端排盘（核心算法·前端不可见）
   ↓
生成付费报告（订单绑定·仅付费者可见）
```

### 信任缓解（防盲付流失·二选一或组合）
1. **样例报告**：展示一份演示盘的完整报告样例，让用户清楚"花钱能得到什么"。**不是**免费算用户本人的盘。
2. **极简结论免费**：如"日主甲木、身弱"一句话，完整分析付费。尺度由董事长定，不泄露独家判断层即可。

## 三、信息校验（三层·付费后、排盘前）

放在「付费后、调用算法前」，不合格则拦下让用户补充，绝不让废数据触发核心算法/AI。

| 层 | 校验内容 | 拦截目标 |
|---|---|---|
| 必填校验 | 出生年月日时、性别、出生地齐全 | 信息不完整 |
| 合理性校验 | 日期非未来、年份合理区间、时辰有效、出生地可匹配经纬度（真太阳时校正需要） | 明显虚假/手滑乱填 |
| 幂等/重复校验 | 同信息+同解读类型已算过 → 复用缓存，不重复消耗 | 重复计算浪费 |

### ⚠️ 必须向业务方点破的现实
**"填了别人真实生日"这种虚假，系统无法在计算前识别。** 校验能防的是"格式错误/明显不合理"，防不了"张三填李四的真生日"。别对"防虚假"期待过高——它防手滑和乱填，不防蓄意欺骗。

## 四、合盘状态机（解决老工具断链）

老合盘断链根因＝想做"邀请对方填"却无状态机+无通知。新工具必须补齐：

**流程**：发起人付费下单 → 填自己 + 生成邀请（链接/二维码）→ 对方打开填自己的 → 双方齐且校验通过 → 服务端排盘 → 付费报告。

**订单状态机**：
```
待填写(发起人) → 待对方填写 → 信息齐待校验 → 校验通过待计算 → 计算中 → 报告就绪
                     ↓(超时/对方不填)
              可催促 / 改自己代填 / 超时退款
```

**关键设计**：
- 发起人页面明确显示状态：「等待对方填写 / 对方已填写 / 可以开始」；对方填完发起人收到**通知**（站内信/短信）。
- 付费在信息齐之前，钱不因对方拖延而消耗算法——**待对方填写期间零成本**。
- **默认给两种入口**：①「我自己填双方」（知道两人生辰，一步到位）②「邀请对方填」（不知对方信息时）。别只留邀请一条，多一人多一道流失。

## 五、防蹭 / 防破解落地清单

1. **算法服务端运行**，前端只收结果 —— 根本
2. **报告按订单绑定**，服务端校验"该用户为该盘付过费"才返回，防越权查看他人报告
3. **接口鉴权 + 频控限流**：防批量调用蹭算力/结果
4. **报告防抓取**：水印、防批量爬取、关键结论图片化（防文本直接复制）
5. **AI 层锁死服务端**：prompt、知识库永不出现在前端或接口响应中
6. **结果缓存绑定用户+订单**，不可跨用户复用可见性（缓存为省成本，不是共享报告）

---

## 六、成本控制（AI 是真成本，排盘几乎免费）

- **成本认知**：排盘计算＝确定性 CPU 运算，成本近零；**AI 解读＝真金白银（token 费）**。保护火力放 AI。
- **缓存/幂等**：同出生信息+同解读类型，结果复用，不重复烧 AI。
- **AI 分级**：基础解读用便宜模型，高级付费档才上更贵深度模型。
- **校验前置到"填写时"**：出生地/日期在用户输入当下实时校验（红框提示），更早拦废数据、体验更好。

---

## 七、与硬切换的衔接（复用同一套地基）

新工具同时是**老用户迁移的落点**（见《排盘系统硬切换》方案）：

- 老用户回收的生辰 → 用新工具的**服务端算法批量预重算历史盘** → 入库为"待认领"影子盘。
- 用户用手机号登录新平台 → 影子盘归位，历史盘无感还原（且是自研引擎出的、从此不受制于第三方）。
- 重算历史盘同样走"信息校验 + 缓存"体系，既验证工具正确性、又填充平台内容。

## 八、前后端职责边界（开发落地要点）

| 职责 | 归属 | 说明 |
|---|---|---|
| 排盘核心算法 / 格局判断 / 评分 | **后端** | 永不下发前端 |
| AI 解读 prompt / 知识库 / 调用 | **后端** | 锁死服务端 |
| 信息校验（必填/合理性/幂等） | **后端为准**（前端可即时提示但不可替代后端终校验） | 防绕过 |
| 付费状态校验、报告绑定订单 | **后端** | 防越权 |
| 表单填写、状态展示、报告渲染 | 前端 | 只收结果，不含算法 |
| 出生地经纬度匹配（真太阳时） | 后端（地理库） | 校正需要 |

## 九、待董事长拍板项
1. 信任缓解方式：样例报告 / 极简结论免费 / 两者组合 —— 给多少不泄露独家判断层？
2. 合盘报告：对方是否也可见，还是仅发起人可见？
3. 定价与解读分档（基础/进阶/专项：事业/婚姻/财运/大运流年）。
4. 独家判断/评分模型的具体规则（自研算法核心，需命理专业输入）。
5. 报告防抓取强度（水印/图片化程度 vs 用户体验）。
