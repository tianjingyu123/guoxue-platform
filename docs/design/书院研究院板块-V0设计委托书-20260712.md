## 〇、定位与主线（先读·最重要，原型在这里跑偏过）

**书院研究院 = 平台的「精英师资筛选培养体系」。** 它不是一个卖课的书院，而是一条**把付费会员筛成签约讲师、再输送到线下驿站授课**的漏斗。核心主线一条：

**① 付费准入（会费 1 万/年·交钱即进·不设审核门槛）
→ ② 自主选择是否「申请分享」
→ ③ 申请者完成月/季/年任务 → 年度退还会费；不申请者纯学习、不退费
→ ④ 平台观察评估 → 优秀者被平台主动签约成讲师
→ ⑤ 签约讲师进入线下驿站讲师库授课。**

分配：会费收入平台/研究院 **50/50 留存**；管理层（院长/副院长/秘书长）由平台任命轮岗，从留存中发分红。

### 三个「别做偏」（原型虚构过，务必避免）
1. **别做「讲师自主申请入库」表单**——讲师是**平台签约遴选制**（观察评估后签约），不是填表自荐。相关页只做"遴选机制说明 + 路径引导"，不做申请表单。
2. **别做「师资需求大厅 / 人才库 / 讲师评分打分」**——那是**线下驿站（offline 模块）**的事，不属研究院。研究院只管"筛人"，不管"派活"。
3. **别把付费准入做成复杂审核门槛**——是**交钱即进**的付费准入；真正的筛选发生在后面的"任务 + 评估 + 签约"，不在入口。

> 会费的机制本质是**可退押金**：申请分享且完成任务 → 年退；否则不退。这个"退费诱因"是整个体系的发动机，要在设计里讲清楚。

## 一、角色

| 角色 | 说明 |
|---|---|
| **普通会员** | 交 1 万/年会费即入。可纯学习（不申请分享则不退费）。 |
| **分享会员** | 主动申请分享，承接月/季/年任务；完成→年度退会费。 |
| **签约讲师** | 被平台观察评估后签约（lecturerLevel=SIGNED），进驿站讲师库授课。 |
| **管理层** | 院长/副院长/秘书长，平台任命轮岗，管审批/任命/财务分红。 |

> **无独立账号体系**：会员/管理层沿用总平台用户身份，不单独登录/设密码。平台侧的入会最终确认、财务发放在管理端完成。

## 二、页面架构总览（19 页 → 砍并为 10 页 + 移交 4 页）

### 砍并原则
- **移交 4 个错配页**：`teacher-pool` / `teacher-demand` / `demand-create` / `demands-create` 本质属**线下驿站（offline）**的"师资需求/人才库"，**从本板块删除**，随 offline 模块实现。
- **展示页合并**：讲师/排行合一；成员/委员会合一；内容/讲座合一；活动列表/详情合一。
- **主线聚焦**：入会 → 会籍中心（任务/退费）→ 签约 → 驿站，做成清晰可视的转化路径。

## 三、核心：入会→会籍→退费 转化路径（本委托灵魂）

### 3.1 I7 加入研究院
- 讲清机制：**1 万/年会费**、50/50 留存、**申请分享+完成任务→年退；纯学习不退**。
- 交钱即进（不设资格审核门槛），开通后进 I8 会籍中心。
- 禁承诺式收益宣传，如实说明"退费需完成任务、有不退费风险"。

### 3.2 I8 我的会籍中心（重点出稿）
一页承载会员的全部自服务：
1. **会籍卡**：会员姓名/角色/会籍状态（PENDING/ACTIVE/GRADUATED）/加入年份/到期日/讲师等级徽章。
2. **申请分享开关**：未申请→"申请成为分享会员"入口（说明承接任务=可退费）；已申请→显示任务体系。
3. **任务进度**：月/季/年任务卡（SALON/LIVE/ARTICLE/OFFLINE_EVENT），进度条 tasksCompleted/Required，单任务"提交完成"。
4. **年度退费**：满足条件→"申请退还会费"按钮；未满足→灰置 + 差距提示。
5. **分红记录**：管理层可见（MGMT_BONUS/TEACHER_AWARD/OPERATION）。

### 3.3 I10 管理端（管理层视角）
Tab 式：**待确认/审批**（通过/拒绝入会）· **成员管理**（任命角色/推荐进签约观察）· **财务与分红**（留存概览 + 发放分红弹窗）· **任务模板**（月/季/年模板增改）· **委员会**（board-groups 建/解散）。

## 四、数据能力边界（都是现成后端，画的元素要能对上）

- **展示**：intro（含 counts）、members（裸数组）、talent-pool（取 .teachers）、events（取 .events）、events/:id、signed-lecturers（签约讲师+已入驻驿站）、lectures、rankings、contents。
- **会籍**：eligibility、my（会籍详情/taskProgress）、my/tasks（取 .tasks/.templates）、my/tasks/:id/complete、my/deposit-refund（年度退费）、my/assessment、my/dividends（取 .dividends）、applyMember。
- **管理**：manage/overview、manage/pending-members、members/:id approve、members/:id/role、manage/finance、manage/dividends、members/:id/points、members/:id/recommend、board-groups（建/解散）、task-templates（增改）。
- **签约→驿站闭环**：signed-lecturers + getMember 的 enrolledStations（I3 展示"驿站授课"）。
- **禁止画的能力（后端缺·本次不做）**：活动在线报名/付费、真实会费收银台（现为模拟）、讲师自荐入库、师资需求大厅。

## 五、视觉规范
全站统一 token：宣纸白 #FAF8F5 页底、卡片白 #FFFFFF、朱红 #C41E3A（主按钮/激活/价格）、金 #C9A96E（价值强调/等级/分红）、文字 #2C2C2C/#6E6E73/#999、圆角 18px·胶囊 999px、页边距 20px。
- 研究院气质偏"精英学府/庄重"：可用金色点缀强调师承、等级、荣誉；克制留白、国学雅致、禁荧光渐变与娱乐贴纸感。
- 讲师等级/会籍状态/任务态用清晰标签色系；签约讲师给专属徽章。
- ⚠️ 禁同色系底字；封面图上文字必须有渐变衬底。

## 六、技术兼容（安卓微信 X5 内核）
1. 封面/比例用 padding-top 方案（不用 aspect-ratio，稿内标注比例）。
2. 不用 writing-mode 竖排。
3. 活动排期日历、任务进度、分红弹窗用实色卡片，毛玻璃不承载关键信息。
4. 退费/审批/发放分红等写操作交互由我方实现，V0 只出视觉与态。

## 七、交付格式
1. 纯 HTML 静态稿，390px 移动端宽，稿内 HTML 注释标数据来源与交互（注释即规格）。
2. 交付清单：
   - **展示**：I1 首页 / I2 精英讲师 / I3 讲师详情 / I4 活动排期 / I5 研究院内容 / I6 组织架构。
   - **入会/会籍**：I7 加入研究院 / **I8 我的会籍中心（会籍卡+分享开关+任务进度+退费+分红）** / I9 讲师遴选说明。
   - **管理**：I10 管理端（审批/任命/财务分红/任务模板/委员会·多 Tab）。
   - 附《后端待办清单.md》（活动报名/会费收银台等缺口列出）。
3. **两阶段**：先线框级信息架构稿（重点确认定位主线不跑偏、砍并结构、会籍中心转化路径）→ 确认 → 视觉稿。**入会→会籍→退费路径（第三节）是本委托灵魂。**
