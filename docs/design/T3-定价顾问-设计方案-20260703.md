# T3 定价顾问（供给侧）— 设计方案

> 2026-07-03 · 课题 T3 · R2 合规红线（禁大数据杀熟）是第一约束 · 自主拍板

## 一、R2 合规铁律（先定死）

**禁止按用户付费能力差别定价（大数据杀熟·个保法24条+价格法）。** T3 是**供给侧定价顾问**：
- 服务对象=**定价者**（讲师/商家/达人），**不是购买者**
- 数据聚合只按**商品类目维度**（同类均价/区间），**绝不含用户消费能力/画像/购买力任何维度**
- 同一商品对所有购买用户**同价**（T3 不碰商品展示价·不拆价表·只给定价者参考）
- 建议透明可溯源（标注"基于同类 N 件商品近 90 天数据"）+ 免责声明（"最终定价由你决定"）
- 非实时追踪单用户（T+1 或即时类目聚合·不因某用户浏览动态调价）

**代码层禁止项**：定价参考的 SQL 禁止任何 `buyer/user/wealth/segment/income` 维度过滤；规则文案禁止 `{{userSegment}}` 类个人化占位。

## 二、实现方式（拍板：即时参考·非推送式）

侦察建议复用 AdvisorEngine 推送式（周期推建议卡）偏重且耦合主体解析。改为**即时定价参考 API**——定价者在编辑页填价时实时拉同类分布，更轻更贴"定价当下"场景。首批做**课程 + 商品**两个高频对象。

## 三、数据聚合（供给侧·类目维度）

按 categoryLevel1(可选 categoryLevel2) 聚合同类**已上架**（status=ACTIVE/PUBLISHED·非删）商品/课程价格分布：
- avg / median / min / max / p25 / p75 / 样本数
- 关联信号：该类目高评分(rating≥4)商品的价格区间、高销量(studentCount/销量 top)商品价格区间——给"叫好又叫座的定价带"参考
- 样本数<5 时不给具体区间（数据不足·诚实提示"该类目样本较少，参考谨慎"）

## 四、端点契约（新 pricing 模块·或挂 shop/course）

`GET /pricing/reference?bizType=COURSE|PRODUCT&categoryLevel1=X&categoryLevel2=Y&currentPrice=Z`（登录·定价者角色）→
```
{
  bizType, category, sampleSize,
  distribution: { avg, median, min, max, p25, p75 },     // 样本≥5 才有·否则 null
  qualityBand: { min, max } | null,   // 高评分商品价格带
  salesBand: { min, max } | null,     // 高销量商品价格带
  suggestion: { range: [low, high], text },   // 建议区间+一句话(可选 AI·基于分布规则生成·DeepSeek)
  currentPriceHint: "OFFERED_HIGH|OFFERED_LOW|IN_RANGE|null",  // 当前定价 vs 区间位置(有 currentPrice 时)
  disclaimer: "以上为同类市场参考，最终定价由你自主决定；平台不干预、不按用户差别定价"
}
```
- suggestion.text 可用规则模板即时生成（如"同类均价 ¥X，多数定在 ¥p25–¥p75，建议参考此区间"）；AI 版可选（DeepSeek 一句话·成本低·节流防刷）
- 节流 StrictRedisThrottleGuard（防刷）+ 类目分布结果缓存 1h（Redis·降 DB 压力）

## 五、前端

- pkg-merchant 商品编辑页 price 字段旁「定价参考」卡：输入类目+价格→实时拉 reference→展示分布(均价/区间条·当前价标记位置)+建议+免责
- 讲师课程编辑页 price 旁同款卡
- 卡片强调"参考"非"规定"·免责声明常驻·「采纳区间中位」按钮(选填·一键填入建议中位价·定价权仍在用户)
