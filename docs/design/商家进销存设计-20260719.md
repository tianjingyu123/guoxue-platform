# 商家进销存设计（2026-07-19）

## 目标

在不改变商城现有库存扣减口径的前提下，补齐商家采购、入库、库存流水、盘点调整和低库存预警。

## 核心约束

1. `Product.stock` / `ProductSku.stock` 继续作为当前库存余额唯一真源，不新增第二套余额表。
2. `InventoryMovement` 只追加、不修改、不删除，记录每次库存变化前后值、业务来源和操作人。
3. 所有库存写入与流水写入必须处于同一数据库事务。
4. 所有写接口必须带 `requestId`，通过唯一 `idempotencyKey` 防止重复入库、重复调整和重复回补。
5. SKU 商品只变更 `ProductSku.stock`；无 SKU 的商品只变更 `Product.stock`，不把两者混算。
6. 商家身份由 `MerchantGuard` 注入，不接受客户端传入 `merchantId`，商品必须属于当前店铺 owner。
7. 退款前尚未发货的订单可自动回补库存；已发货/已完成的退款必须经退货验收入库，避免“退款但货未退”导致虚增库存。

## 数据模型

### InventoryMovement（不可变库存流水）

- `merchantId`、`productId`、`skuId?`
- `type`：采购入库、销售出库、取消回补、退款回补、手工调增/调减、盘盈/盘亏
- `quantity`：有符号数量，入库为正、出库为负
- `beforeStock`、`afterStock`
- `referenceType`、`referenceId?`
- `idempotencyKey`：全局唯一
- `operatorId?`、`reason?`、`metadata?`、`createdAt`

流水保留商品/SKU 标识但不建立级联外键，确保商品或 SKU 停用后历史审计仍可查询。

### PurchaseOrder / PurchaseOrderItem

- 采购单：店铺、采购单号、供应商信息、状态、预计到货日、总金额、创建人、备注。
- 采购明细：商品、SKU、商品/规格快照、采购数量、已到货数量、采购单价。
- 状态：`DRAFT → ORDERED → PARTIALLY_RECEIVED → RECEIVED`，草稿或已下单但未入库时可取消。
- 每次收货按明细数量增库并写 `PURCHASE_IN` 流水；同一 `requestId` 重放不重复入库。

### InventoryAlertSetting

- 以 `merchantId + stockKey(productId:skuId|PRODUCT)` 唯一。
- 配置低库存阈值及启用状态；未配置时默认阈值为 5。

## 商家后台 API

- `GET /merchant-backend/inventory/overview`：库存总览。
- `GET /merchant-backend/inventory/stocks`：商品/SKU 库存列表。
- `GET /merchant-backend/inventory/movements`：库存流水。
- `POST /merchant-backend/inventory/adjustments`：手工调增、调减或盘点到指定数量。
- `PUT /merchant-backend/inventory/alerts`：设置低库存阈值。
- `GET /merchant-backend/inventory/alerts`：低库存预警列表。
- `POST /merchant-backend/purchase-orders`：创建采购单。
- `GET /merchant-backend/purchase-orders`：采购单列表。
- `GET /merchant-backend/purchase-orders/:id`：采购单详情。
- `POST /merchant-backend/purchase-orders/:id/submit`：确认下单。
- `POST /merchant-backend/purchase-orders/:id/receive`：到货入库。
- `POST /merchant-backend/purchase-orders/:id/cancel`：取消采购单。

## 订单联动

1. 普通订单和拼团订单创建并扣库时，在同一事务写 `SALE_OUT`。
2. 用户取消和超时取消回补库存时，在同一事务写 `ORDER_CANCEL_RETURN`。
3. 已付款但未发货订单退款成功时回补库存并写 `REFUND_RETURN`。
4. 已发货/已完成订单退款不自动回补；后续通过退货验收入库动作写 `REFUND_RETURN`。

## 验收标准

- 并发调整不产生负库存或丢失更新。
- 重复提交同一 `requestId` 不重复改变库存。
- 采购部分到货、全部到货状态正确。
- 商品越权、SKU 与商品不匹配、超量收货全部拒绝。
- 订单出库、取消回补与退款回补均有可追溯流水。
- 后端类型检查、模块测试、全量 Jest、管理端类型检查和构建全部通过。
