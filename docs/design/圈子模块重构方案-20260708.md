# 圈子模块 全面审计与重构方案

> 2026-07-08 · 董事长指出圈子板块"想到啥做啥"堆叠、缺闭环主线、体验混乱 · 项目负责人主导整改至完美

## 一、根本问题
圈子缺一条**清晰的商业闭环主线**，功能各自堆叠，导致：重复页面、入口散乱、权限门控散落、已开发功能没展示出来、加入态有 bug、发布路径反直觉。

## 二、圈子商业闭环主线（重构后的骨架）
```
逛广场 → 进圈(看内容+推荐商品/课程/直播) → 加入(免费/付费) →
参与(最短路径发帖/评论·人人可) → [有权限者]创作(文章/课程/直播·专属入口) →
我的圈子(已加入 / 我创建管理·统一入口) → 圈主管理(单圈运营+数据) → 退出
```
一句话：**普通成员=消费+轻互动(发帖评论)；圈主/管理员=运营(创作+管理+数据)；两条线分开，不互相占用界面。**

## 三、问题清单 × 整改（按闭环阶段归类）

### A. 我的圈子 / 导航（入口混乱·重复页）
- **A1 重复页**：`my-circles/index.vue` 与 `circles/mine.vue` 同功能两份 → **删 mine.vue，统一 my-circles**。
- **A2 找不到"我创建的"**：mine.vue 用 `slice(0,2)` 假装创建圈子（错）；my-circles 已按 role 正确分。→ 统一后按 role 分区：**我加入的 / 我创建管理的**。
- **A3 入口最短路径**：圈子广场/首页顶部直接给「我的圈子」「创建圈子」入口。
- **A4 圈主管理入口浮现**：在"我创建管理的"卡片上直接给「管理」按钮，不再深藏详情页。

### B. 加入状态（核心 bug）
- **B1 只有最近加入的显示已加入**：根因 `circleApi.my()` 用通用 `adaptCircle`、后端 `/circles/my` select 缺 role/intro、列表项没各自反映真实态。→ 新增 `adaptMyCircle`(含 role/intro)；后端 select 补 `intro`；列表项按真实 role/isJoined 渲染。
- **B2 已加入圈子仍出现在"加入列表"**：按董事长意见——**已加入的圈子从"广场/加入列表"移除或明确标记**，不再让人重复加入。
- **B3 加入/退出后不自动刷新**：加入/退出成功 → `onShow` 或全局事件刷新"我的圈子"。

### C. 圈子详情页（体验重灾区）
- **C1 底部"已加入"按钮冗余**：已加入时**只显「发帖」**（最短路径直接发）；退出移到右上"..."更多操作。
- **C2 发帖路径反直觉 + 权限**：
  - 点「发帖」= **直接发帖**（人人可·文本/图片/视频/文件），不再弹"发文章/课程/直播"。
  - 发文章/课程/直播 = 移到**有权限者的专属入口**（如圈主管理里的"创作"或详情页仅管理员可见的"+创作"），且**按 role 显示，无权限不显示**。
- **C3 发帖内容类型**：像微信发消息——文本/图片/**视频/文件(PDF)** 可选。前端 `editor.vue` 补 `uni.chooseVideo`/`uni.chooseFile`；后端 `CirclePost` 确认支持 video/file 字段（缺则补）。
- **C4 内容展示区缺失**：详情页接入**推荐商品 / 推荐课程 / 直播列表**展示区（圈主可配）。后端补端点 `GET /circles/:id/recommended-products|courses|lives`（或复用已有），前端加区块。
- **C5 空壳 Tab**：`文章`/`专栏` 是 stub（后端返回空）→ 要么补后端端点接真数据，要么**收敛 Tab**（只留 首页/帖子/成员 + 有数据的）。

### D. 数据语义（放错位置）
- **D1 "我的圈子数据"语义混乱**：现在是全平台聚合，标题却像单圈数据。→ 改名「我的参与概览」明确聚合语义。
- **D2 单圈数据应在圈主管理**：`circles/stats.vue` 现是纯 mock → 圈主管理里做**单个圈子的真实数据看板**（接后端），多圈时按圈进入看各自数据，不再混。

### E. 权限门控（散落·不一致）
- **E1 统一权限表**：前端建 `CIRCLE_PERMS`（POST 人人 / ARTICLE·COURSE·LIVE 圈主管理员 / MANAGE 圈主），detail/editor/publish 统一引用，前置门控（不再"写完才 403"）。
- **E2 前后端对齐**：写端点均 `ensureCircleAdmin`/成员校验；前端按 role 隐藏无权限入口。

## 四、分阶段执行（建议顺序：先止血 bug + 体验，再补展示/后端）

**阶段1·止血(纯前端·高频痛点)**：B1 加入态修复、B2 已加入不重复、C1 底部栏、C2 发帖最短路径+权限门控、A1 删重复页。
**阶段2·导航与我的圈子**：A2/A3/A4 统一入口+圈主管理浮现、B3 自动刷新、D1 改名。
**阶段3·发帖内容类型**：C3 视频/文件/PDF（前端选择 + 后端字段确认）。
**阶段4·内容展示区(需后端)**：C4 推荐商品/课程/直播端点 + 前端区块、C5 空壳 Tab 收敛或接真数据。
**阶段5·圈主管理与数据**：D2 单圈真实数据看板、E1/E2 权限统一收口。

## 五-B、圈主助理：圈主知识/观点复刻机（核心亮点·董事长强调发挥到极致）

**定位**：以圈主为主导、以圈内内容为语料的**专属知识库 RAG**；成员提问，它第一个答出**圈主的观点并给出处**（"圈主在X时说过/评论过…"）。每个圈子的助理各具特色 = 圈主知识与观点的复刻机。这是知识星球等都没做透的差异化。

**现状（审计·基础设施其实很全）**：多轮对话✅、知识库表 `CircleKnowledge`(含 vectorJson/sourceType/qualityScore)✅、自动采集(精华帖/付费问答/高赞评论·定时任务)✅、双层联邦检索(圈子+全局典籍)✅、出处标注 sources[]✅。**两个 P0 短板**：
- **P0-1 伪 RAG**：`vector.service` 因 embedding API 未配(DeepSeek 无 embedding 端点)→降级字符哈希向量→**语义检索无效**。infra 已支持真 embedding，只差配 DashScope(阿里百炼)/OpenAI 的 `EMBEDDING_API_KEY` + 对历史知识重新 embed。**⚠️需外部 API key(董事长提供/决策)**。
- **P0-2 不识别圈主内容**：采集不区分圈主发的 vs 成员讨论 → 答案混淆。需 `CircleKnowledge.isOwnerContent` 标识 + 采集时 `userId===circle.ownerId` 判定并提权 + RAG 检索/prompt 优先圈主内容并标"[圈主观点]"。**纯代码可做**。

**升级路线**：
1. **P0-1 真 embedding**（需 key）：配 DashScope embedding → `vector.service` 走真 API → 重新 embed 存量知识 → 语义检索生效。
2. **P0-2 圈主观点复刻**（代码）：schema 加 `isOwnerContent` → `ugc-knowledge.service` 采集判定圈主内容+提权 → `rag.service.askCircle` 检索分层(圈主内容优先)、prompt 改"优先引用[圈主观点]、体现圈主独特视角、务必给出处" → 回答形如"圈主曾在《X》中说…"。
3. **P1 出处强化**：sources 带 sourceType/sourceId/isOwnerContent/时间 → C 端 `assistant.vue` 出处可点击跳原帖、标"圈主观点"。
4. **P1 采集扩面**：圈主公告/置顶/课程笔记/直播回放/问答回复纳入语料，圈主新内容更高优先级(小时级)。
5. **P2 质量回路**：圈主审核候选打质量分 → RAG 加权 → 低质定期清理。
