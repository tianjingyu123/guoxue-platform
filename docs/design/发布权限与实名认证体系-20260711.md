# 发布权限与实名认证体系 · 设计方案

> 2026-07-11 · 依据董事长拍板整理。状态：**方案待确认，参数待拍板**（第六节参数表）。

## 一、董事长拍板口径（原文要点）

1. 平台**不是人人创作平台**：首页（全平台流量池）发出的东西要对大家有帮助，而且要守规矩。
2. 筛选原则=**对圈子授权**：圈主达到圈子运营门槛后，可向平台申请开通（全平台发布权），有前置审批（运营天数、成员数、作品数等）。
3. **快速通道**：能证明其他平台粉丝数大于一定数量的，可适当放松前置审批标准直接放权。
4. **实名认证**：所有发短视频、直播、课程的用户（包括圈主）都要实名认证。核心风控任务要**人脸识别认证**；一般风控要**身份证核验**。
5. UI 问题：发现页短视频板块发布按钮右上/右下重复；无权限用户点发布按钮要告知如何获得发布资格。

## 二、现状盘点

| 能力 | 现状 |
|------|------|
| 短视频发布 | ⚠️ 仅登录校验（JwtAuthGuard），任何用户可发——与拍板口径直接冲突，本方案的核心整改点 |
| 课程发布 | 已有 course-creator.guard（讲师认证或管理员），有门槛但与圈子授权体系未打通 |
| 直播开播 | 待实施批核实现有 guard |
| 实名认证 | ✅ identity 模块底座齐全：身份证 OCR、二要素核验（POST /identity/verify）、人脸核身（face/token + face/result）、admin 人工审核流（audit-list/approve/reject）。第三方通道密钥状态待核实 |
| 圈子治理 | ✅ 已有治理体系（三级阶梯状态机/权限矩阵），发布授权可作为圈子的一项"资质"挂进来 |
| 内容架构 | 内容（短视频/文章/课程）=圈子内容，C 端发布已带 circleId，官方圈兜底——授权粒度落在圈子上与现架构天然吻合 |

## 三、权限模型

### 3.1 授权对象与范围

- **授权粒度=圈子**（新表 `CirclePublishGrant`）：圈主以圈子名义申请，平台审批后该圈获得指定范围的**全平台发布权**。
- 授权范围按内容类型分三项独立开关：`SHORT_VIDEO` / `LIVE` / `COURSE`（可单独申请、单独授予、单独吊销）。
- **圈内发布不受本体系限制**（圈内内容只对圈成员可见，走圈子自身管理）；本体系只管"发到全平台流量池（发现页/首页推荐）"。
- 获权后的**发布人**：默认=圈主本人。圈主可提名圈内成员为"发布人"（每位发布人独立满足实名要求后生效）。发布时内容归属仍记发布者本人+所属圈子。

### 3.2 实名认证分级（挂在用户上，独立于圈子）

| 级别 | 手段 | 适用 |
|------|------|------|
| L1 基础实名 | 身份证二要素核验（姓名+身份证号，identity/verify 现成） | 发短视频、发课程的所有用户（含圈主） |
| L2 强实名 | L1 + 人脸核身（identity/face 现成） | **直播开播**（监管要求主播人脸核身）及其他核心风控场景（大额提现等场景可后续复用此级） |

- 认证状态挂 User（`identityLevel: NONE/L1/L2`），一次认证长期有效；发布授权审批时校验，发布/开播动作时 guard 再校验。
- 人脸核身通道若第三方密钥未就绪，先上 L1+人工审核兜底，L2 通道就绪后再强制。

### 3.3 审批通道

**常规通道（自动核验+人工确认）**：圈子达到全部前置门槛（参数见第六节）→ 圈主提交申请（选择申请范围+承诺书勾选）→ 系统自动核验门槛数据（运营天数/成员数/作品数直接查库）→ 进入 admin 人工审批队列（审内容质量与合规）→ 通过/驳回（驳回附原因，30 天后可再申请）。

**快速通道（外站影响力）**：圈主提交其他平台（抖音/快手/B站/小红书/视频号）主页链接+粉丝数后台截图 → admin 人工核验粉丝数达标 → 免除运营天数/成员数/作品数门槛直接放权（实名要求**不豁免**）。

**吊销机制**：接入现有圈子治理三级阶梯——圈子被处置（警告/限流/封禁）时联动冻结/吊销发布授权；发布内容违规累计达阈值自动降级回"仅圈内发布"。

## 四、C 端交互

1. **发布按钮去重**：发现页短视频板块只保留一个发布入口（建议保留右下悬浮按钮，去掉右上角重复入口）。
2. **无权限引导（本次拍板重点）**：无权限用户点发布 → 弹半屏引导层，而不是报错：
   - 标题「开通发布权限」+ 一段平台定位说明（"平台内容面向全体用户，需通过圈子授权开通发布"）；
   - 步骤图示：① 创建/运营你的圈子 → ② 达到运营门槛（列出具体门槛与该用户当前圈子的实时进度，如"运营 12/30 天·成员 45/100"）→ ③ 完成实名认证 → ④ 提交申请等待审批；
   - 快速通道入口："其他平台已有影响力？提交粉丝证明直接申请"；
   - 底部按钮：符合条件=「去申请」；不符合=「去创建圈子」/「查看我的进度」。
3. **申请页**：申请范围勾选（短视频/直播/课程）+ 门槛自动核验结果展示 + 实名状态（未实名先引导去实名，直播项要求 L2）+ 快速通道材料上传 + 提交。
4. **进度与结果**：申请记录页（待审/通过/驳回+原因）；通过后发布按钮直接可用。

## 五、admin 端

- 「发布授权审批」页：申请队列（圈子资料/门槛核验快照/快速通道材料/实名状态）+ 通过/驳回（驳回原因必填）。
- 「授权管理」页：已授权圈子列表（范围/发布人/授权时间/违规记录）+ 冻结/吊销操作。
- 实名审核复用 identity 现有 admin 审核流。

## 七、实施分期

- **P0（可立即做·纯前端+现有能力）**：发布按钮去重；无权限引导弹层（先用静态门槛文案+实名引导，接口就绪后接实时进度）。
- **P1（后端权限收口）**：CirclePublishGrant 表+申请/审批端点+发布 guard（video/live/course 发全平台时校验授权与实名级别）+User.identityLevel 字段与 identity 模块打通。⚠️ 上线时对存量已发布用户设过渡期策略（待拍板：存量内容保留，新发布按新规）。
- **P2（admin 审批页+快速通道材料流+治理联动吊销）**。
- **外部依赖**：人脸核身第三方通道密钥/计费确认（腾讯云人脸核身，按次计费需采购确认）。

## 八、内容审核无感化（董事长 2026-07-11 二次拍板）

> 原话要点：短视频/课程/直播审核不要每个都提示去审核，审核后台完成，用户无感知；最终失败结果可以通知一下，或非严重违规的改为仅自己可见；严重违规直接删除。短视频/课程/直播都是**一次性资格审批**，后期不再审批，只接受监管。

1. **先发后审**：有发布资格的用户发布内容立即可见（不再有"待审核/审核中"任何提示与状态展示），机审（现有三层漏斗：词库→腾讯云→DeepSeek 兜底）后台异步执行。
2. **分级处置**：
   - 机审通过 → 无任何用户感知；
   - **轻度违规** → 内容降级为「仅自己可见」（新可见性状态 SELF_ONLY：作者本人列表/详情可见并有小标识，他人与公开流不可见），站内信通知可选（默认通知，文案温和附申诉入口）；
   - **严重违规** → 直接删除/下架 + 站内信通知（附原因与申诉入口）。
3. **资格一次性**：圈子发布授权（第三节）一次审批长期有效，后续不做逐条内容事前审核，仅事后监管；违规累计触发治理阶梯（冻结/吊销授权，见 3.3）。
4. 机审拿不准的样本进 admin 人工复审队列（用户侧仍无感知，内容保持可见，复审改判再按分级处置）。

## 九、风险与开放问题（✅ 2026-07-11 董事长认可建议方案，按下述执行）

1. 存量发布者：过渡期 14 天公告+引导申请。
2. 官方圈/官方旗舰店/admin 数字员工发布不受限（走现有红线与审核体系）。
3. 课程"讲师认证"与新体系并存：讲师认证=个人资质，圈子授权=渠道资质，发全平台课程两者均需。
