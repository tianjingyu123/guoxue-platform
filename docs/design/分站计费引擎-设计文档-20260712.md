## 0. 一句话范围

计费引擎 = 在**已有的 `Order` + 支付回调基础设施**之上，补齐两条收款流（一级运营商 4999 开通 / 分站 999 年租）与一套**减免·退还账**，全部参数读 `ConfigSystem`，禁硬编码。

**不属于本引擎**（已生效，勿重做）：团队管理奖 10%/20%、站长分销佣金、退款冲正——这些在 `commission.service` 已跑通。计费引擎只管「开通费」和「租赁费」两笔钱。

## 2. 数据模型设计（新建 1 张台账 + 复用 Order）

### 2.1 复用 `Order`（不新建开通/年租订单表）
两笔钱都走现有 `Order`，避免另起支付体系：

| 场景 | Order.type | amount | targetId | 备注 |
|---|---|---|---|---|
| 一级运营商开通 | `OPERATOR` | 读 `station_operator.tier1.price`(4999) | 购买者 userId | 回调建 Operator |
| 分站年租（首开/续费） | `STATION_MASTER` | 读 `station.rental_fee_yearly`(999) | stationId（首开时为申请单占位） | 回调激活/延期 |

> 金额一律**下单时从 ConfigSystem 读快照写入 Order.amount**，改价=改后台配置，历史订单金额不变。

### 2.2 新建 `StationRentalLedger`（年租台账·减免退还审计）
`Order` 记录「收了钱」，但**减免/退还判定依赖“分站累计收入”与“租期周期”**，需要独立台账承载：

```prisma
model StationRentalLedger {
  id             String    @id @default(uuid())
  stationId      String
  periodStart    DateTime  // 本租期起（首开=激活日 / 续费=上期到期日）
  periodEnd      DateTime  // 本租期止（periodStart + 1 年）
  yearIndex      Int       // 第几个租期（1=首年，退还仅 yearIndex=1 生效）
  status         String    @default("PENDING")
  // 生命周期：PENDING 待缴 / PAID 已缴 / WAIVED 减免 / REFUNDED 已退 / ACTIVE 生效中 / EXPIRED 已过期
  feeAmount      Decimal   @db.Decimal(10, 2) // 本期租金快照（下单时读 999）
  paidOrderId    String?   // 缴费对应的 Order.id（status=PAID/ACTIVE 时有值）
  paidAt         DateTime?
  // ── 减免判定快照 ──
  waiverChecked  Boolean   @default(false)
  incomeSnapshot Decimal?  @db.Decimal(12, 2) // 判定时点的分站累计收入
  waiverMultiple Decimal?  @db.Decimal(6, 2)  // 判定用倍数快照（5）
  waivedAt       DateTime?
  // ── 退还判定快照 ──
  refundChecked  Boolean   @default(false)
  refundMultiple Decimal?  @db.Decimal(6, 2)  // 判定用倍数快照（10）
  refundOrderId  String?   // 退款对应的资金流水
  refundedAt     DateTime?
  remark         String?
  createdAt      DateTime  @default(now())
  updatedAt      DateTime  @updatedAt

  station Station @relation(fields: [stationId], references: [id], onDelete: Cascade)

  @@index([stationId, yearIndex])
  @@index([status, periodEnd])
}
```

> 运营商 4999 是**一次性买断名额**，无周期/减免/退还，不需台账——回调直接建 `Operator` 即可。故只为「999 年租」建台账。

### 2.3 「分站累计收入」口径（减免/退还的分母）
统一取 **`Station.totalEarning`**（`StationEarning.earned` 累计，已由 commission.service 维护）。
- 减免判定：`incomeSnapshot < 5 × feeAmount`（<4995）→ 免续交
- 退还判定：`yearIndex=1 && incomeSnapshot ≥ 10 × feeAmount`（≥9990）→ 退 999

倍数与费额**全部读 ConfigSystem**（`rental_waiver_income_multiple` / `rental_refund_income_multiple` / `rental_refund_first_year_only`）。

## 3. 三条业务流（状态机）

### 3.1 一级运营商 4999 开通
```
[C1开通页] 下单 Order(type=OPERATOR, amount=4999读配置)
   → 支付(微信/汇付H5，复用现有下单)
   → 回调 PAID：事务内
       ① 幂等校验(该 userId 无 ACTIVE Operator)
       ② 建 Operator{ level=一级, channelType=ONLINE,
                       containQuota = quota_self(1)+quota_sellable(5)=6,
                       usedQuota=1(自用分站自动占1), purchasedAt=now,
                       expireAt=null(名额买断不设到期，或按拍板) }
       ③ 为购买者自动开通 1 个自用分站(status=ACTIVE, operatorId=本人)
   → 失败/超时：Order 保持 PENDING，不建 Operator
```
> 二级运营商（OFFLINE）**不走此流**——随线下驿站赠送，由驿站后台赠送开通，无收款。

### 3.2 分站 999 年租 · 首开
```
[C 开通分站页] applyStation 建 Station(status=PENDING) + Ledger(yearIndex=1, PENDING)
   → 下单 Order(type=STATION_MASTER, amount=999读配置, targetId=stationId)
   → 支付 → 回调 PAID：事务内
       ① Ledger.status=ACTIVE, paidOrderId, paidAt, periodStart=now, periodEnd=now+1y
       ② Station.status=ACTIVE, expireAt=periodEnd
   → 未支付：Station 停在 PENDING，不可用
```

### 3.3 到期续费 · 减免 · 退还（定时任务驱动）
每日跑一次 `station-rental.cron`：

**A. 到期前 N 天提醒**（`periodEnd - N天`）：站内信/公众号提醒续费。

**B. 减免判定**（到期日当天，续费前先判）：
```
if Station.totalEarning < waiver_multiple(5) × feeAmount(999):
    新建下一租期 Ledger(yearIndex+1, status=WAIVED, waiverChecked, incomeSnapshot快照)
    Station.expireAt = 新 periodEnd      // 免费续，不扣钱
else:
    进入正常续费(status=PENDING, 引导缴 999)
```

**C. 退还判定**（仅首年 yearIndex=1，租期内累计达标即触发，或首年到期时结算）：
```
if refund_first_year_only && yearIndex==1 && Station.totalEarning ≥ refund_multiple(10) × feeAmount(999):
    Ledger.status=REFUNDED, 退 999 到钱包(复用退款/钱包入账)
    记 refundedAt, incomeSnapshot
    幂等：refundChecked 防重复退
```

> ✅ 已定：**达标即退**（cron 每日扫首年·达标立即退，不等结算）；退还与减免**各管各的**——退首年 999 不影响下一租期是否该交（见 §6）。

## 6. ✅ 董事长已拍板（2026-07-12·全部锁定）

| # | 议题 | 决策 | 落地含义 |
|---|---|---|---|
| 1 | 运营商 4999 到期 | **永久买断·不设到期** | `Operator.expireAt` 留空，回调建号后不做年费/过期逻辑 |
| 2 | 退还触发时机 | **达标即退** | 租期内累计收入一达 ≥10×999 立即退，不等首年结算；cron 每日扫 yearIndex=1 未退且达标者 |
| 3 | 减免有效期 | **延续一年** | 收入<5×999 免交时，`Station.expireAt` 顺延整一年，新建 WAIVED 台账 |
| 4 | 累计收入口径 | **净额** | 统一取 `Station.totalEarning`（已被退款冲正扣过，天然净额），防「下大单达标→退还→退货」薅羊毛 |
| 5 | 自用分站 | **付款回调自动建、占 1 名额** | `usedQuota` 0→1，自建 1 个 ACTIVE 自用分站；可售 5 个留待逐个赠/售 |
| 6 | 减免/退还叠加 | **退首年 999 + 下一年正常交** | 两者各管各的：退还只退已交首年，不影响下一租期是否该交；首年高收入者退 999 后次年正常缴费 |
