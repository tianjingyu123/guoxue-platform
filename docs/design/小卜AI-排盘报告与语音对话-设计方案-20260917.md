# 小卜 AI · 排盘报告与语音对话 设计方案（20260917）

> 定位：本板块是平台**主要收入来源**，同时是**全平台流量的聚合器与分发器**。
> 报告负责"专业、客观、有依据"，对话负责"听得懂、用得上、留得住"。
> 费率、分成比例由决策人最后拍板，本文只留出参数位，不预设价格。

---

## 0. 一句话结论

**我们与普通大模型的本质区别，不在于"谁的文笔好"，而在于"报告里的每一个字都能追溯到两样东西：本平台排盘引擎算出的确定性事实，和人工审核过的门派理论与古籍原文。"**

普通 AI 拿到生辰只会"讲得像"，我们是先**算准**（引擎）、再**查证**（知识库）、最后才**表达**（模型）。模型在我们的链路里不负责产生事实，只负责组织与措辞。这一条是本板块所有设计的总纲。

## 3. 报告统一模板（固定骨架，内容随盘变化）

所有 A 类工具共用同一套 **7 段骨架**，保证"格式固定、辨识度统一"；每段内部的内容与图形由工具自己定义。

| 段 | 名称 | 作用 | 无内容时 |
| --- | --- | --- | --- |
| §1 | **盘面速览** | 主视觉图 + 一句话主线 + 3 个关键标签 | 必有 |
| §2 | **起盘校验** | 真太阳时/夏令时/节气/换月换日/起局法/流派设定 | 必有（专业用户第一眼看这里） |
| §3 | **结构判读** | 八字=格局用神；六爻=世应用神；奇门=值符值使；六壬=课体三传 | 必有 |
| §4 | **分维解读** | 按工具定义的维度（见 §3.2） | 按盘裁剪 |
| §5 | **时间轴** | 大运流年 / 应期 / 流日 | 无则隐藏 |
| §6 | **典籍依据** | 门派理论 + 古籍原文（可跳"读原书"） | 无则显示"本节无审核依据"，不编造 |
| §7 | **局限与建议** | 不确定性、门派分歧、可执行建议、免责 | 必有 |

> §2 与 §6 是**专业感的护城河**：普通 AI 不会告诉你"你这个盘按真太阳时校正后月柱变了"，也不会给出可跳转核对的原文出处。

### 3.1 为什么 §2 起盘校验必须独立成段

从业者给客户排盘，最怕盘起错。争议点固定就那几个：真太阳时是否校正、夏令时年份、子时早晚划分、节气交接当天的月柱、闰月处理、起大运的顺逆与岁数。把这些**显式列出来并标注本报告采用了哪种口径**，等于向专业用户交底。这是一句"我们敢把算法口径摊开给你看"的宣告，也是普通 AI 永远给不出的东西。

### 3.2 各工具的分维解读维度（§4）

| 工具 | 维度 |
| --- | --- |
| 八字 | 性格与心性、事业与求财、婚姻与六亲、健康、学业与文书、财富结构、当前大运、风险提示 |
| 紫微 | 命身格局、事业官禄、财帛、夫妻、疾厄、田宅、迁移交友、大限流年 |
| 六爻 | 用神取定、世应关系、旺衰生克、动变与忌神、应期、吉凶断语 |
| 奇门 | 用神落宫、格局吉凶（十干克应/八门九星）、方位取用、时机、应事 |
| 大六壬 | 课体、三传递进、天将临神、年命关涉、应期、吉凶 |
| 玄空飞星 | 元运与坐向、山星向星组合、吉凶方位、流年五黄二黑、化解建议 |
| 八宅 | 命卦与宅卦、八方吉凶、门主灶、布局建议 |

### 3.3 报告的两种视图（同一份数据）

- **专业视图**（默认给从业者）：术语直出、依据全展开、含门派分歧与争议标注。
- **入门视图**（默认给 C 端自查用户）：白话优先，术语折叠为可点注解，隐去争议，突出"对你意味着什么"。

视图切换不重新生成报告，只切换渲染层。**同一份专业内容，两种读法**——这解决了用户提到的"有些用户学得浅或根本不懂"。

## 5. 报告的"仪式感"（一次性揭幕，不做打字机）

用户明确要求：**不要流式打字机效果**，要一次性输出、有仪式感。

### 5.1 交互设计

1. 用户点"生成命书" → 进入**推演页**（非空白 loading）。
2. 推演页按真实进度显示五步，每步显示**真实发生的事**（不是假动画）：
   - 校时定盘：显示真太阳时校正了多少分钟、是否触发换柱
   - 排布盘面：显示四柱/九宫/六爻已排定
   - 结构判读：显示取定的格局与用神
   - 检索典籍：显示命中的门派条目数与古籍条目数（如"检索 6 部典籍，命中 4 条可引用原文"）
   - 组织成书：模型组织中
3. 完成后**整页揭幕**：卷轴展开/印章落定动效（0.8s），报告完整呈现。
4. 报告头部盖**三枚印**：`盘`（引擎已校验）、`派`（所用门派）、`典`（依据条数）。

### 5.2 技术实现

- 生成接口**保持非流式**（现有 `POST /paipan/report/generate` 已是一次性返回，无需改造）。
- 推演进度用轻量 SSE **只推进度事件，不推正文**（`step`/`detail`/`percent`），正文在最后一次性下发。这样既有过程感，又保证"揭幕"体验。
- 报告一旦生成即入库并版本化，二次打开直接读库（不重复付费、不重复调用模型）。

> 仪式感的本质不是动画，而是**让用户看见我们干了普通 AI 不干的活**：校时、排盘、查典籍。所以推演页显示的必须是真实数据。

### 6.1 门派分歧的处理（专业感的关键）

同一个盘，子平派与盲派取用可能完全相反。处理原则：

1. 用户**未指定门派** → 报告只出各派**共识部分**，分歧处显式标注"此处各派分歧，已按 X 派呈现，可切换"。
2. 用户**指定门派** → 按该派框架完整判读，并在 §7 标注"本报告依 X 派"。
3. 报告永不假装"只有一种说法"。**承认分歧本身就是专业的表现**，也是和普通 AI 拉开差距的地方（普通 AI 会把各派说法混在一起自相矛盾）。

## 7. 报告知识库书目与知识来源（2026-09-17 决策人指示后修订）

### 7.0 两类条目，两套规则（这是本板块的著作权红线）

决策人指示：「没有版权的古籍可以不上古籍板块，但知识库不需要考虑版权——古籍作者已去世很久，后人只是标点整理，我们又不完整展示原文，只是总结知识入库。古籍较少的工具可以从网上整理知识体系作为补充，备注来源即可。」

**核心判断成立**：著作权保护的是**表达**，不保护**思想、方法、操作规则**。命理的理论体系（月令取格、身弱喜印比、值符落宫如何断）属于知识与方法，**用自己的话总结入库不构成侵权**。古籍白文本属公有领域；点校本受保护的只是标点校勘那一层成果，不复制它即可。

**一处必须调整的做法**：「备注来源」在著作权法上**不等于取得授权**。网络文章、公众号、课程讲义本身多为受保护作品，逐字复制再署名仍然侵权。因此落地为：

| | 古籍原文条目 `classic_excerpt` | 知识要点条目 `knowledge_point` |
| --- | --- | --- |
| 来源 | **仅公版古籍白文**（`sourceKind=classic_public`） | 现代著作 / 网络资料 / 口传流派 / 平台自撰 |
| 内容 | 与底本逐字一致 | **必须用自己的话重述**，禁止逐字粘贴 |
| 报告中呈现 | 可展示原文、注明书名篇名、**可跳转读原书** | 只作**要点转述**，不冒充某本书的原文 |
| 来源线索 | 书名 + 篇名 | `sourceRefs` 记录来源（供审核追溯与交叉验证），**不对外展示** |
| 落地字段 | `quotable=true`（服务端判定，不接受客户端传入） | `quotable=false`，永不按原文展示 |

**这解决了「报告单薄」的问题**：知识要点不受古籍存量限制，紫微、阴盘奇门、金口诀这些古籍稀少的工具照样能有充足依据，做到无死角。

**工程落地（已完成）**：
- `PaipanReportKnowledge` 新增 `sourceKind` / `sourceRefs` / `restated` / `quotable` 四字段，迁移 `manual_add_knowledge_source` 已在隔离库验证 apply → rollback → apply。
- 服务端强制规则：非公版来源不得建为原文条目；非原文条目必须 `restated=true`；非平台自撰必须留来源线索；`quotable` 由服务端按「条目类型 + 来源」判定。
- **提示词加闸**：依据分「古籍原文 / 门派理论 / 知识要点」三类下发，明确告知模型——只有古籍原文可引述原句并说出处，其余**只能转述其意思，不得写成书中原话、不得为其编造书名篇名**。
- 后台录入页按类型切换表单，并在页面上写明红线原因。

### 7.1 古籍板块与知识库分离

## 8. 知识库结构升级（`PaipanReportKnowledge`）

现有表已可用，需补三处：

```prisma
// 新增字段（向后兼容，默认值不影响既有数据）
applicableTools String[] @default([])  // 一条理论可跨工具复用（如"旬空"同时用于六爻/六壬/奇门）
signalMatch     Json?                  // 结构化匹配条件，替代纯 tags 字符串匹配
conflictWith    String[] @default([])  // 与哪些条目构成门派分歧（报告据此显示"各派分歧"）
excerptRange    Json?                  // 引用片段在原章中的字符区间，支持"读原书"精确定位
```

`signalMatch` 示例（比 tags 精确得多）：

```json
{ "dayGan": ["庚","辛"], "monthZhi": ["寅","卯"], "geJu": ["偏财格"], "strength": "weak" }
```

**匹配逻辑**：引擎事实 → 生成盘面信号集 → 与 `signalMatch` 求交 → 命中条目按 (门派匹配度, 信号覆盖度, 审核时间) 排序取前 N → 作为候选依据交给模型。**模型只能引用命中的条目，引用不存在的编号一律剔除**（现有实现已具备此校验）。

## 9. 语音对话页设计（流量聚合与分发的落点）

### 9.1 角色定位

小卜同时是四个角色，**用意图路由切换，不是混在一起**：

| 角色 | 触发 | 边界 |
| --- | --- | --- |
| **专业助手** | 问盘面、问术语、问依据 | 只讲有依据的内容，不确定就说不确定 |
| **学习陪伴** | 问"这是什么意思""怎么学" | 引导到古籍原文与课程，给学习路径 |
| **客服** | 问订单、会员、功能、退款 | 走平台规则库，规则之外转人工 |
| **顾问/销售** | 用户表达出需求缺口 | **只在用户已表达需求时推荐**，不主动推销；推荐必须说明"为什么推荐这个" |

**红线**（写入系统提示词并在服务端校验）：不承诺效果、不做医疗/法律/投资建议、不下绝对断语（"必离""必死"）、不诱导消费、危机信号立即转介。

### 9.2 页面布局（竖屏）

```
┌─────────────────────────┐
│  ← 返回        命书 · 第3节 │  ← 主线锚点：始终显示在讲哪一节
├─────────────────────────┤
│                         │
│      〔小卜形象〕        │  ← 状态：听 / 想 / 说（呼吸光晕，不用打字机）
│      听你说…            │
│                         │
├─────────────────────────┤
│  你：身弱是什么意思      │  ← 对话转写区（大字，可上滑回看）
│  小卜：船小货多的意思…   │
│                         │
├─────────────────────────┤
│ ▸ 推荐卡片轨道（横滑）   │  ← 关键设计：不打断语音，静默出现
│ ┌────┐┌────┐┌────┐     │
│ │原文││课程││老师│     │
│ └────┘└────┘└────┘     │
├─────────────────────────┤
│  🔇静音   ✋打断   📞挂断  │
└─────────────────────────┘
```

**推荐卡片轨道**是本页的商业核心：
- 位置在对话区下方、控制条上方，**永不遮挡对话，也不打断语音**。
- 卡片随对话内容实时更新，带 0.3s 淡入，**无声**（不与语音抢注意力）。
- 卡片类型：古籍原文、课程、文章、圈子、老师咨询、工具、驿站服务。
- 每张卡片带**推荐理由**（"你刚问的'身弱'，《滴天髓》这一节讲得最清楚"）——推荐必须可解释，这是"顾问"而非"广告"的分界线。
- 用户点卡片 → 语音**自动转为静音待机**（不挂断），看完返回继续聊。

### 9.3 对话主线：跟着报告走

对话不是漫无目的的闲聊，而是**以报告为剧本**：
- 报告生成时同步产出 `dialogueOutline`（每节的要点与依据编号）——现有实现已具备。
- 小卜按节讲解，讲完一节问"这节还有不清楚的吗？没有的话我们看下一节"。
- 用户随时可跳节、可追问，追问回答后自动回到主线。
- 页面顶部始终显示当前节，用户永远知道"讲到哪了"。

这解决了用户指出的"普通语音大模型东一句西一句、没有条理"的问题。

### 9.4 语音之外的承接

- 通话结束自动生成**通话纪要**（聊了哪几节、提了什么问题、推荐了什么），存入报告页。
- 纪要里未看完的推荐卡片保留，用户事后可点。
- **这是把一次性语音流量沉淀为可复访资产的关键。**

### 10.1 已定价格

| 项目 | 价格 | 说明 |
| --- | --- | --- |
| **排盘报告** | **29 元/份** | **含 30 分钟语音对话分析** |
| 语音续费 | **2 元/分钟** | 报告内 30 分钟用尽后充值继续 |
| 广场智能体 | **2 元/分钟** | 同价，统一心智 |
| 广场试聊 | **免费 3 分钟/智能体，每用户最多试聊 5 个** | 合计 15 分钟免费额度 |
| 圈子语音助理 | **圈主充值，0.1 元/分钟** | 暂不向圈成员收费；前期默认开通并**赠圈主 500 分钟** |
| 圈主分成 | 待拍板 | 唯一仍未定项 |

### 10.2 成本与毛利核算（供决策参考，须知的两处风险）

供应商成本：Lite **0.041** 元/分钟，标准 **0.081** 元/分钟。

| 场景 | 收入 | 成本（Lite / 标准） | 毛利率 |
| --- | --- | --- | --- |
| 报告 29 元含 30 分钟（用满） | 29 元 | 1.23 / 2.43 元 + 模型约 0.1 元 | **95% / 91%** |
| 语音续费 1 分钟 | 2 元 | 0.041 / 0.081 元 | **98% / 96%** |
| 广场智能体 1 分钟 | 2 元 | 同上 | **98% / 96%** |

**⚠️ 风险一：圈子助理 0.1 元/分钟在标准档几乎无毛利。**
0.1 − 0.081 = **0.019 元/分钟（毛利 19%）**，且不含模型调用与知识检索成本，实际可能亏损。
→ **建议：圈子助理锁定 Lite 档（0.041），毛利 0.059 元/分钟（59%）**，并在圈主页面明示"标准音色需另行升级"。

**⚠️ 风险二：默认开通 + 赠 500 分钟，是按圈子数量线性放大的平台成本。**
每个圈子赠送成本 = 500 × 0.041 = **20.5 元**（Lite）／ 500 × 0.081 = **40.5 元**（标准）。
1000 个圈子 = **2.05 万 / 4.05 万元**；1 万个圈子 = **20.5 万 / 40.5 万元**。
→ **建议：**
1. 赠送额度锁定 Lite 档计价；
2. "默认开通"改为**默认可开通、圈主点一次确认**（避免给从不使用的圈子白发额度）；
3. 赠送额度设**有效期**（如 90 天）与**并发上限**，防止被压测式消耗；
4. 首期按圈子活跃度灰度放量（如仅 ACTIVE 且成员数 ≥ N 的圈子）。

**⚠️ 试聊成本同理**：每用户 15 分钟 = 0.615 元（Lite）。若 600 万用户中 10% 参与试聊 = **约 37 万元**。必须按实名用户 + 设备指纹双重限额，并灰度放量。

### 10.3 试聊 3 分钟的节奏设计（决定付费转化）

决策人明确指出："通过试聊让用户感兴趣、有好体验，有助于提高付费意愿，所以试聊和服务期的逻辑与节奏设计很重要。"

**底线原则：转化来自真实价值，不来自制造焦虑。** 明令禁止"你有大凶之兆，充值才能看"这类话术——既违规，也毁品牌。小卜的转化逻辑是"这 3 分钟你已经得到了有用的东西，后面还有更多"。

| 时间 | 目标 | 做什么 | 不做什么 |
| --- | --- | --- | --- |
| 0:00—0:20 | **立刻证明"我不一样"** | 开口第一句就给一个**只有排过盘才知道的具体事实**（"你这个盘火 46 分、水 10 分，财旺身弱，这是最关键的一点"） | 不寒暄、不自我介绍、不问"你想了解什么呢~" |
| 0:20—2:00 | **完成一个价值闭环** | 针对用户的真问题给出**可用的完整结论**，含依据（"《滴天髓》讲…所以你适合…"） | 不铺垫、不吊胃口、不半途而止 |
| 2:00—2:40 | **让缺口具体可见** | 明确说出**还剩什么没讲**（"你这盘还有三处关键：戊寅大运的转折、巳午未三会的影响、天乙贵人的用法"） | 不模糊暗示（"还有很多秘密哦"），要具体到条目 |
| 2:40—3:00 | **自然收束** | 给一句可立刻执行的建议 + 说明下一步（报告含 30 分钟完整分析） | 不催促、不倒计时压迫、不重复推销 |

**试聊的技术约束**：
- 剩余时间在 **0:30 时提示一次**（轻量、不打断），不做全程倒计时（压迫感会降低体验）。
- 到点后**给 30 秒宽限说完当前这句**，绝不半句话切断（切断是体验灾难，直接毁掉付费意愿）。
- 试聊结束自动生成**试聊纪要**（聊了什么、还有什么没讲），留在页面上可回看——这是转化的第二次机会。
- 5 个智能体的试聊额度**互相独立**，鼓励用户横向探索（这是广场的分发价值）。

### 10.4 报告内 30 分钟服务期的节奏设计

30 分钟很长，必须有结构，否则用户会觉得"聊了半天没说清"。

| 阶段 | 时长 | 内容 |
| --- | --- | --- |
| 开场 | 0—3 分钟 | 先讲**这 30 分钟会给你什么**（报告 7 段的地图），再给主线结论 |
| 主体 | 3—25 分钟 | 按报告章节推进，每节讲完主动问"这节清楚了吗"，用户可随时跳节/追问，答完自动回主线 |
| 收束 | 25—29 分钟 | **在 25 分钟处提示"还有 5 分钟"**，梳理要点 + 给可执行建议 |
| 结束 | 29—30 分钟 | 生成通话纪要，说明未讲部分与续费方式 |

**安全收尾规则**（写入服务端）：
- 剩余 5 分钟、1 分钟各提示一次。
- 到点后**不立即挂断**：给 60 秒宽限完成当前回答，再进入"是否继续"的选择。
- 续费后**无缝接续**当前话题（上下文不丢），不要求用户重说一遍。
- 用户主动挂断时，未用完的分钟**保留在该报告名下**，下次可继续用（避免"怕浪费而不敢挂"的焦虑）。

### 10.5 圈子语音助理的角色识别

决策人要求："要能区分圈成员角色，根据不同角色有不同的回答角度。"

| 角色 | 回答角度 | 知识边界 |
| --- | --- | --- |
| **圈主** | 经营视角：成员动态、内容建议、答疑热点汇总 | 可见本圈全部公开知识 + 经营数据摘要 |
| **管理员** | 协作视角：待办、审核、活动执行 | 本圈知识 + 管理事务 |
| **付费会员/学员** | 学习视角：按其学习进度深入讲解，可展开付费内容 | 本圈知识含付费部分 |
| **普通成员** | 入门视角：概念优先、引导到公开内容 | 本圈公开知识 |
| **游客/未入圈** | 介绍视角：讲这个圈是做什么的、适合谁 | **仅圈子公开简介**，不展开圈内知识 |

**实现要点**：角色从平台成员关系实时取得（不信任客户端传参）；知识检索在服务端按角色过滤；同一问题不同角色得到不同**深度**而非不同**事实**（不能对成员说 A、对游客说 B，那是双标）。

### 10.6 仍待拍板

| **P6** | 六爻/奇门/六壬/紫微报告（复用骨架，各自图形与书目） | 紫微需先补书（L4-1） |
