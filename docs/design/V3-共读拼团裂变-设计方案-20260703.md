# V3 共读拼团裂变 — 设计方案

> 2026-07-03 · 裂变库 V3 · 自主拍板 · 纯学习激励无资金（合规安全）

## 一、玩法

「7天共读《论语》」：发起人建共读组(设目标书+目标章节数+天数)→分享拉人(3-5人成团)→满员开读→周期内各自在古籍馆阅读→全员完成目标进度 → 每人得学分加成+共读结业卡。缺人时主动邀请拉新=裂变。

## 二、合规

纯学习激励：学分是荣誉成长值(user-growth·不可兑现)，无任何资金/拼团支付。与商城 GroupBuy(支付拼团)物理隔离——独立模型，不碰 marketing/shop/commission。

## 三、数据模型（复用 GroupBuy 语义但独立表）

`SharedReadingGroup`：
- id / classicBookId / bookTitle(冗余) / initiatorId / targetChapters(目标章节数·如全书或前N章) / minMembers(默认3) / maxMembers(默认5) / durationDays(默认7) / startAt? / deadline? / status(RECRUITING|READING|COMPLETED|EXPIRED·默认RECRUITING) / inviteToken(@unique) / createdAt
- @@index([status]) @@index([initiatorId])

`SharedReadingMember`：
- id / groupId / userId / isLeader(Bool) / joinedAt / completedChapters(Int·该成员已读目标内章节数) / completed(Bool) / rewardedAt?(学分发放时间·防重发)
- @@unique([groupId, userId]) @@index([groupId])

## 四、状态流转

- RECRUITING：招募中(未满 minMembers)。满 minMembers → 发起人开读或自动开读(status=READING·startAt=now·deadline=now+durationDays)
- READING：进行中。成员阅读古籍→进度对接(见五)→completedChapters 更新→达 targetChapters 则该成员 completed=true
- 全员 completed 或 deadline 到：结算(见六)→COMPLETED / EXPIRED

## 五、进度对接（复用古籍阅读进度）

用户在古籍馆读书本已写 ClassicReadingProgress(userId,bookId,chapterId,progress)。共读进度=统计该成员在 classicBookId 下 progress≥某阈值(如80%)的章节数。
- 拉取式：GET 组详情时实时统计各成员完成章节数(count ClassicReadingProgress where userId,bookId,progress≥80)，对比 targetChapters
- 或推送式钩子：classic updateReadingProgress 时检测该用户是否在 READING 共读组、更新 completedChapters——**选拉取式**(解耦·避免古籍模块依赖共读·GET 时算)

## 六、结算

全员 completed 或 deadline：
- 全员完成 → 每人 addExp(共读奖励·如+50学分)+发共读结业成就(shared_reading_complete)+可生成结业卡(前端 canvas·不建表)
- 部分完成 → 已完成者仍得奖励(鼓励)·未完成不罚
- rewardedAt 防重发

## 七、端点契约（sharedreading 模块·前缀 shared-reading）

1. `POST /shared-reading/groups` body { classicBookId, targetChapters?, minMembers?, maxMembers?, durationDays? } → 建组(发起人自动入组 isLeader)+inviteToken → { groupId, inviteToken, shareUrl }
2. `GET /shared-reading/groups/:id`（登录·成员或公开预览）→ { book, status, targetChapters, deadline, members:[{ nickname, completedChapters, completed, isLeader }], myProgress, memberCount, minMembers }（实时统计进度）
3. `GET /shared-reading/invite/:token`（公开）→ { bookTitle, initiatorNickname, memberCount, minMembers, status }（招募卡）
4. `POST /shared-reading/join` body { token } → 校验(未满+未加入+RECRUITING) → 入组 → 满 minMembers 自动转 READING → { groupId }
5. `POST /shared-reading/groups/:id/start`（发起人·手动开读·满 minMembers）→ READING
6. `GET /shared-reading/mine` → 我参与的共读组列表
7. `POST /shared-reading/groups/:id/settle`（可 cron 或访问时惰性结算·全员完成/deadline 到触发发奖）——**用惰性结算**：GET 详情时若达成条件且未结算则结算发奖
8. `DELETE /shared-reading/groups/:id/leave`（退组·RECRUITING 期可退·READING 后不可退）

## 八、前端

## 九、裂变闭环
建组缺人→分享招募(带 token+ref)→好友加入(拉新)→共读完成结业卡再传播。学习社交双驱动，零资金 R 安全。
