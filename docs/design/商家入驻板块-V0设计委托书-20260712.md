## 〇、定位与一句话（先读）

**商家板块 = 平台电商的「供货端」，是全平台商品池的唯一入口。** 商家把商品放进平台商品池；圈主 / 驿站 / 商城 / 站长主推位等都是这批商品的**分销渠道**（商家不直接运营 C 端店铺流量，只管供货、履约、结算）。

因此本板块的重心是：**入驻要顺、商品要好上、订单要好管、钱要清楚**。装修/引流/内容运营都不是商家的活。

**现状**：商家板块共 **22 页**（入驻 7 + 后台 15），补丁迭代导致——商品编辑器顺序混乱且有硬伤（详情图加不了、轮播无主图标识、价格与 SKU 价冲突）、后台多页职责重合或空转、入驻链路冗长。**本次推翻重做前端**（后端 68 端点大体完整，只重 UI 与交互 + 狠做减法 + 重构商品编辑器）。

## 一、角色

| 角色 | 说明 |
|---|---|
| **商家（店主）** | 入驻主体，管理店铺、商品、订单、结算。**无独立账号体系**——沿用总平台用户身份，不单独登录/设密码。 |
| **店铺操作员** | 官方旗舰店/大商家可加多操作员，操作员**以店铺身份**发布与管理（归属仍记店主），仅做鉴权与审计，不改分佣归属。 |

> 平台侧审核（入驻审批、商品审核、违规处置、结算发放）在**管理后台**完成，不在本委托范围（本委托只做**商家自己用的移动端**）。

## 二、页面架构总览（22 页 → 砍并为 13 页）

### 砍并原则
- **入驻链路收敛**（7 → 4）：介绍/条款合一；申请与改申请合一（一张可编辑重提的表单）；签约与保证金合一（当前**免保证金/模拟到账**态，别做成复杂财务页）。
- **后台去重合**（15 → 9）：数据分析/内容统计并入工作台；通知/咨询/违规三页合并为「消息中心」三态；店铺资料与预览合并；新增「操作员管理」。
- **诚实降级**：后端无强支撑的（如深度 analytics、圈子绑定 circle-binding）并入相邻页或做占位说明，不硬撑独立页。

## 三、核心重构：商品编辑器 B3（本委托灵魂·重点出稿）

现状硬伤要一次性解决：**顺序混乱、详情图加不了、轮播无主图标识、价格与 SKU 价冲突**。参照平台课程编辑器已确立的「全屏分区块 + 右侧手机预览」范式重做。

### 3.1 结构（全屏编辑页·左侧从上到下分区块，右侧手机实时预览）

1. **商品主图**（1 张·**1:1** 正方·800×800）：单图上传裁剪，标注推荐尺寸；这是列表卡与详情首图。
2. **基本信息**：标题、纯文本卖点简介、类目、标签。
3. **轮播图**（多图·**1:1**·最多 5-8 张）：多图上传可拖拽排序；**第 1 张标"主图"角标**，其余为轮播；明确区分主图与轮播（解决"轮播无标识"）。
4. **商品详情图**（多图·**宽 750px 不限高**）：多图上传、可拖拽排序，纵向拼成详情长图（**这是"详情加不了图"要修复的地方——必须能连续加多张**）。**无富文本编辑器**（与课程编辑器一致的新范式）。
5. **价格与规格**（重点·解决价格/SKU 冲突）：见 3.2。
6. **库存**：无 SKU 时单一库存；有 SKU 时按 SKU 库存。
7. **上架控制**：存草稿 / 保存并上架 / 定时上下架。

### 3.2 价格与 SKU 的口径（把冲突讲死）
- **划线价（原价）**：始终是商品级一个值，仅用于展示"原价 ¥X"划线，**不参与结算**。
- **无 SKU 商品**：用**商品级售价**（一个促销价/现价）结算。
- **有 SKU 商品**：**售价由各 SKU 各自定价**，商品级不再单填售价，而是**自动显示价格区间**"¥最低 ~ ¥最高"；下单按所选 SKU 价结算。
- 编辑器交互：一个「是否多规格」开关。关→只填商品级售价+库存；开→进入 SKU 矩阵（规格名/值组合，每行填 SKU 售价+库存+可选 SKU 图），商品级售价框隐藏、改显区间预览。
- V0 要出：**无 SKU 态**与**有 SKU 态（含 SKU 矩阵表）**两稿。

### 3.3 要 V0 出的稿
B3 全屏编辑器：①整页分区块布局 + 右侧预览 ②详情图多图拖拽排序态 ③价格区块"无 SKU / 有 SKU 矩阵"两态 ④各上传位的**未上传占位**（虚线框 + 推荐尺寸小字）。

## 四、数据能力边界（都是现成后端，画的元素要能对上）

- **入驻**：apply / application(GET·PUT 改) / submit / deposit-info / pay-deposit（模拟）/ agreement-preview / sign-agreement。
- **商品**：products 列表 + CRUD、products/:id/skus（SKU 增）、skus/:skuId（删）、products/:id/list·unlist（上下架）。
- **订单**：orders 列表 + 详情（发货/物流/售后随后端字段）。
- **店铺**：dashboard、profile(GET·PUT)、my/metrics、my/credit。
- **结算**：settlements 列表/详情（商家只读自己的；生成/发放在管理后台）。
- **操作员**：MerchantMember（:id/members GET·POST·DELETE）——B8 用。
- **消息**：punishments（违规）+ 通知 + inquiries（咨询）。
- **禁止画的能力**：真实保证金收银台、店铺流量投放/广告、深度 BI 报表（后端无·本次不做）。

## 五、图片规范（接平台上传规范）

| 位置 | 比例 | 建议尺寸 | 适配 |
|---|---|---|---|
| 商品主图 | **1:1** | 800×800 | 列表卡/详情首图·居中裁剪 |

## 六、视觉规范
全站统一 token：宣纸白 #FAF8F5 页底、卡片白 #FFFFFF、朱红 #C41E3A（主按钮/激活/价格）、金 #C9A96E（价值强调/收益）、文字 #2C2C2C/#6E6E73/#999、圆角 18px·胶囊 999px、页边距 20px。
- 商家后台偏"效率工具"气质：数据数字大、表单清晰、状态标签明确；克制留白、国学雅致、禁荧光渐变与娱乐贴纸感。
- ⚠️ 禁同色系底字；封面图上文字必须有渐变衬底。

---

## 七、技术兼容（安卓微信 X5 内核）
1. 封面/比例用 padding-top 方案（不用 aspect-ratio，稿内标注比例）。
2. 不用 writing-mode 竖排。
3. 表单/上传/SKU 矩阵用实色卡片，毛玻璃不承载关键信息。
4. 商品编辑器的拖拽排序、SKU 矩阵、图片裁剪由我方实现交互，V0 只出视觉与态。

## 八、交付格式
1. 纯 HTML 静态稿，390px 移动端宽，稿内 HTML 注释标数据来源与交互（注释即规格）。
2. 交付清单：
   - **入驻**：M1 成为商家 / M2 入驻申请 / M3 申请状态（三态）/ M4 签约开通。

   - 附《后端待办清单.md》（若发现缺口列出）。
3. **两阶段**：先线框级信息架构稿（确认砍并结构 + 商品编辑器交互 + 价格/SKU 口径）→ 确认 → 视觉稿。**商品编辑器 B3（第三节）是本委托灵魂，请重点设计。**
