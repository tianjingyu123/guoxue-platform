## 一、拍板规则 → 精确语义（七条）

| # | 董事长原话要点 | 工程语义（Fable 解释·标注处可复议） |
|---|---|---|
| 1 | 佣金按商品利润逐品制定，只设"站长推广佣金"一档 | `Product.commissionRate`（新增·可空）：设置了则覆盖类型级默认（CommissionConfig.rateA），没设则回落默认。admin 商品编辑只暴露这一档；平台抽成与运营商管理奖由系统规则推导，不逐品配 |
| 2 | 线上运营商拿名下站长分站推广收入的 10% | 管理奖 = **站长实得佣金 × 10%**（✅P1 执行时查实：现行基数本就是站长佣金额，无需迁移；真正的改制点=比率来源从等级率 8-20% 改为 mgmtRate??渠道默认 10%/20%）。**平台额外支出，不从站长佣金中扣减**（Fable 解释：保站长积极性·与现行口径一致·可复议） |
| 3 | 驿站开通时系统赠送"高级线下运营商"，管理佣金=名下分站的 20% | 驿站 ACTIVE 时自动创建 `Operator(channelType=OFFLINE)` 绑定驿站主，其名下分站的管理奖率 20%（其余权益同线下运营商） |
| 4 | 临时推广链接 > 永久归属链接（近成交优先） | last-click 归因：下单时若存在**有效期内**的临时渠道点击记录，`Order.tempReferrerId` 生效并优先于 `User.attributionStationId` 永久归属。**有效窗口 7 天，同窗口内多次点击取最后一次**（Fable 解释：行业通行 last-click 7 天窗·可复议） |
| 5 | 佣金锁定资格只有站长；普通用户推荐无佣金，可给其他奖励 | 抽象为**渠道主体（ChannelSubject）**：`STATION 分站 / CIRCLE 圈子 / OFFLINE_STATION 驿站` 三类可锁佣；普通用户的分享链接不写 tempReferrerId，成交改发**创作/推广积分**（接学分体系） |
| 6 | 直播间购买佣金归发起直播的圈子；文章、短视频同理 | `Order.sourceContentType/sourceContentId`（新增）记录内容来源；内容所属渠道主体=归因对象（直播→圈子→入圈主账；文章/视频→若作者具备渠道身份则归其渠道，否则给作者积分） |
| 7 | 讲座、课程类推广佣金暂定 20%，后台可调 | CommissionConfig 课程/讲座类 rateA 统一置 20%（admin 分佣规则页已有编辑能力·核对后调整种子值） |

## 二、现状盘点（改造起点·文件坐标）

- **分佣引擎** `modules/commission/commission.service.ts`：rateA(站长)/rateB(平台)/rateC(运营商) 按订单类型取 `CommissionConfig`；运营商管理奖现行=订单金额×等级率（SILVER 8%/GOLD 12%/DIAMOND 15%/BLACK_GOLD 20%，L21-26 硬编码+config 可覆盖）；**无商品级佣金**。
- **归因基建**：`User.attributionStationId`（首次登录永久锁定）+ `Order.referrerId/tempReferrerId`，且 `effectiveReferrerId = tempReferrerId || referrerId` **临时优先的取值逻辑已存在**（commission.service.ts L131）；`ReferralLink` 短码+trackClick 已有。缺：临时点击的**落库与时效窗**、**渠道资格校验**（现在任何用户的 ref 都可能进 tempReferrerId）。
- **渠道主体**：Station（operatorId 归属运营商）/ Operator（level 四档·parentOperatorId 树形·**无线上线下之分**）/ StationOffline（与 Operator 无关联）/ Circle（可绑 stationId）。
- **内容挂品**：LiveProduct / ArticleRecommend(PRODUCT) / VideoProduct 三表齐备；**Order 无内容来源字段**——从直播/文章/视频进入购买时归因断链。
- **积分接口**：`UserGrowthService.addExp(userId, exp, source)` + `ContentExpService`（学分=质量系数·日上限 1500）。
- **结算**：LedgerEntry 状态机 PENDING→SETTLED/FROZEN/REVERSED·缓冲期·审批阈值·冲正幂等（B1/P2-c 已上线），本方案只改**入账前的归因判定**，不动状态机。

## 三、目标模型与判定流程

### 3.1 数据模型变更（全部增量·不删列）

```
Product          + commissionRate Decimal?      // 逐品站长佣金率（空=用类型默认）
Order            + sourceContentType String?    // LIVE / ARTICLE / VIDEO
                 + sourceContentId   String?
Operator         + channelType String @default("ONLINE")   // ONLINE / OFFLINE
                 + mgmtRate    Decimal?                     // 空=按 channelType 默认(0.10/0.20)
ChannelClick(新表) id / subjectType(STATION|CIRCLE|OFFLINE_STATION) / subjectId
                 / userId(被触达用户) / targetType / targetId / clickedAt / expiresAt(+7d)
                 @@index([userId, targetType, targetId, clickedAt])
StationOffline   + operatorId String?           // 开通时赠送的 OFFLINE 运营商回链
```

### 3.2 下单归因判定顺序（order.service 下单时执行·结果写死在 Order 上）

```
1. 查 ChannelClick：该用户对该商品（或全店）7 天内最后一次【渠道主体】点击
   → 命中：Order.tempReferrerId = 渠道受益人，记录 subjectType（临时链接优先·近成交）
2. 未命中 → 用户永久归属（User.attributionStationId）→ Order.referrerId（现行逻辑不变）
3. 两者皆无 → 平台自然流量，无佣金
4. 若下单入口带内容来源（直播间/文章/视频）：写 sourceContentType/Id；
   该内容所属渠道主体的 ChannelClick 视为已发生（进直播间/打开文章≈点击）
5. 分享者非渠道主体：不产生 ChannelClick，成交后走积分奖励（§3.4）
```

### 3.3 佣金计算（commission.service 改造）

```
站长/渠道佣金 = 订单额 × (Product.commissionRate ?? CommissionConfig.rateA)
  受益人按 subjectType：STATION→站长 / CIRCLE→圈主 / OFFLINE_STATION→驿站主
  LedgerEntry.role 增 CIRCLE / OFFLINE_STATION 两枚举值

运营商管理奖（仅 subjectType=STATION 时向上派生·其余渠道不派生管理奖）：
  = 站长佣金额 × (operator.mgmtRate ?? channelType 默认: ONLINE 10% / OFFLINE 20%)
  平台额外支出·不扣站长
  ⚠️ 等级率(8/12/15/20%)废止为默认值来源，存量 Operator 迁移见任务包佣-P1
```

### 3.4 非渠道用户的分享奖励（替代现金佣金）

- 普通用户分享链接成交 → `addExp(分享者, 商品价格档积分, "share_conversion")`，积分档=签到的 20-100 倍（对齐创-P1"优质创作=签到100倍"导向），并计成就（"荐书有功"系列）。
- 防刷：同一买家对同一分享者仅首单计，自购不计（复用自购立减判定）。

## 四、体验与后台

- admin 商品编辑：佣金一档输入框（空=默认·显示"默认 X%"占位）+ 预览"站长得 ¥X/运营商得 ¥Y"。
- 运营商工作台：管理奖报表改口径（名下站长佣金合计 × 我的比率），线下高级运营商标识。
- 站长素材中心：分享链接生成时即写 ChannelClick 短码语义（复用 ReferralLink，落 ChannelClick 在点击侧）。
- C 端无感知；圈子直播间/文章/视频的"讲解中商品"购买链路自动带来源参数。

## 五、合规红线核对（R1 两级）

- 第一级：渠道主体佣金（分站/圈子/驿站·三选一，互斥不叠加）。
- 第二级：运营商管理奖（仅 STATION 渠道向上一层）。
- 圈子/驿站渠道**不向上派生**任何抽成；Operator.parentOperatorId 树形关系**不参与计酬**（现行铁律延续）→ 任何订单最多两级计酬 ✓。
- 普通用户分享=积分非现金 → 不构成计酬层级 ✓。

## 六、普通模型任务包（4 批·文件隔离·可并行度标注）

> 每批验收必含：tsc 0 / 受影响域 jest 全过 / **所属 controller 旧 spec 必跑**（纪律）/ 端到端 curl 实测。

### 佣-V2-P1 商品级佣金 + 运营商比例改制（串行·动公共 schema）
- schema：Product.commissionRate / Operator.channelType+mgmtRate（增量 SQL·勿 db push）
- commission.service：佣金取值链（Product 覆盖→Config 默认）；管理奖基数改站长佣金额×(mgmtRate??默认10%/20%)；存量 Operator 全部 channelType=ONLINE、mgmtRate=NULL（=10%）——**等级率作废公告入 admin 提示**
- admin：商品编辑佣金一档 + 分佣规则页课程类 rateA=20% 种子
- 单测：逐品覆盖/回落默认/基数换算/两级封顶

### 佣-V2-P2 渠道主体与临时链接（串行·依赖 P1 schema）
- ChannelClick 表 + 点击落库端点（复用 ReferralLink 短码解析·校验 subject 资格：站长有 Station/圈主有 Circle/驿站主有 StationOffline）
- order.service 下单归因判定顺序（§3.2）·7 天窗 last-click·非渠道分享不写 temp
- commission.service 受益人按 subjectType 路由（LedgerEntry.role 增枚举）
- 单测：临时抢佣/窗口过期回落永久/非渠道不生效/自购不计

### 佣-V2-P3 内容场景归因（可与 P4 并行·不同文件）
- Order.sourceContentType/Id + 直播间/文章/视频三入口购买链路带参（前端 H5 三处+后端）
- 直播=发起圈子的 ChannelClick 视同发生；文章/视频作者按渠道身份路由或转积分
- 驿站开通钩子：自动建 OFFLINE Operator+回链 StationOffline.operatorId（offline-onboarding.service）
- 单测+e2e：直播间下单归圈主账·驿站开通赠运营商幂等

### 佣-V2-P4 分享积分奖励 + 报表（可与 P3 并行）
- share_conversion 积分发放（addExp 接线·防刷·成就系列）
- 运营商工作台管理奖新口径报表 + 线下高级标识；站长端"被临时抢佣"明细（透明化防纠纷）
- 单测：积分档位/首单限定/报表口径

**部署序**：P1→P2 上线后灰度观察 3 天（灰度开关：新归因判定 ConfigSystem 可回旧逻辑），再上 P3/P4。

## 七、风险与回滚

- 最大风险=归因变更引发站长纠纷 → P4 的"被抢佣明细"透明化 + 灰度开关回切旧逻辑（tempReferrerId 本就存在，回切=不写新 ChannelClick 即回到现状）。
- 管理奖基数变更影响运营商收入预期 → 上线前 admin 公告 + 报表新旧口径对照一个结算周期。
- 资金安全：全部走现有 LedgerEntry 状态机（缓冲期/审批阈值/冲正幂等不动），无新资金通路。
