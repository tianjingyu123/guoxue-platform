# 赛事全闭环二期 · 设计方案

> 2026-07-04 · 补完对象：赛事原始提示词四阶段中缺失的后半闭环（创建系统/自动流转/直播评审/强制分享/人才签约）
> 生态定位（引总设计）：赛事=L2→L3 选拔漏斗+品牌事件+拉新裂变三合一，**不是独立收入线**；北极星=获奖者签约转化率
> 已有地基：参赛侧 9 页✅（报名/答题·切屏防作弊/成绩/证书/海报/档案馆）· 判分契约✅ · 直播分档与低延时播放器✅（C5/C1）· 研究院人才库与签约讲师体系✅ · COMPETITION_ENABLED 门控

## 一、闭环全景（补完后）

```
【创建】admin 赛事创建系统（赛制/赛程/评审团/奖品可配）
   ↓
【报名】选手报名+分享承诺勾选（获奖后参与赛后分享）
   ↓
【流转】多阶段状态机自动运转：海选(答题)→初赛→复赛→决赛(直播PK)
        每阶段结束自动：判分→晋级名单公示→淘汰通知→生成下一场
   ↓
【决赛】直播评审联动：选手连麦 · 评审多维打分+评语 · 观众投票(可配权重) · 实时排名
   ↓
【传播】自动成绩单+荣誉海报(已有) · 获奖者赛后分享直播自动排期
   ↓
【沉淀】人才能力画像 → admin 人才看板 → 一键研究院签约邀请
        赛事专题归档(已有) + 决赛回放/冠军复盘 → 大师讲座知识库(D4 素材)
```

## 二、核心模块设计

### 2.1 赛事创建系统（admin·新建）
- Competition 模型扩展（增量列）：`format`(QUIZ|LIVE_PK|HYBRID)、`stagesConfig Json`（阶段数组：名称/赛制/起止/晋级人数或比例/判分规则）、`judgePanel Json`（评委 userId+头衔+权重）、`voteWeight`（观众票权重 0-0.3）、`prizes Json`、`shareCommitmentRequired Boolean`
- admin 页：赛事列表/创建向导（四步：基本信息→阶段配置→评审团→奖品与承诺）/选手管理（审核·已有端点）/进程监控
- AI 组卷：按题库知识点+难度分布自动组卷（题库管理已有·补组卷策略端点）

### 2.2 赛程自动流转（状态机+cron）
- 新表 `CompetitionStage`：competitionId/seq/name/format/startAt/endAt/advanceRule(Json)/status(PENDING|RUNNING|JUDGING|DONE)
- 流转 cron（runExclusive）：到点开赛→到点收卷判分→按 advanceRule 生成晋级名单→公示+站内通知（晋级/淘汰双话术）→创建下一阶段场次；全程幂等可重跑
- 人工兜底：admin 可暂停/手工调整名单（审计留痕）——自动为主、人工兜底为辅

### 2.3 直播评审联动（决赛·复用直播地基）
- 决赛直播间挂「赛事面板」组件：当前选手/倒计时/评审席
- `JudgeScore`：stageId/judgeId/contestantId/维度分 Json（按赛事配置的维度：功底/表达/临场/案例分析）/评语/submittedAt——评审端打分页（H5 即可·评委扫码进）
- `AudienceVote`：stageId/contestantId/userId 唯一约束（一人一票·纯荣誉不涉资金）
- 实时排名 = Σ(评审均分×(1-voteWeight)) + 观众票归一×voteWeight，直播间实时榜轮询/推送
- AI 评语辅助：评审打完维度分，AI 按分数草拟评语供修改（降低评委负担）
- 实战盲评赛制（创新·可选开关）：决赛环节用授权脱敏案例现场解析，评审盲评（隐藏选手资历）——公信力卖点

### 2.4 强制分享机制（闭环的传播扣）
- 报名页勾选《赛后分享承诺》（shareCommitmentRequired 时必勾）：获奖后参与经验分享直播/案例复盘
- 赛后 cron：为获奖者自动创建「分享直播」排期（默认赛后 7/14 天两场）+ 站内提醒；admin 可调
- 分享直播回放自动挂赛事专题页+进研究院知识库（D4 内容源）

### 2.5 人才看板与一键签约（漏斗出口·对接研究院）
- 能力画像聚合视图（不建新表·查询聚合）：答题正确率/评审各维度均分/观众得票/直播表现（观看峰值/互动）/历史参赛轨迹
- admin「赛事人才看板」：按画像排序筛选 → 行动作「邀请签约」→ 复用研究院特邀席位机制（V6 破格引入）发出邀请通知 → 选手确认后进 talent-pool
- 获奖者主页自动挂赛事荣誉（复用 F1 认证徽章体系加赛事荣誉类型）

## 三、创新玩法（观赏性与传播）

1. **赛季制 IP**：春「经学杯」（论语/诗词答题）· 秋「实战杯」（命理案例）——全年赛历，档案馆自动成 IP 资产
2. **观众学分竞猜**：决赛前竞猜冠军（押学分·纯荣誉·猜中得成就+学分加成）——观赏参与感，零资金合规
3. **败者复活赛**：半决赛淘汰者由观众投票复活 1 名——话题性
4. **战报卡**：每阶段晋级自动生成战报海报（复用 V1 canvas 范式）带 ref——赛事自带裂变

## 四、合规红线

观众投票/竞猜全部纯荣誉零资金（R1）；案例使用须选手自备+授权+脱敏（R3）；赛事定性"传统文化知识与技能交流"（R4）；报名费走正规订单链路（已有）。

## 五、待拍板项

1. 观众票权重默认 20%（可配 0-30%）
2. 赛季制两大 IP 命名与首赛季时间
3. 分享承诺是否作为报名必选（原始需求="强制"·建议获奖者必选+未获奖自愿）
4. 学分竞猜玩法是否启用

## 六、普通模型任务包（4 批·串行）

| 批 | 内容 | 验收 |
|---|---|---|
| P1 创建系统 | Competition 增量列+CompetitionStage 表+admin 创建向导四步页+选手管理增强+AI组卷端点 | 建一个双阶段测试赛全流程配置成功 |
| P2 自动流转 | 流转 cron(幂等·runExclusive)+晋级判定+双话术通知+admin 进程监控页 | 测试赛自动开赛→判分→晋级→建下场·重跑幂等 |
| P3 直播评审联动 | JudgeScore/AudienceVote 表+评审打分页(H5)+直播间赛事面板+实时榜+AI评语 | 模拟决赛：3评委打分+观众投票→实时榜正确 |
| P4 传播与人才 | 分享承诺勾选+赛后自动排期 cron+人才看板(聚合查询)+一键签约邀请(接研究院特邀)+战报卡 | 获奖→自动排期→admin邀约→talent-pool 端到端 |

依赖：P1→P2→P3 串行；P4 可与 P3 并行。全程 COMPETITION_ENABLED 门控内开发，不影响生产。
