## 一、角色化数据看板（指标定义是核心交付，UI 复用现有看板框架）

### 1.1 老板视角（一屏定生死·9 个数）

| 指标 | 定义口径 | 预警线 |
|---|---|---|
| DAU / 新增注册 | TrackEvent 去重 userId / User.createdAt 当日 | 环比 -20% 标红 |
| GMV / 实收 | Order PAID 金额和 / 扣退款净额 | — |
| 付费率 | 当日付费去重用户/DAU | < 1% 关注 |
| 客单价 | 实收/付费用户 | — |
| 会员存量/新增 | MemberPurchase 有效期内去重 | 续费率 < 60% 预警 |
| 次日留存/7日留存 | 注册 cohort 在 D1/D7 有 TrackEvent | D1<25% 预警 |
| 分佣支出比 | 当日 CommissionRecord/GMV | > 25% 异常（两级封顶下理论上限） |
| B 端活跃 | 当日有动作的站长+商家+圈主数 | 生态健康核心数 |
| 资金对账状态 | settlement-reconcile 结果 | 有差异即红 |

### 1.2 运营视角
内容供给（新帖/新课/UGC 审核通过率）、渠道归因效果（ChannelClick→成交转化·佣-V2 数据）、活动效果（触点曝光/点击/成交·触点体系已有埋点）、哨兵告警摘要。

### 1.3 产品视角
功能渗透率（各模块 DAU/总 DAU）、页面漏斗（见下）、新功能采纳曲线、AI 使用量与满意度（点踩率）。

## 二、核心转化漏斗（4 条·基于 TrackEvent 补 6 个关键事件）

**需补埋的事件**（现在只有 page_view，漏斗需要动作事件）：`paipan_submit`、`member_page_view→member_pay_click→member_paid`（paid 从 Order 表回填不用埋）、`course_detail→add_cart/buy_click`、`share_click`、`register_step`。前端埋点走现有 track api，一次性补齐。

| 漏斗 | 步骤 | 关键流失点假设（上线后验证） |
|---|---|---|
| F1 激活 | 注册→首次排盘→次日回访 | 注册后不知道去哪（首页引导） |
| F2 会员 | 排盘结果页→会员页曝光→点购买→支付成功 | 结果页到会员页的转化入口强度 |
| F3 电商 | 商品曝光→详情→下单→支付 | 支付渠道摩擦（模拟支付期无真数据） |
| F4 从业者 | 工具使用→B 端入口点击→认证申请→首次出佣 | 入口太深（课题三判断的瓶颈2） |

**漏斗计算实现**：不引第三方分析系统。DashboardDaily 加漏斗聚合 job（每日按事件序列+同 userId+24h 窗口计数），存 FunnelDaily 表（funnel/step/count/date），admin 加漏斗页（条形递减图）。

## 三、用户标签体系（三层·全部批量 cron 计算，禁实时查询拖库）

### 3.1 事实标签（行为直推·UserTag 表 type=FACT）
活跃度（活跃/沉默7d/流失30d/回流）、付费深度（未付费/单次/复购/会员/高客单）、内容偏好 Top2（易经/风水/中医养生/诗词/国学启蒙——按浏览时长聚类，UserInterest 表已有底子）、角色（C端/创作者/站长/商家/驿站/多重）。

### 3.2 计算标签（规则推导·type=DERIVED）
- **价格敏感型**：只在活动期付费 / 多次进会员页未买 / 买最低档 SKU。
- **高潜从业者**：月排盘 > 20 次 + 浏览过 B 端页 + 未认证（课题三漏斗2的投放对象）。
- **流失风险**：活跃度骤降 + 会员将到期（CRM 提醒已有类似，对齐口径）。
- **鲸鱼用户**：累计消费 top 1%（专属客服/防流失池）。

### 3.3 预测标签（P2 阶段·有数据后再做，不在本批）
付费概率分/流失概率分（逻辑回归就够，不上深度学习）。

### 3.4 使用出口
①admin 用户列表按标签筛选（运营圈人）；②精准推送（站内信/未来短信按标签投）；③**R2 红线**：标签只能用于"给优惠/给内容"，禁止用于差异化定价（杀熟），代码评审时盯死。

## 四、AI 运营周报（在每日简报基础上升维）

- **每周一 09:00** cron：聚合上周 DashboardDaily 7 天 + 漏斗周环比 + 标签迁移（多少人从活跃→沉默）+ 哨兵告警周汇总 → 喂 DeepSeek 出三段式：**本周结论（3 条）/ 异常与原因假设（2-3 条）/ 下周建议动作（3 条，必须具体到"给谁做什么"）**。
- 与日简报差异：日报看"有没有异常"，周报看"趋势与动作"。附"上周建议执行情况回顾"（把上周建议存表，本周核对）——让 AI 建议形成闭环而非一次性输出。
- 送达：站内信+群 webhook（密钥后）。
