V0 待办 #36 +《circle-notifications.html》还原。本地已完成，**未 commit、未部署**。

## 一、表/字段决策：复用全局 Notification，不建新表

- 圈内通知中心 = 全局 `Notification` 表按圈子分类过滤的**视图**（消息中心归主系统，与 V0 交付总览一致）。
- 补两列（幂等 manual SQL）：`apps/server/prisma/manual/2026-07-11-circle-notifications.sql`
  - `category TEXT`：四分类 `INTERACT`(互动) / `TRADE`(交易) / `GOVERN`(圈务) / `LIVE`(直播)；非圈子通知为 NULL
  - `circleId TEXT`：事件所属圈子（无外键）
  - 索引 `Notification_userId_category_createdAt_idx`
- schema.prisma 已同步补字段与 @@index；**未跑 prisma generate**——代码全部经 `$queryRawUnsafe`/`$executeRawUnsafe` 访问新列（沿用 CircleJoinRequest 绕锁范式）。
- **本地库已应用**（列+索引已验证存在）。**生产上线时须先执行该 SQL**：
  `cd apps/server && npx prisma db execute --file prisma/manual/2026-07-11-circle-notifications.sql --schema prisma/schema.prisma`
  （列缺失时：发送侧分类落库 catch 不阻断主流程，但 `/notifications/circle` 端点会查询失败）

## 二、后端

### 端点（notification.controller.ts·均 JWT）
| 端点 | 说明 |
|---|---|
| `GET /notifications/circle?category=&page=&pageSize=` | 圈内通知列表（category 缺省=四类全部）+ `unread`{ALL/INTERACT/TRADE/GOVERN/LIVE} 未读分组计数 |
| `PUT /notifications/circle/read-all` | 圈内全部已读（body 可带 `{category}` 按类） |
| `PUT /notifications/:id/read` | 单条已读（复用既有端点） |

非法 category 抛 400「分类仅支持 INTERACT/TRADE/GOVERN/LIVE」。路由声明在 `:id` 之前防吞。

### 发送侧（notification.service.ts / dto）
- `SendNotificationDto`/`BatchSendDto` 增加可选 `category`(@IsIn 四类) + `circleId`。
- `send()`：create 后若带 category → 原生 UPDATE 补写两列（失败仅 warn 不阻断）。
- `batchSend()`：createMany 拿不到 id → 按 `userId=ANY($) AND type AND targetId AND category IS NULL AND createdAt>now()-5min` 窗口补打标。

## 六、坑

- **prisma client 不认新列**：不跑 generate 的前提下，凡涉及 category/circleId 的读写必须原生 SQL；`send()` 是「create+原生 UPDATE 补写」两步，极端情况下（补写前崩溃）通知存在但无分类，只影响圈内视图收录，不丢通知。
- **batchSend 打标是窗口式**（5 分钟内同 type+targetId 未分类记录），理论上可能把同型旧记录一并打标——同型必属同类，影响可接受。
- 本仓多条并行工作线同时在改 circle/interaction/live/growth（治理 TODO 批、直播 #21/#25、CircleInsightService），编辑时遇到多次「文件已被修改」需重读重放；期间 circle.controller.spec 曾因并行线半成品短暂红，最终全绿复验过。
- schema↔DB 既有漂移（非本轮引入）：schema 有 `@@index([userId, isRead, createdAt])` 但 DB 无该索引。
- COUNT(*) 原生查询返回 BigInt → SQL 里 `::int` + Number() 双保险。
